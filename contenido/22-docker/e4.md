## Enunciado

Los comandos `docker run` de la documentación interna son largos y difíciles de revisar. Escribe `analizar_run(comando)` que lo convierta en un diccionario:

| Clave | Opciones | Valor |
|---|---|---|
| `imagen` | El primer argumento que no es opción | `"telco-pipeline:1.0"` |
| `argumentos` | Todo lo que sigue a la imagen | Lista |
| `nombre` | `--name X` | `"X"` o `None` |
| `borrar` | `--rm` | `True`/`False` |
| `segundo_plano` | `-d` | `True`/`False` |
| `volumenes` | `-v` / `--volume` (repetibles) | Lista de `(origen, destino, solo_lectura)` |
| `puertos` | `-p` / `--publish` | Lista de `(puerto_host, puerto_contenedor)` como enteros |
| `entorno` | `-e CLAVE=valor` / `--env` | Diccionario |
| `memoria` | `--memory 10g` o `--memory=10g` | `"10g"` o `None` |

Detalles importantes:

- Separa el comando con `shlex.split(comando, posix=True)` (respeta comillas). Ignora el `docker run` inicial.
- Las opciones largas aceptan `--opcion valor` y `--opcion=valor`.
- Un volumen puede tener **ruta de Windows** con letra de unidad: `D:\datos:/datos:ro` → `("D:\datos", "/datos", True)`. ¡El `:` de la unidad no separa!
- Una opción desconocida lanza `ValueError` con su nombre.

## Código inicial

```python
import shlex


def analizar_run(comando):
    pass


cmd = r'docker run --rm -v "D:\datos\20GB:/datos:ro" -e TELCO_PERIODO=202609 --memory=10g telco-pipeline:1.0 validar /datos'
print(analizar_run(cmd))
```

## Pruebas

```python
CMD = (r'docker run --rm -d --name bd -v "D:\datos\20GB:/datos:ro" --volume pgdata:/var/lib/postgresql/data '
       r'-p 5433:5432 --publish=8080:80 -e POSTGRES_PASSWORD=x -e "TELCO_NOMBRE=Facturación Telco" '

def prueba_completo():
    """Todas las opciones"""
    requiere("analizar_run")
    igual(analizar_run(CMD), {
        "imagen": "postgres:16",
        "argumentos": ["-c", "max_connections=50"],
        "nombre": "bd",
        "borrar": True,
        "segundo_plano": True,
        "volumenes": [("D:\\datos\\20GB", "/datos", True), ("pgdata", "/var/lib/postgresql/data", False)],
        "puertos": [(5433, 5432), (8080, 80)],
        "entorno": {"POSTGRES_PASSWORD": "x", "TELCO_NOMBRE": "Facturación Telco", "URL": "postgresql://u:p@h/db"},
        "memoria": "10g",
    })


def prueba_minimo():
    """Solo la imagen"""
    r = analizar_run("docker run python:3.12-slim")
    igual((r["imagen"], r["argumentos"], r["borrar"], r["volumenes"], r["entorno"], r["memoria"]),
          ("python:3.12-slim", [], False, [], {}, None))


def prueba_volumenes_linux():
    """Rutas de Linux y relativas"""
    r = analizar_run("docker run -v /home/carlos/datos:/datos -v ./salidas:/salidas:rw img")
    igual(r["volumenes"], [("/home/carlos/datos", "/datos", False), ("./salidas", "/salidas", False)])


def prueba_desconocida():
    """Opciones que no conoce"""
    e = lanza(ValueError, analizar_run, "docker run --privileged img")
    assert "--privileged" in str(e)
```

## Pista 1

Recorre los elementos con un índice, porque algunas opciones consumen el **siguiente**:

```python
partes = shlex.split(comando, posix=True)[2:]     # sin "docker run"
i = 0
while i < len(partes):
    p = partes[i]
    if not p.startswith("-"):
        r["imagen"], r["argumentos"] = p, partes[i + 1:]
        break
    nombre, _, valor = p.partition("=")
    if nombre in CON_VALOR and not valor:
        i += 1
        valor = partes[i]
    ...
    i += 1
```

`shlex` con `posix=True` interpreta `\` como escape **fuera** de comillas; por eso los ejemplos ponen la ruta de Windows entre comillas.

## Pista 2

Para el volumen con letra de unidad: si el texto empieza con una letra seguida de `:` y una barra (`re.match(r"[A-Za-z]:[\\/]", texto)`), el origen incluye esos dos primeros caracteres:

```python
unidad = ""
if re.match(r"[A-Za-z]:[\\/]", texto):
    unidad, texto = texto[:2], texto[2:]
origen, destino, *modo = texto.split(":")
return (unidad + origen, destino, modo == ["ro"])
```

## Solución

```python
import re
import shlex

CON_VALOR = {"--name", "-v", "--volume", "-p", "--publish", "-e", "--env", "--memory"}


def _volumen(texto):
    unidad = ""
    if re.match(r"[A-Za-z]:[\\/]", texto):
        unidad, texto = texto[:2], texto[2:]
    origen, destino, *modo = texto.split(":")
    return (unidad + origen, destino, modo == ["ro"])


def analizar_run(comando):
    r = {"imagen": None, "argumentos": [], "nombre": None, "borrar": False, "segundo_plano": False,
         "volumenes": [], "puertos": [], "entorno": {}, "memoria": None}
    partes = shlex.split(comando, posix=True)[2:]
    i = 0
    while i < len(partes):
        p = partes[i]
        if not p.startswith("-"):
            r["imagen"], r["argumentos"] = p, partes[i + 1:]
            break
        nombre, igual_, valor = p.partition("=")
        if nombre in CON_VALOR and not igual_:
            i += 1
            valor = partes[i]
        if nombre == "--rm":
            r["borrar"] = True
        elif nombre == "-d":
            r["segundo_plano"] = True
        elif nombre == "--name":
            r["nombre"] = valor
        elif nombre in ("-v", "--volume"):
            r["volumenes"].append(_volumen(valor))
        elif nombre in ("-p", "--publish"):
            host, contenedor = valor.split(":")
            r["puertos"].append((int(host), int(contenedor)))
        elif nombre in ("-e", "--env"):
            clave, _, contenido = valor.partition("=")
            r["entorno"][clave] = contenido
        elif nombre == "--memory":
            r["memoria"] = valor
        else:
            raise ValueError(f"Opción no soportada: {nombre}")
        i += 1
    return r


cmd = r'docker run --rm -v "D:\datos\20GB:/datos:ro" -e TELCO_PERIODO=202609 --memory=10g telco-pipeline:1.0 validar /datos'
print(analizar_run(cmd))
```

## Explicación

Un detalle sutil del enunciado: `--env=URL=postgresql://...` tiene **dos** signos `=`. `partition("=")` separa en el primero, así que el nombre de la opción es `--env` y el valor es `URL=postgresql://...`; luego, otro `partition` separa la variable de su valor (que puede tener `=` o `:` sin problema).

El caso de la letra de unidad es la causa de muchos errores reales en Windows: `D:\datos:/datos` tiene **dos** `:`, y una herramienta ingenua lo partiría en `D`, `\datos` y `/datos`. Docker resuelve exactamente igual que tu función: si empieza por letra, dos puntos y barra, es una unidad.

Fíjate en que todo lo que va **después** de la imagen son argumentos del programa del contenedor, aunque empiecen por `-`: `-c "max_connections=50"` es para PostgreSQL, no para Docker. Por eso el ciclo se detiene en la imagen.

Con este análisis podrías, por ejemplo, revisar automáticamente que ningún comando de la documentación pase una contraseña con `-e` en texto plano (debería usar `--env-file`), o generar el `compose.yaml` equivalente.
