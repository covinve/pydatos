**SOLID** son cinco principios de diseño orientado a objetos. No son leyes: son nombres para ideas que ya viste en este módulo, útiles para discutir un diseño con otras personas.

## Los cinco principios

| Letra | Principio | En una frase | En facturación |
|---|---|---|---|
| **S** | Responsabilidad única | Cada clase o módulo tiene **una** razón para cambiar | El lector de CSV cambia si cambia el formato; la regla del IVA, si cambia la ley. No en el mismo lugar |
| **O** | Abierto/cerrado | Abierto a extensión, cerrado a modificación | Agregar una regla de validación nueva sin editar el validador (ejercicio 6) |
| **L** | Sustitución de Liskov | Cualquier implementación de un contrato debe poder usarse en su lugar | `PlanesSQLite` y `PlanesCSV` se comportan igual ante `obtener`, incluso con un plan inexistente (ejercicio 8) |
| **I** | Segregación de interfaces | Contratos pequeños y específicos | Un caso de uso que solo lee planes no debería depender de un repositorio con `borrar` |
| **D** | Inversión de dependencias | Depender de abstracciones, no de detalles | `Conciliador(planes: RepositorioPlanes)`, no `Conciliador()` que crea un `PlanesCSV` |

## O: abierto a extensión

```pyrun
from dataclasses import dataclass


class Regla:
    nombre = "regla"

    def falla(self, cdr: dict) -> bool:
        raise NotImplementedError


class DuracionNegativa(Regla):
    nombre = "duracion_negativa"

    def falla(self, cdr):
        return int(cdr["duracion_seg"]) < 0


class TipoDesconocido(Regla):
    nombre = "tipo_desconocido"

    def falla(self, cdr):
        return cdr["tipo"] not in ("VOZ", "SMS", "DATOS")


class Validador:
    def __init__(self, reglas: list[Regla]):
        self.reglas = reglas

    def motivo(self, cdr: dict) -> str:
        return next((r.nombre for r in self.reglas if r.falla(cdr)), "valido")


# Una regla nueva del negocio: llamadas de más de 4 horas son sospechosas.
class LlamadaSospechosa(Regla):
    nombre = "llamada_sospechosa"

    def falla(self, cdr):
        return cdr["tipo"] == "VOZ" and int(cdr["duracion_seg"]) > 4 * 3600


v = Validador([TipoDesconocido(), DuracionNegativa(), LlamadaSospechosa()])     # el Validador no cambió
for cdr in [{"tipo": "VOZ", "duracion_seg": "120"}, {"tipo": "FAX", "duracion_seg": "1"},
            {"tipo": "VOZ", "duracion_seg": "-3"}, {"tipo": "VOZ", "duracion_seg": "20000"}]:
    print(cdr, "→", v.motivo(cdr))
```

## Estructura de un proyecto en capas

```text
conciliacion/
├── pyproject.toml
├── src/conciliacion/
│   ├── dominio/            # sin imports de E/S
│   │   ├── modelos.py      # Plan, Cliente, Factura, Periodo
│   │   └── reglas.py       # valor_voz, descuento, iva
│   ├── aplicacion/
│   │   ├── puertos.py      # Protocol: RepositorioPlanes, FuenteCDR, SalidaReporte
│   │   └── conciliar.py    # el caso de uso
│   ├── infraestructura/
│   │   ├── csv_.py         # adaptadores CSV
│   │   └── sqlite_.py      # adaptadores SQLite
│   └── cli.py              # raíz de composición (Typer)
└── tests/
    ├── unit/               # dominio y casos de uso con dobles en memoria: milisegundos
    ├── integracion/        # adaptadores contra archivos y bases reales: segundos
    └── test_arquitectura.py
```

## Pruebas de arquitectura

La regla de las dependencias se puede **verificar automáticamente** leyendo los `import` de cada archivo con `ast`:

```python
import ast
from pathlib import Path

PROHIBIDOS_EN_DOMINIO = {"pandas", "sqlite3", "csv", "requests", "sqlalchemy", "conciliacion.infraestructura"}


def importa(archivo: Path) -> set[str]:
    arbol = ast.parse(archivo.read_text(encoding="utf-8"))
    nombres = set()
    for nodo in ast.walk(arbol):
        if isinstance(nodo, ast.Import):
            nombres |= {a.name for a in nodo.names}
        elif isinstance(nodo, ast.ImportFrom) and nodo.module:
            nombres.add(nodo.module)
    return nombres


def test_dominio_no_depende_de_infraestructura():
    for archivo in Path("src/conciliacion/dominio").glob("*.py"):
        malos = {m for m in importa(archivo) for p in PROHIBIDOS_EN_DOMINIO if m == p or m.startswith(p + ".")}
        assert not malos, f"{archivo.name} importa {malos}"
```

Así, si alguien (tú mismo, con prisa, un viernes) agrega `import pandas` en el dominio, la prueba lo detiene.

:::capo El exceso también es un error
Una interfaz con una sola implementación que nunca cambiará, una fábrica para crear un objeto simple, cinco capas para un script de 80 líneas: eso es **sobreingeniería**, y hace el código más difícil de leer, no más fácil. Empieza simple; separa cuando duela (cuando quieras probar algo y no puedas, o cuando cambiar una cosa rompa otra).
:::

? Agregas una regla de validación nueva creando una clase, sin tocar el `Validador`. ¿Qué principio aplicas?
- [ ] Responsabilidad única
- [x] Abierto/cerrado
- [ ] Sustitución de Liskov
- [ ] Segregación de interfaces
> El validador está cerrado a modificación pero abierto a extensión con reglas nuevas.

? `PlanesSQLite.obtener` devuelve `None` para un plan inexistente, pero `PlanesCSV` lanza `PlanNoEncontrado`. ¿Qué principio se rompe?
- [ ] Abierto/cerrado
- [x] Sustitución de Liskov: las implementaciones del mismo contrato se comportan distinto
- [ ] Inversión de dependencias
- [ ] Ninguno
> Quien usa el puerto no puede confiar en él si cada implementación responde distinto al mismo caso.

? ¿Para qué sirve una prueba de arquitectura?
- [ ] Para medir el rendimiento
- [x] Para verificar automáticamente que, por ejemplo, el dominio no importe librerías de infraestructura
- [ ] Para dibujar diagramas
- [ ] Para probar la CLI
