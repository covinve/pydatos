## Enunciado

Vas a trasladar el validador a la base de datos: que sea **imposible** guardar un CDR inválido.

1. `crear_esquema(con)` activa las claves foráneas y crea:

| Tabla | Columnas y reglas |
|---|---|
| `planes` | `plan_id` TEXT clave primaria · `cargo_fijo` INTEGER obligatorio y mayor que 0 |
| `clientes` | `linea` TEXT clave primaria · `plan_id` TEXT obligatorio, debe existir en `planes` |
| `cdr` | `cdr_id` INTEGER clave primaria · `linea_origen` TEXT obligatorio, debe existir en `clientes` · `tipo` TEXT obligatorio, solo `VOZ`, `SMS` o `DATOS` · `fecha_inicio` TEXT obligatorio con formato válido `AAAA-MM-DD HH:MM:SS` · `duracion_seg` INTEGER obligatorio ≥ 0 · `mb` REAL obligatorio, 0 por defecto |

2. `cargar_cdr(con, filas)` recibe una lista de tuplas `(cdr_id, linea_origen, tipo, fecha_inicio, duracion_seg, mb)` y las inserta **una por una** atrapando `sqlite3.IntegrityError`. Devuelve `{"insertados": n, "rechazados": n}` y confirma al final.

import csv
import json
import sqlite3
from pathlib import Path

E = json.loads(Path("esperado.json").read_text(encoding="utf-8"))["cdr"]


def base():
    con = sqlite3.connect(":memory:")
    crear_esquema(con)
    with open("planes.csv", encoding="utf-8", newline="") as f:
        con.executemany("INSERT INTO planes (plan_id, cargo_fijo) VALUES (?, ?)",
                        [(p["plan_id"], int(p["cargo_fijo"])) for p in csv.DictReader(f)])
    with open("clientes.csv", encoding="latin-1", newline="") as f:
        con.executemany("INSERT INTO clientes (linea, plan_id) VALUES (?, ?)",
                        [(c["linea"], c["plan_id"]) for c in csv.DictReader(f)])
    con.commit()
    return con


def filas_cdr():
    with open("cdr.csv", encoding="utf-8", newline="") as f:
        return [(int(r["cdr_id"]), r["linea_origen"], r["tipo"], r["fecha_inicio"], int(r["duracion_seg"]), float(r["mb"]))
                for r in csv.DictReader(f, delimiter="|")]


def prueba_reglas_una_a_una():
    """Cada regla rechaza su caso"""
    requiere("crear_esquema", "cargar_cdr")
    con = base()
    linea = con.execute("SELECT linea FROM clientes LIMIT 1").fetchone()[0]
    bueno = (1, linea, "VOZ", "2026-09-10 08:00:00", 60, 0.0)
    igual(cargar_cdr(con, [bueno]), {"insertados": 1, "rechazados": 0})
    casos = {
        "duplicado": bueno,
        "línea vacía": (2, "", "VOZ", "2026-09-10 08:00:00", 60, 0.0),
        "línea desconocida": (3, "3999999999", "VOZ", "2026-09-10 08:00:00", 60, 0.0),
        "tipo": (4, linea, "FAX", "2026-09-10 08:00:00", 60, 0.0),
        "duración": (5, linea, "VOZ", "2026-09-10 08:00:00", -1, 0.0),
        "fecha imposible": (6, linea, "VOZ", "2026-02-30 08:00:00", 60, 0.0),
        "fecha con otro formato": (7, linea, "VOZ", "10/09/2026 08:00", 60, 0.0),
        "fecha nula": (8, linea, "VOZ", None, 60, 0.0),
    }
    for nombre, fila in casos.items():
        igual(cargar_cdr(con, [fila]), {"insertados": 0, "rechazados": 1}, f"Debería rechazarse: {nombre}")


def prueba_planes_y_clientes():
    """Planes y clientes también tienen reglas"""
    con = base()
    lanza(sqlite3.IntegrityError, con.execute, "INSERT INTO planes VALUES ('X', 0)")
    lanza(sqlite3.IntegrityError, con.execute, "INSERT INTO clientes VALUES ('3000000001', 'NOEXISTE')")

    igual(con.execute("SELECT mb FROM cdr WHERE cdr_id = 9").fetchone()[0], 0)


def prueba_muestra_completa():
    """Con la muestra, entran exactamente los válidos"""
    con = base()
    r = cargar_cdr(con, filas_cdr())
    igual(r, {"insertados": E["registros_validos"], "rechazados": E["registros_totales"] - E["registros_validos"]})

## Pista 2

Para la fecha, compara el texto con su versión normalizada por SQLite:

```sql
fecha_inicio TEXT NOT NULL CHECK (fecha_inicio IS strftime('%Y-%m-%d %H:%M:%S', julianday(fecha_inicio)))
```

`julianday` convierte la fecha en un número (o `NULL` si no la entiende) y `strftime` la vuelve a escribir en formato canónico. Ojo: `CHECK (x = NULL)` **pasa** (en SQL un `CHECK` solo falla si la condición es falsa, no si es desconocida); `IS` compara tratando `NULL` como un valor más, y sí falla.

## Solución

```python
import sqlite3


def crear_esquema(con):
    con.execute("PRAGMA foreign_keys = ON")
    con.executescript("""
        CREATE TABLE planes (
            plan_id    TEXT PRIMARY KEY,
            cargo_fijo INTEGER NOT NULL CHECK (cargo_fijo > 0)
        );
        CREATE TABLE clientes (
            linea   TEXT PRIMARY KEY,
            plan_id TEXT NOT NULL REFERENCES planes (plan_id)
        );
        CREATE TABLE cdr (
            cdr_id       INTEGER PRIMARY KEY,
            linea_origen TEXT NOT NULL REFERENCES clientes (linea),
            tipo         TEXT NOT NULL CHECK (tipo IN ('VOZ', 'SMS', 'DATOS')),
            fecha_inicio TEXT NOT NULL CHECK (fecha_inicio IS strftime('%Y-%m-%d %H:%M:%S', julianday(fecha_inicio))),
            duracion_seg INTEGER NOT NULL CHECK (duracion_seg >= 0),
            mb           REAL NOT NULL DEFAULT 0
        );
    """)


def cargar_cdr(con, filas):
    insertados = rechazados = 0
    for fila in filas:
        try:
            con.execute("INSERT INTO cdr VALUES (?, ?, ?, ?, ?, ?)", fila)
            insertados += 1
        except sqlite3.IntegrityError:
            rechazados += 1
    con.commit()
    return {"insertados": insertados, "rechazados": rechazados}
```

## Explicación

Has convertido seis reglas de negocio en **restricciones**. La diferencia con un validador en Python es enorme: el validador protege **un** programa; las restricciones protegen la tabla de **cualquier** programa, persona o carga manual que intente escribir en ella, para siempre.

¿Y por qué una por una? `executemany` se detiene en el primer error, y no sabrías cuáles filas fallaron. En cargas grandes no se hace así (sería lento): se usa una tabla de paso sin restricciones y se separan válidos y rechazos con SQL, como harás en el ejercicio 7. Las restricciones quedan como **red de seguridad** final.

`fecha_inicio IS strftime(..., julianday(fecha_inicio))` es un truco útil: el viaje de ida y vuelta por `julianday` normaliza la fecha (el 30 de febrero se convierte en el 2 de marzo), así que solo coincide si ya estaba exactamente en ese formato y además era una fecha real. Pasar por `julianday` es importante: según la versión de SQLite, `strftime` aplicado directamente al texto puede devolverlo sin normalizar.
