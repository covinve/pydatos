## Texto, bytes y codificación

Un archivo en disco guarda **bytes** (números de 0 a 255). Una **codificación** (*encoding*) es la regla que traduce esos bytes a caracteres.

```pyrun
texto = "Gómez"

en_utf8 = texto.encode("utf-8")
en_latin1 = texto.encode("latin-1")

print(en_utf8, len(en_utf8), "bytes")
print(en_latin1, len(en_latin1), "bytes")
```

La `ó` ocupa **dos bytes** en UTF-8 (`\xc3\xb3`) y **uno** en latin-1 (`\xf3`). Si lees con una regla distinta a la que se usó para escribir, aparecen los problemas:

```pyrun
bytes_utf8 = "Gómez".encode("utf-8")
bytes_latin1 = "Gómez".encode("latin-1")

print(bytes_utf8.decode("latin-1"))    # UTF-8 leído como latin-1 → mojibake
print(bytes_latin1.decode("utf-8"))    # latin-1 leído como UTF-8 → error  # error esperado
```

|---|---|---|

:::capo latin-1 nunca falla al leer
latin-1 asigna un carácter a **cada uno** de los 256 bytes posibles. Por eso leer cualquier archivo como latin-1 nunca da error… pero si el archivo era UTF-8, el resultado será basura. "No da error" no significa "está bien".
:::

## Cómo saber la codificación de un archivo

No hay una forma 100 % segura, pero esta estrategia funciona casi siempre: **intenta UTF-8; si falla, es latin-1** (o cp1252, su primo de Windows).

```pyrun
from pathlib import Path

Path("clientes_legado.csv").write_bytes("cliente_id,nombre\nCL1,Inés Núñez\n".encode("latin-1"))
Path("clientes_nuevo.csv").write_bytes("cliente_id,nombre\nCL1,Inés Núñez\n".encode("utf-8"))


def detectar_encoding(ruta, muestra=1_000_000):
    datos = Path(ruta).read_bytes()[:muestra]
    try:
        datos.decode("utf-8")
        return "utf-8"
    except UnicodeDecodeError:
        return "latin-1"


for nombre in ["clientes_legado.csv", "clientes_nuevo.csv"]:
    enc = detectar_encoding(nombre)
    print(nombre, "→", enc, "→", Path(nombre).read_text(encoding=enc).splitlines()[1])
```

:::consejo Revisa los bytes cuando dudes
`Path(ruta).read_bytes()[:200]` te muestra los primeros bytes crudos. Si ves `\xc3` seguido de otro byte, es UTF-8; si ves `\xe1`, `\xe9`, `\xf3` sueltos, es latin-1.
:::

## La opción `errors`

Cuando un archivo tiene **algunos** bytes dañados y no puedes pedir otro, `errors=` decide qué hacer:

```pyrun
datos = b"Juan P\xe9rez|3001234567\nAna G\xc3\xb3mez|3109876543\n"   # mezcla de encodings

print(datos.decode("utf-8", errors="replace"))   # reemplaza lo inválido por �
```

| Valor | Efecto |
|---|---|
| `"strict"` (por defecto) | Lanza `UnicodeDecodeError` |
| `"replace"` | Reemplaza por `�` y sigue |
| `"ignore"` | Descarta los bytes inválidos (peligroso: pierdes información sin enterarte) |

## Convertir un archivo a UTF-8

La mejor práctica: convierte los archivos legados a UTF-8 **una vez**, al recibirlos, y trabaja siempre en UTF-8:

```pyrun
from pathlib import Path

Path("legado.csv").write_bytes("nombre\nMuñoz\nPeña\n".encode("latin-1"))

with open("legado.csv", encoding="latin-1") as origen, \
     open("convertido.csv", "w", encoding="utf-8") as destino:
    for linea in origen:
        destino.write(linea)

print(Path("convertido.csv").read_bytes())
```

Fíjate que se procesa **línea por línea**: funciona igual con un archivo de 10 GB.

:::telco El archivo de clientes del curso
`clientes.csv` viene del "sistema legado" en **latin-1**, a propósito. En la vida real pasa todo el tiempo: el CRM exporta en una codificación, el sistema de mediación en otra y Excel agrega un BOM. Indicar siempre el encoding correcto es lo que separa un proceso confiable de uno que "a veces muestra caracteres raros".
:::
