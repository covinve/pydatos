## Enunciado

Escribe `analizar(texto)` que lea el contenido de un `requirements.txt` y devuelva una lista de diccionarios, uno por requisito, con:

| Clave | Contenido |
|---|---|
| `nombre` | El nombre **normalizado**: minúsculas y con `_` y `.` convertidos en `-` (`Scikit_Learn` → `scikit-learn`) |
| `extras` | Lista de extras entre corchetes (`requests[socks,security]` → `["socks", "security"]`), o `[]` |
| `especificador` | Lo que sigue al nombre sin espacios (`>=2.2,<3`), o `""` si no tiene |
| `exacto` | `True` si el especificador es una sola condición `==` |

Reglas del formato:

- Las líneas vacías y las que empiezan por `#` se ignoran; un `#` en medio de la línea inicia un comentario.
- Las líneas que empiezan por `-` (como `-r otro.txt` o `--index-url ...`) se ignoran.
- Puede haber espacios alrededor de los operadores: `pandas >= 2.2`.

Y `sin_fijar(texto)` → los nombres (normalizados, ordenados) de los requisitos que **no** son exactos.

## Pruebas

```python
EJEMPLO = """
# Dependencias del proyecto
pandas>=2.2,<3
duckdb==1.1.3   # motor SQL
Scikit_Learn ~= 1.5
requests[socks,security]==2.32.3
-r requirements-dev.txt
--index-url https://pypi.org/simple

typer
zope.interface==7.0
numpy==2.1.2,!=2.1.1
"""


def prueba_cantidad():
    """Ignora comentarios, opciones y líneas vacías"""
    requiere("analizar")
    igual([r["nombre"] for r in analizar(EJEMPLO)],
          ["pandas", "duckdb", "scikit-learn", "requests", "typer", "zope-interface", "numpy"])


def prueba_campos():
    """Nombre, extras, especificador y exacto"""
    r = {x["nombre"]: x for x in analizar(EJEMPLO)}
    igual(r["pandas"], {"nombre": "pandas", "extras": [], "especificador": ">=2.2,<3", "exacto": False})
    igual(r["duckdb"]["especificador"], "==1.1.3", "El comentario no es parte del especificador")
    igual(r["duckdb"]["exacto"], True)
    igual(r["scikit-learn"]["especificador"], "~=1.5", "Sin espacios")
    igual(r["requests"]["extras"], ["socks", "security"])
    igual(r["typer"], {"nombre": "typer", "extras": [], "especificador": "", "exacto": False})
    igual(r["numpy"]["exacto"], False, "Dos condiciones no es una versión exacta")


def prueba_sin_fijar():
    """Los que no tienen versión exacta"""
    requiere("sin_fijar")
    igual(sin_fijar(EJEMPLO), ["numpy", "pandas", "scikit-learn", "typer"])
    igual(sin_fijar("# nada\n\n"), [])
```

## Pista 1

Limpia cada línea antes de analizarla:

```python
linea = linea.split("#", 1)[0].strip()
if not linea or linea.startswith("-"):
    continue
```

## Pista 2

Una expresión regular separa las tres partes:

```python
m = re.fullmatch(r"([A-Za-z0-9._-]+)\s*(?:\[([^\]]*)\])?\s*(.*)", linea)
nombre, extras, resto = m.groups()
```

Normaliza el nombre con `re.sub(r"[-_.]+", "-", nombre).lower()` y quita los espacios del especificador con `"".join(resto.split())`. Es exacto si empieza por `==` y no tiene coma.

## Solución

```python
import re

PATRON = re.compile(r"([A-Za-z0-9._-]+)\s*(?:\[([^\]]*)\])?\s*(.*)")


def analizar(texto):
    requisitos = []
    for linea in texto.splitlines():
        linea = linea.split("#", 1)[0].strip()
        if not linea or linea.startswith("-"):
            continue
        nombre, extras, resto = PATRON.fullmatch(linea).groups()
        especificador = "".join(resto.split())
        requisitos.append({
            "nombre": re.sub(r"[-_.]+", "-", nombre).lower(),
            "extras": [e.strip() for e in extras.split(",")] if extras else [],
            "especificador": especificador,
            "exacto": especificador.startswith("==") and "," not in especificador,
        })
    return requisitos


def sin_fijar(texto):
    return sorted(r["nombre"] for r in analizar(texto) if not r["exacto"])


EJEMPLO = """
# Dependencias del proyecto
pandas>=2.2,<3
duckdb==1.1.3   # motor SQL
Scikit_Learn ~= 1.5
requests[socks,security]==2.32.3
-r requirements-dev.txt
typer
"""
for r in analizar(EJEMPLO):
    print(r)
print(sin_fijar(EJEMPLO))
```

## Explicación

La **normalización** de nombres es una regla oficial de los paquetes de Python (PEP 503): `Scikit_Learn`, `scikit-learn` y `scikit.learn` son el mismo paquete. Comparar nombres sin normalizar es un error clásico en herramientas que revisan dependencias.

`sin_fijar` es una verificación útil para un archivo de **bloqueo**: en un `requirements.lock` todo debería ser `==`. Si alguien editó a mano y dejó un `>=`, el entorno deja de ser reproducible. En el ejercicio 8 usarás esta idea para verificar que tu entorno coincide con el bloqueo.

En proyectos reales existe la librería `packaging` (la que usa pip por dentro) con `packaging.requirements.Requirement("pandas>=2.2,<3")`, que maneja todos los casos raros del formato. Escribirlo tú una vez te ayuda a entender qué hay en esos archivos.
