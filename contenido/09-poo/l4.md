## Herencia

Una clase puede **heredar** de otra: recibe sus atributos y métodos, y puede **sobrescribir** los que necesite cambiar.

```pyrun
class Plan:
    def __init__(self, plan_id, cargo_fijo, minutos_incluidos, tarifa_minuto):
        self.plan_id = plan_id
        self.cargo_fijo = cargo_fijo
        self.minutos_incluidos = minutos_incluidos
        self.tarifa_minuto = tarifa_minuto

    def valor_voz(self, minutos):
        return max(0, minutos - self.minutos_incluidos) * self.tarifa_minuto

    def describir(self):
        return f"{self.plan_id}: ${self.cargo_fijo} + voz ${self.valor_voz(400)} (con 400 min)"


class PlanIlimitado(Plan):
    def __init__(self, plan_id, cargo_fijo):
        super().__init__(plan_id, cargo_fijo, minutos_incluidos=-1, tarifa_minuto=0)

    def valor_voz(self, minutos):          # sobrescribe
        return 0


planes = [Plan("HOG30", 35900, 300, 120), PlanIlimitado("ILIM", 89900)]
for plan in planes:
    print(plan.describir())               # cada uno usa su propio valor_voz
print(isinstance(planes[1], Plan))
```

- `class PlanIlimitado(Plan)` declara la herencia.
- `super().__init__(...)` llama al `__init__` de la clase padre.
- `describir` está definido una sola vez en `Plan`, pero llama al `valor_voz` **de cada objeto**: eso es **polimorfismo**.

:::reto El plan empresarial
`PlanEmpresarial` es un `Plan`, pero cobra distinto: desde la **sexta** línea, cada línea adicional paga la **mitad** del cargo fijo. Escribe la subclase:

- hereda de `Plan` (su `__init__` sirve tal cual);
- sobrescribe `cargo_mensual(lineas)`.

```pyreto
class Plan:
    def __init__(self, plan_id, cargo_fijo):
        self.plan_id = plan_id
        self.cargo_fijo = cargo_fijo

    def cargo_mensual(self, lineas):
        return self.cargo_fijo * lineas


# class PlanEmpresarial(Plan): ...


planes = [Plan("HOG30", 35900), PlanEmpresarial("EMP100", 79900)]
for plan in planes:
    print(plan.plan_id, plan.cargo_mensual(8))   # HOG30 287200 / EMP100 519350
```

:::pista
Las 5 primeras pagan completo: `min(lineas, 5) * self.cargo_fijo`. Las demás pagan la mitad: `max(0, lineas - 5) * self.cargo_fijo // 2`. Si no necesitas cambiar el `__init__`, ni siquiera hace falta escribirlo: se hereda.
:::

```pyprueba
def prueba_herencia():
    """PlanEmpresarial es un Plan"""
    requiere("PlanEmpresarial")
    p = PlanEmpresarial("EMP100", 79900)
    assert isinstance(p, Plan), "PlanEmpresarial debe heredar de Plan"
    igual((p.plan_id, p.cargo_fijo), ("EMP100", 79900))


def prueba_cargo():
    """Desde la sexta línea cobra la mitad"""
    p = PlanEmpresarial("EMP100", 79900)
    igual(p.cargo_mensual(3), 239700, "3 líneas")
    igual(p.cargo_mensual(5), 399500, "5 líneas")
    igual(p.cargo_mensual(8), 519350, "8 líneas")


def prueba_plan_normal_igual():
    """El Plan normal no cambia"""
    igual(Plan("HOG30", 35900).cargo_mensual(8), 287200)
```

```pysolucion
class Plan:
    def __init__(self, plan_id, cargo_fijo):
        self.plan_id = plan_id
        self.cargo_fijo = cargo_fijo

    def cargo_mensual(self, lineas):
        return self.cargo_fijo * lineas


class PlanEmpresarial(Plan):
    def cargo_mensual(self, lineas):
        completas = min(lineas, 5) * self.cargo_fijo
        adicionales = max(0, lineas - 5) * self.cargo_fijo // 2
        return completas + adicionales


planes = [Plan("HOG30", 35900), PlanEmpresarial("EMP100", 79900)]
for plan in planes:
    print(plan.plan_id, plan.cargo_mensual(8))   # HOG30 287200 / EMP100 519350
```

## Clases abstractas: obligar a implementar

A veces la clase padre solo define **qué** deben saber hacer sus hijas, sin implementarlo. Para eso está `abc`:

```pyrun
from abc import ABC, abstractmethod


class ReglaDeDescuento(ABC):
    @abstractmethod
    def aplicar(self, cargo_fijo: int) -> int:
        """Devuelve el descuento en pesos."""


class SinDescuento(ReglaDeDescuento):
    def aplicar(self, cargo_fijo):
        return 0


class Porcentaje(ReglaDeDescuento):
    def __init__(self, porcentaje):
        self.porcentaje = porcentaje

    def aplicar(self, cargo_fijo):
        return round(cargo_fijo * self.porcentaje / 100)


for regla in [SinDescuento(), Porcentaje(10)]:
    print(type(regla).__name__, regla.aplicar(79900))

ReglaDeDescuento()   # error esperado
```

No se puede crear un objeto de una clase abstracta, ni de una hija que olvidó implementar `aplicar`.

:::reto Reglas de recargo por mora
Define el contrato y dos reglas:

- `ReglaDeRecargo`: clase abstracta con el método abstracto `recargo(self, dias_mora)`;
- `RecargoFijo(valor)`: cobra `valor` si hay al menos un día de mora, y 0 si no;
- `RecargoDiario(valor_dia, tope)`: cobra `valor_dia` por cada día, sin pasar de `tope`.

```pyreto
from abc import ABC, abstractmethod

# ReglaDeRecargo, RecargoFijo y RecargoDiario


for regla in [RecargoFijo(5000), RecargoDiario(800, 12000)]:
    print(type(regla).__name__, regla.recargo(0), regla.recargo(20))
```

:::pista
`class ReglaDeRecargo(ABC):` con `@abstractmethod` sobre `def recargo(self, dias_mora):`. Cada hija hereda de `ReglaDeRecargo`, guarda sus datos en `__init__` e implementa `recargo`. Para el tope: `min(self.tope, dias_mora * self.valor_dia)`.
:::

```pyprueba
def prueba_abstracta():
    """ReglaDeRecargo no se puede instanciar"""
    requiere("ReglaDeRecargo")
    lanza(TypeError, ReglaDeRecargo)


def prueba_fijo():
    """RecargoFijo cobra solo si hay mora"""
    requiere("RecargoFijo")
    r = RecargoFijo(5000)
    assert isinstance(r, ReglaDeRecargo), "RecargoFijo debe heredar de ReglaDeRecargo"
    igual(r.recargo(0), 0, "0 días")
    igual(r.recargo(1), 5000, "1 día")
    igual(r.recargo(40), 5000, "40 días")


def prueba_diario():
    """RecargoDiario cobra por día con tope"""
    requiere("RecargoDiario")
    r = RecargoDiario(800, 12000)
    assert isinstance(r, ReglaDeRecargo), "RecargoDiario debe heredar de ReglaDeRecargo"
    igual(r.recargo(0), 0, "0 días")
    igual(r.recargo(10), 8000, "10 días")
    igual(r.recargo(20), 12000, "20 días (tope)")
```

```pysolucion
from abc import ABC, abstractmethod


class ReglaDeRecargo(ABC):
    @abstractmethod
    def recargo(self, dias_mora):
        """Devuelve el recargo en pesos."""


class RecargoFijo(ReglaDeRecargo):
    def __init__(self, valor):
        self.valor = valor

    def recargo(self, dias_mora):
        return self.valor if dias_mora > 0 else 0


class RecargoDiario(ReglaDeRecargo):
    def __init__(self, valor_dia, tope):
        self.valor_dia = valor_dia
        self.tope = tope

    def recargo(self, dias_mora):
        return min(self.tope, dias_mora * self.valor_dia)


for regla in [RecargoFijo(5000), RecargoDiario(800, 12000)]:
    print(type(regla).__name__, regla.recargo(0), regla.recargo(20))
```

## Composición: "tiene un" en lugar de "es un"

La herencia expresa "**es un**": un `PlanIlimitado` *es un* `Plan`. La composición expresa "**tiene un**": una `Factura` *tiene un* cliente, *tiene un* plan y *tiene* conceptos.

```pyrun
from dataclasses import dataclass, field


@dataclass
class Cliente:
    cliente_id: str
    nombre: str


@dataclass
class Concepto:
    descripcion: str
    valor: int


@dataclass
class Factura:
    cliente: Cliente                                  # tiene un cliente
    conceptos: list[Concepto] = field(default_factory=list)

    @property
    def total(self):
        return sum(c.valor for c in self.conceptos)


f = Factura(Cliente("CL1", "Lucía Gómez"))
f.conceptos.append(Concepto("Cargo fijo HOG30", 35900))
f.conceptos.append(Concepto("Minutos adicionales", 5040))
print(f.cliente.nombre, f.total)
```

:::consejo Prefiere la composición
Las jerarquías de herencia profundas (`Plan` → `PlanPostpago` → `PlanEmpresarial` → `PlanEmpresarialPremium`…) se vuelven rígidas: un cambio arriba afecta a todos. La recomendación clásica es **"composición sobre herencia"**: arma objetos con piezas (un plan *tiene una* regla de descuento) en vez de crear una subclase por cada combinación.
:::

:::reto Una factura armada con piezas
Por composición, la `Factura` **tiene** un subtotal y **tiene una** regla de descuento (cualquier objeto con el método `aplicar(subtotal)`). Completa:

- `Porcentaje(porcentaje)`: su `aplicar` devuelve el porcentaje del subtotal, redondeado;
- `Factura(subtotal, regla)`: la propiedad `total` es el subtotal menos lo que diga la regla.

Cambiar la política comercial debe ser cambiar **qué regla** recibe la factura, sin tocar `Factura`.

```pyreto
from dataclasses import dataclass


class SinDescuento:
    def aplicar(self, subtotal):
        return 0


# Porcentaje y Factura


print(Factura(79900, SinDescuento()).total)    # 79900
print(Factura(79900, Porcentaje(10)).total)    # 71910
```

:::pista
`Factura` puede ser una dataclass con los campos `subtotal: int` y `regla: object`, más `@property def total(self): return self.subtotal - self.regla.aplicar(self.subtotal)`.
:::

```pyprueba
def prueba_porcentaje():
    """Porcentaje calcula el descuento"""
    requiere("Porcentaje")
    igual(Porcentaje(10).aplicar(79900), 7990)
    igual(Porcentaje(0).aplicar(5000), 0)


def prueba_factura():
    """El total depende de la regla que recibe"""
    requiere("Factura")
    igual(Factura(79900, SinDescuento()).total, 79900, "sin descuento")
    igual(Factura(79900, Porcentaje(10)).total, 71910, "10 %")


def prueba_cualquier_regla():
    """Factura acepta cualquier objeto con aplicar()"""
    class Fijo:
        def aplicar(self, subtotal):
            return 1000

    igual(Factura(5000, Fijo()).total, 4000)
```

```pysolucion
from dataclasses import dataclass


class SinDescuento:
    def aplicar(self, subtotal):
        return 0


class Porcentaje:
    def __init__(self, porcentaje):
        self.porcentaje = porcentaje

    def aplicar(self, subtotal):
        return round(subtotal * self.porcentaje / 100)


@dataclass
class Factura:
    subtotal: int
    regla: object

    @property
    def total(self):
        return self.subtotal - self.regla.aplicar(self.subtotal)


print(Factura(79900, SinDescuento()).total)    # 79900
print(Factura(79900, Porcentaje(10)).total)    # 71910
```

## Protocol: contratos sin herencia

`Protocol` (del módulo `typing`) describe **qué métodos** debe tener un objeto, sin obligarlo a heredar de nada. Cualquier clase que tenga esos métodos cumple el contrato. Es la versión formal del "si camina como pato y hace cuac, es un pato":

```pyrun
from typing import Protocol


class Tarificable(Protocol):
    def valor(self) -> int: ...


class Llamada:
    def __init__(self, segundos, tarifa):
        self.segundos, self.tarifa = segundos, tarifa

    def valor(self):
        return (self.segundos + 59) // 60 * self.tarifa


class Sms:
    def valor(self):
        return 60


def total(items: list[Tarificable]) -> int:
    return sum(item.valor() for item in items)


print(total([Llamada(125, 120), Sms(), Llamada(61, 950)]))
```

`Llamada` y `Sms` no heredan de `Tarificable`, pero las herramientas de tipos (Pylance, mypy) verifican que tengan `valor()`.

:::reto Todo lo que se cobra
Define el `Protocol` `Cobrable`, con el método `valor(self) -> int`, y dos clases que lo cumplan **sin heredar de él**:

- `PaqueteSms(cantidad)`: cada mensaje vale 60;
- `Navegacion(mb, tarifa_mb)`: vale `math.ceil(mb) * tarifa_mb`.

Luego escribe `total_cobrable(items: list[Cobrable]) -> int`.

```pyreto
import math
from typing import Protocol

# Cobrable, PaqueteSms, Navegacion y total_cobrable


print(total_cobrable([PaqueteSms(3), Navegacion(15.131, 18)]))   # 468
```

:::pista
`class Cobrable(Protocol):` con `def valor(self) -> int: ...` (los tres puntos son el cuerpo). Las otras dos clases son normales, con su `__init__` y su `valor`. `total_cobrable` suma `item.valor()` de cada uno.
:::

```pyprueba
from typing import Protocol


def prueba_protocolo():
    """Cobrable es un Protocol"""
    requiere("Cobrable")
    assert issubclass(Cobrable, Protocol), "Cobrable debe heredar de Protocol"


def prueba_clases():
    """PaqueteSms y Navegacion calculan su valor sin heredar de Cobrable"""
    requiere("PaqueteSms", "Navegacion")
    igual(PaqueteSms(3).valor(), 180, "PaqueteSms(3)")
    igual(Navegacion(15.131, 18).valor(), 288, "Navegacion(15.131, 18)")
    assert Cobrable not in PaqueteSms.__mro__ and Cobrable not in Navegacion.__mro__, "No hace falta heredar de Cobrable"


def prueba_total():
    """total_cobrable suma cualquier cosa con valor()"""
    requiere("total_cobrable")
    igual(total_cobrable([PaqueteSms(3), Navegacion(15.131, 18)]), 468)
    igual(total_cobrable([]), 0)
```

```pysolucion
import math
from typing import Protocol


class Cobrable(Protocol):
    def valor(self) -> int: ...


class PaqueteSms:
    def __init__(self, cantidad):
        self.cantidad = cantidad

    def valor(self):
        return self.cantidad * 60


class Navegacion:
    def __init__(self, mb, tarifa_mb):
        self.mb = mb
        self.tarifa_mb = tarifa_mb

    def valor(self):
        return math.ceil(self.mb) * self.tarifa_mb


def total_cobrable(items: list[Cobrable]) -> int:
    return sum(item.valor() for item in items)


print(total_cobrable([PaqueteSms(3), Navegacion(15.131, 18)]))   # 468
```
:::

| Herramienta | Úsala cuando |
|---|---|
| Herencia | Hay una relación "es un" clara y compartes mucho comportamiento |
| ABC | Quieres obligar a que las subclases implementen ciertos métodos |
| Composición | Un objeto se arma con piezas intercambiables |
| `Protocol` | Solo te importa que el objeto sepa hacer algo, no de dónde viene |

:::telco Reglas intercambiables
Con composición y un contrato (`ReglaDeDescuento`), cambiar la política comercial es cambiar **qué objeto** se le pasa a la factura, no reescribir la factura. Es la misma idea del validador de reglas enchufables del módulo 5, ahora con objetos.
:::

## Cuestionario

? ¿Qué hace `super().__init__(...)` dentro del `__init__` de una subclase?
- [ ] Crea un objeto nuevo de la clase padre
- [x] Ejecuta el `__init__` de la clase padre sobre el objeto actual
- [ ] Borra los atributos del padre
- [ ] Hace que la clase sea abstracta
> Así la subclase reutiliza la inicialización del padre y luego agrega lo suyo.

? Una factura tiene un cliente y una lista de conceptos. ¿Qué relación es?
- [ ] Herencia: Factura hereda de Cliente
- [x] Composición: Factura tiene un Cliente y tiene Conceptos
- [ ] Polimorfismo
- [ ] Ninguna
> "Tiene un" es composición. Una factura no *es un* cliente.

? ¿Qué pasa al intentar `ReglaDeDescuento()` si es una clase abstracta con un método abstracto?
- [ ] Crea el objeto normalmente
- [x] Lanza `TypeError`: no se pueden crear objetos de clases abstractas
- [ ] Devuelve `None`
- [ ] Crea un objeto sin métodos
> Las clases abstractas son contratos; solo se instancian sus subclases que implementan todo lo abstracto.
