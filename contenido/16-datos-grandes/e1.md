## Enunciado

Escribe `resumen_por_tipo()` que, con **una sola consulta SQL** de DuckDB sobre `cdr.csv` (separado por `|`), devuelva una lista de tuplas `(tipo, registros, mb_total)` con:

- solo los tipos válidos (`VOZ`, `SMS`, `DATOS`);
- `registros`: cantidad de filas;
- `mb_total`: suma de `mb` redondeada a 1 decimal;
- ordenada por `registros` de mayor a menor.

Usa `duckdb.sql(...).fetchall()`.

## Pista 2

Para filtrar los tipos válidos: `WHERE tipo IN ('VOZ', 'SMS', 'DATOS')`. Para ordenar de mayor a menor: `ORDER BY registros DESC`.

## Solución

```python
import duckdb


def resumen_por_tipo():
    return duckdb.sql("""
        SELECT tipo, COUNT(*) AS registros, ROUND(SUM(mb), 1) AS mb_total
        FROM read_csv('cdr.csv', delim='|', header=true)
        WHERE tipo IN ('VOZ', 'SMS', 'DATOS')
        GROUP BY tipo
        ORDER BY registros DESC
    """).fetchall()


print(resumen_por_tipo())
```

## Explicación

DuckDB leyó el CSV, filtró, agrupó y ordenó en una sola instrucción, sin que tuvieras que cargar el archivo en un DataFrame. Con el archivo de 20 GB, la misma consulta funciona igual: DuckDB lee solo las columnas `tipo` y `mb`, en paralelo y por bloques.

Las cláusulas de SQL siempre van en el mismo orden (`SELECT`, `FROM`, `WHERE`, `GROUP BY`, `ORDER BY`), aunque el motor las ejecute en otro: primero `FROM`, luego `WHERE`, luego `GROUP BY`, y al final `SELECT` y `ORDER BY`.
