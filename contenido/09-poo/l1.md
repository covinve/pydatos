Hasta ahora representabas un plan con un diccionario y escribías funciones que lo recibían. Funciona, pero nada impide que alguien escriba `plan["tarifa_minutos"]` (con una "s" de más) o que pase un cliente donde iba un plan. Una **clase** junta los datos y las operaciones que les corresponden.

## Tu primera clase

```pyrun
class Plan:
    def __init__(self, plan_id, cargo_fijo, minutos_incluidos, tarifa_minuto):
        self.plan_id = plan_id
        self.cargo_fijo = cargo_fijo
        self.minutos_incluidos = minutos_incluidos
        self.tarifa_minuto = tarifa_minuto

    def valor_voz(self, minutos):
        if self.minutos_incluidos == -1:
            return 0
        return max(0, minutos - self.minutos_incluidos) * self.tarifa_minuto


hogar = Plan("HOG30", 35900, 300, 120)
ilimitado = Plan("ILIM", 89900, -1, 0)

print(hogar.plan_id, hogar.cargo_fijo)
print(hogar.valor_voz(342))
print(ilimitado.valor_voz(5000))
```

| Concepto | En el ejemplo |
|---|---|
| **Clase**: el molde | `Plan` |
| **Objeto** o **instancia**: algo hecho con el molde | `hogar`, `ilimitado` |
| **Atributo**: un dato del objeto | `hogar.cargo_fijo` |
| **Método**: una función del objeto | `hogar.valor_voz(342)` |
| **`__init__`**: se ejecuta al crear el objeto | `Plan("HOG30", ...)` |

Por convención, las clases se nombran en `PalabrasConMayuscula` (*CamelCase*).

## ¿Qué es self?

`self` es **el objeto sobre el que se llamó el método**. Cuando escribes `hogar.valor_voz(342)`, Python llama a `Plan.valor_voz(hogar, 342)`: `self` es `hogar`.

```pytrace
class Contador:
    def __init__(self):
        self.total = 0

    def sumar(self, n):
        self.total = self.total + n

a = Contador()
b = Contador()
a.sumar(5)
a.sumar(3)
b.sumar(10)
print(a.total, b.total)
```

Cada objeto tiene **sus propios** atributos: `a.total` y `b.total` son independientes.

:::error Olvidar self
Dentro de un método, una variable sin `self.` es local y desaparece al terminar. `total = total + n` daría error; `self.total = self.total + n` modifica el atributo del objeto. Y todo método recibe `self` como primer parámetro, aunque no lo uses.
:::

## Atributos de clase

Un atributo definido directamente en la clase (fuera de `__init__`) es **compartido** por todos los objetos. Úsalo para constantes:

```pyrun
class Plan:
    ILIMITADO = -1                                # atributo de clase

    def __init__(self, plan_id, minutos_incluidos):
        self.plan_id = plan_id                    # atributo de instancia
        self.minutos_incluidos = minutos_incluidos

    def es_ilimitado(self):
        return self.minutos_incluidos == Plan.ILIMITADO


print(Plan("ILIM", -1).es_ilimitado(), Plan("HOG30", 300).es_ilimitado())
print(Plan.ILIMITADO)
```

:::reto La clase Factura
Escribe la clase `Factura`:

- un atributo de clase `TASA_IVA = 0.19`;
- `__init__(self, factura_id, subtotal)` guarda los dos datos como atributos;
- el método `iva()` devuelve el subtotal por `Factura.TASA_IVA`, redondeado con `round`;
- el método `total()` devuelve el subtotal más el IVA (usa `self.iva()`).

```pyreto
# Escribe la clase Factura


f = Factura("F2026090000001", 40940)
print(f.factura_id, f.subtotal, f.iva(), f.total())   # F2026090000001 40940 7779 48719
```

:::pista
Dentro de la clase, `TASA_IVA = 0.19` va antes del `def __init__`. Un método llama a otro con `self.`: `return self.subtotal + self.iva()`.
:::

```pyprueba
def prueba_atributos():
    """Guarda factura_id y subtotal"""
    requiere("Factura")
    f = Factura("F1", 40940)
    igual(f.factura_id, "F1", "factura_id")
    igual(f.subtotal, 40940, "subtotal")


def prueba_tasa():
    """TASA_IVA es un atributo de clase"""
    igual(Factura.TASA_IVA, 0.19)


def prueba_calculos():
    """iva() y total() calculan bien"""
    f = Factura("F1", 40940)
    igual(f.iva(), 7779, "iva")
    igual(f.total(), 48719, "total")
    igual(Factura("F2", 0).total(), 0, "factura en cero")


def prueba_objetos_independientes():
    """Cada factura tiene sus propios datos"""
    a, b = Factura("A", 100), Factura("B", 200)
    igual((a.subtotal, b.subtotal), (100, 200))
```

```pysolucion
class Factura:
    TASA_IVA = 0.19

    def __init__(self, factura_id, subtotal):
        self.factura_id = factura_id
        self.subtotal = subtotal

    def iva(self):
        return round(self.subtotal * Factura.TASA_IVA)

    def total(self):
        return self.subtotal + self.iva()


f = Factura("F2026090000001", 40940)
print(f.factura_id, f.subtotal, f.iva(), f.total())   # F2026090000001 40940 7779 48719
```
:::

## Objetos que cambian de estado

Un objeto puede guardar estado y modificarlo a lo largo del tiempo. Compara con el closure del módulo 5:

```pyrun
class BolsaDeMinutos:
    def __init__(self, incluidos):
        self.incluidos = incluidos
        self.usados = 0

    def consumir(self, segundos):
        self.usados += (segundos + 59) // 60

    def disponibles(self):
        return max(0, self.incluidos - self.usados)

    def exceso(self):
        return max(0, self.usados - self.incluidos)


bolsa = BolsaDeMinutos(300)
for llamada in [125, 3600, 14400]:
    bolsa.consumir(llamada)
    print(f"Usados {bolsa.usados}, disponibles {bolsa.disponibles()}, exceso {bolsa.exceso()}")
```

:::consejo ¿Clase o funciones?
No todo necesita una clase. Si solo tienes una función que transforma datos, una función basta. Las clases brillan cuando **varios datos y varias operaciones van siempre juntos** (un plan con sus tarifas y sus cálculos) o cuando un objeto tiene **estado** que cambia (una bolsa de minutos).
:::

:::reto La bolsa de mensajes
Escribe la clase `BolsaSMS`:

- `__init__(self, incluidos)`: guarda los incluidos y empieza con `enviados = 0`;
- `enviar(self, cantidad=1)`: suma la cantidad a los enviados;
- `disponibles(self)`: los que quedan (nunca negativo);
- `valor_exceso(self, tarifa)`: los mensajes por encima de los incluidos, por la tarifa.

```pyreto
# Escribe la clase BolsaSMS


bolsa = BolsaSMS(100)
bolsa.enviar(80)
bolsa.enviar()
print(bolsa.enviados, bolsa.disponibles())   # 81 19
bolsa.enviar(30)
print(bolsa.valor_exceso(60))                # 660
```

:::pista
Sigue el modelo de `BolsaDeMinutos`: el estado vive en `self.enviados`, y cada método lo lee o lo cambia. El exceso es `max(0, self.enviados - self.incluidos)`.
:::

```pyprueba
def prueba_estado_inicial():
    """Empieza con 0 enviados y todo disponible"""
    requiere("BolsaSMS")
    b = BolsaSMS(100)
    igual(b.enviados, 0, "enviados")
    igual(b.disponibles(), 100, "disponibles")


def prueba_enviar():
    """enviar suma 1 por defecto o la cantidad indicada"""
    b = BolsaSMS(100)
    b.enviar(80)
    b.enviar()
    igual(b.enviados, 81, "enviados")
    igual(b.disponibles(), 19, "disponibles")


def prueba_exceso():
    """valor_exceso cobra solo lo que pasa de los incluidos"""
    b = BolsaSMS(100)
    b.enviar(111)
    igual(b.disponibles(), 0, "disponibles nunca es negativo")
    igual(b.valor_exceso(60), 660, "valor_exceso")
    igual(BolsaSMS(100).valor_exceso(60), 0, "sin exceso")


def prueba_bolsas_independientes():
    """Cada bolsa tiene su propio estado"""
    a, b = BolsaSMS(10), BolsaSMS(10)
    a.enviar(5)
    igual(b.enviados, 0)
```

```pysolucion
class BolsaSMS:
    def __init__(self, incluidos):
        self.incluidos = incluidos
        self.enviados = 0

    def enviar(self, cantidad=1):
        self.enviados += cantidad

    def disponibles(self):
        return max(0, self.incluidos - self.enviados)

    def valor_exceso(self, tarifa):
        return max(0, self.enviados - self.incluidos) * tarifa


bolsa = BolsaSMS(100)
bolsa.enviar(80)
bolsa.enviar()
print(bolsa.enviados, bolsa.disponibles())   # 81 19
bolsa.enviar(30)
print(bolsa.valor_exceso(60))                # 660
```
:::

:::telco El lenguaje del negocio en el código
`plan.valor_voz(minutos)` se lee como el negocio habla: "el valor de voz según el plan". Cuando el código usa los mismos conceptos que las personas de facturación (planes, bolsas, cargos), conversar sobre las reglas y encontrar errores se vuelve mucho más fácil.
:::
