## Enunciado

Muchas veces los CDR no llegan en un archivo gigante sino en **cientos de archivos diarios** o por conmutador. Cada archivo se puede resumir por separado, así que es el caso perfecto para usar **todos los núcleos** del procesador.

En `ejercicios/m16-e9/paralelo.py`:

1. `resumir_archivo(ruta)` → resumen de un archivo con `csv.reader`: nombre, registros, cantidad por tipo (`VOZ`, `SMS`, `DATOS`), minutos facturables de voz con duración ≥ 0 y MB de datos.
2. `combinar(resumenes)` → suma una lista de resúmenes (agrega `archivos`: cuántos se combinaron).
3. `secuencial(carpeta)` → resume los `cdr_*.csv` (ignora otros archivos) uno tras otro y combina.
4. `en_paralelo(carpeta, procesos)` → lo mismo con `ProcessPoolExecutor`. **Debe dar exactamente lo mismo.**

Después, prueba la velocidad con un archivo grande partido por días (las pruebas te muestran cómo partirlo) y compara 1, 2, 4 y 8 procesos.

:::error Windows y los procesos
En Windows cada proceso nuevo **vuelve a importar tu módulo**. Por eso el código que lanza el trabajo debe estar dentro de `if __name__ == "__main__":` (o dentro de una función), y la función que se reparte (`resumir_archivo`) debe estar definida a nivel de módulo, no dentro de otra función ni como `lambda`.
:::

## Pista 1

```python
from concurrent.futures import ProcessPoolExecutor

archivos = sorted(carpeta.glob("cdr_*.csv"))
with ProcessPoolExecutor(max_workers=procesos) as ejecutor:
    resumenes = list(ejecutor.map(resumir_archivo, archivos))
return combinar(resumenes)
```

`ejecutor.map` reparte los archivos entre los procesos y devuelve los resultados en el mismo orden.

## Pista 2

Para combinar, empieza con un resumen vacío y suma cada clave; `por_tipo` se suma tipo por tipo. Redondea `mb` al final con `round(total, 3)`: sumar números ya redondeados en distinto orden puede dar diferencias en el último decimal (las pruebas toleran 0.001).

## Solución

```python paralelo.py
"""Ejercicio m16-e9: procesar una carpeta de archivos diarios usando todos los núcleos.

Uso:
    python ejercicios/m16-e9/paralelo.py carpeta_con_archivos_diarios
"""

from __future__ import annotations

import csv
import sys
from concurrent.futures import ProcessPoolExecutor
from pathlib import Path

TIPOS = ("VOZ", "SMS", "DATOS")


def resumir_archivo(ruta: Path) -> dict:
    por_tipo = dict.fromkeys(TIPOS, 0)
    registros = minutos = 0
    mb = 0.0
    with open(ruta, encoding="utf-8", newline="") as f:
        lector = csv.reader(f, delimiter="|")
        next(lector)
        for fila in lector:
            registros += 1
            tipo, duracion = fila[3], int(fila[6])
            if tipo in por_tipo:
                por_tipo[tipo] += 1
            if tipo == "VOZ" and duracion >= 0:
                minutos += (duracion + 59) // 60
            elif tipo == "DATOS":
                mb += float(fila[7])
    return {"archivo": Path(ruta).name, "registros": registros, "por_tipo": por_tipo,
            "minutos": minutos, "mb": round(mb, 3)}


def combinar(resumenes: list[dict]) -> dict:
    total = {"archivos": 0, "registros": 0, "por_tipo": dict.fromkeys(TIPOS, 0), "minutos": 0, "mb": 0.0}
    for r in resumenes:
        total["archivos"] += 1
        total["registros"] += r["registros"]
        total["minutos"] += r["minutos"]
        total["mb"] += r["mb"]
        for tipo in TIPOS:
            total["por_tipo"][tipo] += r["por_tipo"][tipo]
    total["mb"] = round(total["mb"], 3)
    return total


def _archivos(carpeta: Path) -> list[Path]:
    return sorted(Path(carpeta).glob("cdr_*.csv"))


def secuencial(carpeta: Path) -> dict:
    return combinar([resumir_archivo(a) for a in _archivos(carpeta)])


def en_paralelo(carpeta: Path, procesos: int | None = None) -> dict:
    with ProcessPoolExecutor(max_workers=procesos) as ejecutor:
        return combinar(list(ejecutor.map(resumir_archivo, _archivos(carpeta))))


if __name__ == "__main__":
    import time

    carpeta = Path(sys.argv[1])
    for funcion in (secuencial, en_paralelo):
        inicio = time.perf_counter()
        r = funcion(carpeta)
        print(f"{funcion.__name__:12} {time.perf_counter() - inicio:6.2f} s  {r}")
```

## Explicación

El patrón se llama **map-reduce**: *map* resume cada archivo de forma independiente (en paralelo) y *reduce* combina los resúmenes (rápido, porque son pequeños). Funciona siempre que el resultado se pueda **sumar** por partes, la misma condición que viste con los bloques del módulo 14: conteos y sumas sí; medianas o duplicados entre archivos, no directamente.

¿Por qué procesos y no hilos? En Python, los hilos no ejecutan código Python en paralelo de verdad (por el GIL, aunque Python 3.13+ ya ofrece una versión experimental sin él). Los procesos sí, cada uno con su propio intérprete. El costo es que arrancar procesos y enviarles datos tarda: por eso se les envía la **ruta** del archivo (unos bytes) y no su contenido.

Con 8 núcleos, espera una mejora de 4 a 7 veces, no de 8: el disco también tiene un límite, y alguien tiene que repartir el trabajo y combinarlo. Si el cuello de botella es el disco (archivos en red, disco mecánico), más procesos no ayudan. Esto también explica por qué DuckDB y Polars son tan rápidos: hacen este reparto entre núcleos por ti, internamente.
