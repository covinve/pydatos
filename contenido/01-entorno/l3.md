¿Alguna vez tuviste archivos llamados `reporte_final.py`, `reporte_final_v2.py` y `reporte_final_ahora_si.py`? **Git** resuelve eso: guarda cada versión de tu proyecto con una descripción, y te deja volver a cualquiera de ellas. **GitHub** es un sitio donde guardas una copia en la nube para tenerla en cualquier computador.

## Configuración inicial (una vez por computador)

Git necesita saber quién eres para firmar tus commits:

```powershell
git config --global user.name "Tu Nombre"
git config --global user.email "tu-correo@ejemplo.com"
git config --global init.defaultBranch main
```

Usa el mismo correo de tu cuenta de GitHub.

## Los comandos del día a día

| Comando | Qué hace |
|---|---|
| `git status` | Muestra qué cambió y qué está preparado. **Úsalo siempre**, antes y después de cada paso. |
| `git add archivo.py` | Prepara un archivo para el próximo commit. |
| `git add .` | Prepara todos los cambios de la carpeta actual. |
| `git commit -m "mensaje"` | Guarda la foto con un mensaje. |
| `git log --oneline` | Lista los commits, uno por línea. |
| `git diff` | Muestra exactamente qué líneas cambiaron (aún sin preparar). |
| `git push` | Sube tus commits a GitHub. |
| `git pull` | Descarga los commits que hiciste en el otro computador. |
| `git restore archivo.py` | Descarta los cambios de un archivo y vuelve a su último commit. ⚠️ Lo que no guardaste se pierde. |

:::consejo VS Code también habla Git
El ícono de **Control de código fuente** (`Ctrl + Shift + G`) muestra los cambios, te deja preparar archivos con un clic y escribir el mensaje del commit. Úsalo, pero aprende primero los comandos: así entiendes qué hace cada botón.
:::

## Buenos mensajes de commit

Un buen mensaje dice **qué** cambió y, si no es obvio, **por qué**. Escríbelo como una orden en presente:

:::comparar
:::mal Mensajes que no ayudan
```text
cambios
arreglo
asdf
version final 2
```
:::
:::bien Mensajes útiles
```text
Agrega cálculo de IVA con Decimal
Corrige redondeo de minutos facturables
Módulo 4: ejercicios de diccionarios
Lee clientes.csv con codificación latin-1
```
:::
:::

## El archivo `.gitignore`

Le dice a Git qué **no** debe guardar. El curso ya trae uno con lo importante:

```text
.venv/          # el entorno virtual (se recrea con requirements.txt)
/datos/         # los datos generados (pueden pesar 20 GB)
__pycache__/    # archivos temporales de Python
.env            # contraseñas y configuración secreta
```

:::error Nunca subas datos reales ni contraseñas
GitHub público es **público**: cualquiera puede ver lo que subas. Nunca subas archivos de facturación reales de tu empresa, ni contraseñas, ni tokens. Si alguna vez lo haces por error, borrar el archivo no basta: queda en el historial. En el módulo 21 verás cómo manejar secretos correctamente.
:::

## Poner el curso en GitHub

Esto se hace una sola vez. Necesitas una cuenta gratuita en [github.com](https://github.com).

1. En GitHub, crea un repositorio nuevo llamado `pydatos` (público, **sin** README ni `.gitignore`, porque ya los tienes).
2. En la terminal, dentro de la carpeta del curso:

```powershell
git init
git add .
git commit -m "Curso PyDatos: versión inicial"
git remote add origin https://github.com/TU_USUARIO/pydatos.git
git push -u origin main
```

3. En el otro computador (casa u oficina), en la carpeta donde quieras el curso:

```powershell
git clone https://github.com/TU_USUARIO/pydatos.git
cd pydatos
python -m venv .venv
```

La primera vez que hagas `push`, Git abrirá una ventana para iniciar sesión en GitHub. Las siguientes veces lo recordará.

:::telco Git en un equipo de facturación
Cuando un proceso de facturación falla en producción, la primera pregunta es "¿qué cambió?". Con Git, `git log` y `git diff` responden en segundos. Sin Git, la respuesta es "no sé, alguien tocó algo".
:::

## Cuestionario

? Modificaste `tarifas.py` y ejecutaste `git commit -m "Ajusta tarifas"` sin hacer `git add`. ¿Qué pasa?
- [ ] El commit incluye `tarifas.py` igual.
- [x] El commit no incluye el cambio, porque el archivo no estaba preparado.
- [ ] Git borra el cambio.
- [ ] Se sube directamente a GitHub.
> `git commit` solo guarda lo que está en la zona de preparación. Primero `git add`, después `git commit`. Si no había nada preparado, Git te avisa que no hay nada que guardar.

? Trabajaste en la oficina e hiciste `commit`, pero en la casa no ves los cambios. ¿Qué olvidaste?
- [ ] `git add` en la casa.
- [x] `git push` en la oficina (y luego `git pull` en la casa).
- [ ] `git status` en la oficina.
- [ ] `git init` en la casa.
> El commit queda solo en el computador donde lo hiciste. `push` lo sube a GitHub y `pull` lo baja en el otro.

? ¿Cuál de estos archivos NO debería subirse nunca a un repositorio público?
- [ ] `requirements.txt`
- [ ] `tarifas.py`
- [x] `.env` con la contraseña de la base de datos de facturación
- [ ] `README.md`
> Las contraseñas y la configuración secreta van en `.env`, que está en `.gitignore`. Lo demás es justamente lo que quieres versionar.
