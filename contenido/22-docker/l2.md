Un **Dockerfile** es la receta de la imagen: una lista de instrucciones que Docker ejecuta en orden.

```dockerfile
# Dockerfile
FROM python:3.12-slim

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=1

WORKDIR /app

COPY requirements.lock .
RUN pip install --no-cache-dir -r requirements.lock

COPY src/ src/
COPY pyproject.toml .
RUN pip install --no-cache-dir --no-deps .

RUN useradd --create-home telco
USER telco

ENTRYPOINT ["python", "-m", "conciliacion.cli"]
CMD ["--help"]
```

| Instrucción | Para qué |
|---|---|
| `FROM` | Imagen base. `-slim` pesa ~50 MB en lugar de ~400 MB |
| `ENV` | Variables de entorno de la imagen. `PYTHONUNBUFFERED=1` hace que los `print` se vean de inmediato en `docker logs` |
| `WORKDIR` | Carpeta de trabajo (la crea si no existe) |
| `COPY origen destino` | Copia archivos de tu proyecto a la imagen |
| `RUN` | Ejecuta un comando **al construir** (instalar librerías) |
| `USER` | Con qué usuario corre el contenedor |
| `ENTRYPOINT` | El programa que ejecuta el contenedor |
| `CMD` | Argumentos por defecto (se reemplazan con lo que escribas después de la imagen en `docker run`) |

```powershell
docker build -t telco-pipeline:1.0 .
docker run --rm telco-pipeline:1.0                    # muestra --help
docker run --rm telco-pipeline:1.0 validar /datos     # reemplaza el CMD
```

## Capas y caché: el orden importa

:::pasos Cada instrucción es una capa
:::paso Docker guarda cada paso
Cada `COPY` y `RUN` produce una **capa**. Al reconstruir, Docker reutiliza las capas cuyas entradas no cambiaron.
:::
:::paso Si una capa cambia, las siguientes se rehacen
Si copias **todo** el proyecto antes de instalar (`COPY . .` y luego `pip install`), cualquier cambio en una línea de código invalida la capa de instalación: cada construcción reinstala pandas, numpy, duckdb… (minutos).
:::
:::paso Lo que cambia poco, primero
Copiando primero **solo** `requirements.lock` e instalando, esa capa se reutiliza mientras no cambien las dependencias. Cambiar tu código solo rehace las últimas capas: segundos.
:::
:::

:::reto Ordena el Dockerfile
Este Dockerfile funciona, pero reinstala todas las librerías cada vez que cambias una línea de código, corre como root y usa la forma de texto en `ENTRYPOINT`. Reescríbelo en la variable `dockerfile` para que:

1. empiece con `FROM python:3.12-slim`;
2. copie **solo** `requirements.lock` y lo instale **antes** de copiar `src/`;
3. cree el usuario `telco` con `useradd` y cambie a él con `USER` antes del `ENTRYPOINT`;
4. use `ENTRYPOINT` en forma de **lista**.

```pyreto
dockerfile = """
FROM python:3.12-slim
WORKDIR /app
COPY . .
RUN pip install --no-cache-dir -r requirements.lock
ENTRYPOINT python -m conciliacion.cli
"""
```

:::pista
Guíate por el Dockerfile del principio de la lección: `COPY requirements.lock .` → `RUN pip install ...` → `COPY src/ src/` → `RUN useradd --create-home telco` → `USER telco` → `ENTRYPOINT ["python", "-m", "conciliacion.cli"]`.
:::

```pyprueba
import json


def _instrucciones():
    lineas = [l.strip() for l in dockerfile.strip().splitlines() if l.strip() and not l.strip().startswith("#")]
    return [(l.split()[0].upper(), l[len(l.split()[0]):].strip()) for l in lineas]


def _posicion(condicion, mensaje):
    for i, (instr, args) in enumerate(_instrucciones()):
        if condicion(instr, args):
            return i
    raise AssertionError(mensaje)


def prueba_base():
    """Empieza con FROM python:3.12-slim"""
    igual(_instrucciones()[0], ("FROM", "python:3.12-slim"))


def prueba_cache():
    """Instala las dependencias antes de copiar el código"""
    copia_lock = _posicion(lambda i, a: i == "COPY" and a.startswith("requirements.lock"), "Copia requirements.lock solo")
    instala = _posicion(lambda i, a: i == "RUN" and "pip install" in a and "requirements.lock" in a, "Falta RUN pip install -r requirements.lock")
    copia_src = _posicion(lambda i, a: i == "COPY" and a.startswith("src"), "Copia src/ con su propio COPY")
    assert copia_lock < instala < copia_src, "El orden debe ser: COPY requirements.lock → RUN pip install → COPY src/"
    assert not any(i == "COPY" and a.startswith(". ") for i, a in _instrucciones()), "No copies todo el proyecto con COPY . ."


def prueba_usuario_y_entrypoint():
    """Usuario sin privilegios y ENTRYPOINT en lista"""
    crea = _posicion(lambda i, a: i == "RUN" and "useradd" in a and "telco" in a, "Crea el usuario telco con useradd")
    usa = _posicion(lambda i, a: i == "USER" and a == "telco", "Cambia al usuario con USER telco")
    entrada = _posicion(lambda i, a: i == "ENTRYPOINT", "Falta ENTRYPOINT")
    assert crea < usa < entrada, "useradd y USER van antes del ENTRYPOINT"
    argumentos = _instrucciones()[entrada][1]
    try:
        lista = json.loads(argumentos)
    except json.JSONDecodeError:
        raise AssertionError(f"ENTRYPOINT debe ir en forma de lista JSON: {argumentos}") from None
    igual(lista, ["python", "-m", "conciliacion.cli"], "ENTRYPOINT")
```

## No correr como root

Por defecto, el contenedor corre como **root**. Si tu programa tiene un error de seguridad (o un archivo malicioso se procesa), el daño posible es mucho mayor. `useradd` + `USER` es una práctica estándar y casi gratuita.

## ENTRYPOINT en forma de lista

:::comparar
:::mal Forma de texto
```dockerfile
ENTRYPOINT python -m conciliacion.cli
```
Se ejecuta a través de un *shell* (`/bin/sh -c ...`): tu programa no recibe las señales de `docker stop` (se mata a los 10 segundos sin cerrar archivos ni conexiones) y no puedes pasarle argumentos.
:::
:::bien Forma de lista (exec)
```dockerfile
ENTRYPOINT ["python", "-m", "conciliacion.cli"]
```
Tu programa es el proceso principal, recibe las señales y los argumentos de `docker run imagen ...` se le agregan.
:::
:::

## .dockerignore

Antes de construir, Docker envía la carpeta del proyecto (el **contexto**) al motor. Sin `.dockerignore`, eso incluye `.venv/`, `.git/`… y **tus 20 GB de datos**.

```text
# .dockerignore
.git
.venv
__pycache__/
*.pyc
.pytest_cache/
.mypy_cache/
datos/
salidas/
*.csv
*.parquet
.env
```

:::error Nunca datos ni secretos en la imagen
Una imagen se comparte (un registro, otro equipo, un servidor). Los datos de clientes y el `.env` con contraseñas **no** deben estar dentro: los datos entran por **volúmenes** y los secretos por **variables de entorno** al ejecutar (lección 3). `.dockerignore` es la barrera para que no entren por accidente.
:::

:::reto Tu .dockerignore
Escribe en `dockerignore` las reglas (una por línea) para que la función `excluido` de abajo (una versión simplificada de cómo Docker las aplica) **deje fuera** `.venv`, `.git`, la carpeta `datos/`, cualquier `.csv` o `.parquet` y el `.env`, pero **no** excluya el código ni la configuración del proyecto.

```pyreto
from fnmatch import fnmatch

dockerignore = """
__pycache__/
"""


def excluido(ruta, reglas):
    """True si alguna regla excluye la ruta (o una de sus carpetas)."""
    partes = ruta.split("/")
    candidatos = ["/".join(partes[: i + 1]) for i in range(len(partes))]
    for regla in reglas.splitlines():
        regla = regla.strip().rstrip("/")
        if regla and not regla.startswith("#"):
            if any(fnmatch(c, regla) or fnmatch(partes[-1], regla) for c in candidatos):
                return True
    return False


for ruta in [".venv/Lib/x.py", "datos/20GB/cdr.csv", "src/conciliacion/cli.py", ".env"]:
    print(ruta, "→", "fuera" if excluido(ruta, dockerignore) else "entra")
```

:::pista
Una regla por línea: `.git`, `.venv`, `datos/`, `*.csv`, `*.parquet` y `.env`. No agregues reglas generales como `*.py` o `src/`.
:::

```pyprueba
FUERA = [".venv/Lib/site-packages/pandas/__init__.py", ".git/config", "datos/20GB/cdr.csv", "datos/muestra/clientes.csv",
         "salidas/resumen.parquet", "reporte.csv", ".env", "__pycache__/x.pyc"]
ADENTRO = ["src/conciliacion/cli.py", "pyproject.toml", "requirements.lock", "Dockerfile", ".env.example", "README.md"]


def prueba_excluye():
    """Deja fuera lo que no debe entrar a la imagen"""
    requiere("dockerignore", "excluido")
    for ruta in FUERA:
        assert excluido(ruta, dockerignore), f"{ruta} debería quedar fuera de la imagen"


def prueba_no_excluye_codigo():
    """El código y la configuración sí entran"""
    for ruta in ADENTRO:
        assert not excluido(ruta, dockerignore), f"{ruta} debería entrar a la imagen"
```

## Cuestionario

? ¿Por qué se copia `requirements.lock` e instala ANTES de copiar el código?
- [ ] Porque Docker lo exige
- [x] Para que la capa de instalación se reutilice de la caché mientras las dependencias no cambien
- [ ] Para que la imagen pese menos
- [ ] Para correr como usuario sin privilegios
> Cambiar el código ya no obliga a reinstalar todas las librerías en cada construcción.

? ¿Qué ventaja tiene `ENTRYPOINT ["python", "-m", "app"]` frente a `ENTRYPOINT python -m app`?
- [ ] Ninguna
- [x] El programa recibe directamente las señales (como `docker stop`) y los argumentos de `docker run`
- [ ] Es más rápido de construir
- [ ] Permite usar variables de entorno
> La forma de texto pasa por un shell intermedio que se queda con las señales.

? ¿Para qué sirve `.dockerignore`?
- [ ] Para ignorar errores de construcción
- [x] Para excluir del contexto de construcción archivos como `.venv`, datos y `.env`
- [ ] Para ocultar la imagen
- [ ] Para ignorar contenedores detenidos
> Construcciones más rápidas, imágenes más livianas y sin datos ni secretos.
