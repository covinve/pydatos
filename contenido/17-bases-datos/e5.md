## Enunciado

El área de reclamos envía cada día un lote de **ajustes** (notas crédito o débito) a las facturas. Un lote debe aplicarse **completo o no aplicarse**: si una sola factura del lote tiene un problema, ninguna cambia.

Las pruebas crean dos tablas: `facturas (factura_id TEXT PRIMARY KEY, total INTEGER)` con las facturas de la muestra y `ajustes (lote TEXT, factura_id TEXT, valor INTEGER)` vacía.

Escribe `aplicar_lote(con, lote, ajustes)`, donde `ajustes` es una lista de tuplas `(factura_id, valor)`:

1. Dentro de **una transacción**, para cada ajuste: suma `valor` al `total` de la factura y registra la fila en `ajustes`.
2. Si una factura **no existe** (el `UPDATE` no cambió ninguna fila: `cursor.rowcount == 0`) o su total queda **negativo**, lanza `ValueError` con un mensaje que incluya el `factura_id`, y **nada** del lote debe quedar aplicado.
3. Si un lote con el mismo nombre **ya fue aplicado**, lanza `ValueError` sin cambiar nada (así un lote enviado dos veces no se cobra doble).
4. Si todo sale bien, devuelve la suma de los valores aplicados.

## Pruebas

```python
import sqlite3

import pandas as pd

FACT = pd.read_csv("facturas.csv")


def base():
    con = sqlite3.connect(":memory:")
    con.execute("CREATE TABLE facturas (factura_id TEXT PRIMARY KEY, total INTEGER)")
    con.execute("CREATE TABLE ajustes (lote TEXT, factura_id TEXT, valor INTEGER)")
    con.executemany("INSERT INTO facturas VALUES (?, ?)", FACT[["factura_id", "total"]].values.tolist())
    con.commit()
    return con


def estado(con):
    return (con.execute("SELECT SUM(total) FROM facturas").fetchone()[0],
            con.execute("SELECT COUNT(*) FROM ajustes").fetchone()[0])


F1, F2, F3 = FACT["factura_id"].iloc[:3]
T1 = int(FACT["total"].iloc[0])


def prueba_lote_correcto():
    """Aplica y registra un lote válido"""
    requiere("aplicar_lote")
    con = base()
    antes = estado(con)[0]
    igual(aplicar_lote(con, "L001", [(F1, -5000), (F2, 1200)]), -3800)
    igual(estado(con), (antes - 3800, 2))
    igual(con.execute("SELECT total FROM facturas WHERE factura_id = ?", (F1,)).fetchone()[0], T1 - 5000)
    con.rollback()
    igual(estado(con), (antes - 3800, 2), "Los cambios deben quedar confirmados (commit)")


def prueba_factura_inexistente():
    """Una factura que no existe deshace todo el lote"""
    con = base()
    antes = estado(con)
    e = lanza(ValueError, aplicar_lote, con, "L002", [(F1, -1000), ("F999", -1000), (F3, 500)])
    assert "F999" in str(e), "El mensaje debe decir qué factura falló"
    igual(estado(con), antes, "No debe quedar nada aplicado")


def prueba_total_negativo():
    """Un total negativo deshace todo el lote"""
    con = base()
    antes = estado(con)
    e = lanza(ValueError, aplicar_lote, con, "L003", [(F2, 100), (F1, -T1 - 1)])
    assert F1 in str(e)
    igual(estado(con), antes)


def prueba_lote_repetido():
    """Un lote no se aplica dos veces"""
    con = base()
    aplicar_lote(con, "L004", [(F1, -100)])
    despues = estado(con)
    lanza(ValueError, aplicar_lote, con, "L004", [(F1, -100)])
    igual(estado(con), despues)
    igual(aplicar_lote(con, "L005", [(F1, -100)]), -100, "Otro lote sí se aplica")


def prueba_falla_y_sigue_funcionando():
    """Después de un lote fallido, la conexión sigue usable"""
    con = base()
    lanza(ValueError, aplicar_lote, con, "L006", [("NOEXISTE", 1)])
    igual(aplicar_lote(con, "L006", [(F1, 1)]), 1, "El lote fallido no debe quedar registrado")
```

## Pista 1

`with con:` hace `rollback()` si dentro se lanza **cualquier** excepción, y la deja salir. Así que basta con lanzar el `ValueError` dentro del bloque:

```python
with con:
    for factura_id, valor in ajustes:
        cur = con.execute("UPDATE facturas SET total = total + ? WHERE factura_id = ?", (valor, factura_id))
        if cur.rowcount == 0:
            raise ValueError(f"La factura {factura_id} no existe")
        ...
```

## Pista 2

Para saber si el total quedó negativo, consulta después del `UPDATE`:

```python
total = con.execute("SELECT total FROM facturas WHERE factura_id = ?", (factura_id,)).fetchone()[0]
```

Para el lote repetido: `SELECT 1 FROM ajustes WHERE lote = ? LIMIT 1` antes de empezar (dentro de la transacción).

## Solución

```python
import sqlite3


def aplicar_lote(con, lote, ajustes):
    with con:
        if con.execute("SELECT 1 FROM ajustes WHERE lote = ? LIMIT 1", (lote,)).fetchone():
            raise ValueError(f"El lote {lote} ya fue aplicado")
        for factura_id, valor in ajustes:
            cur = con.execute("UPDATE facturas SET total = total + ? WHERE factura_id = ?", (valor, factura_id))
            if cur.rowcount == 0:
                raise ValueError(f"La factura {factura_id} no existe")
            total = con.execute("SELECT total FROM facturas WHERE factura_id = ?", (factura_id,)).fetchone()[0]
            if total < 0:
                raise ValueError(f"La factura {factura_id} quedaría con total negativo ({total})")
            con.execute("INSERT INTO ajustes VALUES (?, ?, ?)", (lote, factura_id, valor))
    return sum(valor for _, valor in ajustes)
```

## Explicación

La solución es corta porque la transacción hace el trabajo difícil. Sin ella, para "deshacer" tendrías que recordar qué cambiaste y revertirlo a mano, y si el programa se cae a la mitad (un corte de luz, un error inesperado), la base quedaría a medias **sin forma de saberlo**.

Hay dos ideas de producción en este ejercicio:

- **Atomicidad**: el lote completo o nada (`with con:`).
- **Idempotencia**: registrar el nombre del lote impide aplicarlo dos veces, un error clásico cuando alguien reenvía un archivo "por si acaso". En una base real se haría con una tabla `lotes` con `lote` como clave primaria.

La tabla `ajustes` es además una **auditoría**: cualquier total se puede explicar como el valor original más sus ajustes.
