Recorres listas, textos, diccionarios y archivos con el mismo `for`. ¿Cómo sabe Python recorrer cosas tan distintas? Todas cumplen el **protocolo de iteración**.

## Iterable e iterador

- Un **iterable** es algo que se puede recorrer: una lista, un archivo, un `range`.
- Un **iterador** es el objeto que **va entregando** los elementos, uno a la vez, y recuerda por dónde va.

```pyrun
duraciones = [125, 0, 61]

iterador = iter(duraciones)     # pide un iterador al iterable
print(next(iterador))           # 125
print(next(iterador))           # 0
print(next(iterador))           # 61
print(next(iterador))           # error esperado
```

Cuando no quedan elementos, `next` lanza `StopIteration`. Eso es exactamente lo que hace el `for` por dentro:

```python
# Esto…
for d in duraciones:
    print(d)

# …es lo mismo que esto:
iterador = iter(duraciones)
while True:
    try:
        d = next(iterador)
    except StopIteration:
        break
    print(d)
```

:::reto El encabezado con next
`lineas` simula un archivo abierto. Con `iter` y `next`:

1. Saca la primera línea en `encabezado`.
2. Recorre **el mismo iterador** con un `for` y cuenta en `registros` las líneas que quedan.

```pyreto
lineas = ["cdr_id|tipo|duracion_seg", "1|VOZ|125", "2|SMS|0", "3|DATOS|900"]

# encabezado y registros

print(encabezado, registros)
```

:::pista
`iterador = iter(lineas)`, `encabezado = next(iterador)` y después `for linea in iterador:` sigue desde la segunda línea.
:::

```pyprueba
def prueba_valores():
    """encabezado es la primera línea y registros = 3"""
    requiere("encabezado", "registros")
    igual(encabezado, "cdr_id|tipo|duracion_seg", "encabezado")
    igual(registros, 3, "registros")


def prueba_usa_next():
    """Usa iter y next"""
    assert "iter(" in codigo and "next(" in codigo, "Saca el encabezado con iter(...) y next(...)"
    assert "lineas[" not in codigo, "No uses índices: avanza el iterador con next"
```

```pysolucion
lineas = ["cdr_id|tipo|duracion_seg", "1|VOZ|125", "2|SMS|0", "3|DATOS|900"]

iterador = iter(lineas)
encabezado = next(iterador)
registros = 0
for linea in iterador:
    registros += 1

print(encabezado, registros)
```
:::

## Los iteradores se gastan

Un iterador avanza en una sola dirección y no se reinicia:

```pyrun
iterador = iter([125, 0, 61])
print(list(iterador))   # [125, 0, 61]
print(list(iterador))   # [] — ya se consumió
```

:::error El archivo que "solo funciona una vez"
Un archivo abierto es su propio iterador. Si lo recorres dos veces seguidas, la segunda no entrega nada:

```python
with open("cdr.csv") as f:
    total = sum(1 for _ in f)      # recorre todo
    tipos = [l.split("|")[3] for l in f]   # lista vacía: el archivo ya llegó al final
```

Haz todo en una pasada o vuelve a abrir el archivo (o usa `f.seek(0)`).
:::

:::reto Todo en una pasada
Este código recorre el iterador dos veces: la primera vez cuenta bien, pero la segunda ya no encuentra nada y `tipos` queda vacío. Corrígelo para calcular `total` y `tipos` **en un solo recorrido**, sin convertir el iterador en lista.

```pyreto
registros = iter(["1|VOZ|125", "2|SMS|0", "3|DATOS|900", "4|VOZ|61"])

total = sum(1 for _ in registros)
tipos = {r.split("|")[1] for r in registros}

print(total, tipos)
```

:::pista
Un solo `for registro in registros:` en el que sumas 1 a `total` y agregas el tipo a un conjunto (`tipos.add(...)`).
:::

```pyprueba
def prueba_resultados():
    """total = 4 y tipos tiene los tres tipos"""
    requiere("total", "tipos")
    igual(total, 4, "total")
    igual(set(tipos), {"VOZ", "SMS", "DATOS"}, "tipos")


def prueba_sin_lista():
    """No convierte el iterador en lista"""
    assert "list(registros)" not in codigo, "Resuélvelo en una pasada, sin list(registros)"
```

```pysolucion
registros = iter(["1|VOZ|125", "2|SMS|0", "3|DATOS|900", "4|VOZ|61"])

total = 0
tipos = set()
for registro in registros:
    total += 1
    tipos.add(registro.split("|")[1])

print(total, tipos)
```
:::

## Evaluación perezosa

Muchas herramientas de Python son **perezosas**: no calculan nada hasta que alguien pide el siguiente elemento.

```pyrun
import sys

lista = [d * 2 for d in range(1_000_000)]      # calcula y guarda un millón de valores
perezoso = map(lambda d: d * 2, range(1_000_000))   # no calcula nada todavía

print(sys.getsizeof(lista), "bytes")
print(sys.getsizeof(perezoso), "bytes")
print(next(perezoso), next(perezoso))           # calcula solo cuando se pide
```

| Perezosos (entregan uno a uno) | Ansiosos (construyen todo) |
|---|---|
| `range`, `map`, `filter`, `zip`, `enumerate` | `list(...)`, `sorted(...)` |
| Archivos abiertos | `archivo.readlines()` |
| Generadores (lección 2) | Comprensiones de lista `[...]` |
| `itertools` (lección 3) | `set(...)`, `dict(...)` |

## Un iterable propio

Una clase es iterable si su `__iter__` devuelve un iterador. Lo más simple es que `__iter__` sea un generador (lo verás en la próxima lección), pero también puedes escribir el iterador "a mano" con `__next__`:

```pyrun
from datetime import date, timedelta


class DiasDelPeriodo:
    def __init__(self, inicio, fin):
        self.actual = inicio
        self.fin = fin

    def __iter__(self):
        return self

    def __next__(self):
        if self.actual > self.fin:
            raise StopIteration
        dia = self.actual
        self.actual += timedelta(days=1)
        return dia


for dia in DiasDelPeriodo(date(2026, 9, 28), date(2026, 10, 2)):
    print(dia)
```

:::reto Lotes para procesar
Escribe la clase iterable `Lotes(total, tamano)`, que entrega pares `(inicio, fin)` para procesar `total` registros en bloques de `tamano`. El último lote puede ser más corto.

`Lotes(10, 4)` entrega `(0, 4)`, `(4, 8)` y `(8, 10)`.

```pyreto
class Lotes:
    def __init__(self, total, tamano):
        pass


for inicio, fin in Lotes(10, 4):
    print(inicio, fin)
```

:::pista
Guarda `self.actual = 0`. `__iter__` devuelve `self`. En `__next__`: si `self.actual >= self.total`, `raise StopIteration`; si no, calcula `fin = min(self.actual + self.tamano, self.total)`, avanza `self.actual = fin` y devuelve el par.
:::

```pyprueba
def prueba_lotes():
    """Entrega los pares (inicio, fin)"""
    requiere("Lotes")
    igual(list(Lotes(10, 4)), [(0, 4), (4, 8), (8, 10)])
    igual(list(Lotes(8, 4)), [(0, 4), (4, 8)], "total múltiplo del tamaño")
    igual(list(Lotes(0, 4)), [], "sin registros")


def prueba_protocolo():
    """Usa __iter__ y __next__"""
    lotes = Lotes(5, 2)
    igual(next(iter(lotes)), (0, 2))
```

```pysolucion
class Lotes:
    def __init__(self, total, tamano):
        self.total = total
        self.tamano = tamano
        self.actual = 0

    def __iter__(self):
        return self

    def __next__(self):
        if self.actual >= self.total:
            raise StopIteration
        inicio = self.actual
        fin = min(self.actual + self.tamano, self.total)
        self.actual = fin
        return inicio, fin


for inicio, fin in Lotes(10, 4):
    print(inicio, fin)
```
:::

:::telco ¿Por qué importa?
Todo el procesamiento de archivos grandes se basa en esta idea: **pedir un registro, procesarlo, olvidarlo y pedir el siguiente**. Un `for` sobre un archivo de 20 GB nunca tiene más de una línea en memoria, porque el archivo es un iterador perezoso.
:::
