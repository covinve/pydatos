## Enunciado

`descarga.py` (ya está en tu carpeta) tiene `obtener(cliente, url, intentos=3, dormir=time.sleep)`:

- llama `cliente.get(url, timeout=10)`;
- si lanza `ConnectionError`, o la respuesta tiene `status_code >= 500`, **reintenta** esperando `dormir(2 ** n)` (1, 2, 4…) entre intentos;
- un `status_code` 4xx **no** se reintenta: lanza `ValueError` de inmediato;
- si se agotan los intentos, relanza el último `ConnectionError` o lanza `RuntimeError` si el último fallo fue un 5xx;
- si todo va bien devuelve `respuesta.json()`.

**Escribe sus pruebas** con `Mock` y `side_effect` (listas de respuestas y excepciones). `dormir` también puede ser un `Mock`: así verificas las esperas sin esperar. Al menos **5** pruebas.

## Preparación

```python
from pathlib import Path

Path("descarga.py").write_text('''
import time


def obtener(cliente, url, intentos=3, dormir=time.sleep):
    ultimo = None
    for n in range(intentos):
        try:
            respuesta = cliente.get(url, timeout=10)
        except ConnectionError as error:
            ultimo = error
        else:
            if 400 <= respuesta.status_code < 500:
                raise ValueError(f"Error {respuesta.status_code} en {url}")
            if respuesta.status_code < 500:
                return respuesta.json()
            ultimo = RuntimeError(f"Error {respuesta.status_code} en {url}")
        if n < intentos - 1:
            dormir(2 ** n)
    raise ultimo
''', encoding="utf-8")
```

## Pista 2

Para el `timeout`: `cliente.get.assert_called_with("u", timeout=10)`. Para "duerme después del último": cuando se agotan 3 intentos, `dormir` debe haberse llamado exactamente **2** veces. Y no olvides el caso 4xx: `pytest.raises(ValueError)` y `cliente.get.call_count == 1`.

## Solución

```python
from unittest.mock import Mock, call

import pytest

from descarga import obtener


def respuesta(estado, datos=None):
    r = Mock()
    r.status_code = estado
    r.json.return_value = datos
    return r


def test_exito_directo():
    cliente = Mock()
    cliente.get.return_value = respuesta(200, {"ok": True})
    dormir = Mock()
    assert obtener(cliente, "https://api/x", dormir=dormir) == {"ok": True}
    dormir.assert_not_called()
    cliente.get.assert_called_once_with("https://api/x", timeout=10)


def test_recupera_con_espera_exponencial():
    cliente = Mock()
    cliente.get.side_effect = [ConnectionError("caída"), respuesta(503), respuesta(200, {"ok": 1})]
    dormir = Mock()
    assert obtener(cliente, "u", dormir=dormir) == {"ok": 1}
    assert dormir.call_args_list == [call(1), call(2)]
    assert cliente.get.call_count == 3


def test_4xx_no_se_reintenta():
    cliente = Mock()
    cliente.get.side_effect = [respuesta(404), respuesta(200, {})]
    dormir = Mock()
    with pytest.raises(ValueError):
        obtener(cliente, "u", dormir=dormir)
    assert cliente.get.call_count == 1
    dormir.assert_not_called()


def test_agota_con_error_de_conexion():
    cliente = Mock()
    cliente.get.side_effect = ConnectionError("sin red")
    dormir = Mock()
    with pytest.raises(ConnectionError):
        obtener(cliente, "u", intentos=3, dormir=dormir)
    assert cliente.get.call_count == 3
    assert dormir.call_args_list == [call(1), call(2)]


def test_agota_con_5xx():
    cliente = Mock()
    cliente.get.side_effect = [respuesta(500), respuesta(502)]
    with pytest.raises(RuntimeError):
        obtener(cliente, "u", intentos=2, dormir=Mock())
```

## Explicación

Simular "falla de conexión, después un 503, después funciona" con un servidor real sería difícil e inestable. Con `side_effect` es una lista de tres elementos. Esa es la mayor fortaleza de los mocks: **provocar exactamente** los escenarios de error que en la vida real son raros pero que tu código debe manejar.

Inyectar `dormir` (en lugar de llamar `time.sleep` directo) permitió dos cosas: que las pruebas no esperen siete segundos de verdad, y verificar la **política** de espera (`[call(1), call(2)]`), que es parte del comportamiento. El mutante "duerme después del último intento" no cambia ningún resultado, pero hace que el programa tarde más justo cuando ya sabe que falló: solo una prueba que cuente las esperas lo detecta.

Fíjate en un detalle de `Mock`: para que una respuesta tenga `status_code = 404` hay que asignarlo explícitamente. Un `Mock()` sin configurar devolvería otro `Mock` en `status_code`, y la comparación `400 <= Mock()` lanzaría `TypeError`: un recordatorio de que el doble debe parecerse a lo que reemplaza.
