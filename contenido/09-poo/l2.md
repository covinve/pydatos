Muchas clases existen sobre todo para **guardar datos**: un CDR, un cliente, una factura. Escribir el `__init__` con diez `self.x = x` es tedioso. `@dataclass` lo escribe por ti a partir de las anotaciones.

```pyrun
from dataclasses import dataclass


@dataclass
class Cliente:
    cliente_id: str
    nombre: str
    linea: str
    plan_id: str
    segmento: str = "RESIDENCIAL"


c = Cliente("CL0000001", "Lucía Gómez", "3001234567", "HOG30")
print(c)
print(c.nombre, c.segmento)
print(c == Cliente("CL0000001", "Lucía Gómez", "3001234567", "HOG30"))
```

`@dataclass` genera automáticamente:

| Método | Para qué |
|---|---|
| `__init__` | Crear el objeto con los campos en orden |
| `__repr__` | Mostrarlo legible: `Cliente(cliente_id='CL0000001', ...)` |
| `__eq__` | Comparar por valor: dos clientes con los mismos datos son iguales |

## Valores por defecto mutables: field

¿Recuerdas la trampa de las listas por defecto (módulo 5)? Las dataclasses te protegen: no aceptan `= []`. Usa `field(default_factory=list)`:

```pyrun
from dataclasses import dataclass, field


@dataclass
class Factura:
    factura_id: str
    cliente_id: str
    conceptos: list[tuple[str, int]] = field(default_factory=list)

    def agregar(self, descripcion, valor):
        self.conceptos.append((descripcion, valor))

    def total(self):
        return sum(valor for _, valor in self.conceptos)


f1 = Factura("F1", "CL1")
f2 = Factura("F2", "CL2")
f1.agregar("Cargo fijo", 35900)
print(f1.total(), f2.conceptos)
```

## Inmutables: frozen=True

Un CDR es un hecho del pasado: no debería cambiar después de leído. `frozen=True` impide modificar los campos, y además permite usar el objeto en conjuntos y como clave de diccionario:

```pyrun
from dataclasses import dataclass


@dataclass(frozen=True)
class CDR:
    cdr_id: int
    linea_origen: str
    tipo: str
    duracion_seg: int


c = CDR(1, "3001234567", "VOZ", 125)
vistos = {c, CDR(1, "3001234567", "VOZ", 125)}
print(len(vistos))       # 1: son iguales y tienen el mismo hash
c.duracion_seg = 999     # error esperado
```

Para "cambiar" un objeto inmutable se crea uno nuevo con `dataclasses.replace(c, duracion_seg=60)`.

## Validar al crear: __post_init__

`__post_init__` se ejecuta justo después del `__init__` generado. Es el lugar para **validar** y rechazar objetos inválidos desde su nacimiento:

```pyrun
from dataclasses import dataclass

TIPOS = {"VOZ", "SMS", "DATOS"}


@dataclass(frozen=True)
class CDR:
    cdr_id: int
    linea_origen: str
    tipo: str
    duracion_seg: int

    def __post_init__(self):
        if self.tipo not in TIPOS:
            raise ValueError(f"Tipo desconocido: {self.tipo!r}")
        if self.duracion_seg < 0:
            raise ValueError(f"Duración negativa: {self.duracion_seg}")


print(CDR(1, "3001", "VOZ", 125))
try:
    CDR(2, "3001", "VOX", 10)
except ValueError as error:
    print("Rechazado:", error)
```

:::consejo Objetos siempre válidos
Si un `CDR` solo puede existir cuando sus datos son válidos, el resto del programa nunca tiene que volver a preguntarse "¿y si el tipo es raro?". Validar en la frontera (al crear el objeto) simplifica todo lo demás.
:::

## Convertir a diccionario y a tupla

```pyrun
from dataclasses import asdict, astuple, dataclass, fields


@dataclass
class Consumo:
    linea: str
    minutos: int = 0
    mb: float = 0.0


c = Consumo("3001234567", 342, 15360.5)
print(asdict(c))                         # útil para json.dump o csv.DictWriter
print(astuple(c))
print([f.name for f in fields(Consumo)])
```

:::capo slots=True
`@dataclass(slots=True)` hace que cada objeto ocupe menos memoria (no guarda un diccionario interno de atributos). Con millones de objetos en memoria, la diferencia se nota. Aun así, para millones de registros la herramienta correcta es Pandas o Polars, no objetos de Python.
:::
