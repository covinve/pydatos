## Pista 2

```sql
SELECT segmento, COUNT(*), ROUND(AVG(cargo_fijo)) FROM planes GROUP BY segmento
```

`ROUND` en SQLite devuelve un número decimal (`50400.0`): conviértelo con `int()` al armar el diccionario. Y `cur.rowcount` después de `executemany` dice cuántas filas se insertaron (o usa `len(filas)`).

## Solución

```python
import csv
import sqlite3


def crear_planes(con):
    con.execute("""
        CREATE TABLE planes (
            plan_id           TEXT PRIMARY KEY,
            nombre            TEXT NOT NULL,
            segmento          TEXT NOT NULL,
            cargo_fijo        INTEGER NOT NULL,
            minutos_incluidos INTEGER NOT NULL
        )
    """)
    with open("planes.csv", encoding="utf-8", newline="") as f:
        filas = [(p["plan_id"], p["nombre"], p["segmento"], int(p["cargo_fijo"]), int(p["minutos_incluidos"]))
                 for p in csv.DictReader(f)]
    con.executemany("INSERT INTO planes VALUES (?, ?, ?, ?, ?)", filas)
    con.commit()
    return len(filas)


def planes_por_segmento(con):
    filas = con.execute("""
        SELECT segmento, COUNT(*), ROUND(AVG(cargo_fijo))
        FROM planes
        GROUP BY segmento
    """)
    return {segmento: (cantidad, int(promedio)) for segmento, cantidad, promedio in filas}


con = sqlite3.connect(":memory:")
print(crear_planes(con))
print(planes_por_segmento(con))
```

## Explicación

SQLite es **flexible con los tipos**: si insertas el texto `"35900"` en una columna `INTEGER` intenta convertirlo, pero en otras situaciones lo guarda como texto sin avisar (y entonces `"9" > "10"`). Por eso conviene convertir en Python antes de insertar: `typeof(columna)` te dice cómo quedó guardado cada valor. PostgreSQL, en cambio, rechazaría el valor de tipo equivocado.

La clave primaria hace su trabajo de inmediato: la prueba intenta insertar otra vez `BAS10` y la base de datos lo rechaza con `IntegrityError`.
