Si el caso de uso "conciliar" no debe saber de dónde vienen los planes, ¿cómo los obtiene? Pidiéndolos a **algo** que cumpla un contrato: "dame el plan con este código". Ese contrato es un **puerto**; cada forma concreta de cumplirlo (CSV, SQLite, memoria) es un **adaptador**.

## Protocol: el contrato

`typing.Protocol` describe qué métodos debe tener un objeto, sin obligarlo a heredar de nada (es el *duck typing* del módulo 9, pero escrito):

```python
from typing import Protocol


class RepositorioPlanes(Protocol):
    def obtener(self, plan_id: str) -> Plan: ...
    def todos(self) -> list[Plan]: ...
```

Cualquier clase con esos dos métodos **es** un `RepositorioPlanes`. El caso de uso solo depende del protocolo:

```python
class CalculadoraFacturas:
    def __init__(self, planes: RepositorioPlanes):
        self.planes = planes

    def calcular(self, consumo: Consumo) -> Factura:
        plan = self.planes.obtener(consumo.plan_id)
        ...
```

## Adaptadores intercambiables

```pyrun
import csv
import sqlite3
from dataclasses import dataclass
from typing import Protocol


@dataclass(frozen=True)
class Plan:
    plan_id: str
    cargo_fijo: int


class PlanNoEncontrado(LookupError):
    pass


class RepositorioPlanes(Protocol):
    def obtener(self, plan_id: str) -> Plan: ...


class PlanesEnMemoria:
    def __init__(self, planes):
        self._planes = {p.plan_id: p for p in planes}

    def obtener(self, plan_id):
        try:
            return self._planes[plan_id]
        except KeyError:
            raise PlanNoEncontrado(plan_id) from None


class PlanesCSV(PlanesEnMemoria):
    def __init__(self, ruta):
        with open(ruta, encoding="utf-8", newline="") as f:
            super().__init__(Plan(p["plan_id"], int(p["cargo_fijo"])) for p in csv.DictReader(f))


class PlanesSQLite:
    def __init__(self, con):
        self.con = con

    def obtener(self, plan_id):
        fila = self.con.execute("SELECT plan_id, cargo_fijo FROM planes WHERE plan_id = ?", (plan_id,)).fetchone()
        if fila is None:
            raise PlanNoEncontrado(plan_id)
        return Plan(*fila)


def cargo_con_iva(repo: RepositorioPlanes, plan_id: str) -> int:
    """Caso de uso: no sabe ni le importa de dónde salen los planes."""
    return int(repo.obtener(plan_id).cargo_fijo * 1.19 + 0.5)


con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE planes (plan_id TEXT, cargo_fijo INTEGER)")
con.execute("INSERT INTO planes VALUES ('HOG30', 35900)")

for repo in (PlanesEnMemoria([Plan("HOG30", 35900)]), PlanesCSV("planes.csv"), PlanesSQLite(con)):
    print(f"{type(repo).__name__:16} → {cargo_con_iva(repo, 'HOG30'):,}")
```

Tres fuentes, un solo caso de uso, sin un solo `if fuente == "csv"`.

## El patrón repositorio

Un **repositorio** es un adaptador especial: hace que una colección de entidades guardadas (en archivo, base de datos o API) se vea como una colección en memoria. Sus métodos hablan el idioma del dominio, no de la base de datos:

| Repositorio | No… |
|---|---|
| `clientes.obtener(linea)` | `SELECT * FROM clientes WHERE linea = ?` |
| `clientes.activos_de_plan("HOG30")` | `pd.read_csv(...).query(...)` |
| `facturas.guardar(factura)` | `INSERT INTO ...` / `to_sql` |

Toda la SQL o el Pandas queda **encapsulado** dentro del adaptador.

:::reto Dos adaptadores, un contrato
El puerto `RepositorioClientes` pide dos métodos: `obtener(linea)` (lanza `ClienteNoEncontrado` si no existe) y `activos_de_plan(plan_id)` (lista de clientes activos de ese plan, ordenados por línea). Escribe dos adaptadores que lo cumplan **igual**:

- `ClientesEnMemoria(clientes)`: recibe una lista de `Cliente`;
- `ClientesSQLite(con)`: lee de la tabla `clientes (linea, plan_id, activo)`.

```pyreto
import sqlite3
from dataclasses import dataclass
from typing import Protocol


@dataclass(frozen=True)
class Cliente:
    linea: str
    plan_id: str
    activo: bool


class ClienteNoEncontrado(LookupError):
    pass


class RepositorioClientes(Protocol):
    def obtener(self, linea: str) -> Cliente: ...
    def activos_de_plan(self, plan_id: str) -> list[Cliente]: ...


# ClientesEnMemoria y ClientesSQLite
```

:::pista
En memoria: guarda `{c.linea: c for c in clientes}`. En SQLite: `SELECT linea, plan_id, activo FROM clientes WHERE linea = ?` y convierte cada fila en `Cliente(linea, plan_id, bool(activo))`. Si no hay fila, `raise ClienteNoEncontrado(linea)`.
:::

```pyprueba
import sqlite3

DATOS = [Cliente("3003", "HOG30", True), Cliente("3001", "HOG30", True), Cliente("3002", "HOG30", False), Cliente("3004", "ILIM", True)]


def _sqlite():
    con = sqlite3.connect(":memory:")
    con.execute("CREATE TABLE clientes (linea TEXT, plan_id TEXT, activo INTEGER)")
    con.executemany("INSERT INTO clientes VALUES (?, ?, ?)", [(c.linea, c.plan_id, int(c.activo)) for c in DATOS])
    return ClientesSQLite(con)


def _repos():
    requiere("ClientesEnMemoria", "ClientesSQLite")
    return [ClientesEnMemoria(DATOS), _sqlite()]


def prueba_obtener():
    """Los dos adaptadores obtienen igual"""
    for repo in _repos():
        igual(repo.obtener("3002"), Cliente("3002", "HOG30", False), type(repo).__name__)


def prueba_no_encontrado():
    """Los dos lanzan ClienteNoEncontrado"""
    for repo in _repos():
        lanza(ClienteNoEncontrado, repo.obtener, "3999")


def prueba_activos():
    """activos_de_plan: activos, ordenados por línea"""
    for repo in _repos():
        igual([c.linea for c in repo.activos_de_plan("HOG30")], ["3001", "3003"], type(repo).__name__)
        igual(repo.activos_de_plan("BAS10"), [], f"{type(repo).__name__} sin clientes")
```

```pysolucion
import sqlite3
from dataclasses import dataclass
from typing import Protocol


@dataclass(frozen=True)
class Cliente:
    linea: str
    plan_id: str
    activo: bool


class ClienteNoEncontrado(LookupError):
    pass


class RepositorioClientes(Protocol):
    def obtener(self, linea: str) -> Cliente: ...
    def activos_de_plan(self, plan_id: str) -> list[Cliente]: ...


class ClientesEnMemoria:
    def __init__(self, clientes):
        self._clientes = {c.linea: c for c in clientes}

    def obtener(self, linea):
        try:
            return self._clientes[linea]
        except KeyError:
            raise ClienteNoEncontrado(linea) from None

    def activos_de_plan(self, plan_id):
        return sorted((c for c in self._clientes.values() if c.plan_id == plan_id and c.activo), key=lambda c: c.linea)


class ClientesSQLite:
    def __init__(self, con):
        self.con = con

    def obtener(self, linea):
        fila = self.con.execute("SELECT linea, plan_id, activo FROM clientes WHERE linea = ?", (linea,)).fetchone()
        if fila is None:
            raise ClienteNoEncontrado(linea)
        return Cliente(fila[0], fila[1], bool(fila[2]))

    def activos_de_plan(self, plan_id):
        filas = self.con.execute(
            "SELECT linea, plan_id, activo FROM clientes WHERE plan_id = ? AND activo = 1 ORDER BY linea", (plan_id,)
        ).fetchall()
        return [Cliente(l, p, bool(a)) for l, p, a in filas]
```

## Inyección de dependencias

"Inyectar" una dependencia es simplemente **pasarla como parámetro** en lugar de crearla adentro:

:::comparar
:::mal Crear adentro
```python
class Conciliador:
    def __init__(self):
        self.planes = PlanesCSV("D:/datos/planes.csv")   # atado a un archivo concreto
```
Para probarlo necesitas ese archivo en esa ruta. Para usar SQLite, hay que editar la clase.
:::
:::bien Recibir de afuera
```python
class Conciliador:
    def __init__(self, planes: RepositorioPlanes):
        self.planes = planes
```
En las pruebas: `Conciliador(PlanesEnMemoria([...]))`. En producción: `Conciliador(PlanesSQLite(con))`.
:::
:::

¿Y dónde se crean entonces los objetos concretos? En **un solo lugar**, al arrancar el programa, que se suele llamar la **raíz de composición** (normalmente, la CLI o el `main`):

```python
# cli.py — el único archivo que conoce TODAS las piezas concretas
def main(carpeta: Path, periodo: str):
    planes = PlanesCSV(carpeta / "planes.csv")
    facturas = FacturasCSV(carpeta / "facturas.csv")
    reporte = ReporteExcel(Path("salidas") / f"conciliacion_{periodo}.xlsx")
    ConciliarPeriodo(planes, facturas, reporte).ejecutar(Periodo(periodo))
```

:::consejo Dobles de prueba
Un adaptador en memoria no es "código de mentira": es una implementación real del puerto, perfecta para pruebas rápidas (sin archivos ni red) y para prototipos. Se llaman **dobles de prueba** (*fakes*). En el módulo 20 verás también los *mocks*, que además registran cómo se los llamó.
:::

:::reto Inyecta las dependencias
`ResumenDiario` crea por dentro su fuente de CDR y su salida, así que no se puede probar sin archivos reales. Reescríbelo para que **reciba** las dos dependencias en el constructor:

- `fuente`: cualquier objeto con el método `cdr_del_dia(fecha)`, que devuelve una lista de diccionarios con `tipo`;
- `salida`: cualquier objeto con el método `publicar(texto)`.

`ejecutar(fecha)` cuenta los CDR por tipo y publica una línea por tipo, en orden alfabético, con el formato `DATOS: 2`.

```pyreto
from collections import Counter


class ResumenDiario:
    def __init__(self):
        self.fuente = FuenteCSV("D:/datos/cdr")          # atado a una carpeta concreta
        self.salida = SalidaCorreo("facturacion@empresa.com")

    def ejecutar(self, fecha):
        conteo = Counter(c["tipo"] for c in self.fuente.cdr_del_dia(fecha))
        for tipo in sorted(conteo):
            self.salida.publicar(f"{tipo}: {conteo[tipo]}")
```

:::pista
Cambia el constructor a `def __init__(self, fuente, salida):` y guarda lo que recibes. Para probarlo, cualquier clase pequeña con esos métodos sirve (las pruebas usan una fuente en memoria y una salida que guarda los textos en una lista).
:::

```pyprueba
class FuenteFalsa:
    def __init__(self, por_dia):
        self.por_dia = por_dia
        self.pedidas = []

    def cdr_del_dia(self, fecha):
        self.pedidas.append(fecha)
        return self.por_dia.get(fecha, [])


class SalidaFalsa:
    def __init__(self):
        self.textos = []

    def publicar(self, texto):
        self.textos.append(texto)


def prueba_inyeccion():
    """Usa la fuente y la salida que recibe"""
    requiere("ResumenDiario")
    fuente = FuenteFalsa({"2026-09-30": [{"tipo": "VOZ"}, {"tipo": "DATOS"}, {"tipo": "VOZ"}, {"tipo": "DATOS"}, {"tipo": "SMS"}]})
    salida = SalidaFalsa()
    ResumenDiario(fuente, salida).ejecutar("2026-09-30")
    igual(fuente.pedidas, ["2026-09-30"], "fechas pedidas a la fuente")
    igual(salida.textos, ["DATOS: 2", "SMS: 1", "VOZ: 2"], "textos publicados")


def prueba_dia_vacio():
    """Un día sin CDR no publica nada"""
    salida = SalidaFalsa()
    ResumenDiario(FuenteFalsa({}), salida).ejecutar("2026-10-01")
    igual(salida.textos, [])
```

## Cuestionario

? ¿Qué es un puerto en esta arquitectura?
- [ ] Un número de red como el 5432
- [x] Un contrato (por ejemplo, un `Protocol`) que define qué necesita la aplicación del exterior
- [ ] Un archivo CSV
- [ ] Una clase que hereda de `Base`
> El puerto dice "necesito algo que me dé planes"; los adaptadores dicen "yo los doy desde un CSV".

? ¿Qué significa inyectar una dependencia?
- [ ] Instalarla con pip
- [x] Recibirla como parámetro en lugar de crearla dentro de la clase o función
- [ ] Importarla al principio del archivo
- [ ] Heredar de ella
> Así puedes darle una implementación distinta en pruebas y en producción.

? ¿Dónde deben crearse los adaptadores concretos (PlanesCSV, PlanesSQLite)?
- [ ] Dentro del dominio
- [ ] En cada caso de uso
- [x] En un solo lugar al arrancar: la raíz de composición (CLI o main)
- [ ] En las pruebas solamente
> Es el único lugar que conoce todas las piezas concretas y las conecta.
