`argparse` funciona, pero cuando tu herramienta crece a varios comandos (`telco validar`, `telco resumen`, `telco conciliar`) el código se vuelve largo. **Typer** construye la interfaz de línea de comandos a partir de las **anotaciones de tipo** de tus funciones.

## De función a comando

```python
# telco_cli.py
from pathlib import Path
from typing import Annotated

import typer

app = typer.Typer(help="Herramientas de facturación telco.")


@app.command()
def resumen(
    archivo: Annotated[Path, typer.Argument(help="Ruta del cdr.csv", exists=True, dir_okay=False)],
    top: Annotated[int, typer.Option(help="Líneas a mostrar", min=1)] = 5,
    tipo: Annotated[str | None, typer.Option(help="VOZ, SMS o DATOS")] = None,
):
    """Resume un archivo de CDR."""
    ...
    typer.echo(f"Resumen de {archivo} (top {top})")


@app.command()
def validar(carpeta: Path, salida: Annotated[Path, typer.Option("--salida", "-o")] = Path("salidas")):
    """Valida los CDR de una carpeta y escribe los rechazos."""
    ...
    if hay_errores_graves:
        raise typer.Exit(code=1)


if __name__ == "__main__":
    app()
```

```powershell
python telco_cli.py --help
python telco_cli.py resumen datos/10MB/cdr.csv --top 3
python telco_cli.py validar datos/10MB -o salidas/hoy
```

| En la función | En la terminal |
|---|---|
| Parámetro sin valor por defecto | Argumento obligatorio |
| Parámetro con valor por defecto | Opción `--nombre` |
| `bool = False` | Bandera `--nombre / --no-nombre` |
| `Path` con `exists=True` | Typer verifica que la ruta exista |
| `int` con `min=1` | Typer valida el rango |
| Docstring | Texto de `--help` |

:::consejo Typer usa Rich
Si tienes instalado `rich` (viene con Typer), los errores y la ayuda salen con colores y recuadros. `from rich.progress import track` te da barras de progreso: `for archivo in track(archivos, description="Procesando"):`.
:::

## Probar una CLI

`typer.testing.CliRunner` ejecuta los comandos **dentro** de pytest, capturando la salida y el código:

```python
from typer.testing import CliRunner

from telco_cli import app

runner = CliRunner()


def test_resumen(tmp_path):
    archivo = tmp_path / "cdr.csv"
    archivo.write_text("cdr_id|linea_origen|...\n...", encoding="utf-8")
    resultado = runner.invoke(app, ["resumen", str(archivo), "--top", "2"])
    assert resultado.exit_code == 0
    assert "top 2" in resultado.output


def test_archivo_inexistente():
    resultado = runner.invoke(app, ["resumen", "no_existe.csv"])
    assert resultado.exit_code == 2           # error de uso
```

## Comando instalable

En el proyecto 2 ya lo hiciste: en `pyproject.toml`,

```toml
[project.scripts]
telco = "telco_cli:app"
```

y después de `pip install -e .` tienes el comando `telco` en el entorno virtual, sin escribir `python ...`.

:::capo La lógica fuera de la CLI
La función del comando debe ser **delgada**: leer opciones, llamar funciones de tu paquete, mostrar el resultado y decidir el código de salida. La lógica (validar, conciliar) vive en módulos normales que se prueban sin CLI. Es la idea de capas que formalizarás en el módulo 19.
:::
