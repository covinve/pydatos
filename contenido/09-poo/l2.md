Muchas clases existen sobre todo para **guardar datos**: un CDR, un cliente, una factura. Escribir el `__init__` con diez `self.x = x` es tedioso. `@dataclass` lo escribe por ti a partir de las anotaciones.

```pyrun
from dataclasses import dataclass


@dataclass
class Cliente:
    cliente_id: str
    nombre: str
    linea: str
    plan_id: str
    segmento: str = "RESIDENCIAL"


c = Cliente("CL0000001", "Lucía Gómez", "3001234567", "HOG30")
print(c)
print(c.nombre, c.segmento)
print(c == Cliente("CL0000001", "Lucía Gómez", "3001234567", "HOG30"))
```

`@dataclass` genera automáticamente:

| Método | Para qué |
|---|---|
| `__init__` | Crear el objeto con los campos en orden |
| `__repr__` | Mostrarlo legible: `Cliente(cliente_id='CL0000001', ...)` |
| `__eq__` | Comparar por valor: dos clientes con los mismos datos son iguales |

:::reto El plan como dataclass
Convierte este diccionario en una dataclass `Plan` con los campos `plan_id` (texto), `cargo_fijo` (entero) y `minutos_incluidos` (entero, **por defecto 0**).

Después crea `hog30` con `"HOG30"`, `35900` y `300`, y `basico` solo con `"BAS0"` y `9900`.

```pyreto
from dataclasses import dataclass

plan_viejo = {"plan_id": "HOG30", "cargo_fijo": 35900, "minutos_incluidos": 300}

# La dataclass Plan, hog30 y basico

print(hog30)
print(basico)
```

:::pista
Los campos se declaran con anotaciones dentro de la clase: `cargo_fijo: int`. El valor por defecto va así: `minutos_incluidos: int = 0`. Pon `@dataclass` encima de `class Plan:`.
:::

```pyprueba
import dataclasses


def prueba_es_dataclass():
    """Plan es una dataclass con los tres campos"""
    requiere("Plan")
    assert dataclasses.is_dataclass(Plan), "Decora la clase con @dataclass"
    igual([f.name for f in dataclasses.fields(Plan)], ["plan_id", "cargo_fijo", "minutos_incluidos"])


def prueba_objetos():
    """hog30 y basico tienen sus datos (y el valor por defecto)"""
    requiere("hog30", "basico")
    igual(hog30, Plan("HOG30", 35900, 300), "hog30")
    igual(basico.minutos_incluidos, 0, "minutos_incluidos por defecto")


def prueba_igualdad():
    """Dos planes con los mismos datos son iguales"""
    igual(Plan("X", 1, 2) == Plan("X", 1, 2), True)
```

```pysolucion
from dataclasses import dataclass

plan_viejo = {"plan_id": "HOG30", "cargo_fijo": 35900, "minutos_incluidos": 300}


@dataclass
class Plan:
    plan_id: str
    cargo_fijo: int
    minutos_incluidos: int = 0


hog30 = Plan("HOG30", 35900, 300)
basico = Plan("BAS0", 9900)

print(hog30)
print(basico)
```

## Valores por defecto mutables: field

¿Recuerdas la trampa de las listas por defecto (módulo 5)? Las dataclasses te protegen: no aceptan `= []`. Usa `field(default_factory=list)`:

```pyrun
from dataclasses import dataclass, field


@dataclass
class Factura:
    factura_id: str
    cliente_id: str
    conceptos: list[tuple[str, int]] = field(default_factory=list)

    def agregar(self, descripcion, valor):
        self.conceptos.append((descripcion, valor))

    def total(self):
        return sum(valor for _, valor in self.conceptos)


f1 = Factura("F1", "CL1")
f2 = Factura("F2", "CL2")
f1.agregar("Cargo fijo", 35900)
print(f1.total(), f2.conceptos)
```

:::reto Un lote con su propia lista
Escribe la dataclass `Lote` con:

- `nombre` (texto);
- `archivos` (lista de textos), que empieza **vacía** y propia de cada lote;
- el método `agregar(self, archivo)`;
- el método `cantidad(self)`, que devuelve cuántos archivos tiene.

```pyreto
from dataclasses import dataclass, field

# La dataclass Lote


noche = Lote("nocturno")
reproceso = Lote("reproceso")
noche.agregar("cdr_01.csv")
noche.agregar("cdr_02.csv")
print(noche.cantidad(), reproceso.archivos)   # 2 []
```

:::pista
`archivos: list[str] = field(default_factory=list)`. Los métodos se escriben como en cualquier clase, con `self`.
:::

```pyprueba
def prueba_listas_propias():
    """Cada lote tiene su propia lista"""
    requiere("Lote")
    a, b = Lote("a"), Lote("b")
    a.agregar("x.csv")
    igual(a.archivos, ["x.csv"], "lote a")
    igual(b.archivos, [], "lote b")


def prueba_cantidad():
    """cantidad cuenta los archivos"""
    lote = Lote("n")
    for nombre in ("1.csv", "2.csv", "3.csv"):
        lote.agregar(nombre)
    igual(lote.cantidad(), 3)


def prueba_usa_field():
    """Usa field(default_factory=list)"""
    assert "default_factory" in codigo, "Declara la lista con field(default_factory=list)"
```

```pysolucion
from dataclasses import dataclass, field


@dataclass
class Lote:
    nombre: str
    archivos: list[str] = field(default_factory=list)

    def agregar(self, archivo):
        self.archivos.append(archivo)

    def cantidad(self):
        return len(self.archivos)


noche = Lote("nocturno")
reproceso = Lote("reproceso")
noche.agregar("cdr_01.csv")
noche.agregar("cdr_02.csv")
print(noche.cantidad(), reproceso.archivos)   # 2 []
```

## Inmutables: frozen=True

Un CDR es un hecho del pasado: no debería cambiar después de leído. `frozen=True` impide modificar los campos, y además permite usar el objeto en conjuntos y como clave de diccionario:

```pyrun
from dataclasses import dataclass


@dataclass(frozen=True)
class CDR:
    cdr_id: int
    linea_origen: str
    tipo: str
    duracion_seg: int


c = CDR(1, "3001234567", "VOZ", 125)
vistos = {c, CDR(1, "3001234567", "VOZ", 125)}
print(len(vistos))       # 1: son iguales y tienen el mismo hash
c.duracion_seg = 999     # error esperado
```

Para "cambiar" un objeto inmutable se crea uno nuevo con `dataclasses.replace(c, duracion_seg=60)`.

## Validar al crear: __post_init__

`__post_init__` se ejecuta justo después del `__init__` generado. Es el lugar para **validar** y rechazar objetos inválidos desde su nacimiento:

```pyrun
from dataclasses import dataclass

TIPOS = {"VOZ", "SMS", "DATOS"}


@dataclass(frozen=True)
class CDR:
    cdr_id: int
    linea_origen: str
    tipo: str
    duracion_seg: int

    def __post_init__(self):
        if self.tipo not in TIPOS:
            raise ValueError(f"Tipo desconocido: {self.tipo!r}")
        if self.duracion_seg < 0:
            raise ValueError(f"Duración negativa: {self.duracion_seg}")


print(CDR(1, "3001", "VOZ", 125))
try:
    CDR(2, "3001", "VOX", 10)
except ValueError as error:
    print("Rechazado:", error)
```

:::consejo Objetos siempre válidos
Si un `CDR` solo puede existir cuando sus datos son válidos, el resto del programa nunca tiene que volver a preguntarse "¿y si el tipo es raro?". Validar en la frontera (al crear el objeto) simplifica todo lo demás.
:::

:::reto Una llamada que no nace inválida
Escribe la dataclass **inmutable** `Llamada` con `linea` (texto), `destino` (texto) y `segundos` (entero). Al crearla debe validar:

- `destino` es `LOCAL`, `NACIONAL` o `INTERNACIONAL`; si no, `ValueError`;
- `segundos` no es negativo; si lo es, `ValueError`.

Además, agrega el método `minutos(self)` con los minutos facturables.

```pyreto
from dataclasses import dataclass

# La dataclass Llamada


ok = Llamada("3001234567", "NACIONAL", 125)
print(ok, ok.minutos())
```

:::pista
`@dataclass(frozen=True)` la hace inmutable. Las validaciones van en `def __post_init__(self):` con `raise ValueError(...)`.
:::

```pyprueba
import dataclasses


def prueba_valida():
    """Una llamada válida se crea y calcula sus minutos"""
    requiere("Llamada")
    llamada = Llamada("3001234567", "NACIONAL", 125)
    igual(llamada.minutos(), 3)
    igual(Llamada("3001", "LOCAL", 0).minutos(), 0, "llamada de 0 segundos")


def prueba_rechaza():
    """Rechaza destinos desconocidos y duraciones negativas"""
    lanza(ValueError, Llamada, "3001", "SATELITAL", 10)
    lanza(ValueError, Llamada, "3001", "LOCAL", -5)


def prueba_inmutable():
    """No se puede modificar después de creada"""
    llamada = Llamada("3001", "LOCAL", 60)
    lanza(dataclasses.FrozenInstanceError, setattr, llamada, "segundos", 1)
```

```pysolucion
from dataclasses import dataclass

DESTINOS = {"LOCAL", "NACIONAL", "INTERNACIONAL"}


@dataclass(frozen=True)
class Llamada:
    linea: str
    destino: str
    segundos: int

    def __post_init__(self):
        if self.destino not in DESTINOS:
            raise ValueError(f"Destino desconocido: {self.destino!r}")
        if self.segundos < 0:
            raise ValueError(f"Duración negativa: {self.segundos}")

    def minutos(self):
        return (self.segundos + 59) // 60


ok = Llamada("3001234567", "NACIONAL", 125)
print(ok, ok.minutos())
```
:::

## Convertir a diccionario y a tupla

```pyrun
from dataclasses import asdict, astuple, dataclass, fields


@dataclass
class Consumo:
    linea: str
    minutos: int = 0
    mb: float = 0.0


c = Consumo("3001234567", 342, 15360.5)
print(asdict(c))                         # útil para json.dump o csv.DictWriter
print(astuple(c))
print([f.name for f in fields(Consumo)])
```

:::capo slots=True
`@dataclass(slots=True)` hace que cada objeto ocupe menos memoria (no guarda un diccionario interno de atributos). Con millones de objetos en memoria, la diferencia se nota. Aun así, para millones de registros la herramienta correcta es Pandas o Polars, no objetos de Python.
:::

> `default_factory` crea una lista nueva para cada objeto. `= []` no se permite porque sería compartida.

? ¿Qué ventaja tiene `frozen=True`?
- [ ] Hace el código más rápido de escribir

- [ ] Guarda el objeto en disco
- [ ] Valida los tipos de los campos
