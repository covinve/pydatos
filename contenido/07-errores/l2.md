Capturar errores es la mitad del trabajo. La otra mitad es **lanzar buenos errores**: que cuando algo falle, el mensaje diga exactamente qué y dónde.

## raise

```pyrun
def minutos_facturables(segundos):
    if segundos < 0:
        raise ValueError(f"La duración no puede ser negativa: {segundos}")
    return (segundos + 59) // 60


print(minutos_facturables(125))
print(minutos_facturables(-45))   # error esperado
```

:::reto Un error que se explica solo
Escribe `normalizar_tipo(tipo)`: quita espacios, pasa a mayúsculas y devuelve el tipo. Si el resultado no es `VOZ`, `SMS` ni `DATOS`, lanza `ValueError` con un mensaje que incluya **el valor recibido** y los tipos válidos, por ejemplo:

`Tipo 'VOX' inválido: se esperaba VOZ, SMS o DATOS`

```pyreto
def normalizar_tipo(tipo):
    pass


print(normalizar_tipo(" voz "))   # VOZ
try:
    normalizar_tipo("vox")
except ValueError as error:
    print("Error:", error)
```

:::pista
Primero `limpio = tipo.strip().upper()`. Después `if limpio not in ("VOZ", "SMS", "DATOS"): raise ValueError(f"Tipo '{limpio}' inválido: se esperaba VOZ, SMS o DATOS")`.
:::

```pyprueba
def prueba_normaliza():
    """Devuelve el tipo limpio"""
    requiere("normalizar_tipo")
    igual(normalizar_tipo(" voz "), "VOZ")
    igual(normalizar_tipo("Datos"), "DATOS")


def prueba_lanza():
    """Lanza ValueError con el valor recibido en el mensaje"""
    error = lanza(ValueError, normalizar_tipo, "vox")
    assert "VOX" in str(error), f"El mensaje debe mencionar el valor recibido. Mensaje: {error}"
    assert "SMS" in str(error), f"El mensaje debe decir qué se esperaba. Mensaje: {error}"
```

```pysolucion
def normalizar_tipo(tipo):
    limpio = tipo.strip().upper()
    if limpio not in ("VOZ", "SMS", "DATOS"):
        raise ValueError(f"Tipo '{limpio}' inválido: se esperaba VOZ, SMS o DATOS")
    return limpio


print(normalizar_tipo(" voz "))   # VOZ
try:
    normalizar_tipo("vox")
except ValueError as error:
    print("Error:", error)
```

## Excepciones propias

Crear tu propia excepción permite que quien llama la distinga de los errores de Python. Basta con una línea (las clases se ven en el módulo 9):

```pyrun
class ErrorDeFacturacion(Exception):
    """Error en una regla de negocio de facturación."""


class PlanInexistente(ErrorDeFacturacion):
    """El plan del cliente no está en el catálogo."""


PLANES = {"HOG30": 35900}


def cargo_fijo(plan_id):
    if plan_id not in PLANES:
        raise PlanInexistente(f"El plan '{plan_id}' no existe")
    return PLANES[plan_id]


try:
    cargo_fijo("PLAN99")
except ErrorDeFacturacion as error:      # atrapa también las subclases
    print(type(error).__name__, "→", error)
```

### Excepciones con datos

Una excepción es un objeto y puede llevar información útil, no solo un mensaje:

```pyrun
class ErrorDeRegistro(Exception):
    def __init__(self, numero_linea, campo, valor):
        self.numero_linea = numero_linea
        self.campo = campo
        self.valor = valor
        super().__init__(f"Línea {numero_linea}, campo {campo}: valor inválido {valor!r}")


try:
    raise ErrorDeRegistro(1534, "duracion_seg", "abc")
except ErrorDeRegistro as e:
    print(e)
    print("Para el reporte:", e.numero_linea, e.campo)
```

:::reto Tu propia excepción
1. Crea la excepción `LineaInvalida`, que herede de `Exception` y guarde la línea recibida en el atributo `linea`. Su mensaje debe ser `Línea inválida: <la línea>`.
2. Escribe `validar_linea(linea)`: si `linea` no tiene 10 dígitos o no empieza por `"3"`, lanza `LineaInvalida(linea)`. Si está bien, la devuelve.

```pyreto
# 1. class LineaInvalida(Exception): ...

# 2. def validar_linea(linea): ...


try:
    validar_linea("31577")
except LineaInvalida as e:
    print("Error:", e, "| línea:", e.linea)
```

:::pista
Sigue el ejemplo de `ErrorDeRegistro`: en `__init__(self, linea)` guarda `self.linea = linea` y llama a `super().__init__(f"Línea inválida: {linea}")`.
:::

```pyprueba
def prueba_excepcion():
    """LineaInvalida hereda de Exception y guarda la línea"""
    requiere("LineaInvalida")
    assert issubclass(LineaInvalida, Exception), "LineaInvalida debe heredar de Exception"
    e = LineaInvalida("123")
    igual(e.linea, "123", "atributo linea")
    igual(str(e), "Línea inválida: 123", "mensaje")


def prueba_validar_ok():
    """Una línea móvil válida se devuelve igual"""
    requiere("validar_linea")
    igual(validar_linea("3001234567"), "3001234567")


def prueba_validar_mal():
    """Las líneas inválidas lanzan LineaInvalida con su línea"""
    for mala in ("31577", "6014445566", "300123456X"):
        error = lanza(LineaInvalida, validar_linea, mala)
        igual(error.linea, mala, f"atributo linea para {mala}")
```

```pysolucion
class LineaInvalida(Exception):
    def __init__(self, linea):
        self.linea = linea
        super().__init__(f"Línea inválida: {linea}")


def validar_linea(linea):
    if not (len(linea) == 10 and linea.isdigit() and linea.startswith("3")):
        raise LineaInvalida(linea)
    return linea


try:
    validar_linea("31577")
except LineaInvalida as e:
    print("Error:", e, "| línea:", e.linea)
```

## raise ... from: encadenar errores

Cuando conviertes un error de bajo nivel en uno tuyo, usa `from` para conservar la causa original:

```pyrun
class ErrorDeRegistro(Exception):
    pass


def leer_duracion(numero, texto):
    try:
        return int(texto)
    except ValueError as e:
        raise ErrorDeRegistro(f"Línea {numero}: duración inválida {texto!r}") from e


leer_duracion(7, "1,5")   # error esperado
```

El traceback muestra **las dos** excepciones: la tuya, con el contexto de negocio, y la original, con el detalle técnico.

:::reto Traduce el error técnico
Escribe `leer_monto(numero_linea, texto)` que convierta `texto` a entero. Si `int()` falla, lanza `ErrorDeMonto` con el mensaje `Línea <n>: monto inválido '<texto>'`, **encadenado** con `from` al `ValueError` original.

```pyreto
class ErrorDeMonto(Exception):
    pass


def leer_monto(numero_linea, texto):
    pass


print(leer_monto(3, "35900"))
try:
    leer_monto(7, "35.900")
except ErrorDeMonto as e:
    print(e, "| causa:", repr(e.__cause__))
```

:::pista
`try: return int(texto)` y `except ValueError as e: raise ErrorDeMonto(f"Línea {numero_linea}: monto inválido '{texto}'") from e`.
:::

```pyprueba
def prueba_valido():
    """Convierte los montos válidos"""
    requiere("leer_monto")
    igual(leer_monto(3, "35900"), 35900)


def prueba_error_con_contexto():
    """Lanza ErrorDeMonto con el número de línea y el texto"""
    error = lanza(ErrorDeMonto, leer_monto, 7, "35.900")
    igual(str(error), "Línea 7: monto inválido '35.900'")


def prueba_encadenado():
    """Conserva el ValueError original como causa"""
    error = lanza(ErrorDeMonto, leer_monto, 7, "abc")
    assert isinstance(error.__cause__, ValueError), "Encadena con «from e» para conservar el ValueError original"
```

```pysolucion
class ErrorDeMonto(Exception):
    pass


def leer_monto(numero_linea, texto):
    try:
        return int(texto)
    except ValueError as e:
        raise ErrorDeMonto(f"Línea {numero_linea}: monto inválido '{texto}'") from e

try:
    leer_monto(7, "35.900")
except ErrorDeMonto as e:

```

## Volver a lanzar

A veces quieres registrar el error y dejar que siga subiendo. Un `raise` solo, dentro de un `except`, relanza la misma excepción:

```python
try:
    procesar_archivo(ruta)
except OSError:
    print(f"No se pudo procesar {ruta}")
    raise
```

## Pedir perdón o pedir permiso

Hay dos estilos para manejar casos problemáticos:

:::columnas
:::columna LBYL: mira antes de saltar
```python
if texto.isdigit():
    segundos = int(texto)
else:
    segundos = None
```
Comprueba antes. Claro, pero `isdigit()` falla con `"-45"` aunque sea un entero válido.
:::
:::columna EAFP: pide perdón
```python
try:
    segundos = int(texto)
except ValueError:
    segundos = None
```
Intenta y maneja el error. Es el estilo más común en Python: deja que `int` decida qué es un entero.
:::
:::

En Python se prefiere **EAFP** (*Easier to Ask Forgiveness than Permission*) cuando la comprobación previa duplicaría la lógica de la operación.

## assert no es para validar datos

`assert condicion, "mensaje"` lanza `AssertionError` si la condición es falsa. Úsalo para **verificar supuestos de tu propio código** y en las pruebas (módulo 10), **nunca** para validar datos de entrada: Python puede ejecutarse con `-O`, que desactiva todos los `assert`.

:::telco Errores que cuentan una historia
"ValueError: invalid literal for int()" a las 3 de la mañana no le dice nada a quien está de turno. "Archivo cdr_20260930.csv, línea 1.534.221, campo duracion_seg: 'abc' no es un entero" le dice exactamente dónde mirar. La diferencia está en lanzar buenos errores.
:::
