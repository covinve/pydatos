## Enunciado

El CRM responde con JSON anidado: cada cliente tiene una lista de líneas y cada línea puede tener (o no) un plan y unos consumos. Para analizarlo necesitas una **tabla plana**: una fila por línea.

La preparación crea `respuesta_crm.json`. Escribe `aplanar(ruta)` que devuelva una lista de diccionarios con las claves:

| Clave | De dónde sale | Si falta |
|---|---|---|
| `cliente_id` | `cliente.id` | — |
| `nombre` | `cliente.nombre` | — |
| `segmento` | `cliente.segmento` | `"SIN_SEGMENTO"` |
| `linea` | `linea.numero` | — |
| `plan` | `linea.plan.codigo` | `None` (el plan puede ser `null` o no venir) |
| `activa` | `linea.estado == "ACTIVA"` | — |
| `minutos` | `linea.consumo.minutos` | `0` |
| `mb` | `linea.consumo.datos_mb` | `0.0` |

En el orden en que aparecen. Después escribe `resumen(filas)` → diccionario `{plan: minutos_totales}` solo de líneas activas con plan, ordenado por plan.

    requiere("aplanar")

## Pista 1

Dos ciclos anidados: uno por cliente y otro por sus líneas. Para los campos que pueden faltar, `.get()` con valor por defecto:

```python
for cliente in datos["datos"]:
    for linea in cliente["lineas"]:
        consumo = linea.get("consumo") or {}
        ...
```

## Pista 2

El plan es el caso más delicado: puede no venir (`get` devuelve `None`) o venir como `null` (también `None`). En ambos casos:

```python
plan = (linea.get("plan") or {}).get("codigo")
```

`algo or {}` reemplaza `None` por un diccionario vacío, así el segundo `.get` nunca falla.

## Solución

```python
import json


def aplanar(ruta):
    with open(ruta, encoding="utf-8") as f:
        datos = json.load(f)
    filas = []
    for cliente in datos["datos"]:
        for linea in cliente.get("lineas", []):
            consumo = linea.get("consumo") or {}
            filas.append({
                "cliente_id": cliente["id"],
                "nombre": cliente["nombre"],
                "segmento": cliente.get("segmento", "SIN_SEGMENTO"),
                "linea": linea["numero"],
                "plan": (linea.get("plan") or {}).get("codigo"),
                "activa": linea["estado"] == "ACTIVA",
                "minutos": consumo.get("minutos", 0),
                "mb": float(consumo.get("datos_mb", 0)),
            })
    return filas


def resumen(filas):
    totales = {}
    for f in filas:
        if f["activa"] and f["plan"]:
            totales[f["plan"]] = totales.get(f["plan"], 0) + f["minutos"]
    return dict(sorted(totales.items()))


filas = aplanar("respuesta_crm.json")
for fila in filas:
    print(fila)
print(resumen(filas))
```

## Explicación

Las APIs reales son así de irregulares: campos que a veces no vienen, `null` donde esperabas un objeto, listas vacías. El patrón `(x.get("a") or {}).get("b")` es tu mejor amigo para navegarlas sin `KeyError` ni `TypeError`.

Una vez plana, la lista va directo a Pandas: `pd.DataFrame(filas)`. Pandas también tiene `pd.json_normalize(datos["datos"], record_path="lineas", meta=["id", "nombre"])`, que hace parte de este trabajo automáticamente; pero entender cómo aplanar a mano te permite manejar los casos raros que `json_normalize` no resuelve solo.

Fíjate en `CL04`: un cliente sin líneas no genera filas. Si el análisis necesitara contarlo, habría que tratarlo aparte: aplanar siempre implica decidir qué pasa con los vacíos.
