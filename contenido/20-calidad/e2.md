## Enunciado

El módulo `alertas.py` (ya está en tu carpeta) tiene `revisar_validacion(resumen, notificador, umbral=5.0)`, que envía **una** alerta con asunto `"ALERTA validación"` si el porcentaje de rechazos **supera** el umbral, y devuelve `True`; si no, no envía nada y devuelve `False` (también con 0 registros).

**Escribe sus pruebas** usando `unittest.mock.Mock` como notificador: verifica con `assert_called_once()`, `assert_not_called()`, `call_args`, etc. Al menos **4** pruebas.

El curso las ejecuta contra la versión correcta (deben pasar) y contra cinco versiones con errores (cada una debe hacer fallar al menos una de tus pruebas).

## Preparación

```python
from pathlib import Path

Path("alertas.py").write_text('''
def revisar_validacion(resumen, notificador, umbral=5.0):
    total = resumen["registros_totales"]
    if total == 0:
        return False
    porcentaje = (total - resumen["registros_validos"]) / total * 100
    if porcentaje <= umbral:
        return False
    notificador.enviar("ALERTA validación", f"{porcentaje:.2f} % rechazados (umbral {umbral} %)")
    return True
''', encoding="utf-8")
```

## Pista 1

Para revisar los argumentos de la llamada:

```python
asunto, mensaje = notificador.enviar.call_args.args
assert asunto == "ALERTA validación"
assert "10.00 %" in mensaje
```

O de una vez: `notificador.enviar.assert_called_once_with("ALERTA validación", ANY)` (con `from unittest.mock import ANY`).

## Pista 2

Los casos que no pueden faltar: supera (envía una vez), no supera (no envía), **igual** al umbral (no envía) y 0 registros (no envía y devuelve `False`). Un caso borde por cada `if` del código.

## Solución

```python
from unittest.mock import ANY, Mock

from alertas import revisar_validacion


def test_alerta_si_supera_el_umbral():
    notificador = Mock()
    resumen = {"registros_totales": 100, "registros_validos": 90}
    assert revisar_validacion(resumen, notificador, umbral=5) is True
    notificador.enviar.assert_called_once()


def test_asunto_y_mensaje():
    notificador = Mock()
    revisar_validacion({"registros_totales": 200, "registros_validos": 180}, notificador, umbral=5)
    notificador.enviar.assert_called_once_with("ALERTA validación", ANY)
    asunto, mensaje = notificador.enviar.call_args.args
    assert "10.00 %" in mensaje


def test_no_alerta_bajo_el_umbral():
    notificador = Mock()
    assert revisar_validacion({"registros_totales": 100, "registros_validos": 99}, notificador) is False
    notificador.enviar.assert_not_called()


def test_igual_al_umbral_no_alerta():
    notificador = Mock()
    assert revisar_validacion({"registros_totales": 100, "registros_validos": 95}, notificador, umbral=5) is False
    notificador.enviar.assert_not_called()


def test_sin_registros():
    notificador = Mock()
    assert revisar_validacion({"registros_totales": 0, "registros_validos": 0}, notificador, umbral=0) is False
    notificador.enviar.assert_not_called()
```

## Explicación

Aquí el `Mock` es la herramienta correcta porque la **interacción es el resultado**: lo que importa de `revisar_validacion` es *si* envía, *cuántas veces* y *con qué asunto*. Un doble en memoria también serviría (`NotificadorMemoria` del módulo 19), pero `Mock` ya trae las verificaciones listas.

Los mutantes muestran qué verifica cada método:

| Mutante | Lo atrapa |
|---|---|
| Envía dos veces | `assert_called_once()` (un simple "se llamó" no basta) |
| No envía nunca | `assert_called_once()` |
| Asunto equivocado | `assert_called_once_with(...)` o `call_args` |
| Igual al umbral | Un caso borde exacto: 5 de 100 con umbral 5 |
| Envía sin superar | `assert_not_called()` |

`ANY` es útil cuando un argumento importa y el otro no: verificas el asunto sin acoplar la prueba al texto exacto del mensaje, que podría cambiar de redacción sin que sea un error.
