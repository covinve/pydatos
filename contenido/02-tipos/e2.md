## Enunciado

Contabilidad reportó que la suma del IVA de las facturas no coincide con sus cálculos. El sistema actual usa `float` y `round()`. Escribe tres funciones que calculen la factura **en pesos enteros**, con `Decimal`, según las reglas del curso:

1. `calcular_subtotal(cargo_fijo, consumo_adicional, descuento)` → `cargo_fijo + consumo_adicional - descuento`.
2. `calcular_iva(subtotal)` → 19 % del subtotal, **redondeado al peso con la regla comercial** (0,5 sube).
3. `calcular_total(cargo_fijo, consumo_adicional, descuento)` → `subtotal + iva`, usando las dos funciones anteriores.

Todas deben **devolver `Decimal`**. Los parámetros pueden llegar como `int`, `float`, `str` o `Decimal`.

```python
calcular_iva(150)                     # Decimal('29')   ← round() daría 28
calcular_total(35900, 5040, 0)        # Decimal('48719')
calcular_total("149900", 0, "14990")  # Decimal('160543')
```

## Pruebas

```python
from decimal import Decimal


def prueba_subtotal():
    """El subtotal resta el descuento y devuelve Decimal"""
    requiere("calcular_subtotal")
    resultado = calcular_subtotal(149900, 2000, 14990)
    igual(resultado, Decimal("136910"))
    assert isinstance(resultado, Decimal), f"Debe devolver Decimal, devolvió {type(resultado).__name__}"


def prueba_iva_redondeo_comercial():
    """El IVA de 150 es 29 (28,5 sube), no 28"""
    requiere("calcular_iva")
    igual(calcular_iva(150), Decimal("29"))
    igual(calcular_iva(45950), Decimal("8731"))


def prueba_iva_redondeo_normal():
    """El IVA de 40.940 es 7.779 y el de 100 es 19"""
    igual(calcular_iva(40940), Decimal("7779"))
    igual(calcular_iva(100), Decimal("19"))


def prueba_iva_sin_decimales():
    """El IVA queda en pesos enteros (sin decimales)"""
    iva = calcular_iva(40940)
    igual(iva.as_tuple().exponent, 0, "El IVA debe quedar redondeado a 0 decimales")


def prueba_total():
    """El total es subtotal + IVA"""
    requiere("calcular_total")
    igual(calcular_total(35900, 5040, 0), Decimal("48719"))
    igual(calcular_total(149900, 0, 14990), Decimal("160543"))


def prueba_acepta_texto_y_float():
    """Acepta valores como texto o float sin perder precisión"""
    igual(calcular_total("149900", "0", "14990"), Decimal("160543"))
    igual(calcular_total(19900.0, 1100.0, 0.0), Decimal("24990"))


def prueba_suma_de_muchas_facturas():
    """La suma de 1.000 IVA de $150 da exactamente 29.000"""
    total = sum(calcular_iva(150) for _ in range(1000))
```

## Pista 1

Convierte cada parámetro a `Decimal` pasando por `str()`, así funciona con cualquier tipo de entrada:

```python
def calcular_subtotal(cargo_fijo, consumo_adicional, descuento):
    return Decimal(str(cargo_fijo)) + Decimal(str(consumo_adicional)) - Decimal(str(descuento))
```

## Pista 2

Para el IVA, multiplica por la constante `IVA` y redondea con `quantize`:

```python
(Decimal(str(subtotal)) * IVA).quantize(Decimal("1"), rounding=ROUND_HALF_UP)
```

Ojo con `Decimal(str(19900.0))`: da `Decimal('19900.0')`, con un decimal. Al sumarle el IVA (sin decimales) el total queda `24990.0`, que **es igual** a `Decimal('24990')` al comparar con `==`.

## Solución

```python
from decimal import Decimal, ROUND_HALF_UP

IVA = Decimal("0.19")
PESO = Decimal("1")


def a_decimal(valor):
    return Decimal(str(valor))


def calcular_subtotal(cargo_fijo, consumo_adicional, descuento):
    return a_decimal(cargo_fijo) + a_decimal(consumo_adicional) - a_decimal(descuento)


def calcular_iva(subtotal):
    return (a_decimal(subtotal) * IVA).quantize(PESO, rounding=ROUND_HALF_UP)


def calcular_total(cargo_fijo, consumo_adicional, descuento):
    subtotal = calcular_subtotal(cargo_fijo, consumo_adicional, descuento)
    return subtotal + calcular_iva(subtotal)


print(calcular_total(35900, 5040, 0))
```

## Explicación

La solución agrega una función auxiliar, `a_decimal`, para no repetir `Decimal(str(...))` cuatro veces. Es pequeña, pero hace que el resto se lea como la regla de negocio.

Fíjate en la última prueba: 1.000 facturas de $150. Con `round()` el IVA total sería $28.000; con la regla correcta, $29.000. **Mil pesos de diferencia** por un detalle de redondeo. Este es exactamente el tipo de error que hace que la facturación y la contabilidad no cuadren.

El orden importa: se redondea **el IVA de cada factura** y después se suma. Si sumas los IVA sin redondear y redondeas al final, obtienes otro número. La regla de negocio dice cuál es el correcto, y el código debe seguirla al pie de la letra.
