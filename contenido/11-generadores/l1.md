Recorres listas, textos, diccionarios y archivos con el mismo `for`. ¿Cómo sabe Python recorrer cosas tan distintas? Todas cumplen el **protocolo de iteración**.

## Iterable e iterador

- Un **iterable** es algo que se puede recorrer: una lista, un archivo, un `range`.
- Un **iterador** es el objeto que **va entregando** los elementos, uno a la vez, y recuerda por dónde va.

```pyrun
duraciones = [125, 0, 61]

iterador = iter(duraciones)     # pide un iterador al iterable
print(next(iterador))           # 125
print(next(iterador))           # 0
print(next(iterador))           # 61
print(next(iterador))           # error esperado
```

Cuando no quedan elementos, `next` lanza `StopIteration`. Eso es exactamente lo que hace el `for` por dentro:

```python
# Esto…
for d in duraciones:
    print(d)

# …es lo mismo que esto:
iterador = iter(duraciones)
while True:
    try:
        d = next(iterador)
    except StopIteration:
        break
    print(d)
```

## Los iteradores se gastan

Un iterador avanza en una sola dirección y no se reinicia:

```pyrun
iterador = iter([125, 0, 61])
print(list(iterador))   # [125, 0, 61]
print(list(iterador))   # [] — ya se consumió
```

:::error El archivo que "solo funciona una vez"
Un archivo abierto es su propio iterador. Si lo recorres dos veces seguidas, la segunda no entrega nada:

```python
with open("cdr.csv") as f:
    total = sum(1 for _ in f)      # recorre todo
    tipos = [l.split("|")[3] for l in f]   # lista vacía: el archivo ya llegó al final
```

Haz todo en una pasada o vuelve a abrir el archivo (o usa `f.seek(0)`).
:::

## Evaluación perezosa

Muchas herramientas de Python son **perezosas**: no calculan nada hasta que alguien pide el siguiente elemento.

```pyrun
import sys

lista = [d * 2 for d in range(1_000_000)]      # calcula y guarda un millón de valores
perezoso = map(lambda d: d * 2, range(1_000_000))   # no calcula nada todavía

print(sys.getsizeof(lista), "bytes")
print(sys.getsizeof(perezoso), "bytes")
print(next(perezoso), next(perezoso))           # calcula solo cuando se pide
```

| Perezosos (entregan uno a uno) | Ansiosos (construyen todo) |
|---|---|
| `range`, `map`, `filter`, `zip`, `enumerate` | `list(...)`, `sorted(...)` |
| Archivos abiertos | `archivo.readlines()` |
| Generadores (lección 2) | Comprensiones de lista `[...]` |
| `itertools` (lección 3) | `set(...)`, `dict(...)` |

## Un iterable propio

Una clase es iterable si su `__iter__` devuelve un iterador. Lo más simple es que `__iter__` sea un generador (lo verás en la próxima lección), pero también puedes escribir el iterador "a mano" con `__next__`:

```pyrun
from datetime import date, timedelta


class DiasDelPeriodo:
    def __init__(self, inicio, fin):
        self.actual = inicio
        self.fin = fin

    def __iter__(self):
        return self

    def __next__(self):
        if self.actual > self.fin:
            raise StopIteration
        dia = self.actual
        self.actual += timedelta(days=1)
        return dia


for dia in DiasDelPeriodo(date(2026, 9, 28), date(2026, 10, 2)):
    print(dia)
```

:::telco ¿Por qué importa?
Todo el procesamiento de archivos grandes se basa en esta idea: **pedir un registro, procesarlo, olvidarlo y pedir el siguiente**. Un `for` sobre un archivo de 20 GB nunca tiene más de una línea en memoria, porque el archivo es un iterador perezoso.
:::
