Python no revisa los tipos al ejecutar: `minutos_facturables("120")` explota recién cuando llega a esa línea, quizás a las 3 de la mañana con el archivo de 20 GB. **mypy** lee tu código sin ejecutarlo y encuentra esos errores en segundos.

## Anotaciones, repaso rápido

```python
def minutos_facturables(segundos: int) -> int: ...
def buscar(linea: str, clientes: dict[str, Cliente]) -> Cliente | None: ...
def leer(ruta: Path, columnas: list[str] | None = None) -> pd.DataFrame: ...
```

| Anotación | Significa |
|---|---|
| `list[int]`, `dict[str, float]`, `set[str]`, `tuple[str, int]` | Colecciones con el tipo de sus elementos |
| `tuple[int, ...]` | Tupla de enteros de cualquier largo |
| `X \| None` (u `Optional[X]`) | Puede ser `None`: mypy te obliga a revisarlo antes de usarlo |
| `Iterable[str]`, `Iterator[dict]` | Cualquier cosa que se recorra (lista, generador…) |
| `Callable[[float], None]` | Una función que recibe un `float` y no devuelve nada |
| `Literal["VOZ", "SMS", "DATOS"]` | Solo esos valores exactos |
| `Any` | "No lo sé": mypy no revisa nada. Úsalo lo menos posible |

## TypedDict: diccionarios con forma

Cuando una función devuelve un diccionario con claves fijas (como el resumen del validador), `TypedDict` documenta qué claves tiene y de qué tipo:

```pyrun
from typing import Literal, TypedDict, get_type_hints

Tipo = Literal["VOZ", "SMS", "DATOS"]


class Errores(TypedDict):
    duplicado: int
    fecha_invalida: int


class Resumen(TypedDict):
    registros_totales: int
    registros_validos: int
    errores: Errores


def resumen_vacio() -> Resumen:
    return {"registros_totales": 0, "registros_validos": 0,
            "errores": {"duplicado": 0, "fecha_invalida": 0}}


r = resumen_vacio()
print(r, type(r))                    # en ejecución es un dict normal
print(get_type_hints(Resumen))       # pero sus tipos quedan registrados
```

Con `TypedDict`, `r["registros_valido"]` (sin la s) es un error de mypy, no un `KeyError` en producción.

:::reto Dale forma al resumen de una línea
1. Define `TipoCDR` como `Literal["VOZ", "SMS", "DATOS"]`.
2. Define el `TypedDict` `ResumenLinea` con `linea: str`, `minutos: int` y `por_tipo: dict[TipoCDR, int]`.
3. Escribe `resumir(linea: str, cdrs: list[tuple[TipoCDR, int]]) -> ResumenLinea`: recibe pares `(tipo, segundos)` y devuelve el resumen con los minutos facturables de VOZ y la cantidad de registros por tipo.

```pyreto
from typing import Literal, TypedDict

# TipoCDR, ResumenLinea y resumir


print(resumir("3001", [("VOZ", 125), ("SMS", 0), ("VOZ", 61), ("DATOS", 900)]))
# {'linea': '3001', 'minutos': 5, 'por_tipo': {'VOZ': 2, 'SMS': 1, 'DATOS': 1}}
```

:::pista
`class ResumenLinea(TypedDict):` con las tres anotaciones. En `resumir`, recorre los pares acumulando los minutos (`(s + 59) // 60` solo si es VOZ) y el conteo en un diccionario; devuelve `{"linea": ..., "minutos": ..., "por_tipo": ...}`.
:::

```pyprueba
from typing import Literal, get_args, get_type_hints


def prueba_tipos():
    """TipoCDR y ResumenLinea tienen la forma pedida"""
    requiere("TipoCDR", "ResumenLinea")
    igual(set(get_args(TipoCDR)), {"VOZ", "SMS", "DATOS"}, "valores de TipoCDR")
    hints = get_type_hints(ResumenLinea)
    igual(set(hints), {"linea", "minutos", "por_tipo"}, "claves de ResumenLinea")
    igual(hints["minutos"], int, "tipo de minutos")


def prueba_resumir():
    """resumir devuelve el resumen y está anotada"""
    requiere("resumir")
    igual(resumir("3001", [("VOZ", 125), ("SMS", 0), ("VOZ", 61), ("DATOS", 900)]),
          {"linea": "3001", "minutos": 5, "por_tipo": {"VOZ": 2, "SMS": 1, "DATOS": 1}})
    igual(resumir("3002", []), {"linea": "3002", "minutos": 0, "por_tipo": {}}, "sin CDR")
    igual(get_type_hints(resumir)["return"], ResumenLinea, "anotación de retorno")
```

```pysolucion
from typing import Literal, TypedDict

TipoCDR = Literal["VOZ", "SMS", "DATOS"]


class ResumenLinea(TypedDict):
    linea: str
    minutos: int
    por_tipo: dict[TipoCDR, int]


def resumir(linea: str, cdrs: list[tuple[TipoCDR, int]]) -> ResumenLinea:
    minutos = 0
    por_tipo: dict[TipoCDR, int] = {}
    for tipo, segundos in cdrs:
        if tipo == "VOZ":
            minutos += (segundos + 59) // 60
        por_tipo[tipo] = por_tipo.get(tipo, 0) + 1
    return {"linea": linea, "minutos": minutos, "por_tipo": por_tipo}


print(resumir("3001", [("VOZ", 125), ("SMS", 0), ("VOZ", 61), ("DATOS", 900)]))
# {'linea': '3001', 'minutos': 5, 'por_tipo': {'VOZ': 2, 'SMS': 1, 'DATOS': 1}}
```

## mypy en acción

```python
# reglas.py
def valor_voz(minutos: int, incluidos: int, tarifa: int) -> int:
    if incluidos == -1:
        return 0
    return max(0, minutos - incluidos) * tarifa

def buscar_plan(planes: dict[str, Plan], plan_id: str) -> Plan | None:
    return planes.get(plan_id)

total = valor_voz("342", 300, 120)                 # ❌ error
plan = buscar_plan(planes, "HOG30")
print(plan.cargo_fijo)                              # ❌ error: plan puede ser None
```

```text
$ mypy reglas.py
reglas.py:9: error: Argument 1 to "valor_voz" has incompatible type "str"; expected "int"  [arg-type]
reglas.py:11: error: Item "None" of "Plan | None" has no attribute "cargo_fijo"  [union-attr]
Found 2 errors in 1 file (checked 1 source file)
```

La corrección del segundo error es exactamente lo que olvidarías un viernes:

```python
plan = buscar_plan(planes, "HOG30")
if plan is None:
    raise PlanNoEncontrado("HOG30")
print(plan.cargo_fijo)                              # ✅ mypy sabe que aquí no es None
```

:::reto Lo que mypy te pediría
`cargo_con_iva` usa el resultado de `buscar_plan` sin revisar si es `None`: mypy marcaría `union-attr`, y en ejecución un plan inexistente da un `AttributeError` confuso. Corrígela:

- si el plan no existe, lanza `PlanNoEncontrado` con el `plan_id`;
- anótala completa: `planes: dict[str, Plan]`, `plan_id: str` y devuelve `int`.

```pyreto
from dataclasses import dataclass


@dataclass(frozen=True)
class Plan:
    plan_id: str
    cargo_fijo: int


class PlanNoEncontrado(LookupError):
    pass


def buscar_plan(planes: dict[str, Plan], plan_id: str) -> Plan | None:
    return planes.get(plan_id)


def cargo_con_iva(planes, plan_id):
    plan = buscar_plan(planes, plan_id)
    return int(plan.cargo_fijo * 1.19 + 0.5)


PLANES = {"HOG30": Plan("HOG30", 35900)}
print(cargo_con_iva(PLANES, "HOG30"))   # 42721
```

:::pista
Después de buscar: `if plan is None: raise PlanNoEncontrado(plan_id)`. La firma: `def cargo_con_iva(planes: dict[str, Plan], plan_id: str) -> int:`.
:::

```pyprueba
from typing import get_type_hints


def prueba_valor():
    """Calcula el cargo con IVA"""
    requiere("cargo_con_iva")
    igual(cargo_con_iva({"HOG30": Plan("HOG30", 35900)}, "HOG30"), 42721)


def prueba_none():
    """Un plan inexistente lanza PlanNoEncontrado"""
    error = lanza(PlanNoEncontrado, cargo_con_iva, {}, "PLAN99")
    assert "PLAN99" in str(error), f"El error debe nombrar el plan: {error}"


def prueba_anotaciones():
    """Está anotada"""
    igual(get_type_hints(cargo_con_iva), {"planes": dict[str, Plan], "plan_id": str, "return": int})
```

```pysolucion
from dataclasses import dataclass


@dataclass(frozen=True)
class Plan:
    plan_id: str
    cargo_fijo: int


class PlanNoEncontrado(LookupError):
    pass


def buscar_plan(planes: dict[str, Plan], plan_id: str) -> Plan | None:
    return planes.get(plan_id)


def cargo_con_iva(planes: dict[str, Plan], plan_id: str) -> int:
    plan = buscar_plan(planes, plan_id)
    if plan is None:
        raise PlanNoEncontrado(plan_id)
    return int(plan.cargo_fijo * 1.19 + 0.5)


PLANES = {"HOG30": Plan("HOG30", 35900)}
print(cargo_con_iva(PLANES, "HOG30"))   # 42721
```

## Configuración en pyproject.toml

```toml
[tool.mypy]
python_version = "3.12"
strict = true                     # todas las verificaciones; recomendable en código nuevo
warn_unused_ignores = true

[[tool.mypy.overrides]]
module = ["duckdb.*", "polars.*"]
ignore_missing_imports = true     # librerías sin información de tipos
```

```powershell
pip install mypy pandas-stubs
mypy src/
```

:::consejo Adopción gradual
En un proyecto existente, `strict = true` puede dar cientos de errores. Empieza sin `strict`, anota primero el **dominio** (lo más valioso y lo más fácil: funciones puras) y ve subiendo. Para silenciar un error que entiendes y aceptas: `# type: ignore[arg-type]`, siempre con el código del error, nunca un `ignore` genérico.
:::

:::capo Los tipos no son pruebas
mypy verifica que pasas un `int` donde va un `int`, no que el cálculo del IVA sea correcto. Tipos y pruebas se complementan: los tipos eliminan una clase entera de errores (nombres, `None`, argumentos cambiados) para que las pruebas se concentren en la lógica.
:::
