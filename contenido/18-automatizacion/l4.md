El último paso de la automatización: que el programa se ejecute **solo**, todos los días a las 6:00, aunque no estés.

## El Programador de tareas de Windows

Puedes crear tareas **para tu propio usuario sin permisos de administrador**, desde la interfaz (busca "Programador de tareas" en el menú Inicio → *Crear tarea básica*) o desde PowerShell con `schtasks`:

```powershell
schtasks /Create /TN "Telco\ResumenDiario" /SC DAILY /ST 06:00 `
  /TR "\"D:\curso\.venv\Scripts\python.exe\" \"D:\curso\scripts\resumen_diario.py\""

schtasks /Query /TN "Telco\ResumenDiario" /V /FO LIST     # ver estado y último resultado
schtasks /Run /TN "Telco\ResumenDiario"                   # ejecutarla ya, para probar
schtasks /Delete /TN "Telco\ResumenDiario" /F             # eliminarla
```

| Opción | Significa |
|---|---|
| `/TN` | Nombre de la tarea (puedes usar carpetas: `Telco\...`) |
| `/SC DAILY` · `WEEKLY /D LUN,MAR` · `HOURLY` | Frecuencia |
| `/ST 06:00` | Hora de inicio |
| `/TR` | Qué ejecutar: **ruta completa** del `python.exe` del entorno virtual y del script |

:::error Las tres causas de "a mano funciona y programado no"
1. **Rutas relativas**: el directorio actual de la tarea no es el del script. Usa `Path(__file__).resolve().parent`.
2. **El Python equivocado**: `python` a secas puede ser otro intérprete sin tus librerías. Usa la ruta del `.venv\Scripts\python.exe`.
3. **Variables de entorno**: la tarea no ve las variables de tu terminal; las de `setx` sí (son de tu usuario).
:::

En Linux y macOS (o en Docker, módulo 22) el equivalente es **cron**: `0 6 * * 1-5 /ruta/.venv/bin/python /ruta/resumen_diario.py` = a las 6:00, de lunes a viernes.

## No ejecutar dos veces a la vez

Si el proceso de las 6:00 tarda más de lo normal y otro lo lanza de nuevo, dos copias procesando la misma bandeja pueden duplicar o corromper resultados. Un **archivo de bloqueo** lo evita:

```pyrun
import os
from pathlib import Path


class Bloqueo:
    """Crea el archivo en modo exclusivo: si ya existe, otro proceso está trabajando."""

    def __init__(self, ruta):
        self.ruta = Path(ruta)

    def __enter__(self):
        try:
            self.descriptor = os.open(self.ruta, os.O_CREAT | os.O_EXCL | os.O_WRONLY)
        except FileExistsError:
            raise RuntimeError(f"Ya hay un proceso en curso ({self.ruta})") from None
        os.write(self.descriptor, str(os.getpid()).encode())
        return self

    def __exit__(self, *error):
        os.close(self.descriptor)
        self.ruta.unlink()


with Bloqueo("proceso.lock"):
    print("Trabajando...")
    try:
        with Bloqueo("proceso.lock"):
            print("Esto no debería verse")
    except RuntimeError as e:
        print("Segundo intento:", e)
print("¿Quedó el archivo?", Path("proceso.lock").exists())
```

`O_EXCL` hace que crear el archivo y comprobar que no existía sea **una sola operación atómica**: no hay un instante en que dos procesos puedan pasar a la vez.

:::consejo Bloqueos huérfanos
Si el proceso muere de golpe (corte de luz), el archivo queda y bloquea las ejecuciones siguientes. Las soluciones habituales: guardar dentro el PID y la hora, y considerar vencido un bloqueo de más de N horas.
:::

## Registros que sirven al día siguiente

Nadie ve la pantalla de una tarea programada: el **registro** (módulo 7) es tu único testigo. Para procesos diarios:

```python
import logging
from logging.handlers import TimedRotatingFileHandler

manejador = TimedRotatingFileHandler("logs/resumen.log", when="midnight", backupCount=30, encoding="utf-8")
manejador.setFormatter(logging.Formatter("%(asctime)s %(levelname)s %(message)s"))
logging.basicConfig(level=logging.INFO, handlers=[manejador])
```

Un archivo por día, 30 días de historia. Registra el **inicio**, cada archivo procesado con sus conteos, los errores con `logging.exception` (incluye el *traceback*) y el **fin** con el tiempo total. Y termina con el código de salida correcto: el Programador de tareas lo muestra como "Resultado de la última ejecución".

## Calendarios de negocio

"Todos los días hábiles a las 6:00" no es lo mismo que "todos los días": fines de semana y festivos cambian el cálculo. Las fechas de corte y de emisión de facturas suelen depender de esto, y es una lógica que conviene tener en **una función probada** (lo harás en el ejercicio 6).

:::telco Una cadena diaria
Una automatización típica de facturación: 5:30 llega el CDR del día anterior → 6:00 tarea: validar, cargar y resumir → 6:20 si hubo más de X % de rechazos, el código de salida es distinto de 0 y otra tarea envía la alerta → 7:00 el reporte está en la carpeta compartida antes de que llegue el equipo.
:::

## Cuestionario

? ¿Qué ruta de Python debe usar la tarea programada?
- [ ] `python`, el que esté en el PATH
- [x] La ruta completa del `python.exe` del entorno virtual del proyecto
- [ ] La de Python 2
- [ ] Ninguna: el Programador ejecuta `.py` directamente
> Así la tarea usa exactamente el intérprete con las librerías del proyecto.

? ¿Por qué el archivo de bloqueo se crea con `O_CREAT | O_EXCL`?
- [ ] Para que sea oculto
- [x] Para que comprobar que no existe y crearlo sea una sola operación atómica
- [ ] Para escribir más rápido
- [ ] Para que se borre solo
> Si se comprobara y luego se creara en dos pasos, dos procesos podrían pasar a la vez entre ambos.

? Un proceso programado falla de madrugada. ¿Dónde lo investigas?
- [ ] En la pantalla
- [x] En el archivo de registro y en el resultado de la última ejecución de la tarea
- [ ] En el código, adivinando
- [ ] No se puede saber
> El registro y el código de salida son los testigos de lo que pasó sin nadie mirando.
