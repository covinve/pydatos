## Enunciado

Llegó el momento: vas a procesar el archivo de **20 GB** en tu computador de 16 GB, con validación **exacta** de duplicados, en minutos.

Completa `procesar(carpeta, salida, memoria)` en `ejercicios/m16-e7/validar_duckdb.py`:

1. Conéctate a DuckDB y limita la memoria: `con.sql(f"SET memory_limit = '{memoria}'")`. DuckDB usará el disco para lo que no quepa.
2. Clasifica los CDR con las seis reglas en SQL (como en el ejercicio 4) y guarda el resultado en una tabla temporal.
3. Escribe `validos.parquet` y `rechazos.csv` con `COPY ... TO`.
4. Calcula y devuelve el resumen (las claves de `esperado.json`).

Primero con la muestra (`python comprobar.py m16-e7`); después en grande:

```powershell
python herramientas/generar_datos.py --tamano 20GB
python ejercicios/m16-e7/validar_duckdb.py datos/20GB salidas/20GB
```

Mide el tiempo, mira la memoria en el Administrador de tareas y compara el resultado con `datos/20GB/esperado.json`. Anota todo en un comentario al final del archivo.

:::consejo Disco y tiempo
Necesitarás unos 20 GB para el CSV más unos 5 GB para el Parquet y el espacio temporal de DuckDB. Con un disco SSD, espera del orden de 5 a 15 minutos; con disco mecánico, bastante más.
:::

## Pista 1

Guardar la clasificación en una tabla evita releer el CSV tres veces:

```python
con = duckdb.connect()
con.sql(f"SET memory_limit = '{memoria}'")
con.sql(f"""
    CREATE TEMP TABLE clasificados AS
    WITH cdr AS (SELECT *, ROW_NUMBER() OVER () AS rn FROM read_csv('{carpeta / "cdr.csv"}', delim='|', header=true, all_varchar=true)),
    ...
    SELECT *, CASE ... END AS motivo FROM marcado
""")
```

Las rutas de Windows llevan `\`: conviértelas con `.as_posix()` antes de ponerlas dentro del SQL.

## Pista 2

El resumen sale de una sola consulta con agregaciones condicionales:

```sql
SELECT COUNT(*) AS total,
       SUM(CASE WHEN motivo = 'valido' AND tipo = 'VOZ' AND destino <> 'INTERNACIONAL'
                THEN (CAST(duracion_seg AS INTEGER) + 59) // 60 ELSE 0 END) AS min_nac,
       ...
FROM clasificados
```

DuckDB también tiene `COUNT(*) FILTER (WHERE ...)` y `SUM(x) FILTER (WHERE ...)`, más legibles.

## Solución

```python validar_duckdb.py
"""Ejercicio m16-e7: validar cualquier tamaño de CDR con DuckDB y guardar los válidos en Parquet.

Uso:
    python ejercicios/m16-e7/validar_duckdb.py datos/20GB salidas/20GB
"""

from __future__ import annotations

import sys
from pathlib import Path

import duckdb

ORDEN = ["duplicado", "duracion_negativa", "fecha_invalida", "linea_vacia", "linea_desconocida", "tipo_desconocido"]


def procesar(carpeta: Path, salida: Path, memoria: str = "4GB") -> dict:
    salida.mkdir(parents=True, exist_ok=True)
    cdr = (carpeta / "cdr.csv").as_posix()
    clientes = (carpeta / "clientes.csv").as_posix()
    con = duckdb.connect()
    con.sql(f"SET memory_limit = '{memoria}'")
    con.sql(f"SET temp_directory = '{(salida / '.temporal').as_posix()}'")
    con.sql(f"""
        CREATE TEMP TABLE clasificados AS
        WITH cdr AS (
            SELECT *, ROW_NUMBER() OVER () AS rn
            FROM read_csv('{cdr}', delim='|', header=true, all_varchar=true)
        ),
        clientes AS (
            SELECT linea FROM read_csv('{clientes}', encoding='latin-1', header=true, all_varchar=true)
        ),
        marcado AS (
            SELECT *, ROW_NUMBER() OVER (PARTITION BY cdr_id ORDER BY rn) AS aparicion FROM cdr
        )
        SELECT * EXCLUDE (rn, aparicion),
               CASE
                   WHEN aparicion > 1 THEN 'duplicado'
                   WHEN coalesce(linea_origen, '') = '' THEN 'linea_vacia'
                   WHEN linea_origen NOT IN (SELECT linea FROM clientes) THEN 'linea_desconocida'
                   WHEN tipo NOT IN ('VOZ', 'SMS', 'DATOS') THEN 'tipo_desconocido'
                   WHEN CAST(duracion_seg AS INTEGER) < 0 THEN 'duracion_negativa'
                   WHEN TRY_STRPTIME(fecha_inicio, '%Y-%m-%d %H:%M:%S') IS NULL THEN 'fecha_invalida'
                   ELSE 'valido'
               END AS motivo
        FROM marcado
    """)
    con.sql(f"""
        COPY (SELECT * EXCLUDE (motivo) FROM clasificados WHERE motivo = 'valido')
        TO '{(salida / "validos.parquet").as_posix()}' (FORMAT parquet, COMPRESSION zstd)
    """)
    con.sql(f"""
        COPY (SELECT cdr_id, motivo FROM clasificados WHERE motivo <> 'valido')
        TO '{(salida / "rechazos.csv").as_posix()}' (HEADER)
    """)
    total, validos, min_nac, min_int, mb, sms = con.sql("""
        SELECT COUNT(*),
               COUNT(*) FILTER (WHERE motivo = 'valido'),
               SUM((CAST(duracion_seg AS INTEGER) + 59) // 60) FILTER (WHERE motivo = 'valido' AND tipo = 'VOZ' AND destino <> 'INTERNACIONAL'),
               SUM((CAST(duracion_seg AS INTEGER) + 59) // 60) FILTER (WHERE motivo = 'valido' AND tipo = 'VOZ' AND destino = 'INTERNACIONAL'),
               SUM(CAST(mb AS DOUBLE)) FILTER (WHERE motivo = 'valido' AND tipo = 'DATOS'),
               COUNT(*) FILTER (WHERE motivo = 'valido' AND tipo = 'SMS')
        FROM clasificados
    """).fetchone()
    errores = dict(con.sql("SELECT motivo, COUNT(*) FROM clasificados WHERE motivo <> 'valido' GROUP BY motivo").fetchall())
    return {
        "registros_totales": int(total),
        "registros_validos": int(validos),
        "errores": {e: int(errores.get(e, 0)) for e in ORDEN},
        "minutos_nacionales": int(min_nac or 0),
        "minutos_internacionales": int(min_int or 0),
        "mb_totales": round(float(mb or 0), 3),
        "sms_totales": int(sms),
    }


if __name__ == "__main__":
    print(procesar(Path(sys.argv[1]), Path(sys.argv[2])))
```

## Explicación

Este es el cierre de un recorrido que empezó en el módulo 6:

| Módulo | Técnica | ¿20 GB en 16 GB de RAM? | Duplicados exactos |
|---|---|---|---|
| 6, 11 | Python puro línea por línea | Sí, en más de una hora | No (o 15 GB de memoria) |
| 11 | Ventana deslizante | Sí | Solo si llegan cerca |
| 13 | Pandas completo | No | Sí |
| 14 | Pandas por bloques | Sí | Solo con ventana |
| **16** | **DuckDB** | **Sí, en minutos** | **Sí** |

`SET memory_limit` es la clave: le dice a DuckDB cuánta RAM puede usar; lo que no cabe (la ordenación para encontrar duplicados, por ejemplo) se procesa en disco en la carpeta temporal.

Guardar los válidos en **Parquet** cambia todo lo que sigue: de aquí en adelante, cualquier análisis lee unos pocos GB comprimidos y por columnas, en segundos, en lugar de los 20 GB de texto.
