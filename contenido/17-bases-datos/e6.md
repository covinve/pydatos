## Enunciado

Cada mes llega el archivo completo de clientes. La tabla `clientes` debe quedar **sincronizada** con él, sin borrar a nadie (la facturación histórica los necesita):

| Situación | Acción |
|---|---|
| Línea nueva | Insertarla |
| Línea existente con otro `plan_id` o `estado` | Actualizarla |
| Línea existente igual | No tocarla |
| Línea en la tabla que **no** viene en el archivo | Marcarla con `estado = 'RETIRADO'` |

1. `crear_tabla(con)` crea `clientes (linea TEXT PRIMARY KEY, cliente_id TEXT, plan_id TEXT, estado TEXT, actualizado TEXT)`.
2. `sincronizar(con, ruta_csv, fecha)` aplica el archivo (latin-1) en **una transacción**, usando un **upsert** (`INSERT ... ON CONFLICT (linea) DO UPDATE`), pone `actualizado = fecha` solo en las filas que cambian, y devuelve `{"nuevos": n, "actualizados": n, "sin_cambios": n, "retirados": n}` (`retirados` cuenta solo las que se retiran **en esta** sincronización).

La preparación crea `clientes_oct.csv`: 2 clientes menos, 2 nuevos y 3 con cambio de plan.

## Pista 1

Antes del upsert, lee el estado actual en un diccionario para clasificar cada fila del archivo:

```python
actuales = {linea: (plan, estado) for linea, plan, estado in con.execute("SELECT linea, plan_id, estado FROM clientes")}
```

Una fila es nueva si su línea no está en `actuales`; actualizada si `(plan_id, estado)` cambió; si no, sin cambios. Solo las nuevas y actualizadas necesitan el upsert.

## Pista 2

```sql
INSERT INTO clientes (linea, cliente_id, plan_id, estado, actualizado) VALUES (?, ?, ?, ?, ?)
ON CONFLICT (linea) DO UPDATE SET
    plan_id = excluded.plan_id, estado = excluded.estado, actualizado = excluded.actualizado
```

Los retirados: las líneas de `actuales` que no vienen en el archivo y cuyo estado aún no es `RETIRADO`.

## Solución

```python
import csv
import sqlite3

UPSERT = """
    INSERT INTO clientes (linea, cliente_id, plan_id, estado, actualizado) VALUES (?, ?, ?, ?, ?)
    ON CONFLICT (linea) DO UPDATE SET
        plan_id = excluded.plan_id,
        estado = excluded.estado,
        actualizado = excluded.actualizado
"""


def crear_tabla(con):
    con.execute("""
        CREATE TABLE clientes (
            linea       TEXT PRIMARY KEY,
            cliente_id  TEXT,
            plan_id     TEXT,
            estado      TEXT,
            actualizado TEXT
        )
    """)


def sincronizar(con, ruta_csv, fecha):
    with open(ruta_csv, encoding="latin-1", newline="") as f:
        archivo = {c["linea"]: c for c in csv.DictReader(f)}
    resultado = {"nuevos": 0, "actualizados": 0, "sin_cambios": 0, "retirados": 0}
    with con:
        actuales = {l: (p, e) for l, p, e in con.execute("SELECT linea, plan_id, estado FROM clientes")}
        cambios = []
        for linea, c in archivo.items():
            if linea not in actuales:
                resultado["nuevos"] += 1
            elif actuales[linea] != (c["plan_id"], c["estado"]):
                resultado["actualizados"] += 1
            else:
                resultado["sin_cambios"] += 1
                continue
            cambios.append((linea, c["cliente_id"], c["plan_id"], c["estado"], fecha))
        con.executemany(UPSERT, cambios)
        retirar = [(fecha, l) for l, (_, estado) in actuales.items() if l not in archivo and estado != "RETIRADO"]
        con.executemany("UPDATE clientes SET estado = 'RETIRADO', actualizado = ? WHERE linea = ?", retirar)
        resultado["retirados"] = len(retirar)
    return resultado


con = sqlite3.connect(":memory:")
crear_tabla(con)
print(sincronizar(con, "clientes.csv", "2026-09-01"))
print(sincronizar(con, "clientes_oct.csv", "2026-10-01"))
```

## Explicación

Esto es una **carga incremental** con historia mínima: nunca se borra, los retiros se marcan y `actualizado` dice cuándo cambió cada fila por última vez. Es idempotente: cargar el mismo archivo dos veces no cambia nada (ni siquiera la fecha).

Con millones de clientes, leer `actuales` en un diccionario puede ser pesado. La versión 100 % SQL carga el archivo en una tabla de paso y resuelve todo con consultas (`INSERT ... SELECT ... ON CONFLICT` y un `UPDATE ... WHERE linea NOT IN (SELECT linea FROM paso)`).

Si necesitas saber **qué plan tenía** un cliente en marzo, esto no alcanza: se necesita una tabla de historial con fechas de vigencia (lo que en bodegas de datos se llama *dimensión lenta tipo 2*). Lo harás con el ORM en el ejercicio 8.
