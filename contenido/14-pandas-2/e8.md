## Enunciado

Vas a convertir el CDR en un **dataset Parquet particionado**: una carpeta por día, para que leer un día no obligue a tocar los demás.

```text
cdr_parquet/
├── dia=2026-09-01/
│   ├── parte-0.parquet
│   └── parte-1.parquet
├── dia=2026-09-02/
│   └── ...
└── dia=invalida/
    └── ...
```

Completa `ejercicios/m14-e8/a_parquet.py`:

1. `convertir(ruta_csv, carpeta, tamano_bloque)` → lee el CSV **por bloques**, agrega las columnas `inicio` (fecha y hora, `NaT` si es inválida) y `dia` (`"AAAA-MM-DD"` o `"invalida"`), y escribe cada bloque en el dataset con `pyarrow.parquet.write_to_dataset(..., partition_cols=["dia"])`. Devuelve los registros escritos.
2. `leer_dia(carpeta, dia, columnas=None)` → con `pd.read_parquet(carpeta, filters=[("dia", "==", dia)], columns=...)`.

Después, conviértelo en grande y compara:

```powershell
python ejercicios/m14-e8/a_parquet.py datos/1GB/cdr.csv datos/1GB/cdr_parquet
```

¿Cuánto ocupa la carpeta frente al CSV? ¿Cuánto tarda leer un día del CSV (filtrando con Pandas) y uno del Parquet?

:::nota Archivos pequeños engañan
Con la muestra de prueba, la carpeta Parquet puede pesar **más** que el CSV: cada archivo guarda metadatos y esquema, y con pocos registros ese costo fijo domina. Con 1 GB verás la diferencia real (suele quedar en una fracción del tamaño).
:::

## Pista 1

Cada bloque debe escribir archivos con nombres distintos para no pisar los del bloque anterior. `basename_template` lo resuelve:

```python
import pyarrow as pa
import pyarrow.parquet as pq

tabla = pa.Table.from_pandas(bloque, preserve_index=False)
pq.write_to_dataset(tabla, carpeta, partition_cols=["dia"], basename_template=f"parte-{numero}-{{i}}.parquet",
                    existing_data_behavior="overwrite_or_ignore")
```

## Pista 2

Para la columna `dia`:

```python
bloque["inicio"] = pd.to_datetime(bloque["fecha_inicio"], format="%Y-%m-%d %H:%M:%S", errors="coerce")
```

Si la carpeta ya existe de una ejecución anterior, bórrala primero (`shutil.rmtree`) para no mezclar datos viejos.

## Solución

```python a_parquet.py
"""Ejercicio m14-e8: convertir un CSV de CDR en un dataset Parquet particionado por día.

Uso:
    python ejercicios/m14-e8/a_parquet.py datos/1GB/cdr.csv datos/1GB/cdr_parquet
"""

from __future__ import annotations

import shutil
import sys
from pathlib import Path

import pandas as pd
import pyarrow as pa
import pyarrow.parquet as pq

TIPOS = {"linea_origen": "string", "linea_destino": "string", "tipo": "string", "destino": "string", "celda": "string"}


def convertir(ruta_csv: Path, carpeta: Path, tamano_bloque: int = 1_000_000) -> int:
    if carpeta.exists():
        shutil.rmtree(carpeta)
    escritos = 0
    lector = pd.read_csv(ruta_csv, sep="|", keep_default_na=False, dtype=TIPOS, chunksize=tamano_bloque)
    for numero, bloque in enumerate(lector):
        bloque["inicio"] = pd.to_datetime(bloque["fecha_inicio"], format="%Y-%m-%d %H:%M:%S", errors="coerce")
        bloque["dia"] = bloque["inicio"].dt.strftime("%Y-%m-%d").fillna("invalida")
        tabla = pa.Table.from_pandas(bloque, preserve_index=False)
        pq.write_to_dataset(
            tabla, carpeta, partition_cols=["dia"], compression="zstd",
            basename_template=f"parte-{numero}-{{i}}.parquet", existing_data_behavior="overwrite_or_ignore",
        )
        escritos += len(bloque)
    return escritos


def leer_dia(carpeta: Path, dia: str, columnas: list[str] | None = None) -> pd.DataFrame:
    return pd.read_parquet(carpeta, filters=[("dia", "==", dia)], columns=columnas)


if __name__ == "__main__":
    print(convertir(Path(sys.argv[1]), Path(sys.argv[2])), "registros convertidos")
```

## Explicación

El particionado convierte el nombre de la carpeta en un **filtro gratuito**: `filters=[("dia", "==", "2026-09-15")]` hace que Parquet ni siquiera abra los archivos de los otros 29 días. Combinado con la lectura por columnas, leer "las megas del 15 de septiembre" de un dataset de 20 GB toma una fracción de segundo.

Algunas recomendaciones de la vida real:

- **No particiones de más.** Particionar por línea (cientos de miles de carpetas) generaría millones de archivos diminutos y sería lentísimo. La regla práctica: particiones de cientos de MB, por columnas con pocos valores que uses mucho para filtrar (periodo, día, región).
- **Compresión `zstd`**: muy buena relación entre tamaño y velocidad.
- **Cada bloque escribe archivos nuevos**: con 20 GB y bloques de un millón de filas tendrás varios archivos por día. Se puede compactar después, pero para leer no es problema.
