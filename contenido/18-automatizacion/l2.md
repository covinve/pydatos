Una **API** es una puerta para que los programas hablen entre sí. Muchos sistemas de una telco ofrecen APIs: el de clientes (CRM), el de tasación, la mesa de ayuda, los proveedores de portabilidad. En lugar de exportar un archivo a mano, tu programa le pide los datos directamente.

## Una petición

```python
import requests

respuesta = requests.get(
    "https://api.ejemplo.com/v1/clientes",
    params={"segmento": "EMPRESARIAL", "pagina": 1},          # → ?segmento=EMPRESARIAL&pagina=1
    headers={"Authorization": f"Bearer {token}"},
    timeout=30,                                               # ¡siempre!
)
respuesta.raise_for_status()      # excepción si el estado es 4xx o 5xx
datos = respuesta.json()          # el cuerpo JSON como dict/list de Python
```

| Parte | Para qué |
|---|---|
| Método | `GET` leer · `POST` crear · `PUT`/`PATCH` modificar · `DELETE` borrar |
| URL y `params` | Qué recurso y con qué filtros |
| `headers` | Metadatos: autenticación, formato |
| `json=` (en POST) | El cuerpo que envías |
| `timeout=` | Cuánto esperar como máximo. **Sin él, tu programa puede quedar colgado para siempre** |

## Códigos de estado

| Rango | Significa | Ejemplos | ¿Reintentar? |
|---|---|---|---|
| 2xx | Éxito | 200 OK, 201 Creado | — |
| 4xx | Error **tuyo** | 400 petición mal formada, 401 sin autenticar, 403 sin permiso, 404 no existe | No (salvo 429) |
| 429 | Demasiadas peticiones | Superaste el límite | Sí, después de esperar (`Retry-After`) |
| 5xx | Error **del servidor** | 500, 502, 503, 504 | Sí, con espera |

## JSON en Python

JSON se convierte directamente en diccionarios y listas:

```pyrun
import json

texto = '''{"cliente": {"id": "CL01", "lineas": [
    {"numero": "3001112233", "plan": "HOG30", "activa": true},
    {"numero": "3104445566", "plan": null, "activa": false}]},
  "pagina": {"actual": 1, "siguiente": "abc123"}}'''

datos = json.loads(texto)                       # requests: respuesta.json()
for linea in datos["cliente"]["lineas"]:
    print(linea["numero"], linea["plan"] or "sin plan", "✅" if linea["activa"] else "❌")
print(datos["pagina"].get("siguiente"))
print(json.dumps({"ok": True, "valor": 12.5}, ensure_ascii=False))
```

`true`/`false`/`null` de JSON llegan como `True`/`False`/`None`. Usa `.get("campo")` para los campos opcionales.

## Tokens y secretos

Las APIs piden identificarte, casi siempre con un **token** en la cabecera `Authorization`. El token es una contraseña: **nunca** en el código ni en Git. Léelo de una variable de entorno:

```python
import os

token = os.environ.get("TELCO_API_TOKEN")
if not token:
    raise SystemExit("Define la variable de entorno TELCO_API_TOKEN")
```

En PowerShell, para la sesión actual: `$env:TELCO_API_TOKEN = "..."`. Para que quede guardada para tu usuario (sin admin): `setx TELCO_API_TOKEN "..."` y abre una terminal nueva.

## Paginación

Ninguna API devuelve un millón de registros de una vez: los entrega por **páginas**. Hay dos estilos comunes:

:::columnas
:::columna Por número de página
`?pagina=1&tamano=100`, `?pagina=2...` hasta que llegue una página vacía o se alcance `total_paginas`.
:::
:::columna Por cursor
La respuesta trae `"siguiente": "abc123"`; la próxima petición envía `?cursor=abc123`. Se termina cuando `siguiente` es nulo. Más robusto si los datos cambian mientras descargas.
:::
:::

Un **generador** (módulo 11) es la forma natural de esconder la paginación:

```python
def todos_los_clientes(sesion, url):
    cursor = None
    while True:
        r = sesion.get(url, params={"cursor": cursor} if cursor else {}, timeout=30)
        r.raise_for_status()
        cuerpo = r.json()
        yield from cuerpo["datos"]
        cursor = cuerpo.get("siguiente")
        if not cursor:
            break

for cliente in todos_los_clientes(sesion, URL):     # quien lo usa no sabe que hay páginas
    ...
```

## Reintentos con espera exponencial

Las redes fallan. Un error 503 o un *timeout* muchas veces se resuelve si esperas un poco y lo intentas otra vez. La estrategia estándar es la **espera exponencial**: 1 s, 2 s, 4 s, 8 s… para no saturar a un servidor que ya está en problemas.

```pyrun
import random

def espera(intento, base=1.0, maximo=30.0):
    """Espera exponencial con un poco de azar (jitter) para que muchos clientes no reintenten a la vez."""
    return min(maximo, base * 2 ** intento) * random.uniform(0.8, 1.2)

random.seed(1)
for intento in range(6):
    print(f"Intento {intento + 1} falló → espero {espera(intento):5.1f} s")
```

:::error Reintentar solo lo que tiene sentido
Reintenta errores **transitorios**: problemas de conexión, *timeouts*, 429 y 5xx. **No** reintentes un 400 o un 401: la petición está mal y fallará siempre. Y si la petición crea algo (un `POST` que registra un pago), reintentar a ciegas puede duplicarlo; esas APIs suelen aceptar una "clave de idempotencia".
:::

## Sesiones

`requests.Session()` reutiliza la conexión entre peticiones (mucho más rápido con cientos de ellas) y guarda cabeceras comunes:

```python
sesion = requests.Session()
sesion.headers["Authorization"] = f"Bearer {token}"
sesion.headers["User-Agent"] = "conciliacion-telco/1.0"
```

:::telco Las APIs de la empresa
Antes de automatizar contra una API interna, pregunta tres cosas: ¿hay un ambiente de **pruebas**?, ¿cuál es el **límite** de peticiones?, ¿qué **permisos** tiene el token que me dan? Un script con un error en un ciclo puede lanzar miles de peticiones por minuto contra un sistema de producción.
:::

## Cuestionario

? Una API responde 503. ¿Qué haces?
- [ ] Abandonar: el servidor no existe
- [x] Reintentar después de esperar, con espera creciente
- [ ] Reintentar inmediatamente en un ciclo sin pausa
- [ ] Cambiar la contraseña
> 503 es un error transitorio del servidor; reintentar con espera exponencial es lo indicado.

? ¿Por qué hay que poner siempre `timeout=` en requests?
- [ ] Para que la petición sea más rápida
- [x] Porque sin él, si el servidor no responde, el programa puede esperar indefinidamente
- [ ] Porque la API lo exige
- [ ] Para reintentar automáticamente
> requests no tiene tiempo límite por defecto; un programa automatizado colgado es peor que uno que falla.

? En la paginación por cursor, ¿cuándo dejas de pedir páginas?
- [ ] Cuando llevas 100 páginas
- [x] Cuando la respuesta no trae un cursor `siguiente`
- [ ] Cuando la página trae menos de 10 registros
- [ ] Nunca
> El cursor nulo es la señal de que no hay más datos.
