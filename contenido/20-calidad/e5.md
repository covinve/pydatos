## Enunciado

`informe.py` (ya está en tu carpeta) usa la fecha actual directamente (no la recibe como parámetro):

```python
from datetime import datetime

def nombre_reporte(prefijo="conciliacion"):
    ahora = datetime.now()
    return f"{prefijo}_{ahora:%Y%m%d_%H%M}.xlsx"

def periodo_a_facturar():
    """El mes anterior a hoy, en formato AAAAMM."""
    hoy = datetime.now()
    anio, mes = (hoy.year - 1, 12) if hoy.month == 1 else (hoy.year, hoy.month - 1)
    return f"{anio}{mes:02d}"
```

**Escribe sus pruebas** usando `unittest.mock.patch` para fijar `datetime.now()`. Al menos **4** pruebas, incluyendo el caso de **enero** (el periodo debe ser diciembre del año anterior).

Recuerda la regla: se parchea **donde se usa** (`"informe.datetime"`).

## Pista 1

`patch` también funciona como decorador; el objeto falso llega como argumento:

```python
@patch("informe.datetime")
def test_periodo_en_enero(falso):
    falso.now.return_value = datetime(2027, 1, 15)
    assert informe.periodo_a_facturar() == "202612"
```

## Pista 2

Usa una fecha donde el mes anterior tenga **un dígito** (por ejemplo, octubre → `"202609"`) para atrapar el cero a la izquierda, y un minuto distinto de cero en el nombre del reporte (por ejemplo, `06:30`). Prueba también un prefijo propio: `nombre_reporte("rechazos")`.

## Solución

```python
from datetime import datetime
from unittest.mock import patch

import informe


def test_nombre_reporte():
    with patch("informe.datetime") as falso:
        falso.now.return_value = datetime(2026, 10, 5, 6, 30)
        assert informe.nombre_reporte() == "conciliacion_20261005_0630.xlsx"


def test_nombre_con_prefijo():
    with patch("informe.datetime") as falso:
        falso.now.return_value = datetime(2026, 3, 9, 23, 5)
        assert informe.nombre_reporte("rechazos") == "rechazos_20260309_2305.xlsx"


@patch("informe.datetime")
def test_periodo_mes_normal(falso):
    falso.now.return_value = datetime(2026, 10, 17)
    assert informe.periodo_a_facturar() == "202609"


@patch("informe.datetime")
def test_periodo_en_enero(falso):
    falso.now.return_value = datetime(2027, 1, 15)
    assert informe.periodo_a_facturar() == "202612"


@patch("informe.datetime")
def test_periodo_en_diciembre(falso):
    falso.now.return_value = datetime(2026, 12, 1)
    assert informe.periodo_a_facturar() == "202611"
```

## Explicación

Sin `patch`, estas pruebas solo podrían verificar "algo con el formato correcto": el resultado cambia cada minuto. Y el caso de enero solo se probaría… en enero. Con el tiempo congelado, cada prueba elige su "hoy".

`patch("informe.datetime")` reemplaza el nombre `datetime` **dentro del módulo `informe`** por un `MagicMock` durante la prueba. Como `informe.py` hizo `from datetime import datetime`, ese es el nombre que usa. Parchear `"datetime.datetime"` no funcionaría: es una clase de C que no se puede modificar, y además `informe` ya tiene su propia referencia.

Esto también es una señal de diseño: si fuera código tuyo, sería más simple recibir la fecha como parámetro (`periodo_a_facturar(hoy: date)`), como el reloj inyectado del módulo 19. `patch` es la herramienta para cuando el código **ya existe** y no conviene cambiarlo todavía, por ejemplo antes de refactorizarlo (¡con estas pruebas como red!).
