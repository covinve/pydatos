## Pista 2

Los intervalos logarítmicos: `bins = np.logspace(np.log10(mb.min()), np.log10(mb.max()), 31)` (31 bordes son 30 intervalos). Las megas mínimas son mayores que 0, así que el logaritmo existe.

Cuidado: por redondeo de float, el último borde puede quedar una millonésima por debajo del máximo y ese valor quedaría fuera del histograma. Fija los extremos: `bordes[0], bordes[-1] = mb.min(), mb.max()`.

## Solución

```python
import matplotlib.pyplot as plt
import numpy as np
import pandas as pd

cdr = pd.read_csv("cdr.csv", sep="|", dtype={"linea_origen": "string"}, keep_default_na=False)


def grafico_megas(cdr):
    mb = cdr.loc[cdr["tipo"] == "DATOS", "mb"]
    fig, (izq, der) = plt.subplots(1, 2, figsize=(10, 3.5), constrained_layout=True)
    izq.hist(mb, bins=30, color="#0891b2", edgecolor="white")
    izq.set_title("Escala normal")
    bordes = np.logspace(np.log10(mb.min()), np.log10(mb.max()), 31)
    bordes[0], bordes[-1] = mb.min(), mb.max()   # evita perder los extremos por redondeo
    der.hist(mb, bins=bordes, color="#4f46e5", edgecolor="white")
    der.set_xscale("log")
    der.set_title("Escala logarítmica")
    for ax in (izq, der):
        ax.set_xlabel("MB")
    izq.set_ylabel("Sesiones")
    fig.suptitle("Megas por sesión de datos")
    return fig


fig = grafico_megas(cdr)
```

## Explicación

En escala normal casi todo cae en la primera barra; en escala logarítmica aparece la forma real: una "campana" en torno a unas decenas de megas, con colas hacia sesiones de pocos KB y descargas de gigas. Esa forma (log-normal) es la que el generador usa para las megas, y es típica de muchas variables de consumo.

Con datos de cola larga, la escala logarítmica no es un truco: es la forma honesta de mostrar **todos** los órdenes de magnitud a la vez.
