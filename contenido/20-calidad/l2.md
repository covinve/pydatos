En el módulo 19 aislaste dependencias con **dobles en memoria** escritos a mano. `unittest.mock` crea dobles **automáticos** que, además, registran cómo se los llamó. Son ideales cuando quieres verificar una **interacción** ("¿se envió exactamente un correo con este asunto?") o reemplazar algo que no inyectaste.

## Mock: un objeto que acepta todo

```pyrun
from unittest.mock import Mock

notificador = Mock()
notificador.enviar("ALERTA", "7 % rechazados")         # cualquier método existe
notificador.enviar("ALERTA", "9 % rechazados")

print(notificador.enviar.call_count)                     # 2
print(notificador.enviar.call_args)                      # la última llamada
print(notificador.enviar.call_args_list)
notificador.enviar.assert_called_with("ALERTA", "9 % rechazados")

api = Mock()
api.tarifa.return_value = {"plan_id": "HOG30", "tarifa_minuto": 120}   # qué devuelve
print(api.tarifa("HOG30"))

api.consumos.side_effect = [ConnectionError("caída"), [{"linea": "3001"}]]   # una excepción y luego un valor
for _ in range(2):
    try:
        print(api.consumos("202609"))
    except ConnectionError as e:
        print("falló:", e)
```

| Atributo / método | Para qué |
|---|---|
| `m.return_value = x` | Lo que devuelve al llamarlo |
| `m.side_effect = Excepcion(...)` | Lanza esa excepción |
| `m.side_effect = [a, b, c]` | Devuelve (o lanza) uno por llamada, en orden |
| `m.side_effect = funcion` | Calcula la respuesta con tu función |
| `m.assert_called_once_with(...)` | Falla si no se llamó exactamente una vez con esos argumentos |
| `m.assert_not_called()` | Falla si se llamó |
| `m.call_args_list` | Todas las llamadas, para revisarlas a mano |

:::error El peligro del Mock que acepta todo
`notificador.enviarr(...)` (con un error de tipeo) **no falla**: un `Mock` acepta cualquier método. Usa `Mock(spec=NotificadorArchivo)` o `create_autospec(NotificadorArchivo)` para que solo acepte los métodos (y argumentos) que existen de verdad.
:::

:::reto Verifica la alerta con un Mock
El módulo `alertas.py` tiene `revisar_rechazos(rechazados, total, notificador)`: si más del **5 %** de los registros fueron rechazados, llama **una vez** a `notificador.enviar("ALERTA", "<pct> % rechazados")` (por ejemplo `"7 % rechazados"`); si no, no llama nada.

Escribe pruebas de pytest que usen `Mock` para verificar las dos situaciones. El curso las corre contra la versión correcta y contra dos con errores: una que nunca avisa y otra que avisa siempre.

```pyreto
from unittest.mock import Mock

from alertas import revisar_rechazos


def test_avisa_si_supera_el_umbral():
    notificador = Mock()
    revisar_rechazos(70, 1000, notificador)
    # verifica la llamada


def test_no_avisa_si_esta_bien():
    ...
```

:::pista
En la primera: `notificador.enviar.assert_called_once_with("ALERTA", "7 % rechazados")`. En la segunda, crea otro `Mock`, llama con `(30, 1000, notificador)` y usa `notificador.enviar.assert_not_called()`.
:::

```pyprueba
CORRECTA = (
    "def revisar_rechazos(rechazados, total, notificador):\n"
    "    pct = rechazados / total * 100\n"
    "    if pct > 5:\n"
    "        notificador.enviar('ALERTA', f'{pct:.0f} % rechazados')\n"
)


def correr(implementacion):
    return correr_pytest(codigo, {"alertas": implementacion})


def prueba_usa_mock():
    """Usa Mock y verifica llamadas"""
    assert "Mock(" in codigo and "assert_" in codigo, "Crea un Mock() y verifica con assert_called_once_with / assert_not_called"


def prueba_pasan():
    """Tus pruebas pasan con el código correcto"""
    resultado, texto = correr(CORRECTA)
    assert resultado != 5, "pytest no encontró pruebas"
    assert resultado == 0, "Alguna prueba falla con el código CORRECTO:\n" + texto[-900:]


def prueba_atrapa_nunca():
    """Atrapan la versión que nunca avisa"""
    resultado, _ = correr("def revisar_rechazos(rechazados, total, notificador):\n    pass\n")
    assert resultado == 1, "Ninguna prueba falló con la versión que nunca avisa"


def prueba_atrapa_siempre():
    """Atrapan la versión que avisa siempre"""
    mutante = CORRECTA.replace("if pct > 5:", "if True:")
    resultado, _ = correr(mutante)
    assert resultado == 1, "Ninguna prueba falló con la versión que avisa siempre"
```


## patch: reemplazar lo que no inyectaste

A veces el código usa algo directamente (`requests.get`, `time.sleep`, `datetime.now`) y no puedes o no quieres cambiar su diseño. `patch` lo reemplaza **temporalmente** durante la prueba:

```python
# descarga.py
import requests

def tarifa(plan_id):
    r = requests.get(f"https://api.telco.example/tarifas/{plan_id}", timeout=10)
    r.raise_for_status()
    return r.json()

# test_descarga.py
from unittest.mock import patch
import descarga

def test_tarifa():
    with patch("descarga.requests.get") as get:            # se reemplaza DONDE SE USA
        get.return_value.json.return_value = {"tarifa_minuto": 120}
        assert descarga.tarifa("HOG30") == {"tarifa_minuto": 120}
        get.assert_called_once_with("https://api.telco.example/tarifas/HOG30", timeout=10)
```

:::consejo Parchea donde se usa, no donde se define
Si `informe.py` hace `from datetime import datetime`, el nombre que usa es `informe.datetime`: hay que parchear `"informe.datetime"`, no `"datetime.datetime"`. Es el error más común con `patch`.
:::

:::reto Congela la fecha con patch
El módulo `informe.py` hace `from datetime import date` y tiene `titulo_informe()`, que devuelve `"Informe de facturación 2026-09"` usando el mes de **hoy** (`date.today()`). Escribe una prueba que, con `patch`, haga que hoy sea el **30 de septiembre de 2026** y verifique el título exacto.

El curso la corre contra la versión correcta y contra una que usa el formato `202609` (sin guion).

```pyreto
from datetime import date
from unittest.mock import patch

import informe


def test_titulo_del_mes():
    ...
```

:::pista
Parchea donde se usa: `with patch("informe.date") as falsa:` y `falsa.today.return_value = date(2026, 9, 30)`. Dentro del `with`, `assert informe.titulo_informe() == "Informe de facturación 2026-09"`.
:::

```pyprueba
CORRECTA = (
    "from datetime import date\n\n"
    "def titulo_informe():\n"
    "    return f'Informe de facturación {date.today():%Y-%m}'\n"
)


def correr(implementacion):
    return correr_pytest(codigo, {"informe": implementacion})


def prueba_usa_patch():
    """Usa patch sobre informe.date"""
    assert "patch(" in codigo and "informe.date" in codigo, "Parchea \"informe.date\" (donde se usa)"


def prueba_pasa():
    """Tu prueba pasa con el código correcto"""
    resultado, texto = correr(CORRECTA)
    assert resultado != 5, "pytest no encontró pruebas"
    assert resultado == 0, "Tu prueba falla con el código CORRECTO:\n" + texto[-900:]


def prueba_atrapa_formato():
    """Atrapa el formato sin guion"""
    resultado, _ = correr(CORRECTA.replace("%Y-%m", "%Y%m"))
    assert resultado == 1, "Tu prueba no falló con el formato 202609: verifica el título completo"
```

```pypreparacion
    "from datetime import date\n\n"
    "def titulo_informe():\n"
    "    return f'Informe de facturación {date.today():%Y-%m}'\n",
    encoding="utf-8",

```

## monkeypatch de pytest

Para variables de entorno, atributos y el directorio actual, el *fixture* `monkeypatch` es más simple y deshace todo al terminar la prueba:

```python
def test_token_desde_entorno(monkeypatch):
    monkeypatch.setenv("TELCO_API_TOKEN", "abc")
    monkeypatch.delenv("HTTPS_PROXY", raising=False)
    assert leer_token() == "abc"

def test_sin_esperas(monkeypatch):
    esperas = []
    monkeypatch.setattr("cliente.time.sleep", esperas.append)
    ...

def test_relativo(monkeypatch, tmp_path):
    monkeypatch.chdir(tmp_path)          # el directorio actual es una carpeta temporal
```

:::reto Una caída y luego funciona
El módulo `descarga.py` tiene `obtener_con_reintento(api, periodo)`: llama `api.consumos(periodo)` y, si lanza `ConnectionError`, lo intenta **una vez más**. Si vuelve a fallar, deja salir el error.

Escribe dos pruebas con `Mock` y `side_effect`:

1. la API falla una vez y luego devuelve `[{"linea": "3001"}]`: el resultado es esa lista y `consumos` se llamó **2** veces;
2. la API falla dos veces: la función lanza `ConnectionError`.

El curso las corre contra la versión correcta, contra una que **no reintenta** y contra una que reintenta **más de una vez**.

```pyreto
import pytest
from unittest.mock import Mock

from descarga import obtener_con_reintento


def test_reintenta_una_vez():
    ...


def test_dos_caidas_dejan_salir_el_error():
    ...
```

:::pista
`api = Mock()` y `api.consumos.side_effect = [ConnectionError("caída"), [{"linea": "3001"}]]`. Verifica con `api.consumos.call_count == 2`. Para la segunda: `side_effect = [ConnectionError(), ConnectionError(), []]` y `with pytest.raises(ConnectionError):`.
:::

```pyprueba
CORRECTA = (
    "def obtener_con_reintento(api, periodo):\n"
    "    try:\n"
    "        return api.consumos(periodo)\n"
    "    except ConnectionError:\n"
    "        return api.consumos(periodo)\n"
)


def correr(implementacion):
    return correr_pytest(codigo, {"descarga": implementacion})


def prueba_side_effect():
    """Usa side_effect"""
    assert "side_effect" in codigo, "Simula las caídas con side_effect"


def prueba_pasan():
    """Tus pruebas pasan con el código correcto"""
    resultado, texto = correr(CORRECTA)
    assert resultado != 5, "pytest no encontró pruebas"
    assert resultado == 0, "Alguna prueba falla con el código CORRECTO:\n" + texto[-900:]


def prueba_atrapa_sin_reintento():
    """Atrapan la versión que no reintenta"""
    resultado, _ = correr("def obtener_con_reintento(api, periodo):\n    return api.consumos(periodo)\n")
    assert resultado == 1, "Ninguna prueba falló con la versión que no reintenta"


def prueba_atrapa_demasiados():
    """Atrapan la versión que reintenta más de una vez"""
    mutante = (
        "def obtener_con_reintento(api, periodo):\n"
        "    for _ in range(3):\n"
        "        try:\n"
        "            return api.consumos(periodo)\n"
        "        except ConnectionError:\n"
        "            pass\n"
        "    raise ConnectionError('sin respuesta')\n"
    )
    resultado, _ = correr(mutante)
    assert resultado == 1, "Ninguna prueba falló con la versión que reintenta de más. Pista: en la prueba de dos caídas, agrega un tercer valor que sí funcione"
```

```pypreparacion
from pathlib import Path

Path("descarga.py").write_text(
    "def obtener_con_reintento(api, periodo):\n"
    "    try:\n"
    "        return api.consumos(periodo)\n"
    "    except ConnectionError:\n"
    "        return api.consumos(periodo)\n",
    encoding="utf-8",
)
```

```pysolucion
import pytest
from unittest.mock import Mock

from descarga import obtener_con_reintento


def test_reintenta_una_vez():
    api = Mock()
    api.consumos.side_effect = [ConnectionError("caída"), [{"linea": "3001"}]]
    assert obtener_con_reintento(api, "202609") == [{"linea": "3001"}]
    assert api.consumos.call_count == 2


def test_dos_caidas_dejan_salir_el_error():
    api = Mock()
    api.consumos.side_effect = [ConnectionError(), ConnectionError(), []]
    with pytest.raises(ConnectionError):
        obtener_con_reintento(api, "202609")
```

## ¿Mock o doble en memoria?

| Situación | Mejor opción |
|---|---|
| Verificar **que** se llamó algo y **cómo** (un envío, un reintento) | `Mock` |
| Simular errores en un orden preciso (falla, falla, funciona) | `Mock` con `side_effect` |
| Reemplazar algo que no inyectaste (`requests.get`, `time.sleep`) | `patch` / `monkeypatch` |
| Un repositorio con datos que el caso de uso consulta varias veces | Doble en memoria (`ClientesEnMemoria`) |
| Muchas pruebas sobre la misma dependencia | Doble en memoria: las pruebas quedan más legibles |

:::capo Demasiados mocks
Si una prueba necesita parchear cinco cosas, el código probablemente está muy acoplado: es una señal de diseño, no un problema de las pruebas. Y una prueba que verifica cada llamada interna se rompe con cualquier refactorización aunque el resultado siga siendo correcto. Verifica **resultados** siempre que puedas, e **interacciones** solo cuando la interacción **es** el resultado (como enviar una alerta).
:::

## Cuestionario

? ¿Qué hace `m.side_effect = [ValueError(), 5]`?
- [ ] Siempre lanza ValueError
- [x] La primera llamada lanza ValueError y la segunda devuelve 5
- [ ] Devuelve la lista
- [ ] Nada: side_effect solo acepta funciones
> Con una lista, cada llamada toma el siguiente elemento: si es una excepción, la lanza.

? `informe.py` hace `from datetime import datetime`. ¿Qué parcheas?
- [ ] `"datetime.datetime"`
- [x] `"informe.datetime"`
- [ ] `"datetime"`
- [ ] No se puede parchear
> Se parchea el nombre en el módulo donde se usa.

? Llamas por error `mock.enviarr(...)` en el código. ¿Qué pasa con un `Mock()` normal?
- [ ] AttributeError
- [x] Nada: el Mock acepta cualquier método, por eso conviene `spec=` o `create_autospec`
- [ ] La prueba falla siempre
- [ ] Python corrige el nombre
> Sin `spec`, el Mock no conoce la interfaz real y acepta errores de tipeo.
