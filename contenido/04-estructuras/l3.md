Si tuvieras que aprender **una sola** estructura para trabajar con datos, sería el diccionario. Guarda pares **clave → valor** y encuentra cualquier valor por su clave casi instantáneamente, sin importar cuántos haya.

```pyrun
plan = {
    "plan_id": "HOG30",
    "cargo_fijo": 35900,
    "minutos_incluidos": 300,
    "tarifa_minuto": 120,
}

print(plan["cargo_fijo"])
plan["tarifa_minuto"] = 125          # modificar
plan["segmento"] = "RESIDENCIAL"     # agregar
del plan["segmento"]                 # borrar
print(plan)
print(len(plan), "claves")
```

## Leer sin errores: get

Pedir una clave que no existe lanza `KeyError`. `get` devuelve un valor por defecto:

```pyrun
plan = {"plan_id": "HOG30", "cargo_fijo": 35900}

print(plan.get("descuento"))        # None
print(plan.get("descuento", 0))     # 0
print("descuento" in plan)          # ¿existe la clave?
print(plan["descuento"])            # error esperado
```

## Recorrer un diccionario

```pyrun
tarifas = {"LOCAL": 100, "NACIONAL": 120, "INTERNACIONAL": 950}

for destino in tarifas:                 # recorre las claves
    print(destino)

for destino, tarifa in tarifas.items(): # claves y valores juntos
    print(f"{destino:<14} ${tarifa}")

print(list(tarifas.keys()))
print(list(tarifas.values()))
```

Desde Python 3.7 los diccionarios **conservan el orden** en que insertaste las claves.

Compruébalo tú mismo (el número exacto depende del equipo, pero la diferencia es enorme):

```pyrun
import time

n = 200_000
lista = [f"3{i:09d}" for i in range(n)]
diccionario = {linea: i for i, linea in enumerate(lista)}
buscadas = lista[-200:]   # las 200 últimas: el peor caso para la lista

inicio = time.perf_counter()
for b in buscadas:
    b in lista
t_lista = time.perf_counter() - inicio

inicio = time.perf_counter()
for b in buscadas:
    b in diccionario
t_dict = time.perf_counter() - inicio

print(f"Lista:       {t_lista * 1000:8.1f} ms")
print(f"Diccionario: {t_dict * 1000:8.3f} ms")
print(f"El diccionario fue ~{t_lista / t_dict:,.0f} veces más rápido")
```

## Construir un índice

El patrón: recorre una vez la lista y crea un diccionario cuya clave es lo que vas a buscar.

```pyrun
clientes = [
    {"cliente_id": "CL001", "linea": "3001234567", "plan_id": "HOG30"},
    {"cliente_id": "CL002", "linea": "3109876543", "plan_id": "ILIM"},
]

por_linea = {c["linea"]: c for c in clientes}     # comprensión de diccionario

cdrs = [("3109876543", 125), ("3001234567", 61), ("3999999999", 30)]
for linea, segundos in cdrs:
    cliente = por_linea.get(linea)
    if cliente is None:
        print(f"{linea}: línea desconocida")
    else:
        print(f"{linea}: plan {cliente['plan_id']}")
```

## Contar con diccionarios

```pyrun
tipos = ["VOZ", "DATOS", "DATOS", "SMS", "DATOS", "VOZ", "VOX"]

conteo = {}
for t in tipos:
    conteo[t] = conteo.get(t, 0) + 1
print(conteo)

# La biblioteca estándar lo hace por ti:
from collections import Counter
c = Counter(tipos)
print(c)
print(c.most_common(2))
```

## Agrupar con diccionarios

```pyrun
from collections import defaultdict

cdrs = [("3001", 125), ("3002", 61), ("3001", 300), ("3003", 0), ("3002", 45)]

minutos_por_linea = defaultdict(int)       # si la clave no existe, empieza en 0
for linea, segundos in cdrs:
    minutos_por_linea[linea] += (segundos + 59) // 60

print(dict(minutos_por_linea))

llamadas_por_linea = defaultdict(list)     # si no existe, empieza en []
for linea, segundos in cdrs:
    llamadas_por_linea[linea].append(segundos)

print(dict(llamadas_por_linea))
```

## Diccionarios anidados

Los datos reales tienen estructura: un cliente tiene un plan, el plan tiene tarifas…

```pyrun
planes = {
    "HOG30": {"cargo_fijo": 35900, "incluidos": {"minutos": 300, "mb": 15360}},
    "ILIM": {"cargo_fijo": 89900, "incluidos": {"minutos": -1, "mb": -1}},
}

print(planes["HOG30"]["incluidos"]["minutos"])
for plan_id, plan in planes.items():
    print(plan_id, plan["cargo_fijo"])
```

:::telco El diccionario es un cruce (JOIN)
Cruzar los CDR con los clientes por la línea es exactamente lo que hace un `JOIN` en SQL o un `merge` en Pandas. Por dentro, ambos construyen un índice parecido a un diccionario. Entender esto te ayudará a razonar por qué algunos cruces son rápidos y otros no.
:::

## Cuestionario

? ¿Qué devuelve `{"a": 1}.get("b", 0)`?
- [ ] `None`
- [x] `0`
- [ ] `1`
- [ ] Un `KeyError`
> `get` devuelve el valor por defecto (el segundo argumento) cuando la clave no existe.

? Necesitas buscar el plan de cada uno de 10 millones de CDR entre 300.000 clientes. ¿Qué es lo correcto?
- [ ] Recorrer la lista de clientes para cada CDR
- [x] Construir una vez un diccionario línea → cliente y consultarlo para cada CDR
- [ ] Ordenar los CDR primero
- [ ] Usar una tupla de clientes
> Construir el índice cuesta un recorrido; luego cada consulta es instantánea. Con la lista serían billones de comparaciones.

? ¿Qué ventaja tiene `defaultdict(int)` al contar?
- [ ] Ordena las claves
- [x] Las claves nuevas empiezan en 0, así que no hace falta comprobar si existen
- [ ] Es más rápido que `Counter`
- [ ] Evita los duplicados
> Con un diccionario normal tendrías que usar `get(clave, 0)` o preguntar si la clave existe antes de sumar.
