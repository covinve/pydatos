"En mi computador funciona" casi siempre significa "en mi computador hay **otras versiones** de las librerías". Pandas 2 y Pandas 3 no se comportan igual; una actualización de numpy puede romper otra librería. Esta lección es sobre controlar exactamente qué se instala.

## Versionado semántico

La mayoría de las librerías numeran sus versiones como `MAYOR.MENOR.PARCHE`:

| Cambia | Significa | Ejemplo | ¿Puede romper tu código? |
|---|---|---|---|
| PARCHE | Correcciones | 2.2.2 → 2.2.3 | No debería |
| MENOR | Funciones nuevas, compatibles | 2.2 → 2.3 | No debería (pero a veces avisa que algo desaparecerá) |
| MAYOR | Cambios incompatibles | 2.x → 3.0 | **Sí** |

## Especificadores de versión

En `pyproject.toml` (o `requirements.txt`) declaras **qué rango** de versiones acepta tu proyecto:

| Especificador | Acepta | Uso típico |
|---|---|---|
| `pandas` | Cualquiera | Scripts personales rápidos |
| `pandas>=2.2` | 2.2 o superior (¡incluida la 3.0!) | Bibliotecas que publicas |
| `pandas>=2.2,<3` | Desde 2.2, sin pasar a la 3 | Aplicaciones: protege de cambios mayores |
| `pandas~=2.2.0` | `>=2.2.0, <2.3`: solo parches | Muy conservador |
| `pandas==2.2.3` | Exactamente esa | Archivos de **bloqueo**, no `pyproject.toml` |

```toml
[project]
name = "conciliacion"
version = "1.2.0"
requires-python = ">=3.12"
dependencies = [
    "pandas>=2.2,<4",
    "duckdb>=1.1",
    "typer>=0.12",
    "pydantic-settings>=2.4",
]

[project.optional-dependencies]
dev = ["pytest>=8", "ruff", "mypy"]
```

## Dependencias transitivas

Tú pides 4 librerías; pip instala 25. Cada una trae las suyas (pandas trae numpy, python-dateutil, pytz, tzdata…). Esas **dependencias transitivas** también cambian de versión, y no las controlas en `pyproject.toml`.

```powershell
pip install pipdeptree
pipdeptree -p pandas
```

```text
pandas==2.2.3
├── numpy [required: >=1.26.0, installed: 2.1.2]
├── python-dateutil [required: >=2.8.2, installed: 2.9.0]
│   └── six [required: >=1.5, installed: 1.16.0]
├── pytz [required: >=2020.1, installed: 2024.2]
└── tzdata [required: >=2022.7, installed: 2024.2]
```

## El archivo de bloqueo

:::pasos Rango vs. bloqueo
:::paso pyproject.toml: lo que ACEPTAS
`pandas>=2.2,<4`: un rango. Dice qué versiones son compatibles con tu código. Lo escribes tú, a mano.
:::
:::paso Archivo de bloqueo: lo que INSTALASTE
`pandas==2.2.3`, `numpy==2.1.2`, `six==1.16.0`… **todas** las librerías, incluidas las transitivas, con su versión exacta (y a veces su *hash*). Lo genera una herramienta.
:::
:::paso Reproducir
En la oficina, en casa, en GitHub Actions y en Docker instalas **desde el bloqueo**: exactamente las mismas versiones en todas partes.
:::
:::paso Actualizar a propósito
Cuando quieres versiones nuevas, regeneras el bloqueo, corres las pruebas y, si pasan, lo subes a Git. Las actualizaciones dejan de ser sorpresas.
:::
:::

Con **pip-tools** (se instala con pip, sin admin):

```powershell
pip install pip-tools
pip-compile pyproject.toml -o requirements.lock            # genera el bloqueo
pip-compile --extra dev pyproject.toml -o requirements-dev.lock
pip-sync requirements-dev.lock                              # deja el entorno EXACTAMENTE así
pip-compile --upgrade pyproject.toml -o requirements.lock   # actualizar a propósito
```

```text
# requirements.lock (generado: no lo edites a mano)
duckdb==1.1.3
    # via conciliacion (pyproject.toml)
numpy==2.1.2
    # via pandas
pandas==2.2.3
    # via conciliacion (pyproject.toml)
...
```

:::consejo pip freeze no es un bloqueo
`pip freeze > requirements.txt` guarda todo lo instalado, incluido lo que instalaste para probar y olvidaste. Sirve como foto, pero no distingue lo que tu proyecto **necesita** de lo que **sobra**. `pip-compile` y `uv lock` parten de tus dependencias declaradas.
:::

:::telco Un análisis que se puede repetir
Si en marzo te piden "vuelve a correr la conciliación de enero con los mismos resultados", necesitas el mismo código (Git), los mismos datos y **las mismas librerías** (el bloqueo). Un cambio en cómo una librería redondea o interpreta fechas puede mover un total por unos pesos, y explicar esa diferencia en una auditoría es muy incómodo.
:::

## Cuestionario

? ¿Qué especificador protege tu aplicación de un cambio de versión MAYOR de pandas?
- [ ] `pandas>=2.2`
- [x] `pandas>=2.2,<3`
- [ ] `pandas`
- [ ] `pandas!=3.0`
> El límite superior `<3` impide que se instale la 3.0, que puede traer cambios incompatibles.

? ¿Qué contiene un archivo de bloqueo?
- [ ] Solo las librerías que escribiste en pyproject.toml, con rangos
- [x] Todas las librerías, incluidas las transitivas, con su versión exacta
- [ ] El código fuente de las librerías
- [ ] Las contraseñas del proyecto
> Por eso permite reproducir exactamente el mismo entorno en cualquier lugar.

? ¿Dónde van las versiones exactas (`==`)?
- [ ] En `pyproject.toml`, siempre
- [x] En el archivo de bloqueo, generado por una herramienta
- [ ] En el README
- [ ] En ningún lado
> `pyproject.toml` declara rangos compatibles; el bloqueo fija lo instalado.
