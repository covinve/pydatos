`read_csv` carga todo el archivo en memoria. Con 1 GB, en tu computador funciona; con 20 GB, no. La salida con Pandas es **leer por bloques**.

## chunksize: un DataFrame a la vez

```pyrun
import pandas as pd

total = 0
minutos = 0
for bloque in pd.read_csv("cdr.csv", sep="|", chunksize=1000, dtype={"linea_origen": "string"}):
    total += len(bloque)
    voz = bloque[(bloque["tipo"] == "VOZ") & (bloque["duracion_seg"] >= 0)]
    minutos += int(((voz["duracion_seg"] + 59) // 60).sum())
    print(f"bloque de {len(bloque)} filas")

print(total, "registros,", minutos, "minutos")
```

Con `chunksize=1_000_000`, cada bloque ocupa unos 200 MB, sin importar si el archivo pesa 1 o 20 GB.

## Combinar resultados parciales

Lo que se puede sumar se acumula fácil. Para agrupar por bloques, **agrupa cada bloque y luego agrupa los resultados**:

```pyrun
import pandas as pd

parciales = []
for bloque in pd.read_csv("cdr.csv", sep="|", chunksize=1000, dtype={"linea_origen": "string"}):
    voz = bloque[(bloque["tipo"] == "VOZ") & (bloque["duracion_seg"] >= 0)].copy()
    voz["minutos"] = (voz["duracion_seg"] + 59) // 60
    parciales.append(voz.groupby("linea_origen")["minutos"].sum())

por_linea = pd.concat(parciales).groupby(level=0).sum()
print(por_linea.sort_values(ascending=False).head())
```

:::error Cuidado con lo que no se suma
Sumas, conteos, mínimos y máximos se combinan bien entre bloques. El **promedio** no: el promedio de los promedios es incorrecto si los bloques tienen tamaños distintos. Acumula suma y conteo por separado y divide al final. La **mediana** no se puede combinar así: necesita otra estrategia (o DuckDB).
:::

También hay que pensar en lo que **cruza** los bloques: un CDR duplicado puede estar en un bloque y su original en el anterior. Lo resolverás en el ejercicio 7 guardando los últimos IDs entre bloques (la ventana del módulo 11).

:::reto El promedio que sí cuadra
Este código calcula la duración promedio de las llamadas de VOZ (válidas) promediando los promedios de cada bloque, y da un resultado **incorrecto**, porque el último bloque es más pequeño. Corrígelo: acumula la suma y la cantidad por separado, y divide al final. Guarda el resultado en `promedio`.

```pyreto
import pandas as pd

promedios = []
for bloque in pd.read_csv("cdr.csv", sep="|", chunksize=1500, dtype={"linea_origen": "string"}):
    voz = bloque[(bloque["tipo"] == "VOZ") & (bloque["duracion_seg"] >= 0)]
    promedios.append(voz["duracion_seg"].mean())

promedio = sum(promedios) / len(promedios)
print(round(promedio, 2))
```

:::pista
Antes del bucle, `suma = 0` y `cantidad = 0`. En cada bloque, `suma += voz["duracion_seg"].sum()` y `cantidad += len(voz)`. Al final, `promedio = suma / cantidad`.
:::


## Parquet: el formato para datos analíticos

**Parquet** guarda los datos **por columnas**, comprimidos y **con sus tipos**:

| | CSV | Parquet |
|---|---|---|
| Tamaño | 100 % | Suele ser 10–25 % |
| Leer solo algunas columnas | Hay que leer todo | Solo lee esas columnas |
| Tipos (fechas, category, Int64) | Se pierden, hay que reconvertir | Se conservan |
| Legible en un editor | Sí | No (es binario) |
| Velocidad de lectura | Lenta | Muy rápida |

```pyrun
import os

import pandas as pd
import pyarrow  # Pandas lo usa para leer y escribir Parquet

cdr = pd.read_csv("cdr.csv", sep="|", dtype={"linea_origen": "string", "linea_destino": "string", "tipo": "category"})
cdr["inicio"] = pd.to_datetime(cdr["fecha_inicio"], format="%Y-%m-%d %H:%M:%S", errors="coerce")

cdr.to_parquet("cdr.parquet", index=False)
print(f"CSV: {os.path.getsize('cdr.csv') / 1024:.0f} KB · Parquet: {os.path.getsize('cdr.parquet') / 1024:.0f} KB")

solo_dos = pd.read_parquet("cdr.parquet", columns=["tipo", "mb"])
print(solo_dos.dtypes)
filtrado = pd.read_parquet("cdr.parquet", filters=[("tipo", "==", "DATOS")])
print(len(filtrado), "registros de datos leídos con filtro")
```

### Convertir un CSV gigante a Parquet, por bloques

```python
import pyarrow as pa
import pyarrow.parquet as pq

escritor = None
for bloque in pd.read_csv("datos/20GB/cdr.csv", sep="|", chunksize=2_000_000, dtype=TIPOS):
    tabla = pa.Table.from_pandas(bloque, preserve_index=False)
    escritor = escritor or pq.ParquetWriter("datos/20GB/cdr.parquet", tabla.schema, compression="zstd")
    escritor.write_table(tabla)
escritor.close()
```

Convertir una vez a Parquet y trabajar siempre sobre el Parquet es una de las mejoras de rendimiento más grandes que puedes hacer. DuckDB y Polars (módulo 16) leen Parquet de 20 GB en segundos.

:::telco Una carpeta de Parquet por mes
En un equipo de datos de facturación, lo habitual es guardar los CDR en Parquet **particionado**: una carpeta por periodo (`periodo=202609/`, `periodo=202610/`). Leer septiembre no toca los demás meses. Lo practicarás en el ejercicio 8.
:::

## Cuestionario

? ¿Por qué el promedio de los promedios de cada bloque puede ser incorrecto?
- [ ] Porque los bloques se leen en desorden
- [x] Porque los bloques pueden tener distinta cantidad de filas; hay que acumular suma y conteo
- [ ] Porque Pandas redondea
- [ ] Siempre es correcto
> Un bloque de 10 filas pesaría lo mismo que uno de un millón.

? ¿Qué ventaja tiene leer `pd.read_parquet(ruta, columns=["tipo", "mb"])`?
- [ ] Ninguna, lee todo igual
- [x] Solo lee del disco esas dos columnas, porque Parquet guarda por columnas
- [ ] Ordena las columnas
- [ ] Convierte los tipos
> En CSV hay que leer cada línea completa; en Parquet cada columna está separada.

? ¿Qué se pierde al guardar un DataFrame en CSV y volver a leerlo?
- [ ] Las filas
- [x] Los tipos: fechas, categorías y enteros con faltantes vuelven como texto o float
- [ ] Los nombres de las columnas
- [ ] Nada
> Parquet guarda el esquema con los tipos; CSV es solo texto.
