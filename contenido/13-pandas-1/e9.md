## Enunciado

Llegó un archivo de un aliado con problemas: líneas con **campos de más o de menos**, montos con coma decimal, una fecha con otro formato y bytes que no son UTF-8. `pd.read_csv` normal falla. Escribe `leer_robusto(ruta)` que devuelva una tupla `(df, rechazos)`:

- `df`: DataFrame con las filas que tienen exactamente 5 campos, con estas columnas y tipos: `cdr_id` (Int64), `linea` (texto), `fecha` (datetime64, inválidas como `NaT`), `duracion` (Int64, inválidas como faltante), `valor` (float; acepta coma decimal: `"1.234,5"` → `1234.5`).
- `rechazos`: lista de tuplas `(numero_de_linea_en_el_archivo, texto_de_la_linea)` de las filas con cantidad de campos incorrecta. El encabezado es la línea 1.

Los bytes inválidos deben reemplazarse (`encoding_errors="replace"`), no detener la lectura.

Pistas de `read_csv`: `on_bad_lines` acepta una **función** que recibe la lista de campos de la línea mala; si devuelve `None`, la línea se descarta.

## Pista 1

Para saber el número de línea de cada fila mala, lo más confiable es contar tú mismo: lee el archivo como texto (con `errors="replace"`) y registra las líneas cuya cantidad de campos no es 5. Luego pásale a `read_csv` una función que descarte las malas:

```python
df = pd.read_csv(ruta, sep=";", dtype=str, encoding="utf-8", encoding_errors="replace",
                 on_bad_lines=lambda campos: None, engine="python")
```

Con `engine="python"`, las líneas con **menos** campos no se consideran "malas": se rellenan con faltantes. Por eso filtra después las filas que tengan algún faltante en `valor`.

## Solución

```python
import pandas as pd

COLUMNAS = 5


def lineas_malas(ruta, separador=";"):
    rechazos = []
    with open(ruta, encoding="utf-8", errors="replace") as archivo:
        for numero, linea in enumerate(archivo, start=1):
            texto = linea.rstrip("\n")
            if numero > 1 and texto and len(texto.split(separador)) != COLUMNAS:
                rechazos.append((numero, texto))
    return rechazos


def leer_robusto(ruta):
    rechazos = lineas_malas(ruta)
    df = pd.read_csv(
        ruta, sep=";", dtype=str, encoding="utf-8", encoding_errors="replace",
        on_bad_lines=lambda campos: None, engine="python", keep_default_na=False, na_values=[""],
    )
    df = df.dropna(subset=["valor"]).reset_index(drop=True)
    df["cdr_id"] = pd.to_numeric(df["cdr_id"]).astype("Int64")
    df["duracion"] = pd.to_numeric(df["duracion"], errors="coerce").astype("Int64")
    df["fecha"] = pd.to_datetime(df["fecha"], format="%Y-%m-%d %H:%M:%S", errors="coerce")
    df["valor"] = pd.to_numeric(df["valor"].str.replace(".", "", regex=False).str.replace(",", ".", regex=False))
    return df, rechazos


df, rechazos = leer_robusto("aliado.csv")
print(df)
print(df.dtypes)
print(rechazos)
```

## Explicación

Un proceso real nunca debe fallar completo por unas pocas líneas malas, pero tampoco debe descartarlas en silencio. La solución separa tres cosas:

1. **Estructura** (cantidad de campos): las líneas malas se descartan **y se reportan** con su número de línea, para que el aliado pueda corregirlas.
2. **Codificación**: los bytes inválidos se reemplazan por `�` en lugar de detener la lectura; el carácter extraño queda visible para revisión.
3. **Contenido** (tipos): lo que no se puede convertir queda faltante (`<NA>`, `NaT`) en la columna correspondiente, sin perder el resto de la fila.

Los tipos `Int64` (con mayúscula) son enteros que admiten faltantes. Con el `int64` de NumPy, una sola duración inválida obligaría a convertir toda la columna a `float`.

Fíjate en el punto de miles: `"1.234,5"` primero pierde los puntos y después la coma pasa a ser punto decimal. El orden de los reemplazos importa.
