- el primer error: `CASE WHEN ... THEN ... WHEN ... END`.

## Solución

```python
import duckdb

LECTURA_CDR = """read_csv('cdr.csv', delim='|', header=true, all_varchar=true)"""
ORDEN = ["duplicado", "duracion_negativa", "fecha_invalida", "linea_vacia", "linea_desconocida", "tipo_desconocido"]


def clasificar():
    return duckdb.sql(f"""
        WITH cdr AS (
            SELECT *, ROW_NUMBER() OVER () AS rn FROM {LECTURA_CDR}
        ),
        clientes AS (
            SELECT linea FROM read_csv('clientes.csv', encoding='latin-1', header=true, all_varchar=true)
        ),
        marcado AS (
            SELECT *, ROW_NUMBER() OVER (PARTITION BY cdr_id ORDER BY rn) AS aparicion FROM cdr
        )
        SELECT CAST(cdr_id AS BIGINT) AS cdr_id,
               CASE
                   WHEN aparicion > 1 THEN 'duplicado'
                   WHEN coalesce(linea_origen, '') = '' THEN 'linea_vacia'
                   WHEN linea_origen NOT IN (SELECT linea FROM clientes) THEN 'linea_desconocida'
                   WHEN tipo NOT IN ('VOZ', 'SMS', 'DATOS') THEN 'tipo_desconocido'
                   WHEN CAST(duracion_seg AS INTEGER) < 0 THEN 'duracion_negativa'
                   WHEN TRY_STRPTIME(fecha_inicio, '%Y-%m-%d %H:%M:%S') IS NULL THEN 'fecha_invalida'
                   ELSE 'valido'
               END AS motivo
        FROM marcado
        ORDER BY rn
    """).df()


def conteo_errores():
    conteo = clasificar()["motivo"].value_counts()
    return {error: int(conteo.get(error, 0)) for error in ORDEN}


print(conteo_errores())
```

## Explicación

`CASE WHEN` evalúa las condiciones en orden y se queda con la primera verdadera: es el `np.select` de SQL, y su orden es la regla de negocio.

La regla de duplicados, que en Python puro necesitaba un conjunto con todos los IDs (15 GB con el archivo grande), aquí es una función de ventana. DuckDB la resuelve ordenando por `cdr_id` y, si no cabe en memoria, usa el disco. Por eso esta misma consulta funciona con 20 GB en tu computador de 16 GB.

`all_varchar=true` y `coalesce(linea_origen, '')` evitan una trampa: según cómo se lea, un campo vacío puede llegar como `NULL`, y `NULL = ''` no es verdadero en SQL (`NULL` no es igual a nada, ni siquiera a sí mismo).
