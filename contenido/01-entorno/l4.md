## Variables y print

Una **variable** es un nombre que apunta a un valor. Se crea con `=`:

```pyrun
linea = "3001234567"
plan = "HOG30"
minutos_usados = 342
minutos_incluidos = 300

print("Línea:", linea)
print("Plan:", plan)
print("Minutos adicionales:", minutos_usados - minutos_incluidos)
```

Mira cómo se van creando las variables, una línea a la vez:

```pytrace
cargo_fijo = 35900
minutos_extra = 42
tarifa = 120
valor_voz = minutos_extra * tarifa
subtotal = cargo_fijo + valor_voz
print(subtotal)
```

## f-strings: texto con valores adentro

Para mezclar texto y variables, pon una `f` antes de las comillas y las variables entre llaves `{}`:

```pyrun
cliente = "Lucía Gómez"
total = 48719

print(f"Hola {cliente}, el total de tu factura es ${total}")
print(f"Con separador de miles: ${total:,}")
```

En el módulo 2 verás cómo darle formato a números, fechas y monedas.

## Funciones: recetas reutilizables

Una **función** es un bloque de código con nombre que recibe datos y **devuelve** un resultado. La verás a fondo en el módulo 5, pero la necesitas desde ya porque **casi todos los ejercicios del curso te piden escribir una función**.

```pyrun
def calcular_iva(subtotal):
    return subtotal * 0.19


print(calcular_iva(40940))
print(calcular_iva(100000))
```

La anatomía es siempre la misma:

```python
def nombre_de_la_funcion(dato_que_recibe):   # def + nombre + (parámetros) + :
    resultado = dato_que_recibe * 2          # el cuerpo va con 4 espacios de sangría
    return resultado                          # return devuelve el resultado
```

:::error print no es lo mismo que return
`print` **muestra** un valor en pantalla; `return` lo **entrega** a quien llamó la función para que lo siga usando. Una función que solo hace `print` devuelve `None` y sus resultados no se pueden sumar, guardar ni comprobar.

```python
def iva_mal(subtotal):
    print(subtotal * 0.19)    # lo muestra… y devuelve None

def iva_bien(subtotal):
    return subtotal * 0.19    # lo entrega
```
:::

## Cómo se comprueban tus ejercicios

Cuando pulsas **✔ Comprobar**, el curso ejecuta **pruebas automáticas**: pequeñas funciones que llaman a tu código con distintos datos y verifican el resultado. Se parecen a esto:

```python
def prueba_iva_de_cien_mil():
    """El IVA de 100.000 es 19.000"""
    assert calcular_iva(100000) == 19000
```

`assert` significa "afirmo que esto es verdad". Si no lo es, la prueba falla y te muestra qué esperaba y qué obtuvo. En el módulo 10 escribirás tus propias pruebas con **pytest**, la herramienta que usan los equipos profesionales.

:::consejo Lee el nombre exacto que pide el enunciado
Si el enunciado dice "escribe la función `calcular_iva`", las pruebas buscan exactamente ese nombre. `calcularIva` o `calcular_IVA` no sirven.
:::

## PEP 8: el estilo de la comunidad Python

**PEP 8** es la guía de estilo oficial de Python. No cambia lo que hace el código, pero hace que todos los programadores de Python escriban de forma parecida, así que leer código ajeno se vuelve fácil.

:::comparar
:::mal Funciona, pero cuesta leerlo
```python
def CalcTotal(CF,c,d):
  T=CF+c-d
  return T*1.19
X=CalcTotal(35900,5040,0)
print(X)
```
:::
:::bien Mismo resultado, mucho más claro
```python
def calcular_total(cargo_fijo, consumo, descuento):
    subtotal = cargo_fijo + consumo - descuento
    return subtotal * 1.19


total = calcular_total(35900, 5040, 0)
print(total)
```
:::
:::

Las reglas más importantes:

| Regla | Ejemplo |
|---|---|
| Variables y funciones en `minusculas_con_guiones` (*snake_case*) | `minutos_incluidos`, `calcular_iva()` |
| Constantes en MAYÚSCULAS | `IVA = 0.19` |
| Clases en `PalabrasConMayuscula` (módulo 9) | `Factura`, `PlanTarifario` |
| Sangría de **4 espacios** (nunca tabuladores) | |
| Espacios alrededor de `=` y de operadores | `total = subtotal + iva` |
| Dos líneas en blanco antes de cada función | |
| Nombres que dicen qué guardan | `cargo_fijo` mejor que `cf` o `x` |
| Líneas de máximo 79 a 99 caracteres | |

## Ruff: tu revisor automático

No necesitas memorizar PEP 8. **Ruff** revisa tu código en segundos y te dice qué arreglar:

```powershell
ruff check mi_script.py          # lista los problemas
ruff check --fix mi_script.py    # arregla los que puede solo
ruff format mi_script.py         # reformatea el archivo con el estilo estándar
```

Con la extensión **Ruff** de VS Code verás los problemas subrayados mientras escribes, y el archivo se formatea al guardar si activas *Format on Save* (`Ctrl + ,` → busca "format on save").

## Scripts y notebooks

| | Script `.py` | Notebook `.ipynb` |
|---|---|---|
| Qué es | Un archivo de código que se ejecuta de principio a fin | Celdas de código y texto que ejecutas una por una |
| Ideal para | Procesos automáticos, programas reutilizables, proyectos | Explorar datos, probar ideas, gráficos, presentar análisis |
| Control de versiones | Excelente | Regular (guarda también los resultados) |
| En el curso | Ejercicios de VS Code y proyectos | Análisis exploratorio (módulo 15) |

Para crear un notebook en VS Code: `Ctrl + Shift + P` → **Create: New Jupyter Notebook**, y elige el kernel de tu `.venv`.

:::telco La regla de oro
Explora los datos de facturación en un notebook; cuando el proceso funcione, pásalo a un script `.py` con funciones y pruebas. Los notebooks no son buenos para procesos que deben correr solos cada noche.
:::
