## Enunciado

El equipo de auditoría puede revisar facturas antes de enviarlas. Revisar una cuesta **$5.000** (tiempo de un analista); dejar escapar una factura con error cuesta en promedio **$80.000** (reclamo, ajuste, cliente molesto). ¿Conviene usar el modelo? ¿Con qué umbral? ¿Cuánto se ahorra?

En `ejercicios/m23-e8/evaluacion.py` implementa las cinco funciones del docstring:

1. `costo` y `elegir_umbral`: el costo de una decisión y el umbral que lo minimiza.
2. `probabilidades_fuera_de_muestra`: probabilidades para elegir el umbral **sin hacer trampa** (cada caso, predicho por un modelo que no lo vio).
3. `validacion_cruzada`: precisión, *recall* y precisión promedio, con media y desviación.
4. `informe`: todo junto, comparando contra **no revisar nada** y **revisar todo**.

## Solución

```python evaluacion.py
"""Ejercicio m23-e8: evaluar un clasificador con validación cruzada y elegir el umbral por costo."""

from __future__ import annotations

import numpy as np
from sklearn.model_selection import StratifiedKFold, cross_val_predict, cross_validate

METRICAS = ["precision", "recall", "average_precision"]


def costo(y, proba, umbral, costo_fp, costo_fn) -> int:
    y = np.asarray(y)
    marca = np.asarray(proba) >= umbral
    fp = int(np.sum(marca & (y == 0)))
    fn = int(np.sum(~marca & (y == 1)))
    return int(fp * costo_fp + fn * costo_fn)


def elegir_umbral(y, proba, costo_fp, costo_fn, umbrales=None) -> tuple[float, int]:
    if umbrales is None:
        umbrales = np.round(np.arange(0.01, 1.0, 0.01), 2)
    mejor, mejor_costo = None, None
    for u in umbrales:
        c = costo(y, proba, u, costo_fp, costo_fn)
        if mejor_costo is None or c <= mejor_costo:
            mejor, mejor_costo = float(u), c
    return mejor, mejor_costo


def _cv(k, semilla):
    return StratifiedKFold(n_splits=k, shuffle=True, random_state=semilla)


def probabilidades_fuera_de_muestra(modelo, X, y, k=5, semilla=0) -> np.ndarray:
    return cross_val_predict(modelo, X, y, cv=_cv(k, semilla), method="predict_proba")[:, 1]


def validacion_cruzada(modelo, X, y, k=5, semilla=0) -> dict:
    r = cross_validate(modelo, X, y, cv=_cv(k, semilla), scoring=METRICAS)
    return {m: (round(float(r[f"test_{m}"].mean()), 3), round(float(r[f"test_{m}"].std()), 3)) for m in METRICAS}


def informe(modelo, X, y, costo_fp, costo_fn, k=5, semilla=0) -> dict:
    y = np.asarray(y)
    proba = probabilidades_fuera_de_muestra(modelo, X, y, k, semilla)
    umbral, costo_modelo = elegir_umbral(y, proba, costo_fp, costo_fn)
    sin_modelo = int(y.sum()) * costo_fn
    revisar_todo = int((y == 0).sum()) * costo_fp
    return {
        "umbral": umbral,
        "costo_modelo": costo_modelo,
        "costo_sin_modelo": sin_modelo,
        "costo_revisar_todo": revisar_todo,
        "ahorro": min(sin_modelo, revisar_todo) - costo_modelo,
        "metricas": validacion_cruzada(modelo, X, y, k, semilla),
    }
```

## Explicación

El resultado del informe es una frase que entiende cualquier gerente: "usando el modelo con umbral 0,07, el costo baja de X a Y: ahorramos Z al mes". Eso es lo que convierte un modelo en una **decisión**.

Dos detalles evitan engañarse:

- **Probabilidades fuera de muestra**: si eligieras el umbral con las probabilidades que el modelo da a los mismos datos con que entrenó, serían optimistas (el modelo "recuerda" esos casos) y el umbral quedaría mal calibrado. `cross_val_predict` da a cada caso la probabilidad de un modelo que no lo vio.
- **Comparar con estrategias sin modelo**: un modelo solo vale si mejora a "no revisar nada" y a "revisar todo". Con costos muy distintos (aquí 16 a 1), a veces revisar todo es imbatible, y no hace falta un modelo.

La desviación de la validación cruzada indica cuánto confiar en el número: un *recall* de 0,82 ± 0,02 es estable; uno de 0,82 ± 0,15 depende mucho de qué casos tocaron en la prueba, y conviene más datos antes de prometer ahorros.

Fíjate en que el umbral óptimo resultó **muy por debajo de 0,5**: cuando un error se escapa cuesta 16 veces más que una revisión, conviene revisar cualquier factura con una probabilidad modesta de tener error.
