El dominio debe leerse casi como el reglamento de facturación. Para eso, los conceptos del negocio (dinero, periodo, plan, factura) se vuelven **tipos** con nombre, en lugar de números y textos sueltos.

## Objetos de valor

Un **objeto de valor** se define por su contenido: dos `Periodo("202609")` son el mismo periodo. Son **inmutables** y se validan al crearlos, así que si existe, es válido.

```pyrun
from dataclasses import dataclass


@dataclass(frozen=True, order=True)
class Periodo:
    valor: str

    def __post_init__(self):
        if len(self.valor) != 6 or not self.valor.isdigit() or not 1 <= int(self.valor[4:]) <= 12:
            raise ValueError(f"Periodo inválido: {self.valor!r} (formato AAAAMM)")

    @property
    def anio(self) -> int:
        return int(self.valor[:4])

    @property
    def mes(self) -> int:
        return int(self.valor[4:])

    def siguiente(self) -> "Periodo":
        return Periodo(f"{self.anio + self.mes // 12}{self.mes % 12 + 1:02d}")


p = Periodo("202612")
print(p, p.anio, p.mes, "→", p.siguiente())
print(Periodo("202609") == Periodo("202609"), Periodo("202609") < Periodo("202610"))
for malo in ("202613", "2026-09", "26"):
    try:
        Periodo(malo)
    except ValueError as e:
        print("❌", e)
try:
    p.valor = "202701"
except Exception as e:
    print("Inmutable:", type(e).__name__)
```

| `@dataclass(...)` | Efecto |
|---|---|
| `frozen=True` | No se pueden cambiar los atributos (y se puede usar como clave de diccionario) |
| `order=True` | Permite `<`, `>`, `sorted()` |
| `__post_init__` | Se ejecuta después de crear: el lugar para **validar** |
| `slots=True` | Usa menos memoria (útil con millones de objetos) |

:::reto La línea móvil como objeto de valor
Escribe el objeto de valor `LineaMovil`:

- dataclass **inmutable** con un solo campo, `numero` (texto);
- al crearla valida que tenga 10 dígitos y empiece por `"3"`; si no, `ValueError` con el número en el mensaje;
- la propiedad `operador_prefijo`: los tres primeros dígitos;
- dos `LineaMovil` con el mismo número son iguales y sirven como clave de diccionario.

```pyreto
from dataclasses import dataclass

# class LineaMovil: ...


a = LineaMovil("3001112233")
print(a, a.operador_prefijo, a == LineaMovil("3001112233"))
```

:::pista
`@dataclass(frozen=True)` y la validación en `__post_init__`: `if not (len(self.numero) == 10 and self.numero.isdigit() and self.numero.startswith("3")): raise ValueError(...)`. La propiedad: `return self.numero[:3]`.
:::

```pyprueba
import dataclasses


def prueba_valida():
    """Una línea válida se crea y compara por valor"""
    requiere("LineaMovil")
    a = LineaMovil("3001112233")
    igual(a.operador_prefijo, "300", "operador_prefijo")
    igual(a == LineaMovil("3001112233"), True, "igualdad por valor")
    igual(len({a, LineaMovil("3001112233")}), 1, "sirve en conjuntos")


def prueba_invalidas():
    """Las líneas inválidas no se pueden crear"""
    for malo in ("31577", "6014445566", "300111223X", ""):
        error = lanza(ValueError, LineaMovil, malo)
        assert malo in str(error), f"El mensaje debe incluir el número recibido: {error}"


def prueba_inmutable():
    """Es inmutable"""
    lanza(dataclasses.FrozenInstanceError, setattr, LineaMovil("3001112233"), "numero", "3109998877")
```

```pysolucion
from dataclasses import dataclass


@dataclass(frozen=True)
class LineaMovil:
    numero: str

    def __post_init__(self):

            raise ValueError(f"Línea móvil inválida: {self.numero!r}")

    @property
    def operador_prefijo(self) -> str:

print(a, a.operador_prefijo, a == LineaMovil("3001112233"))
```

## ¿Por qué no un simple `str` o `int`?

:::comparar
:::mal Tipos primitivos
```python
def emitir(periodo: str, total: int, iva: int): ...

emitir(total, "202609", iva)          # ¿error? Python no se queja hasta que algo explota
emitir("2026-09", 50000, 0.19)        # formato equivocado, IVA como porcentaje
```
:::
:::bien Tipos del dominio
```python
def emitir(periodo: Periodo, total: Dinero): ...

emitir(Periodo("2026-09"), ...)       # ValueError inmediato, con un mensaje claro
```
El error aparece **donde se cometió**, no tres funciones después. Y mypy (módulo 20) puede detectar argumentos cambiados antes de ejecutar.
:::
:::

## Entidades

Una **entidad** tiene identidad propia que se mantiene aunque cambien sus datos: un cliente sigue siendo el mismo aunque cambie de plan. Se comparan por su identificador:

```python
@dataclass
class Cliente:
    linea: str              # identidad
    plan_id: str            # puede cambiar
    segmento: str

    def __eq__(self, otro):
        return isinstance(otro, Cliente) and otro.linea == self.linea

    def __hash__(self):
        return hash(self.linea)
```

:::reto Un cliente que cambia de plan
Escribe la entidad `Cliente` (una dataclass **normal**, no inmutable) con `linea`, `plan_id` y `historial` (lista vacía por defecto, propia de cada cliente):

- dos clientes son iguales si tienen la misma `linea`, aunque su plan sea distinto (y `__hash__` coherente con eso);
- el método `cambiar_plan(nuevo)` guarda el plan anterior en `historial` y actualiza `plan_id`. Si `nuevo` es igual al plan actual, no hace nada.

```pyreto
from dataclasses import dataclass, field

# class Cliente: ...


c = Cliente("3001112233", "BAS10")
c.cambiar_plan("HOG30")
c.cambiar_plan("HOG30")
c.cambiar_plan("HOG60")
print(c.plan_id, c.historial)                 # HOG60 ['BAS10', 'HOG30']
print(c == Cliente("3001112233", "ILIM"))     # True
```

:::pista
`historial: list[str] = field(default_factory=list)`. Define `__eq__` comparando `linea` (si el otro no es `Cliente`, devuelve `NotImplemented`) y `__hash__` con `hash(self.linea)`. Usa `@dataclass(eq=False)` para que la dataclass no genere su propio `__eq__`.
:::

```pyprueba
def prueba_identidad():
    """Iguales por línea, aunque cambie el plan"""
    requiere("Cliente")
    igual(Cliente("3001", "BAS10") == Cliente("3001", "ILIM"), True, "misma línea")
    igual(Cliente("3001", "BAS10") == Cliente("3002", "BAS10"), False, "distinta línea")
    igual(len({Cliente("3001", "A"), Cliente("3001", "B")}), 1, "conjunto")


def prueba_cambiar_plan():
    """cambiar_plan lleva el historial"""
    c = Cliente("3001", "BAS10")
    c.cambiar_plan("HOG30")
    c.cambiar_plan("HOG30")
    c.cambiar_plan("HOG60")
    igual((c.plan_id, c.historial), ("HOG60", ["BAS10", "HOG30"]))
    igual(Cliente("3002", "ILIM").historial, [], "cada cliente tiene su propio historial")
```

```pysolucion
from dataclasses import dataclass, field


@dataclass(eq=False)
class Cliente:
    linea: str
    plan_id: str
    historial: list[str] = field(default_factory=list)

    def __eq__(self, otro):
        if not isinstance(otro, Cliente):
            return NotImplemented
        return self.linea == otro.linea

    def __hash__(self):
        return hash(self.linea)

    def cambiar_plan(self, nuevo):
        if nuevo == self.plan_id:
            return
        self.historial.append(self.plan_id)
        self.plan_id = nuevo


c = Cliente("3001112233", "BAS10")
c.cambiar_plan("HOG30")
c.cambiar_plan("HOG30")
c.cambiar_plan("HOG60")
print(c.plan_id, c.historial)                 # HOG60 ['BAS10', 'HOG30']
print(c == Cliente("3001112233", "ILIM"))     # True
```

## Reglas puras

Las reglas del dominio son **funciones puras**: el mismo resultado para la misma entrada, sin efectos secundarios. Son las más fáciles de probar y de entender.

```pyrun
from dataclasses import dataclass
from datetime import date

FECHA_CORTE_ANTIGUEDAD = date(2023, 9, 1)


@dataclass(frozen=True)
class Plan:
    plan_id: str
    cargo_fijo: int
    minutos_incluidos: int
    tarifa_minuto: int
    tarifa_minuto_internacional: int


@dataclass(frozen=True)
class Consumo:
    minutos_nacionales: int
    minutos_internacionales: int


def redondear(valor: float) -> int:
    """Al peso más cercano; 0,5 sube."""
    return int(valor + 0.5)


def descuento(plan: Plan, segmento: str, fecha_alta: date) -> int:
    if segmento == "EMPRESARIAL" and fecha_alta < FECHA_CORTE_ANTIGUEDAD:
        return redondear(plan.cargo_fijo * 0.10)
    return 0


def valor_consumo(plan: Plan, c: Consumo) -> int:
    voz = 0 if plan.minutos_incluidos == -1 else max(0, c.minutos_nacionales - plan.minutos_incluidos) * plan.tarifa_minuto
    return voz + c.minutos_internacionales * plan.tarifa_minuto_internacional


emp = Plan("EMP100", 79900, 1000, 100, 800)
print(descuento(emp, "EMPRESARIAL", date(2022, 5, 1)), descuento(emp, "EMPRESARIAL", date(2024, 1, 1)))
print(valor_consumo(emp, Consumo(1042, 3)))
```

:::reto La regla del recargo por mora
Escribe la regla pura `recargo_mora(total, dias_mora)` según el reglamento:

- sin mora (0 días o menos), no hay recargo;
- por cada **mes iniciado** de mora (cada 30 días o fracción) se cobra el **2 %** del total;
- el recargo nunca supera el **10 %** del total;
- se redondea al peso con la regla comercial (usa la función `redondear` del dominio).

```pyreto
def redondear(valor: float) -> int:
    """Al peso más cercano; 0,5 sube."""
    return int(valor + 0.5)


def recargo_mora(total: int, dias_mora: int) -> int:
    pass


print(recargo_mora(48719, 0), recargo_mora(48719, 1), recargo_mora(48719, 31), recargo_mora(48719, 400))
# 0 974 1949 4872
```

:::pista
Los meses iniciados: `meses = (dias_mora + 29) // 30`. La tasa es `min(0.10, 0.02 * meses)`. Devuelve `redondear(total * tasa)` y, antes, un `return 0` si `dias_mora <= 0`.
:::

```pyprueba
def prueba_sin_mora():
    """Sin mora no hay recargo"""
    requiere("recargo_mora")
    igual(recargo_mora(48719, 0), 0)
    igual(recargo_mora(48719, -3), 0)


def prueba_meses():
    """2 % por mes iniciado"""
    igual(recargo_mora(48719, 1), 974, "1 día")
    igual(recargo_mora(48719, 30), 974, "30 días")
    igual(recargo_mora(48719, 31), 1949, "31 días")
    igual(recargo_mora(10000, 90), 600, "90 días")


def prueba_tope():
    """Nunca supera el 10 %"""
    igual(recargo_mora(48719, 400), 4872, "400 días")
    igual(recargo_mora(10000, 150), 1000, "150 días")
```

```pysolucion
def redondear(valor: float) -> int:
    """Al peso más cercano; 0,5 sube."""
    return int(valor + 0.5)


def recargo_mora(total: int, dias_mora: int) -> int:
    if dias_mora <= 0:
        return 0
    meses = (dias_mora + 29) // 30
    tasa = min(0.10, 0.02 * meses)
    return redondear(total * tasa)


print(recargo_mora(48719, 0), recargo_mora(48719, 1), recargo_mora(48719, 31), recargo_mora(48719, 400))
# 0 974 1949 4872
```

:::telco El dominio como documentación
Un archivo `dominio.py` bien escrito es la mejor documentación de las reglas de facturación: alguien de negocio puede leerlo con tu ayuda y confirmar "sí, así es el descuento". Y cuando la regla cambie (porque cambiará), sabes exactamente qué archivo tocar y qué pruebas actualizar.

## Cuestionario

? ¿Qué caracteriza a un objeto de valor?
- [ ] Tiene un identificador único que nunca cambia
- [x] Se define por su contenido, es inmutable y se valida al crearse
- [ ] Siempre guarda dinero
- [ ] Se guarda en la base de datos
> Dos objetos de valor con el mismo contenido son intercambiables, como dos billetes de 10.000.

? ¿Dónde se valida que un `Periodo` tenga formato `AAAAMM`?
- [ ] En cada función que lo usa
- [x] En `__post_init__`, al crearlo
- [ ] En la CLI
- [ ] En la base de datos
> Validar al crear garantiza que todo `Periodo` que exista sea válido.

? ¿Por qué las reglas del dominio deberían ser funciones puras?
- [ ] Porque son más rápidas
- [x] Porque con la misma entrada dan el mismo resultado y no tienen efectos secundarios: se prueban y entienden fácilmente
- [ ] Porque Python lo exige
- [ ] Porque así no necesitan parámetros
> Una función pura se prueba con una línea, sin preparar archivos ni bases de datos.
