Un archivo plano acepta cualquier cosa: un CDR duplicado, una línea que no existe, una duración negativa. Una base de datos bien diseñada **rechaza** esos datos antes de que entren. Todo lo que tu validador revisaba a mano, la base de datos lo puede vigilar siempre.

Cada plan se escribe **una vez** en `planes`; los clientes solo guardan su `plan_id`. Si cambia el cargo fijo de un plan, se cambia en un solo lugar. Esto se llama **normalizar**.
:::
:::paso Claves primarias 🔑
La **clave primaria** identifica cada fila y no se puede repetir. Un segundo CDR con el mismo `cdr_id` es rechazado: los duplicados se vuelven **imposibles**.
:::
:::paso Claves foráneas 🔗
Una **clave foránea** dice "este valor debe existir en otra tabla". Un CDR de una línea que no está en `clientes` es rechazado: adiós a las líneas desconocidas.
:::
:::

```pyrun
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("PRAGMA foreign_keys = ON")      # en SQLite hay que activarlas (en PostgreSQL siempre lo están)
con.executescript("""
    CREATE TABLE planes (
        plan_id    TEXT PRIMARY KEY,
        cargo_fijo INTEGER NOT NULL CHECK (cargo_fijo > 0)
    );
    CREATE TABLE clientes (
        linea   TEXT PRIMARY KEY,
        plan_id TEXT NOT NULL REFERENCES planes (plan_id)
    );
    CREATE TABLE cdr (
        cdr_id       INTEGER PRIMARY KEY,
        linea_origen TEXT NOT NULL REFERENCES clientes (linea),
        tipo         TEXT NOT NULL CHECK (tipo IN ('VOZ', 'SMS', 'DATOS')),
        duracion_seg INTEGER NOT NULL CHECK (duracion_seg >= 0)
    );
    INSERT INTO planes VALUES ('BAS10', 25900);
    INSERT INTO clientes VALUES ('3001112233', 'BAS10');
""")

intentos = [
    (1, "3001112233", "VOZ", 125),    # bien
    (1, "3001112233", "VOZ", 125),    # duplicado
    (2, "3999999999", "VOZ", 60),     # línea desconocida
    (3, "3001112233", "FAX", 10),     # tipo inválido
    (4, "3001112233", "VOZ", -5),     # duración negativa
]
for cdr in intentos:
    try:
        con.execute("INSERT INTO cdr VALUES (?, ?, ?, ?)", cdr)
        print("✅", cdr)
    except sqlite3.IntegrityError as error:
        print("❌", cdr, "→", error)
```

| Restricción | Garantiza |
|---|---|
| `PRIMARY KEY` | Único y no nulo |
| `UNIQUE` | Sin repetidos (puede haber varias por tabla) |
| `NOT NULL` | Siempre tiene valor |
| `CHECK (condición)` | Regla de negocio |
| `REFERENCES tabla (col)` | El valor existe en la otra tabla |
| `DEFAULT valor` | Valor cuando no se indica |

:::error SQLite y las claves foráneas
Por compatibilidad histórica, SQLite **ignora** las claves foráneas si no ejecutas `PRAGMA foreign_keys = ON` en **cada conexión**. Es un error muy común creer que te protegen cuando están apagadas.
:::

## Índices: el índice del libro

Para encontrar los CDR de una línea entre 200 millones, sin índice la base de datos lee **todas** las filas. Un **índice** es una estructura ordenada (un árbol B) que le permite saltar directamente a ellas, como el índice al final de un libro.

```pyrun
import sqlite3, random, time

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE cdr (cdr_id INTEGER PRIMARY KEY, linea TEXT, duracion INTEGER)")
random.seed(1)
con.executemany("INSERT INTO cdr (linea, duracion) VALUES (?, ?)",
                ((f"300{random.randrange(100000):07d}", random.randrange(600)) for _ in range(300_000)))

def medir():
    inicio = time.perf_counter()
    for _ in range(200):
        con.execute("SELECT SUM(duracion) FROM cdr WHERE linea = ?", ("3000004242",)).fetchone()
    return (time.perf_counter() - inicio) / 200 * 1000

print(con.execute("EXPLAIN QUERY PLAN SELECT SUM(duracion) FROM cdr WHERE linea = '3000004242'").fetchall())
print(f"Sin índice: {medir():.2f} ms por consulta")
con.execute("CREATE INDEX ix_cdr_linea ON cdr (linea)")
print(con.execute("EXPLAIN QUERY PLAN SELECT SUM(duracion) FROM cdr WHERE linea = '3000004242'").fetchall())
print(f"Con índice: {medir():.3f} ms por consulta")
```

`EXPLAIN QUERY PLAN` muestra la estrategia: `SCAN` (leer todo) o `SEARCH ... USING INDEX` (saltar).

Los índices no son gratis: ocupan espacio y hacen más lentas las inserciones (cada `INSERT` actualiza también el índice). Crea índices para las columnas por las que **buscas, cruzas o filtras** con frecuencia, no para todas.

## Transacciones: todo o nada

Una **transacción** agrupa varias operaciones que deben ocurrir juntas. Si una falla, se deshacen todas. Es la propiedad **A** (atomicidad) de **ACID**.

```pyrun
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE facturas (factura_id INTEGER PRIMARY KEY, total INTEGER CHECK (total >= 0))")
con.executemany("INSERT INTO facturas VALUES (?, ?)", [(1, 50000), (2, 30000)])
con.commit()

ajustes = [(1, -10000), (2, -40000)]          # el segundo dejaría un total negativo
try:
    with con:                                  # una transacción
        for factura, ajuste in ajustes:
            con.execute("UPDATE facturas SET total = total + ? WHERE factura_id = ?", (ajuste, factura))
except sqlite3.IntegrityError as e:
    print("Se deshizo todo:", e)

print(con.execute("SELECT * FROM facturas").fetchall())   # la factura 1 NO quedó a medias
```

| Letra | Propiedad | Significa |
|---|---|---|
| **A** | Atomicidad | Todo o nada |
| **C** | Consistencia | Las restricciones siempre se cumplen |
| **I** | Aislamiento | Las transacciones simultáneas no se pisan |
| **D** | Durabilidad | Lo confirmado sobrevive a un corte de luz |

:::telco Cargas que no quedan a medias
Si un proceso de carga se cae en el registro 6 millones de 10, ¿qué quedó en la tabla? Con una transacción por archivo, la respuesta es simple: o el archivo completo o nada, y puedes volver a ejecutarlo sin duplicar.
:::

## Cuestionario

? ¿Qué impide que se inserte un CDR de una línea que no existe en `clientes`?
- [ ] La clave primaria
- [x] Una clave foránea `REFERENCES clientes (linea)` (en SQLite, con `PRAGMA foreign_keys = ON`)
- [ ] Un índice
- [ ] `NOT NULL`
> La clave foránea exige que el valor exista en la tabla referenciada.

? ¿Cuándo conviene crear un índice?
- [ ] En todas las columnas, siempre
- [x] En columnas por las que filtras, buscas o cruzas con frecuencia
- [ ] Solo en tablas pequeñas
- [ ] Nunca en SQLite
> Aceleran las búsquedas, pero ocupan espacio y hacen más lentas las inserciones.

? Dentro de `with con:` el segundo de tres `UPDATE` viola un `CHECK`. ¿Qué queda en la tabla?
- [ ] El primer `UPDATE` aplicado
- [ ] Los tres, porque el error se ignora
- [x] Nada: la transacción se deshace completa
- [ ] El primero y el tercero
> Es la atomicidad: la transacción ocurre completa o no ocurre.
