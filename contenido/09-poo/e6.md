## Enunciado

Hay tres tipos de plan con reglas distintas para el consumo adicional. Implementa la jerarquía:

- `Plan` (clase base abstracta con `ABC`):
  - `__init__(self, plan_id, cargo_fijo)`;
  - método abstracto `valor_adicional(self, minutos, mb)`;
  - método concreto `total_sin_iva(self, minutos, mb)` → `cargo_fijo + valor_adicional(...)`.
- `PlanPorConsumo(Plan)`: recibe además `minutos_incluidos`, `tarifa_minuto`, `mb_incluidos`, `tarifa_mb`. Cobra los excesos (megas redondeadas hacia arriba).
- `PlanIlimitado(Plan)`: el adicional siempre es 0.
- `PlanTopeado(PlanPorConsumo)`: igual que por consumo, pero el adicional **nunca supera** un `tope` (parámetro extra). Reutiliza el cálculo del padre con `super()`.

Y la función `total_cartera(planes_y_consumos)` que recibe una lista de tuplas `(plan, minutos, mb)` y devuelve la suma de `total_sin_iva` de todas, **sin preguntar de qué tipo es cada plan**.

## Pista 1

La base abstracta:

```python
class Plan(ABC):
    def __init__(self, plan_id, cargo_fijo):
        self.plan_id = plan_id
        self.cargo_fijo = cargo_fijo

    @abstractmethod
    def valor_adicional(self, minutos, mb):
        ...

    def total_sin_iva(self, minutos, mb):
        return self.cargo_fijo + self.valor_adicional(minutos, mb)
```

Las subclases llaman a `super().__init__(plan_id, cargo_fijo)` y guardan sus atributos extra.

## Pista 2

En `PlanTopeado`, el `__init__` recibe todo lo de `PlanPorConsumo` más `tope`, y `valor_adicional` limita el resultado del padre:

```python
def valor_adicional(self, minutos, mb):
    return min(self.tope, super().valor_adicional(minutos, mb))
```

`total_cartera` es una sola línea con `sum(...)`.

## Solución

```python
import math
from abc import ABC, abstractmethod


class Plan(ABC):
    def __init__(self, plan_id, cargo_fijo):
        self.plan_id = plan_id
        self.cargo_fijo = cargo_fijo

    @abstractmethod
    def valor_adicional(self, minutos, mb):
        """Valor del consumo adicional en pesos."""

    def total_sin_iva(self, minutos, mb):
        return self.cargo_fijo + self.valor_adicional(minutos, mb)


class PlanPorConsumo(Plan):
    def __init__(self, plan_id, cargo_fijo, *, minutos_incluidos, tarifa_minuto, mb_incluidos, tarifa_mb):
        super().__init__(plan_id, cargo_fijo)
        self.minutos_incluidos = minutos_incluidos
        self.tarifa_minuto = tarifa_minuto
        self.mb_incluidos = mb_incluidos
        self.tarifa_mb = tarifa_mb

    def valor_adicional(self, minutos, mb):
        voz = max(0, minutos - self.minutos_incluidos) * self.tarifa_minuto
        datos = max(0, math.ceil(mb) - self.mb_incluidos) * self.tarifa_mb
        return voz + datos


class PlanIlimitado(Plan):
    def valor_adicional(self, minutos, mb):
        return 0


class PlanTopeado(PlanPorConsumo):
    def __init__(self, plan_id, cargo_fijo, *, tope, **tarifas):
        super().__init__(plan_id, cargo_fijo, **tarifas)
        self.tope = tope

    def valor_adicional(self, minutos, mb):
        return min(self.tope, super().valor_adicional(minutos, mb))


def total_cartera(planes_y_consumos):
    return sum(plan.total_sin_iva(minutos, mb) for plan, minutos, mb in planes_y_consumos)
```

## Explicación

- **`total_sin_iva` se escribe una sola vez** en la base y funciona para todos: llama al `valor_adicional` del objeto concreto. Eso es polimorfismo.
- **`total_cartera` no sabe que existen tres tipos de plan.** Si mañana aparece un `PlanPrepago`, la función sigue funcionando sin cambios.
- **`PlanTopeado` reutiliza** el cálculo de su padre con `super().valor_adicional(...)` y solo agrega el límite. `**tarifas` reenvía todos los parámetros con nombre al padre sin repetirlos.
- **`PlanIlimitado` no necesita `__init__`**: hereda el de `Plan`.

La prueba `prueba_cartera_sin_isinstance` vigila el antipatrón clásico: una cadena de `if isinstance(plan, PlanIlimitado): ... elif ...`. Cada vez que aparezca un tipo nuevo, habría que buscar y modificar todas esas cadenas.
