**uv** es una herramienta moderna (escrita en Rust) que reemplaza a `pip`, `venv`, `pip-tools` y más, y es **10 a 100 veces más rápida**. Se instala con pip en tu usuario, sin admin:

```powershell
pip install --user uv          # o dentro de cualquier entorno: pip install uv
uv --version
```

## El flujo con uv

```powershell
uv init conciliacion             # crea pyproject.toml, .python-version, README, src/...
cd conciliacion
uv add pandas duckdb typer       # agrega a pyproject.toml, instala y actualiza uv.lock
uv add --dev pytest ruff mypy    # dependencias de desarrollo
uv run pytest                    # ejecuta dentro del entorno del proyecto (lo crea si no existe)
uv run python -m conciliacion.cli --help
uv lock --upgrade-package pandas # actualizar UNA librería, a propósito
uv sync                          # deja el entorno exactamente como dice uv.lock
```

| Archivo | Lo escribe | Va a Git |
|---|---|---|
| `pyproject.toml` | Tú (o `uv add`) | Sí |
| `uv.lock` | uv | **Sí**: es el bloqueo |
| `.venv/` | uv | No (`.gitignore`) |
| `.python-version` | `uv init` / `uv python pin` | Sí |

:::consejo uv también instala Python
`uv python install 3.13` descarga un Python en tu carpeta de usuario, **sin admin**. Útil en la oficina si el Python instalado es viejo: `uv venv --python 3.13` crea un entorno con esa versión.
:::

Si prefieres no cambiar tu forma de trabajar, uv también funciona como un pip más rápido:

```powershell
uv venv
uv pip install -r requirements.txt
uv pip compile pyproject.toml -o requirements.lock    # como pip-compile
uv pip sync requirements.lock
```

## ¿Y Poetry?

**Poetry** es la herramienta "todo en uno" más popular antes de uv; la encontrarás en muchos proyectos.

| | pip + venv | pip-tools | Poetry | uv |
|---|---|---|---|---|
| Crear entorno | `python -m venv` | (venv) | `poetry install` | `uv venv` / automático |
| Agregar dependencia | Editar a mano | Editar a mano | `poetry add` | `uv add` |
| Bloqueo | — | `requirements.lock` | `poetry.lock` | `uv.lock` |
| Velocidad | Normal | Normal | Normal | Muy rápida |
| Sin admin | Sí | Sí | Sí (`pipx` o `pip --user`) | Sí |

Lo importante no es la herramienta sino la idea: **rango declarado + bloqueo exacto + instalar desde el bloqueo**. Si llegas a un proyecto con Poetry: `poetry install` y `poetry run pytest`; con uv: `uv sync` y `uv run pytest`.

## pip detrás del proxy de la empresa

Si `pip install` falla en la oficina con errores de conexión o de certificado, casi siempre es el **proxy** corporativo. Puedes configurarlo **para tu usuario** (sin admin) en `%APPDATA%\pip\pip.ini`:

```ini
[global]
proxy = http://proxy.empresa.com:8080
cert = C:\Users\tu_usuario\certificados\raiz-empresa.pem
# Algunas empresas tienen un espejo interno de PyPI:
# index-url = https://artifactory.empresa.com/api/pypi/pypi/simple
```

uv usa las variables `HTTPS_PROXY` y `SSL_CERT_FILE`, o `UV_INDEX_URL` para un espejo. Pide los valores a TI; nunca desactives la verificación de certificados (`--trusted-host` para todo) "para que funcione".

:::reto Tu pip.ini de la oficina
TI te pasó estos datos: el proxy es `http://proxy.empresa.com:8080`, el certificado raíz está en `C:\Users\carlos\certificados\raiz-empresa.pem` y hay un espejo interno en `https://artifactory.empresa.com/api/pypi/pypi/simple`. Escribe en `pip_ini` el contenido del archivo (formato INI, sección `[global]`) y luego léelo con `configparser` para comprobar que quedó bien.

No pongas `trusted-host`: el certificado es la forma correcta.

```pyreto
import configparser

pip_ini = """
[global]

"""

lector = configparser.ConfigParser()
lector.read_string(pip_ini)
print(dict(lector["global"]))
```

:::pista
Dentro de `[global]`, una opción por línea: `proxy = ...`, `cert = ...` e `index-url = ...`. En INI las barras invertidas de la ruta se escriben tal cual.
:::

```pyprueba
import configparser


def _global():
    lector = configparser.ConfigParser()
    lector.read_string(pip_ini)
    assert lector.has_section("global"), "Falta la sección [global]"
    return lector["global"]


def prueba_valores():
    """proxy, cert e index-url"""
    g = _global()
    igual(g.get("proxy"), "http://proxy.empresa.com:8080", "proxy")
    igual(g.get("cert"), r"C:\Users\carlos\certificados\raiz-empresa.pem", "cert")
    igual(g.get("index-url"), "https://artifactory.empresa.com/api/pypi/pypi/simple", "index-url")


def prueba_sin_atajos():
    """Sin trusted-host"""
    assert "trusted-host" not in _global(), "No desactives la verificación con trusted-host"
```

```pysolucion
import configparser

pip_ini = r"""
[global]
proxy = http://proxy.empresa.com:8080
cert = C:\Users\carlos\certificados\raiz-empresa.pem
index-url = https://artifactory.empresa.com/api/pypi/pypi/simple
"""

lector = configparser.ConfigParser()
lector.read_string(pip_ini)
print(dict(lector["global"]))
```

## Cuestionario

? ¿Qué archivo de uv debe subirse a Git para que otros reproduzcan tu entorno?
- [ ] `.venv/`
- [x] `uv.lock` (junto con `pyproject.toml`)
- [ ] Ninguno
- [ ] `uv.exe`
> El bloqueo, junto con `pyproject.toml`, permite que `uv sync` cree el mismo entorno en cualquier lugar.

? ¿Qué hace `uv run pytest`?
- [ ] Instala pytest globalmente
- [x] Ejecuta pytest dentro del entorno del proyecto, creándolo o sincronizándolo si hace falta
- [ ] Sube las pruebas a GitHub
- [ ] Nada si no activaste el entorno
> No necesitas activar el entorno a mano: uv lo usa automáticamente.

? `pip install` falla en la oficina con un error de certificado. ¿Qué es lo correcto?
- [ ] Desactivar la verificación SSL
- [x] Configurar el proxy y el certificado raíz de la empresa en tu `pip.ini` de usuario
- [ ] Instalar desde una memoria USB
- [ ] Pedir permisos de administrador
> El proxy corporativo inspecciona el tráfico con su propio certificado; hay que indicarle a pip que confíe en él.
