Cuando algo sale mal, Python **lanza una excepción**: detiene lo que estaba haciendo y, si nadie la atrapa, termina el programa mostrando un *traceback*.

## Leer un traceback

```pyrun
def minutos_facturables(texto_duracion):
    segundos = int(texto_duracion)
    return (segundos + 59) // 60


def total_minutos(duraciones):
    total = 0
    for d in duraciones:
        total += minutos_facturables(d)
    return total


print(total_minutos(["125", "61", "1,5"]))   # error esperado
```

Un traceback se lee **de abajo hacia arriba**:

1. **La última línea** dice qué pasó: `ValueError: invalid literal for int() with base 10: '1,5'`.
2. **Las líneas de arriba** muestran el camino: quién llamó a quién hasta llegar al error.
3. **La línea más baja que es tuya** suele ser la culpable (o la que recibió el dato malo).

:::consejo Busca el error en internet
Copia la última línea del traceback (sin los datos específicos) en tu buscador. Casi cualquier error que veas ya lo tuvo alguien antes y está explicado en Stack Overflow o la documentación.
:::

## Las excepciones más comunes

| Excepción | Cuándo aparece | Ejemplo telco |
|---|---|---|
| `ValueError` | El valor tiene el tipo correcto pero no sirve | `int("1,5")` |
| `TypeError` | Operación con un tipo incorrecto | `"125" + 5` |
| `KeyError` | Clave inexistente en un diccionario | `tarifas["SATELITAL"]` |
| `IndexError` | Posición fuera de la lista | `campos[9]` en una fila de 8 campos |
| `ZeroDivisionError` | División entre cero | promedio de una lista vacía |
| `FileNotFoundError` | El archivo no existe | ruta mal escrita |
| `UnicodeDecodeError` | Encoding incorrecto | leer latin-1 como UTF-8 |
| `AttributeError` | El objeto no tiene ese atributo | `None.strip()` |

## try/except: atrapar un error

```pyrun
textos = ["125", "61", "1,5", "", "3600"]

for texto in textos:
    try:
        segundos = int(texto)
    except ValueError:
        print(f"'{texto}' no es una duración válida, se ignora")
        continue
    print(f"{segundos} s → {(segundos + 59) // 60} min")
```

El bloque `try` se ejecuta normalmente. Si ocurre un `ValueError`, Python salta al `except` en lugar de detener el programa.

:::reto Suma lo que se pueda
Los montos llegaron como texto y algunos están dañados. Recórrelos y:

- suma en `total` los que se puedan convertir a entero;
- cuenta en `danados` los que no.

El programa no debe detenerse.

```pyreto
montos = ["35900", "5040", "1.200", "", "62900", "N/A", "-2000"]
total = 0
danados = 0

# Recorre con try/except ValueError

print(total, danados)
```

:::pista
Dentro del `for`: `try: total += int(m)` y `except ValueError: danados += 1`. Fíjate que `"-2000"` sí es un entero válido.
:::

```pyprueba
def prueba_total():
    """total = 101840"""
    requiere("total")
    igual(total, 101840)


def prueba_danados():
    """danados = 3"""
    requiere("danados")
    igual(danados, 3)


def prueba_usa_try():
    """Usa try/except ValueError"""
    assert "except ValueError" in codigo, "Atrapa el error con except ValueError"
```

```pysolucion
montos = ["35900", "5040", "1.200", "", "62900", "N/A", "-2000"]
total = 0
danados = 0

for m in montos:
    try:
        total += int(m)
    except ValueError:
        danados += 1

print(total, danados)
```

## Atrapa solo lo que esperas

:::error Nunca uses `except:` solo (ni `except Exception:` a la ligera)
```python
try:
    total = calcular_factura(cliente, plan, consumo)
except:
    total = 0          # ¿un error de dato? ¿un error de programación? ¿Ctrl+C? Todo se esconde
```
Un `except` genérico esconde errores de programación (un nombre mal escrito, una clave equivocada) y produce facturas en cero sin que nadie se entere. **Atrapa solo la excepción que sabes manejar.**
:::

```pyrun
tarifas = {"LOCAL": 100, "NACIONAL": 120}


def tarifa_de(destino):
    try:
        return tarifas[destino]
    except KeyError:
        return None


print(tarifa_de("LOCAL"), tarifa_de("SATELITAL"))
```

:::reto El except que escondía un error
Esta función usa un `except` genérico. Cuando por error le llega `None` en lugar de un destino, devuelve `None` como si el destino no existiera, y el problema pasa inadvertido.

Corrígela para que atrape **solo** el caso esperado (destino que no está en la tabla). Un `None` debe producir su error normal.

```pyreto
def tarifa_de(destino, tarifas):
    try:
        return tarifas[destino.strip().upper()]
    except:
        return None


TARIFAS = {"LOCAL": 100, "NACIONAL": 120}
print(tarifa_de(" local ", TARIFAS))   # 100
print(tarifa_de("SATELITAL", TARIFAS))  # None
```

:::pista
Una clave inexistente lanza `KeyError`; `None.strip()` lanza `AttributeError`. Cambia `except:` por `except KeyError:`.
:::

```pyprueba
TARIFAS = {"LOCAL": 100, "NACIONAL": 120}


def prueba_normal():
    """Encuentra la tarifa y devuelve None si el destino no existe"""
    requiere("tarifa_de")
    igual(tarifa_de(" local ", TARIFAS), 100)
    igual(tarifa_de("SATELITAL", TARIFAS), None)


def prueba_no_esconde_errores():
    """Un None no se esconde: lanza AttributeError"""
    lanza(AttributeError, tarifa_de, None, TARIFAS)
```

```pysolucion

```
:::

## Varias excepciones y el objeto del error

```pyrun
def leer_duracion(campos):
    try:
        return int(campos[6])
    except IndexError:
        print("La fila tiene menos campos de los esperados")
    except ValueError as error:
        print(f"Duración inválida: {error}")
    return None


leer_duracion(["1", "3001"])
leer_duracion(["1", "3001", "", "VOZ", "LOCAL", "2026-09-13", "abc"])
print(leer_duracion(["1", "3001", "", "VOZ", "LOCAL", "2026-09-13", "125"]))
```

`except ValueError as error` guarda la excepción en `error` para usar su mensaje. También puedes agrupar: `except (ValueError, IndexError):`.

:::reto Cada error con su nombre
Escribe `leer_mb(campos)`, que recibe los campos de un CDR (una lista de textos) y devuelve las megas de la posición 7 como `float`. Si algo falla, en lugar de detenerse devuelve un texto con el motivo:

- si la fila tiene menos de 8 campos → `"fila_corta"`;
- si el valor no es un número → `"mb_invalido"`.

```pyreto
def leer_mb(campos):
    pass


print(leer_mb(["1", "3001", "", "DATOS", "", "2026-09-13", "0", "15.131"]))   # 15.131
print(leer_mb(["1", "3001"]))                                               # fila_corta
print(leer_mb(["1", "3001", "", "DATOS", "", "2026-09-13", "0", "15,1"]))   # mb_invalido
```

:::pista
Un solo `try` con `return float(campos[7])`, y dos `except`: uno para `IndexError` y otro para `ValueError`, cada uno con su `return`.
:::

```pyprueba
def prueba_valido():
    """Devuelve las megas como float"""
    requiere("leer_mb")
    igual(leer_mb(["1", "3001", "", "DATOS", "", "2026-09-13", "0", "15.131"]), 15.131)


def prueba_fila_corta():
    """Fila con menos campos → fila_corta"""
    igual(leer_mb(["1", "3001"]), "fila_corta")
    igual(leer_mb([]), "fila_corta")


def prueba_invalido():
    """Valor no numérico → mb_invalido"""
    igual(leer_mb(["1", "3001", "", "DATOS", "", "2026-09-13", "0", "15,1"]), "mb_invalido")
    igual(leer_mb(["1", "3001", "", "DATOS", "", "2026-09-13", "0", ""]), "mb_invalido")
```

```pysolucion
def leer_mb(campos):
    try:
        return float(campos[7])
    except IndexError:
        return "fila_corta"
    except ValueError:
        return "mb_invalido"


print(leer_mb(["1", "3001", "", "DATOS", "", "2026-09-13", "0", "15.131"]))   # 15.131
print(leer_mb(["1", "3001"]))                                               # fila_corta
print(leer_mb(["1", "3001", "", "DATOS", "", "2026-09-13", "0", "15,1"]))   # mb_invalido
```
:::

## else y finally

```pyrun
def dividir_minutos(total, lineas):
    try:
        promedio = total / lineas
    except ZeroDivisionError:
        print("No hay líneas: no se puede promediar")
        return None
    else:
        print("Cálculo exitoso")          # solo si NO hubo excepción
        return round(promedio, 1)
    finally:
        print("Esto se ejecuta siempre")  # haya o no excepción, incluso con return


print(dividir_minutos(342, 4))
print(dividir_minutos(342, 0))
```

| Bloque | Se ejecuta… |
|---|---|
| `try` | siempre, hasta que ocurra una excepción |
| `except` | solo si ocurrió esa excepción |
| `else` | solo si **no** ocurrió ninguna |
| `finally` | **siempre**, al final (ideal para cerrar conexiones o liberar recursos) |

:::reto La bitácora siempre se cierra
Escribe `promedio_por_linea(total_minutos, lineas, bitacora)`, que agrega mensajes a la lista `bitacora`:

- si `lineas` es 0: agrega `"sin lineas"` y devuelve `None`;
- si el cálculo sale bien: agrega `"ok"` y devuelve el promedio redondeado a 1 decimal;
- **en cualquier caso**, al final agrega `"fin"`.

Usa `try`, `except`, `else` y `finally`.

```pyreto
def promedio_por_linea(total_minutos, lineas, bitacora):
    pass


log = []
print(promedio_por_linea(342, 4, log), log)   # 85.5 ['ok', 'fin']
log = []
print(promedio_por_linea(342, 0, log), log)   # None ['sin lineas', 'fin']
```

:::pista
Copia la estructura de `dividir_minutos`: la división va en el `try`, el `"sin lineas"` en el `except ZeroDivisionError`, el `"ok"` y el `return` del promedio en el `else`, y `bitacora.append("fin")` en el `finally`.
:::

```pyprueba
def prueba_exito():
    """Con líneas: devuelve el promedio y registra ok y fin"""
    requiere("promedio_por_linea")
    log = []
    igual(promedio_por_linea(342, 4, log), 85.5)
    igual(log, ["ok", "fin"])


def prueba_sin_lineas():
    """Sin líneas: devuelve None y registra sin lineas y fin"""
    log = []
    igual(promedio_por_linea(342, 0, log), None)
    igual(log, ["sin lineas", "fin"])


def prueba_usa_finally():
    """Usa else y finally"""
    assert "finally" in codigo and "else" in codigo, "Usa los bloques else y finally"
```

```pysolucion
def promedio_por_linea(total_minutos, lineas, bitacora):
    try:
        promedio = total_minutos / lineas
    except ZeroDivisionError:
        bitacora.append("sin lineas")
        return None
    else:
        bitacora.append("ok")
        return round(promedio, 1)
    finally:
        bitacora.append("fin")


log = []
print(promedio_por_linea(342, 4, log), log)   # 85.5 ['ok', 'fin']
log = []
print(promedio_por_linea(342, 0, log), log)   # None ['sin lineas', 'fin']
```
:::

:::telco Un registro malo no debe detener la facturación
En un archivo de 10 millones de CDR siempre habrá registros dañados. Si el proceso se detiene con el primero, la facturación no sale. El patrón correcto: atrapar el error **del registro**, anotarlo y seguir con el siguiente. Lo practicarás en el ejercicio 3.
:::

## Cuestionario

? ¿Por dónde empiezas a leer un traceback?
- [ ] Por la primera línea
- [x] Por la última línea, que dice qué excepción ocurrió
- [ ] Por la línea del medio
- [ ] Los tracebacks no se leen, se borran
> La última línea tiene el tipo de error y el mensaje. Las de arriba muestran el camino de llamadas.

? ¿Qué excepción lanza `{"LOCAL": 100}["SATELITAL"]`?
- [ ] `ValueError`
- [ ] `IndexError`
- [x] `KeyError`
- [ ] Ninguna, devuelve `None`
> Acceder a una clave inexistente con corchetes lanza `KeyError`. Con `.get()` obtendrías `None`.

? ¿Cuándo se ejecuta el bloque `else` de un `try`?
- [ ] Siempre
- [ ] Solo si hubo una excepción
- [x] Solo si no hubo ninguna excepción en el `try`
- [ ] Nunca, es opcional
> `else` es para el código que debe correr solo si todo salió bien; `finally` es el que corre siempre.
