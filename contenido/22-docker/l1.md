En el módulo 21 fijaste las versiones de las **librerías**. Pero un programa también depende del **sistema**: la versión de Python, librerías del sistema operativo, el idioma de las fechas, las rutas. Docker empaqueta **todo** eso en una **imagen** que corre igual en tu portátil, en un servidor Linux o en la nube.

## Imagen y contenedor

:::columnas
:::columna Imagen
Una "foto" inmutable: sistema operativo mínimo + Python + tus librerías + tu código. Se construye una vez con un `Dockerfile` y se identifica con un nombre y una etiqueta: `telco-pipeline:1.2.0`.
:::
:::columna Contenedor
Un proceso **en ejecución** creado a partir de una imagen, aislado del resto de la máquina. De una imagen puedes lanzar muchos contenedores; cuando el contenedor termina, lo que escribió dentro se pierde (salvo en **volúmenes**).
:::
:::

La analogía clásica: la imagen es la **clase**, el contenedor es el **objeto** (módulo 9).

| | Entorno virtual (venv) | Contenedor Docker | Máquina virtual |
|---|---|---|---|
| Aísla | Librerías de Python | Python, sistema, librerías, procesos | Todo, incluido el núcleo |
| Tamaño | Decenas de MB | 100–500 MB | Varios GB |
| Arranque | Instantáneo | 1 segundo | Minutos |
| Requiere admin | No | Para instalar Docker, sí | Sí |

## Dónde usarlo

- **En casa** (tienes permisos de administrador): instala **Docker Desktop** para Windows; usa WSL2 por debajo.
- **En la oficina** (sin admin): normalmente no podrás instalar Docker. Opciones: **GitHub Codespaces** (un entorno en la nube, desde el navegador, con Docker incluido; lección 4) o pedir a TI un servidor con Docker.
- **En producción**: los servidores de la empresa, Kubernetes o servicios en la nube ejecutan la **misma** imagen que probaste en casa.

## Primeros comandos

```powershell
docker run --rm python:3.12-slim python -c "import sys; print(sys.version)"
```

`docker` descarga la imagen oficial de Python (la primera vez), crea un contenedor, ejecuta el comando y, por `--rm`, lo borra al terminar.

| Comando | Qué hace |
|---|---|
| `docker pull postgres:16` | Descarga una imagen |
| `docker images` | Lista las imágenes locales |
| `docker run --rm -it python:3.12-slim bash` | Abre una terminal **dentro** de un contenedor nuevo |
| `docker run -d --name bd -p 5432:5432 -e POSTGRES_PASSWORD=x postgres:16` | Lanza PostgreSQL en segundo plano |
| `docker ps` / `docker ps -a` | Contenedores en ejecución / todos |
| `docker logs -f bd` | Ver la salida del contenedor |
| `docker exec -it bd psql -U postgres` | Ejecutar un comando en un contenedor que ya corre |
| `docker stop bd` / `docker rm bd` | Detener / borrar |
| `docker system df` / `docker system prune` | Espacio usado / limpiar lo que no se usa |

:::telco PostgreSQL en 10 segundos
Con la línea de `docker run ... postgres:16` de la tabla tienes un PostgreSQL real escuchando en `localhost:5432`, sin instalador ni configuración. Es lo que necesitabas para la prueba `test_en_postgresql` del módulo 17: `TELCO_DB_URL_PRUEBAS=postgresql+psycopg://postgres:x@localhost:5432/postgres`.
:::

:::consejo Las etiquetas importan
`python:latest` cambia cada vez que sale una versión: lo que hoy funciona, mañana puede no hacerlo. Usa siempre una etiqueta **concreta** (`python:3.12-slim`, `postgres:16`): es el archivo de bloqueo del sistema operativo.
:::

## Cuestionario

? ¿Cuál es la relación entre imagen y contenedor?
- [ ] Son lo mismo
- [x] La imagen es una plantilla inmutable; un contenedor es una ejecución de esa plantilla
- [ ] El contenedor se convierte en imagen al terminar
- [ ] La imagen corre dentro del contenedor
> Como una clase y sus objetos: de una imagen salen muchos contenedores.

? ¿Qué hace `--rm` en `docker run --rm ...`?
- [ ] Borra la imagen
- [x] Borra el contenedor cuando termina
- [ ] Borra los volúmenes
- [ ] Ejecuta como root
> Evita acumular contenedores detenidos después de tareas cortas.

? En la oficina no puedes instalar Docker. ¿Qué alternativa tienes?
- [ ] Ninguna
- [x] GitHub Codespaces, que ofrece un entorno con Docker en el navegador
- [ ] Instalar Docker en un entorno virtual
- [ ] Usar `pip install docker`
> `pip install docker` es solo un cliente de Python; el motor de Docker sí necesita instalación con permisos.
