## Enunciado

En facturación, mezclar pesos con porcentajes o con cantidades de minutos es un error clásico. Crea el objeto de valor `Dinero` (pesos colombianos enteros):

- `@dataclass(frozen=True, order=True)` con un atributo `pesos: int`. Al crearlo, `TypeError` si `pesos` no es `int` (cuidado: `bool` es subclase de `int` y tampoco vale).
- `a + b` y `a - b` entre `Dinero` → `Dinero`. Con cualquier otra cosa (`Dinero(5) + 5`) → `TypeError`.
- `a * n` con `n` entero → `Dinero`. Con decimales (`a * 1.19`) → `TypeError` (para eso está `porcentaje`).
- `porcentaje(p)` → `Dinero` con el `p` % del valor, redondeado al peso más cercano con 0,5 hacia arriba (`p` puede ser decimal, como `19` o `2.5`).
- `str(Dinero(1234567))` → `"$1.234.567"`; negativos: `"-$5.000"`.
- `Dinero.cero()` → `Dinero(0)`, y `sum(lista_de_dineros, Dinero.cero())` debe funcionar.

## Código inicial

```python
from dataclasses import dataclass


@dataclass(frozen=True, order=True)
class Dinero:
    pesos: int


subtotal = Dinero(135660)
print(subtotal, subtotal.porcentaje(19), subtotal + subtotal.porcentaje(19))
```

## Pista 2

- `@classmethod def cero(cls): return cls(0)`.
- Redondeo sin errores de punto flotante: `int(Decimal(self.pesos) * Decimal(str(p)) / 100 + Decimal("0.5"))` (ojo con los negativos si quieres ser muy estricto; aquí basta para positivos).
- El formato: `f"{abs(self.pesos):,}".replace(",", ".")` y el signo adelante del `$`.

## Solución

```python
from dataclasses import dataclass
from decimal import ROUND_HALF_UP, Decimal


@dataclass(frozen=True, order=True)
class Dinero:
    pesos: int

    def __post_init__(self):
        if type(self.pesos) is not int:
            raise TypeError(f"Dinero necesita pesos enteros, no {type(self.pesos).__name__}")

    @classmethod
    def cero(cls):
        return cls(0)

    def __add__(self, otro):
        if not isinstance(otro, Dinero):
            return NotImplemented
        return Dinero(self.pesos + otro.pesos)

    def __sub__(self, otro):
        if not isinstance(otro, Dinero):
            return NotImplemented
        return Dinero(self.pesos - otro.pesos)

    def __mul__(self, n):
        if type(n) is not int:
            return NotImplemented
        return Dinero(self.pesos * n)

    def porcentaje(self, p):
        valor = Decimal(self.pesos) * Decimal(str(p)) / 100
        return Dinero(int(valor.quantize(Decimal("1"), rounding=ROUND_HALF_UP)))

    def __str__(self):
        signo = "-" if self.pesos < 0 else ""
        return f"{signo}${abs(self.pesos):,}".replace(",", ".")


subtotal = Dinero(135660)
print(subtotal, subtotal.porcentaje(19), subtotal + subtotal.porcentaje(19))
```

## Explicación

`return NotImplemented` (no `raise`) es la forma correcta de decir "no sé operar con eso": Python prueba entonces la operación del otro lado (`5.__radd__`) y, si tampoco existe, lanza `TypeError` con un mensaje estándar.

`sum(lista, Dinero.cero())` funciona porque `sum` empieza con el valor inicial y va sumando con `+`. Sin el valor inicial, `sum` empezaría en `0` (un `int`) y `0 + Dinero(1)` fallaría: justo el tipo de mezcla que queríamos impedir.

`Decimal` con `ROUND_HALF_UP` hace el redondeo comercial **exacto**. Con `float`, `0.5` no siempre es exactamente `0.5` después de multiplicar, y `round()` de Python redondea al par (`round(2.5) == 2`). En dinero, esos centavos de diferencia en millones de facturas se notan en una auditoría.
