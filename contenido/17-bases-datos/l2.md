Un archivo plano acepta cualquier cosa: un CDR duplicado, una línea que no existe, una duración negativa. Una base de datos bien diseñada **rechaza** esos datos antes de que entren. Todo lo que tu validador revisaba a mano, la base de datos lo puede vigilar siempre.

Cada plan se escribe **una vez** en `planes`; los clientes solo guardan su `plan_id`. Si cambia el cargo fijo de un plan, se cambia en un solo lugar. Esto se llama **normalizar**.
:::
:::paso Claves primarias 🔑
La **clave primaria** identifica cada fila y no se puede repetir. Un segundo CDR con el mismo `cdr_id` es rechazado: los duplicados se vuelven **imposibles**.
:::
:::paso Claves foráneas 🔗
Una **clave foránea** dice "este valor debe existir en otra tabla". Un CDR de una línea que no está en `clientes` es rechazado: adiós a las líneas desconocidas.
:::
:::

```pyrun
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("PRAGMA foreign_keys = ON")      # en SQLite hay que activarlas (en PostgreSQL siempre lo están)
con.executescript("""
    CREATE TABLE planes (
        plan_id    TEXT PRIMARY KEY,
        cargo_fijo INTEGER NOT NULL CHECK (cargo_fijo > 0)
    );
    CREATE TABLE clientes (
        linea   TEXT PRIMARY KEY,
        plan_id TEXT NOT NULL REFERENCES planes (plan_id)
    );
    CREATE TABLE cdr (
        cdr_id       INTEGER PRIMARY KEY,
        linea_origen TEXT NOT NULL REFERENCES clientes (linea),
        tipo         TEXT NOT NULL CHECK (tipo IN ('VOZ', 'SMS', 'DATOS')),
        duracion_seg INTEGER NOT NULL CHECK (duracion_seg >= 0)
    );
    INSERT INTO planes VALUES ('BAS10', 25900);
    INSERT INTO clientes VALUES ('3001112233', 'BAS10');
""")

intentos = [
    (1, "3001112233", "VOZ", 125),    # bien
    (1, "3001112233", "VOZ", 125),    # duplicado
    (2, "3999999999", "VOZ", 60),     # línea desconocida
    (3, "3001112233", "FAX", 10),     # tipo inválido
    (4, "3001112233", "VOZ", -5),     # duración negativa
]
for cdr in intentos:
    try:
        con.execute("INSERT INTO cdr VALUES (?, ?, ?, ?)", cdr)
        print("✅", cdr)
    except sqlite3.IntegrityError as error:
        print("❌", cdr, "→", error)
```

| Restricción | Garantiza |
|---|---|
| `PRIMARY KEY` | Único y no nulo |
| `UNIQUE` | Sin repetidos (puede haber varias por tabla) |
| `NOT NULL` | Siempre tiene valor |
| `CHECK (condición)` | Regla de negocio |
| `REFERENCES tabla (col)` | El valor existe en la otra tabla |
| `DEFAULT valor` | Valor cuando no se indica |

:::reto Una tabla de facturas que se defiende
Crea la tabla `facturas` con estas reglas, para que la base de datos **rechace** los datos malos:

- `factura_id`: texto, clave primaria;
- `linea`: texto, obligatorio;
- `total`: entero, obligatorio y mayor o igual a 0;
- `estado`: texto, obligatorio, solo `PENDIENTE`, `PAGADA` o `ANULADA`, con `PENDIENTE` por defecto.

```pyreto
import sqlite3

con = sqlite3.connect(":memory:")

# CREATE TABLE facturas (...)

con.execute("INSERT INTO facturas (factura_id, linea, total) VALUES ('F1', '3001', 48719)")
print(con.execute("SELECT * FROM facturas").fetchall())
```

:::pista
`total INTEGER NOT NULL CHECK (total >= 0)` y `estado TEXT NOT NULL DEFAULT 'PENDIENTE' CHECK (estado IN ('PENDIENTE', 'PAGADA', 'ANULADA'))`.
:::

```pyprueba
import sqlite3


def _rechaza(sql):
    try:
        con.execute(sql)
    except sqlite3.IntegrityError:
        return True
    return False


def prueba_buena():
    """Una factura buena entra con estado PENDIENTE por defecto"""
    requiere("con")
    igual(con.execute("SELECT estado FROM facturas WHERE factura_id = 'F1'").fetchone(), ("PENDIENTE",))


def prueba_rechazos():
    """Rechaza duplicados, totales negativos, estados raros y nulos"""
    assert _rechaza("INSERT INTO facturas (factura_id, linea, total) VALUES ('F1', '3002', 100)"), "Debe rechazar un factura_id repetido"
    assert _rechaza("INSERT INTO facturas (factura_id, linea, total) VALUES ('F2', '3002', -5)"), "Debe rechazar un total negativo"
    assert _rechaza("INSERT INTO facturas VALUES ('F3', '3002', 100, 'PERDIDA')"), "Debe rechazar un estado desconocido"
    assert _rechaza("INSERT INTO facturas (factura_id, total) VALUES ('F4', 100)"), "Debe rechazar una factura sin línea"
```

:::error SQLite y las claves foráneas
Por compatibilidad histórica, SQLite **ignora** las claves foráneas si no ejecutas `PRAGMA foreign_keys = ON` en **cada conexión**. Es un error muy común creer que te protegen cuando están apagadas.
:::

:::reto Solo planes que existen
Las tablas `planes` y `clientes` ya están creadas, con la clave foránea `clientes.plan_id → planes.plan_id`. Escribe `agregar_cliente(con, linea, plan_id)`: intenta insertar el cliente y devuelve `True` si entró o `False` si la base de datos lo rechazó (sin detener el programa).

Ojo: si las claves foráneas no están activas en la conexión, un plan inexistente entraría sin problema.

```pyreto
import sqlite3


def crear_base():
    con = sqlite3.connect(":memory:")
    con.executescript("""
        CREATE TABLE planes (plan_id TEXT PRIMARY KEY);
        CREATE TABLE clientes (linea TEXT PRIMARY KEY, plan_id TEXT NOT NULL REFERENCES planes (plan_id));
        INSERT INTO planes VALUES ('HOG30'), ('ILIM');
    """)
    return con


def agregar_cliente(con, linea, plan_id):
    con.execute("INSERT INTO clientes VALUES (?, ?)", (linea, plan_id))
    return True


con = crear_base()
print(agregar_cliente(con, "3001", "HOG30"))    # True
print(agregar_cliente(con, "3002", "PLAN99"))   # False
```

:::pista
Activa las claves foráneas en `crear_base` con `con.execute("PRAGMA foreign_keys = ON")`. En `agregar_cliente`, envuelve el `INSERT` en `try` y devuelve `False` en `except sqlite3.IntegrityError`.
:::

```pyprueba
def prueba_acepta():
    """Un cliente con plan válido entra"""
    requiere("agregar_cliente", "crear_base")
    c = crear_base()
    igual(agregar_cliente(c, "3001", "HOG30"), True)
    igual(c.execute("SELECT COUNT(*) FROM clientes").fetchone()[0], 1)


def prueba_rechaza_plan():
    """Un plan inexistente se rechaza"""
    c = crear_base()
    igual(agregar_cliente(c, "3002", "PLAN99"), False, "plan inexistente")
    igual(c.execute("SELECT COUNT(*) FROM clientes").fetchone()[0], 0, "no debe quedar el cliente")


def prueba_rechaza_duplicado():
    """Una línea repetida se rechaza"""
    c = crear_base()
    agregar_cliente(c, "3001", "HOG30")
    igual(agregar_cliente(c, "3001", "ILIM"), False, "línea repetida")
```

## Índices: el índice del libro

Para encontrar los CDR de una línea entre 200 millones, sin índice la base de datos lee **todas** las filas. Un **índice** es una estructura ordenada (un árbol B) que le permite saltar directamente a ellas, como el índice al final de un libro.

```pyrun
import sqlite3, random, time

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE cdr (cdr_id INTEGER PRIMARY KEY, linea TEXT, duracion INTEGER)")
random.seed(1)
con.executemany("INSERT INTO cdr (linea, duracion) VALUES (?, ?)",
                ((f"300{random.randrange(100000):07d}", random.randrange(600)) for _ in range(300_000)))

def medir():
    inicio = time.perf_counter()
    for _ in range(200):
        con.execute("SELECT SUM(duracion) FROM cdr WHERE linea = ?", ("3000004242",)).fetchone()
    return (time.perf_counter() - inicio) / 200 * 1000

print(con.execute("EXPLAIN QUERY PLAN SELECT SUM(duracion) FROM cdr WHERE linea = '3000004242'").fetchall())
print(f"Sin índice: {medir():.2f} ms por consulta")
con.execute("CREATE INDEX ix_cdr_linea ON cdr (linea)")
print(con.execute("EXPLAIN QUERY PLAN SELECT SUM(duracion) FROM cdr WHERE linea = '3000004242'").fetchall())
print(f"Con índice: {medir():.3f} ms por consulta")
```

`EXPLAIN QUERY PLAN` muestra la estrategia: `SCAN` (leer todo) o `SEARCH ... USING INDEX` (saltar).

Los índices no son gratis: ocupan espacio y hacen más lentas las inserciones (cada `INSERT` actualiza también el índice). Crea índices para las columnas por las que **buscas, cruzas o filtras** con frecuencia, no para todas.

:::reto Haz que la consulta salte
La consulta de abajo busca las facturas de una línea y hoy recorre toda la tabla (`SCAN`). Crea el índice adecuado para que el plan diga `USING INDEX`, y guarda en `plan_despues` el texto del plan después de crearlo.

```pyreto
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE facturas (factura_id INTEGER PRIMARY KEY, linea TEXT, periodo TEXT, total INTEGER)")
con.executemany("INSERT INTO facturas (linea, periodo, total) VALUES (?, ?, ?)",
                [(f"300{i % 5000:07d}", "202609", i % 90000) for i in range(20000)])

CONSULTA = "SELECT SUM(total) FROM facturas WHERE linea = '3000004242'"
plan_antes = str(con.execute("EXPLAIN QUERY PLAN " + CONSULTA).fetchall())
print(plan_antes)

# Crea el índice y guarda plan_despues

print(plan_despues)
```

:::

def prueba_plan():
    """El plan usa el índice"""
    requiere("plan_despues")
    assert "USING INDEX" in plan_despues or "USING COVERING INDEX" in plan_despues, f"El plan todavía no usa un índice: {plan_despues}"


def prueba_indice():
    """Hay un índice sobre la columna linea"""
    requiere("con")
    indices = con.execute("SELECT name FROM sqlite_master WHERE type = 'index' AND tbl_name = 'facturas'").fetchall()
    columnas = [con.execute(f"PRAGMA index_info({n!r})").fetchall() for (n,) in indices]

## Transacciones: todo o nada

Una **transacción** agrupa varias operaciones que deben ocurrir juntas. Si una falla, se deshacen todas. Es la propiedad **A** (atomicidad) de **ACID**.

```pyrun
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE facturas (factura_id INTEGER PRIMARY KEY, total INTEGER CHECK (total >= 0))")
con.executemany("INSERT INTO facturas VALUES (?, ?)", [(1, 50000), (2, 30000)])
con.commit()

ajustes = [(1, -10000), (2, -40000)]          # el segundo dejaría un total negativo
try:
    with con:                                  # una transacción
        for factura, ajuste in ajustes:
            con.execute("UPDATE facturas SET total = total + ? WHERE factura_id = ?", (ajuste, factura))
except sqlite3.IntegrityError as e:
    print("Se deshizo todo:", e)

print(con.execute("SELECT * FROM facturas").fetchall())   # la factura 1 NO quedó a medias
```

| Letra | Propiedad | Significa |
|---|---|---|
| **A** | Atomicidad | Todo o nada |
| **C** | Consistencia | Las restricciones siempre se cumplen |
| **I** | Aislamiento | Las transacciones simultáneas no se pisan |
| **D** | Durabilidad | Lo confirmado sobrevive a un corte de luz |

:::reto Ajustes todo o nada
Escribe `aplicar_ajustes(con, ajustes)`: recibe una lista de pares `(factura_id, ajuste)` y los aplica **en una sola transacción**. Si alguno viola una regla, no debe quedar **ninguno** aplicado. Devuelve `True` si se aplicaron todos y `False` si se deshizo todo.

```pyreto
import sqlite3


def crear_base():
    con = sqlite3.connect(":memory:")
    con.execute("CREATE TABLE facturas (factura_id INTEGER PRIMARY KEY, total INTEGER CHECK (total >= 0))")
    con.executemany("INSERT INTO facturas VALUES (?, ?)", [(1, 50000), (2, 30000)])
    con.commit()
    return con


def aplicar_ajustes(con, ajustes):
    for factura, ajuste in ajustes:
        con.execute("UPDATE facturas SET total = total + ? WHERE factura_id = ?", (ajuste, factura))
    con.commit()
    return True


con = crear_base()
print(aplicar_ajustes(con, [(1, -10000), (2, -40000)]))   # False
print(con.execute("SELECT * FROM facturas").fetchall())   # [(1, 50000), (2, 30000)]
```

:::pista
Mete el `for` dentro de `with con:` (commit o rollback automático), y todo eso dentro de un `try` que devuelva `False` en `except sqlite3.IntegrityError`.
:::

```pyprueba
def prueba_todo():
    """Si todos son válidos, se aplican"""
    requiere("aplicar_ajustes", "crear_base")
    c = crear_base()
    igual(aplicar_ajustes(c, [(1, -10000), (2, 5000)]), True)
    igual(c.execute("SELECT total FROM facturas ORDER BY factura_id").fetchall(), [(40000,), (35000,)])


def prueba_nada():
    """Si uno falla, no queda ninguno"""
    c = crear_base()
    igual(aplicar_ajustes(c, [(1, -10000), (2, -40000)]), False)
    igual(c.execute("SELECT total FROM facturas ORDER BY factura_id").fetchall(), [(50000,), (30000,)], "la factura 1 no debe quedar a medias")
```

```pysolucion
import sqlite3


def crear_base():
    con = sqlite3.connect(":memory:")
    con.execute("CREATE TABLE facturas (factura_id INTEGER PRIMARY KEY, total INTEGER CHECK (total >= 0))")
    con.executemany("INSERT INTO facturas VALUES (?, ?)", [(1, 50000), (2, 30000)])
    con.commit()
    return con


def aplicar_ajustes(con, ajustes):

        with con:
            for factura, ajuste in ajustes:

    except sqlite3.IntegrityError:

    return True

print(aplicar_ajustes(con, [(1, -10000), (2, -40000)]))   # False
print(con.execute("SELECT * FROM facturas").fetchall())   # [(1, 50000), (2, 30000)]
```

:::telco Cargas que no quedan a medias
Si un proceso de carga se cae en el registro 6 millones de 10, ¿qué quedó en la tabla? Con una transacción por archivo, la respuesta es simple: o el archivo completo o nada, y puedes volver a ejecutarlo sin duplicar.
:::

## Cuestionario

? ¿Qué impide que se inserte un CDR de una línea que no existe en `clientes`?
- [ ] La clave primaria
- [x] Una clave foránea `REFERENCES clientes (linea)` (en SQLite, con `PRAGMA foreign_keys = ON`)
- [ ] Un índice
- [ ] `NOT NULL`
> La clave foránea exige que el valor exista en la tabla referenciada.

? ¿Cuándo conviene crear un índice?
- [ ] En todas las columnas, siempre
- [x] En columnas por las que filtras, buscas o cruzas con frecuencia
- [ ] Solo en tablas pequeñas
- [ ] Nunca en SQLite
> Aceleran las búsquedas, pero ocupan espacio y hacen más lentas las inserciones.

? Dentro de `with con:` el segundo de tres `UPDATE` viola un `CHECK`. ¿Qué queda en la tabla?
- [ ] El primer `UPDATE` aplicado
- [ ] Los tres, porque el error se ignora
- [x] Nada: la transacción se deshace completa
- [ ] El primero y el tercero
> Es la atomicidad: la transacción ocurre completa o no ocurre.
