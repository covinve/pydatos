## Enunciado

Vas a escribir tu "carta de navegación" del curso y guardarla con Git, como harías con cualquier cambio de un proyecto real.

1. Configura Git si no lo has hecho (`user.name` y `user.email`).
2. Crea el archivo `ejercicios/m01-e2/presentacion.md` con este contenido, adaptado a ti:

```markdown
# Mi ruta en PyDatos

## Quién soy
Una o dos líneas sobre tu trabajo.

## Qué quiero lograr
- Un objetivo concreto (por ejemplo: automatizar la validación de los CDR).
- Otro objetivo.
- Uno más.

## Mi horario de estudio
Cuándo vas a estudiar (por ejemplo: lunes a viernes, 7:00 a 9:00).
```

3. Revisa el estado con `git status`.
4. Prepara el archivo con `git add` y guárdalo con un `git commit` con un mensaje claro.
5. Sube el cambio a GitHub con `git push`.
6. Comprueba: `python comprobar.py m01-e2`.

Las pruebas revisan que Git esté configurado, que el archivo tenga un título y al menos tres objetivos, y que **esté guardado en un commit** sin cambios pendientes.

## Pista 1

Si la prueba dice que el archivo tiene cambios sin guardar, es porque lo editaste después del último commit. Ejecuta `git status`: si aparece en rojo o verde, falta `git add` y/o `git commit`.

## Pista 2

Los comandos, desde la carpeta raíz del curso:

```powershell
git add ejercicios/m01-e2/presentacion.md
git commit -m "Agrega mi presentación del curso"
git push
```

Si `git commit` dice *"Please tell me who you are"*, falta configurar `user.name` y `user.email`.

## Solución

```powershell
git config --global user.name "Tu Nombre"
git config --global user.email "tu-correo@ejemplo.com"
git status
git add ejercicios/m01-e2/presentacion.md
git commit -m "Agrega mi presentación del curso"
git push
python comprobar.py m01-e2
```

## Explicación

Acabas de hacer el ciclo completo que repetirás cientos de veces: **modificar → `git add` → `git commit` → `git push`**.

Fíjate en `git log --oneline`: tu commit aparece con un identificador corto (por ejemplo `a3f9c1e`) y tu mensaje. Si mañana borras el archivo por error, puedes recuperarlo con `git restore`.

Un hábito profesional: ejecuta `git status` antes de cada `add` y de cada `commit`. Te evita subir archivos que no querías.
