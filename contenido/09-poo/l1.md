Hasta ahora representabas un plan con un diccionario y escribías funciones que lo recibían. Funciona, pero nada impide que alguien escriba `plan["tarifa_minutos"]` (con una "s" de más) o que pase un cliente donde iba un plan. Una **clase** junta los datos y las operaciones que les corresponden.

## Tu primera clase

```pyrun
class Plan:
    def __init__(self, plan_id, cargo_fijo, minutos_incluidos, tarifa_minuto):
        self.plan_id = plan_id
        self.cargo_fijo = cargo_fijo
        self.minutos_incluidos = minutos_incluidos
        self.tarifa_minuto = tarifa_minuto

    def valor_voz(self, minutos):
        if self.minutos_incluidos == -1:
            return 0
        return max(0, minutos - self.minutos_incluidos) * self.tarifa_minuto


hogar = Plan("HOG30", 35900, 300, 120)
ilimitado = Plan("ILIM", 89900, -1, 0)

print(hogar.plan_id, hogar.cargo_fijo)
print(hogar.valor_voz(342))
print(ilimitado.valor_voz(5000))
```

| Concepto | En el ejemplo |
|---|---|
| **Clase**: el molde | `Plan` |
| **Objeto** o **instancia**: algo hecho con el molde | `hogar`, `ilimitado` |
| **Atributo**: un dato del objeto | `hogar.cargo_fijo` |
| **Método**: una función del objeto | `hogar.valor_voz(342)` |
| **`__init__`**: se ejecuta al crear el objeto | `Plan("HOG30", ...)` |

Por convención, las clases se nombran en `PalabrasConMayuscula` (*CamelCase*).

## ¿Qué es self?

`self` es **el objeto sobre el que se llamó el método**. Cuando escribes `hogar.valor_voz(342)`, Python llama a `Plan.valor_voz(hogar, 342)`: `self` es `hogar`.

```pytrace
class Contador:
    def __init__(self):
        self.total = 0

    def sumar(self, n):
        self.total = self.total + n

a = Contador()
b = Contador()
a.sumar(5)
a.sumar(3)
b.sumar(10)
print(a.total, b.total)
```

Cada objeto tiene **sus propios** atributos: `a.total` y `b.total` son independientes.

:::error Olvidar self
Dentro de un método, una variable sin `self.` es local y desaparece al terminar. `total = total + n` daría error; `self.total = self.total + n` modifica el atributo del objeto. Y todo método recibe `self` como primer parámetro, aunque no lo uses.
:::

## Atributos de clase

Un atributo definido directamente en la clase (fuera de `__init__`) es **compartido** por todos los objetos. Úsalo para constantes:

```pyrun
class Plan:
    ILIMITADO = -1                                # atributo de clase

    def __init__(self, plan_id, minutos_incluidos):
        self.plan_id = plan_id                    # atributo de instancia
        self.minutos_incluidos = minutos_incluidos

    def es_ilimitado(self):
        return self.minutos_incluidos == Plan.ILIMITADO


print(Plan("ILIM", -1).es_ilimitado(), Plan("HOG30", 300).es_ilimitado())
print(Plan.ILIMITADO)
```

## Objetos que cambian de estado

Un objeto puede guardar estado y modificarlo a lo largo del tiempo. Compara con el closure del módulo 5:

```pyrun
class BolsaDeMinutos:
    def __init__(self, incluidos):
        self.incluidos = incluidos
        self.usados = 0

    def consumir(self, segundos):
        self.usados += (segundos + 59) // 60

    def disponibles(self):
        return max(0, self.incluidos - self.usados)

    def exceso(self):
        return max(0, self.usados - self.incluidos)


bolsa = BolsaDeMinutos(300)
for llamada in [125, 3600, 14400]:
    bolsa.consumir(llamada)
    print(f"Usados {bolsa.usados}, disponibles {bolsa.disponibles()}, exceso {bolsa.exceso()}")
```

:::consejo ¿Clase o funciones?
No todo necesita una clase. Si solo tienes una función que transforma datos, una función basta. Las clases brillan cuando **varios datos y varias operaciones van siempre juntos** (un plan con sus tarifas y sus cálculos) o cuando un objeto tiene **estado** que cambia (una bolsa de minutos).
:::

:::telco El lenguaje del negocio en el código
`plan.valor_voz(minutos)` se lee como el negocio habla: "el valor de voz según el plan". Cuando el código usa los mismos conceptos que las personas de facturación (planes, bolsas, cargos), conversar sobre las reglas y encontrar errores se vuelve mucho más fácil.
:::
