Python trae muchas herramientas incluidas (la *biblioteca estándar*), pero lo más potente para datos viene en **librerías externas**: Pandas, NumPy, DuckDB, pytest… Se instalan con `pip`. La pregunta es: **¿dónde** se instalan?

## El problema: un solo Python para todo

Imagina que en la oficina tienes un script viejo que funciona con Pandas 1.5 y en este curso necesitas Pandas 3. Si ambos usan el mismo Python, actualizar uno rompe el otro.

## Crear el entorno (una sola vez por computador)

Desde la terminal de VS Code, dentro de la carpeta del curso:

```powershell
python -m venv .venv
```

Esto crea la carpeta `.venv` con una copia ligera de Python. Por convención se llama `.venv` (con punto) y **nunca se sube a Git**: cada computador crea el suyo.

## Activarlo (cada vez que abres la terminal)

```powershell
.venv\Scripts\Activate.ps1
```

Sabrás que funcionó porque la terminal muestra `(.venv)` al inicio:

```text
(.venv) PS D:\Carlos\pydatos>
```

:::error "La ejecución de scripts está deshabilitada"
PowerShell bloquea scripts por defecto. Ejecuta esto una sola vez; no necesita permisos de administrador:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

Si la política de tu empresa no lo permite, no pasa nada: puedes usar el Python del entorno sin activarlo, escribiendo la ruta completa: `.venv\Scripts\python archivo.py`.
:::

:::consejo Deja que VS Code lo active por ti
Pulsa `Ctrl + Shift + P`, escribe **Python: Select Interpreter** y elige el que dice `.venv`. Desde entonces, cada terminal nueva se abre con el entorno activado y el botón ▶ de VS Code usa ese Python.
:::

## Instalar librerías con pip

Con el entorno activo:

```powershell
python -m pip install pandas            # una librería
python -m pip install -r requirements.txt   # todas las del curso
python -m pip list                      # qué tengo instalado
python -m pip show pandas               # detalles de una librería
```

El archivo `requirements.txt` es la **lista de compras** del proyecto. Así cualquier computador (tu casa, la oficina, un servidor) puede instalar exactamente lo mismo.

:::capo ¿Por qué `python -m pip` y no solo `pip`?
`python -m pip` garantiza que usas el `pip` del mismo Python que vas a ejecutar. Con varios Python instalados, un `pip` suelto puede instalar las librerías en otro lado y luego no las encuentras.
:::

## ¿Estoy en el entorno correcto?

Este pequeño programa te dice qué Python se está usando. Ejecútalo aquí (verás el Python del navegador) y luego en tu terminal:

```pyrun
import sys

print("Versión:", sys.version.split()[0])
print("Ejecutable:", sys.executable)
en_venv = sys.prefix != sys.base_prefix
print("¿Dentro de un entorno virtual?", en_venv)
```

En tu computador, con el entorno activo, el ejecutable debe terminar en `.venv\Scripts\python.exe`.

## Genera tus primeros datos

Con todo instalado, crea el conjunto de datos de 10 MB que usarás en los próximos módulos:

```powershell
python herramientas/generar_datos.py --tamano 10MB
```

Revisa la carpeta `datos/10MB/`. Encontrarás planes, clientes, CDR, facturas y `esperado.json`. En la página **Referencia → Datos del curso** está la descripción de cada columna.

:::telco Entornos en producción
Cuando un proceso de facturación se programa en un servidor, se instala exactamente lo de `requirements.txt` en un entorno virtual limpio. Si el proceso funcionaba en tu PC pero falla en el servidor, casi siempre es porque faltó anotar una librería. Por eso se mantiene la lista desde el día uno.
:::

## Cuestionario

? ¿Qué problema resuelve un entorno virtual?
- [ ] Hace que Python se ejecute más rápido.
- [x] Permite que cada proyecto tenga sus propias librerías y versiones sin afectar a los demás.
- [ ] Permite ejecutar Python sin tenerlo instalado.
- [ ] Sube automáticamente el código a GitHub.
> Cada entorno es una carpeta con sus propias librerías. Así dos proyectos pueden usar versiones distintas de Pandas sin pelearse.

? Abriste una terminal nueva y no aparece `(.venv)` al inicio. ¿Qué pasa si ejecutas `python -m pip install duckdb`?
- [x] Se instala en el Python global, no en el entorno del curso.
- [ ] Da error porque no hay entorno activo.
- [ ] Se instala en el entorno del curso igual.
- [ ] Se instala en todos los entornos a la vez.
> Sin activar el entorno, `python` apunta al Python del sistema. La librería quedaría ahí y tu proyecto no la encontraría.

? ¿Por qué la carpeta `.venv` no se sube a Git?
- [ ] Porque es secreta.
- [ ] Porque Git no puede guardar carpetas.
- [x] Porque cada computador la recrea con `requirements.txt` y además pesa mucho.
- [ ] Porque GitHub la borra automáticamente.
> Lo que se versiona es la *receta* (`requirements.txt`), no el resultado. El entorno se reconstruye en segundos en cada máquina.
