## Enunciado

Las facturas llegan de dos sistemas y algunas aparecen **repetidas** (mismo `factura_id`, aunque con datos levemente distintos, por ejemplo la fecha de carga). Implementa la clase `Factura` (`factura_id`, `cliente_id`, `total`) de modo que:

1. Dos facturas son **iguales** si tienen el mismo `factura_id` (`__eq__`), y se pueden usar en **conjuntos** (`__hash__` coherente con `__eq__`).
2. Se **ordenan por total** (`__lt__`); con `@total_ordering` obtienes también `>`, `<=` y `>=`.
3. `__repr__` → `Factura('F1', 'CL1', 48719)`.

Y la función `consolidar(*listas)` → recibe varias listas de facturas y devuelve **una lista sin repetidas** (se conserva la **primera** aparición de cada `factura_id`), ordenada de **mayor a menor total**.

    """En un conjunto, las repetidas cuentan una vez"""

## Pista 1

```python
def __eq__(self, otra):
    if not isinstance(otra, Factura):
        return NotImplemented
    return self.factura_id == otra.factura_id

def __hash__(self):
    return hash(self.factura_id)
```

`NotImplemented` le dice a Python "no sé comparar con eso"; Python termina devolviendo `False` en vez de lanzar un error.

## Pista 2

Para conservar la **primera** aparición, recorre las listas en orden y usa un conjunto de IDs ya vistos (un conjunto de facturas también serviría, gracias a `__hash__`). Al final, `sorted(unicas, reverse=True)` usa tu `__lt__`.

## Solución

```python
from functools import total_ordering


@total_ordering
class Factura:
    def __init__(self, factura_id, cliente_id, total):
        self.factura_id = factura_id
        self.cliente_id = cliente_id
        self.total = total

    def __eq__(self, otra):
        if not isinstance(otra, Factura):
            return NotImplemented
        return self.factura_id == otra.factura_id

    def __hash__(self):
        return hash(self.factura_id)

    def __lt__(self, otra):
        if not isinstance(otra, Factura):
            return NotImplemented
        return self.total < otra.total

    def __repr__(self):
        return f"Factura({self.factura_id!r}, {self.cliente_id!r}, {self.total!r})"


def consolidar(*listas):
    vistas = set()
    unicas = []
    for lista in listas:
        for factura in lista:
            if factura not in vistas:
                vistas.add(factura)
                unicas.append(factura)
    return sorted(unicas, reverse=True)


sistema_a = [Factura("F1", "CL1", 48719), Factura("F2", "CL2", 160543)]
sistema_b = [Factura("F2", "CL2", 160500), Factura("F3", "CL3", 85573)]
print(consolidar(sistema_a, sistema_b))
```

## Explicación

Este diseño tiene una sutileza importante: **la igualdad es por ID, pero el orden es por total**. Es una decisión de negocio ("dos registros con el mismo ID son la misma factura"), y queda escrita en un solo lugar, la clase. Todo el resto del programa (conjuntos, `in`, `sorted`, `max`) la respeta automáticamente.

La regla de oro: si dos objetos son iguales (`a == b`), deben tener el mismo hash. Por eso `__hash__` usa exactamente el mismo dato que `__eq__`. Si usaras el total en el hash, dos facturas "iguales" podrían caer en lugares distintos del conjunto y no se detectarían como repetidas.
