Capturar errores es la mitad del trabajo. La otra mitad es **lanzar buenos errores**: que cuando algo falle, el mensaje diga exactamente qué y dónde.

## raise

```pyrun
def minutos_facturables(segundos):
    if segundos < 0:
        raise ValueError(f"La duración no puede ser negativa: {segundos}")
    return (segundos + 59) // 60


print(minutos_facturables(125))
print(minutos_facturables(-45))   # error esperado
```

:::comparar
:::mal Mensajes que no ayudan
```python
raise ValueError("Error")
raise ValueError("Dato inválido")
```
:::
:::bien Mensajes que dicen qué, dónde y qué se esperaba
```python
raise ValueError(f"Línea {n}: duración '{texto}' no es un entero")
raise KeyError(f"Plan '{plan_id}' no existe en planes.csv")
```

## Excepciones propias

Crear tu propia excepción permite que quien llama la distinga de los errores de Python. Basta con una línea (las clases se ven en el módulo 9):

```pyrun
class ErrorDeFacturacion(Exception):
    """Error en una regla de negocio de facturación."""


class PlanInexistente(ErrorDeFacturacion):
    """El plan del cliente no está en el catálogo."""


PLANES = {"HOG30": 35900}


def cargo_fijo(plan_id):
    if plan_id not in PLANES:
        raise PlanInexistente(f"El plan '{plan_id}' no existe")
    return PLANES[plan_id]


try:
    cargo_fijo("PLAN99")
except ErrorDeFacturacion as error:      # atrapa también las subclases
    print(type(error).__name__, "→", error)
```

### Excepciones con datos

Una excepción es un objeto y puede llevar información útil, no solo un mensaje:

```pyrun
class ErrorDeRegistro(Exception):
    def __init__(self, numero_linea, campo, valor):
        self.numero_linea = numero_linea
        self.campo = campo
        self.valor = valor
        super().__init__(f"Línea {numero_linea}, campo {campo}: valor inválido {valor!r}")


try:
    raise ErrorDeRegistro(1534, "duracion_seg", "abc")
except ErrorDeRegistro as e:
    print(e)
    print("Para el reporte:", e.numero_linea, e.campo)
```

## raise ... from: encadenar errores

Cuando conviertes un error de bajo nivel en uno tuyo, usa `from` para conservar la causa original:

```pyrun
class ErrorDeRegistro(Exception):
    pass


def leer_duracion(numero, texto):
    try:
        return int(texto)
    except ValueError as e:
        raise ErrorDeRegistro(f"Línea {numero}: duración inválida {texto!r}") from e


leer_duracion(7, "1,5")   # error esperado
```

El traceback muestra **las dos** excepciones: la tuya, con el contexto de negocio, y la original, con el detalle técnico.

## Volver a lanzar

A veces quieres registrar el error y dejar que siga subiendo. Un `raise` solo, dentro de un `except`, relanza la misma excepción:

```python
try:
    procesar_archivo(ruta)
except OSError:
    print(f"No se pudo procesar {ruta}")
    raise
```

## Pedir perdón o pedir permiso

Hay dos estilos para manejar casos problemáticos:

:::columnas
:::columna LBYL: mira antes de saltar
```python
if texto.isdigit():
    segundos = int(texto)
else:
    segundos = None
```
Comprueba antes. Claro, pero `isdigit()` falla con `"-45"` aunque sea un entero válido.
:::
:::columna EAFP: pide perdón
```python
try:
    segundos = int(texto)
except ValueError:
    segundos = None
```
Intenta y maneja el error. Es el estilo más común en Python: deja que `int` decida qué es un entero.
:::
:::

En Python se prefiere **EAFP** (*Easier to Ask Forgiveness than Permission*) cuando la comprobación previa duplicaría la lógica de la operación.

## assert no es para validar datos

`assert condicion, "mensaje"` lanza `AssertionError` si la condición es falsa. Úsalo para **verificar supuestos de tu propio código** y en las pruebas (módulo 10), **nunca** para validar datos de entrada: Python puede ejecutarse con `-O`, que desactiva todos los `assert`.

:::telco Errores que cuentan una historia
"ValueError: invalid literal for int()" a las 3 de la mañana no le dice nada a quien está de turno. "Archivo cdr_20260930.csv, línea 1.534.221, campo duracion_seg: 'abc' no es un entero" le dice exactamente dónde mirar. La diferencia está en lanzar buenos errores.
:::
