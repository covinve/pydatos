## Enunciado

Llegó el momento de trabajar con un archivo de verdad. En `ejercicios/m06-e4/ancho_fijo.py` completa la función `resumir(ruta)` que recorre un archivo de CDR en **ancho fijo** y devuelve:

| Clave | Contenido |
|---|---|
| `"registros"` | Cantidad de registros |
| `"por_tipo"` | Diccionario `tipo → cantidad` (tipo sin espacios, tal como viene), ordenado por tipo |
| `"minutos_voz"` | Suma de minutos facturables de los registros `VOZ` con duración mayor o igual a 0 |
| `"mb_datos"` | Suma de megas de los registros `DATOS`, redondeada a 3 decimales |

El diseño del registro está en el diccionario `DISENO` del archivo (y en Referencia → Datos del curso).

**Paso 1 · Con la muestra.** Comprueba tu función con el archivo pequeño que viene en la carpeta:

```powershell
python comprobar.py m06-e4
```

**Paso 2 · Con 1 GB.** Genera el archivo grande y procésalo (toma un par de minutos):

```powershell
python herramientas/generar_datos.py --tamano 1GB --formato ancho
python ejercicios/m06-e4/ancho_fijo.py datos/1GB/cdr_ancho_fijo.txt
```

Abre el **Administrador de tareas** mientras corre: la memoria de Python debe mantenerse en unos pocos MB aunque el archivo pese más de 1 GB. Compara `registros` con `registros_totales` de `datos/1GB/esperado.json`.

:::consejo Anota tus tiempos
Escribe en un comentario al final del archivo cuántos segundos tardó con 1 GB. En los módulos 11, 12 y 16 procesarás el mismo archivo con técnicas cada vez más rápidas y podrás comparar.

## Pista 1

La estructura es la de la lección 1: abrir con `with`, recorrer con `for` y acumular. Para cada línea, corta los campos con el slicing del diseño (`linea[inicio - 1:fin]`):

```python
with open(ruta, encoding="utf-8") as archivo:
    for linea in archivo:
        tipo = linea[35:40].strip()
        ...
```

## Pista 2

Recuerda convertir: `int(linea[67:73])` para la duración (acepta el signo menos) y `float(linea[73:83])` para las megas. Para el diccionario ordenado: `dict(sorted(por_tipo.items()))`.

Las pruebas prohíben `.read()`, `.readlines()` y `.read_text()`: son justamente las que cargarían el gigabyte entero en memoria.

## Solución

```python ancho_fijo.py
"""Ejercicio m06-e4: resumir un archivo de CDR en ancho fijo de cualquier tamaño.

Uso:
    python ejercicios/m06-e4/ancho_fijo.py                                   # usa la muestra
    python ejercicios/m06-e4/ancho_fijo.py datos/1GB/cdr_ancho_fijo.txt      # archivo grande
"""

import sys
import time
from collections import Counter
from pathlib import Path

# (posición inicial, posición final) desde 1 e incluidas, según Referencia → Datos del curso
DISENO = {
    "cdr_id": (1, 12),
    "linea_origen": (13, 22),
    "tipo": (36, 40),
    "duracion_seg": (68, 73),
    "mb": (74, 83),
}


def corte(campo: str) -> slice:
    inicio, fin = DISENO[campo]
    return slice(inicio - 1, fin)


def resumir(ruta: Path) -> dict:
    tipo_c, duracion_c, mb_c = corte("tipo"), corte("duracion_seg"), corte("mb")
    registros = 0
    por_tipo = Counter()
    minutos_voz = 0
    mb_datos = 0.0
    with open(ruta, encoding="utf-8") as archivo:
        for linea in archivo:
            registros += 1
            tipo = linea[tipo_c].strip()
            por_tipo[tipo] += 1
            if tipo == "VOZ":
                duracion = int(linea[duracion_c])
                if duracion >= 0:
                    minutos_voz += (duracion + 59) // 60
            elif tipo == "DATOS":
                mb_datos += float(linea[mb_c])
    return {
        "registros": registros,
        "por_tipo": dict(sorted(por_tipo.items())),
        "minutos_voz": minutos_voz,
        "mb_datos": round(mb_datos, 3),
    }


if __name__ == "__main__":
    ruta = Path(sys.argv[1]) if len(sys.argv) > 1 else Path(__file__).parent / "muestra_ancho_fijo.txt"
    inicio = time.perf_counter()
    resultado = resumir(ruta)
    segundos = time.perf_counter() - inicio
    tamano_mb = ruta.stat().st_size / 1_000_000
    print(resultado)
    print(f"{tamano_mb:,.0f} MB procesados en {segundos:.1f} s ({tamano_mb / segundos:,.0f} MB/s)")
```

## Explicación

Con Python puro, un archivo de 1 GB se procesa en uno o dos minutos, usando **unos pocos megas de memoria**. La clave es que lo único que crece es `por_tipo`, que tiene seis claves.

Dos detalles de rendimiento:

- **`slice(inicio - 1, fin)`** se calcula una sola vez, fuera del bucle. `linea[tipo_c]` funciona igual que `linea[35:40]`, pero el diseño sigue viviendo en `DISENO`.
- **Convertir solo lo necesario.** La duración se convierte solo en los registros de voz y las megas solo en los de datos. Con 14 millones de registros, cada conversión innecesaria suma segundos.

¿Y si el archivo fuera de 20 GB? Este mismo código funciona, solo que tarda unas 20 veces más. En el módulo 16 harás lo mismo con DuckDB y Polars en una fracción del tiempo, y entenderás por qué son tan rápidos.
