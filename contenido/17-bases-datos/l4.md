Insertar 100 millones de CDR uno por uno, con un `commit` por fila, puede tardar **días**. Con las técnicas de esta lección, minutos. La diferencia está en cuántas veces le pides algo a la base de datos y cuántas veces la obligas a escribir en disco.

## Las cuatro reglas de la carga rápida

```pyrun
import sqlite3, time, os

filas = [(i, f"300{i % 5000:07d}", "VOZ", i % 600) for i in range(60_000)]

def nueva():
    if os.path.exists("prueba.db"):
        os.remove("prueba.db")
    con = sqlite3.connect("prueba.db")
    con.execute("CREATE TABLE cdr (cdr_id INTEGER PRIMARY KEY, linea TEXT, tipo TEXT, dur INTEGER)")
    return con

con = nueva(); inicio = time.perf_counter()
for fila in filas[:500]:                                   # ❌ commit por fila (solo 500, ¡es lentísimo!)
    con.execute("INSERT INTO cdr VALUES (?, ?, ?, ?)", fila); con.commit()
t = time.perf_counter() - inicio
print(f"Commit por fila:      {t / 500 * 60000:6.2f} s estimados para 60 000")
con.close()

con = nueva(); inicio = time.perf_counter()
with con:                                                  # ✅ una transacción
    for fila in filas:
        con.execute("INSERT INTO cdr VALUES (?, ?, ?, ?)", fila)
print(f"Una transacción:      {time.perf_counter() - inicio:6.2f} s")
con.close()

con = nueva(); inicio = time.perf_counter()
with con:                                                  # ✅✅ executemany
    con.executemany("INSERT INTO cdr VALUES (?, ?, ?, ?)", filas)
print(f"executemany:          {time.perf_counter() - inicio:6.2f} s")
con.close()
os.remove("prueba.db")
```

:::pasos Reglas
:::paso 1. Pocas transacciones
Cada `commit` obliga a escribir en disco de forma segura (lento). Confirma por **lotes** grandes (100 000 filas) o un archivo completo.
:::
:::paso 2. Pocas llamadas
`executemany(sql, filas)` envía muchas filas en una sola llamada. Pásale un **generador** o lotes de `itertools.batched` para no tener todo en memoria.
:::
:::paso 3. Índices al final
Mantener un índice actualizado durante la carga es caro. Para cargas iniciales grandes: carga primero y **crea los índices después**.
:::
:::paso 4. Usa la herramienta nativa
Cada base tiene su cargador masivo: `COPY` en PostgreSQL, `bcp` en SQL Server, `SQL*Loader` en Oracle, y DuckDB puede escribir directo en SQLite y PostgreSQL. Son 5 a 50 veces más rápidos que `INSERT`.
:::
:::

## Cargar por lotes desde un archivo

```python
import csv
import sqlite3
from itertools import batched          # Python 3.12+

def cargar(ruta_csv, con, lote=100_000):
    with open(ruta_csv, encoding="utf-8", newline="") as f:
        lector = csv.reader(f, delimiter="|")
        next(lector)                                    # cabecera
        for grupo in batched(lector, lote):
            with con:                                   # una transacción por lote
                con.executemany("INSERT INTO cdr VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)", grupo)
```

Memoria constante, una transacción cada 100 000 filas y una llamada por lote.

## Cargas que se pueden repetir

Si la carga falla a la mitad y la vuelves a ejecutar, ¿se duplican los registros? Una carga **idempotente** da el mismo resultado si la ejecutas una o diez veces. La clave primaria más una de estas instrucciones lo logra:

| Instrucción | Si la clave ya existe |
|---|---|
| `INSERT INTO ...` | Error (`IntegrityError`) |
| `INSERT OR IGNORE INTO ...` (SQLite) / `ON CONFLICT DO NOTHING` | La fila nueva se descarta |
| `INSERT ... ON CONFLICT (clave) DO UPDATE SET ...` | Se actualiza la existente (**upsert**) |

```pyrun
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE clientes (linea TEXT PRIMARY KEY, plan_id TEXT, actualizado TEXT)")
SQL = """
    INSERT INTO clientes (linea, plan_id, actualizado) VALUES (?, ?, ?)
    ON CONFLICT (linea) DO UPDATE SET plan_id = excluded.plan_id, actualizado = excluded.actualizado
"""
con.executemany(SQL, [("3001", "BAS10", "2026-09-01"), ("3002", "HOG30", "2026-09-01")])
con.executemany(SQL, [("3002", "HOG60", "2026-10-01"), ("3003", "ILIM", "2026-10-01")])   # cambio de plan + cliente nuevo
print(con.execute("SELECT * FROM clientes ORDER BY linea").fetchall())
```

`excluded` es la fila que se intentó insertar. Esto es exactamente lo que necesitas para cargar cada mes el maestro de clientes: los nuevos se agregan y los que cambiaron de plan se actualizan.

:::reto Cargas que se pueden repetir
Escribe dos cargas idempotentes:

- `cargar_cdr(con, filas)`: inserta CDR `(cdr_id, tipo)`; si el `cdr_id` ya existe, **ignora** la fila nueva.
- `cargar_planes(con, filas)`: inserta precios `(plan_id, cargo_fijo)`; si el plan ya existe, **actualiza** su cargo (upsert).

Ejecutar cada carga dos veces debe dejar el mismo resultado que una.

```pyreto
import sqlite3


def nueva_base():
    con = sqlite3.connect(":memory:")
    con.executescript("""
        CREATE TABLE cdr (cdr_id INTEGER PRIMARY KEY, tipo TEXT);
        CREATE TABLE planes (plan_id TEXT PRIMARY KEY, cargo_fijo INTEGER);
    """)
    return con


def cargar_cdr(con, filas):
    with con:
        con.executemany("INSERT INTO cdr VALUES (?, ?)", filas)


def cargar_planes(con, filas):
    with con:
        con.executemany("INSERT INTO planes VALUES (?, ?)", filas)


con = nueva_base()
cargar_cdr(con, [(1, "VOZ"), (2, "SMS")])
cargar_cdr(con, [(2, "SMS"), (3, "DATOS")])          # el 2 ya estaba
cargar_planes(con, [("HOG30", 35900)])
cargar_planes(con, [("HOG30", 37900), ("ILIM", 89900)])   # HOG30 cambió de precio
print(con.execute("SELECT * FROM cdr").fetchall(), con.execute("SELECT * FROM planes ORDER BY plan_id").fetchall())
```

:::pista
Para los CDR: `INSERT OR IGNORE INTO cdr VALUES (?, ?)` (o `... ON CONFLICT DO NOTHING`). Para los planes: `INSERT INTO planes VALUES (?, ?) ON CONFLICT (plan_id) DO UPDATE SET cargo_fijo = excluded.cargo_fijo`.
:::

```pyprueba
def prueba_cdr():
    """Los CDR repetidos se ignoran"""
    requiere("cargar_cdr", "nueva_base")
    c = nueva_base()
    for _ in range(2):
        cargar_cdr(c, [(1, "VOZ"), (2, "SMS")])
    cargar_cdr(c, [(2, "OTRO"), (3, "DATOS")])
    igual(c.execute("SELECT * FROM cdr ORDER BY cdr_id").fetchall(), [(1, "VOZ"), (2, "SMS"), (3, "DATOS")])


def prueba_planes():
    """Los planes existentes se actualizan"""
    requiere("cargar_planes")
    c = nueva_base()
    cargar_planes(c, [("HOG30", 35900)])
    for _ in range(2):
        cargar_planes(c, [("HOG30", 37900), ("ILIM", 89900)])
    igual(c.execute("SELECT * FROM planes ORDER BY plan_id").fetchall(), [("HOG30", 37900), ("ILIM", 89900)])
```

```pysolucion
import sqlite3


def nueva_base():
    con = sqlite3.connect(":memory:")
    con.executescript("""
        CREATE TABLE cdr (cdr_id INTEGER PRIMARY KEY, tipo TEXT);
        CREATE TABLE planes (plan_id TEXT PRIMARY KEY, cargo_fijo INTEGER);
    """)

    with con:
        con.executemany("INSERT OR IGNORE INTO cdr VALUES (?, ?)", filas)

```

## DuckDB como cargador

DuckDB lee el CSV en paralelo y puede escribir directamente en una base SQLite (o PostgreSQL con la extensión `postgres`):

```python
import duckdb

duckdb.sql("""
    INSTALL sqlite; LOAD sqlite;
    ATTACH 'telco.db' AS bd (TYPE sqlite);
    CREATE TABLE bd.cdr AS SELECT * FROM read_csv('datos/1GB/cdr.csv', delim='|', header=true);
""")
```

## COPY en PostgreSQL

```python
import psycopg

with psycopg.connect(url) as con, con.cursor() as cur:
    with open("cdr.csv", "rb") as f, cur.copy("COPY cdr FROM STDIN (FORMAT csv, DELIMITER '|', HEADER true)") as copia:
        while bloque := f.read(1024 * 1024):
            copia.write(bloque)
```

`COPY` envía el archivo como un flujo y PostgreSQL lo carga sin interpretar instrucción por instrucción. Es la forma estándar de cargar los 20 GB.

:::telco Una carga de producción
Una carga mensual robusta de CDR suele ser: tabla de **paso** (*staging*) sin restricciones → carga masiva con `COPY` → validación con SQL (como tu validador del módulo 16) → `INSERT ... SELECT` de los válidos a la tabla definitiva con `ON CONFLICT DO NOTHING` → rechazos a su propia tabla, todo con un registro de cuántas filas entraron en cada paso.
:::
