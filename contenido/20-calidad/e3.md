## Enunciado

El módulo `configuracion.py` (ya está en tu carpeta) lee la configuración del entorno:

- `carpeta_datos()` → `Path` de la variable `TELCO_DATOS`, o `Path("datos")` si no existe.
- `token()` → el valor de `TELCO_API_TOKEN`; si no existe **o está vacío**, lanza `RuntimeError`.
- `umbral_rechazo()` → `float` de `TELCO_UMBRAL`, por defecto `5.0`; si no es un número, lanza `ValueError` con un mensaje que incluye el valor recibido.

**Escribe sus pruebas** con el *fixture* `monkeypatch` de pytest (`setenv`, `delenv`). Al menos **5** pruebas. Cuidado: tus pruebas no deben depender de las variables que existan en el computador donde corren.

## Preparación

```python
from pathlib import Path

Path("configuracion.py").write_text('''
import os
from pathlib import Path


def carpeta_datos():
    return Path(os.environ.get("TELCO_DATOS", "datos"))


def token():
    valor = os.environ.get("TELCO_API_TOKEN", "")
    if not valor:
        raise RuntimeError("Define la variable de entorno TELCO_API_TOKEN")
    return valor


def umbral_rechazo():
    texto = os.environ.get("TELCO_UMBRAL", "5.0")
    try:
        return float(texto)
    except ValueError:
        raise ValueError(f"TELCO_UMBRAL debe ser un número, no {texto!r}") from None
''', encoding="utf-8")
```

## Pista 2

Para el mensaje del error: `with pytest.raises(ValueError, match="abc"):` verifica que el mensaje contenga el texto. Y recuerda borrar (con `delenv(..., raising=False)`) las variables que **no** quieres que existan en cada prueba: la última comprobación del curso define todas antes de correr tus pruebas.

## Solución

```python
from pathlib import Path

import pytest

import configuracion


def test_carpeta_por_defecto(monkeypatch):
    monkeypatch.delenv("TELCO_DATOS", raising=False)
    assert configuracion.carpeta_datos() == Path("datos")


def test_carpeta_desde_entorno(monkeypatch):
    monkeypatch.setenv("TELCO_DATOS", "D:/cdr")
    assert configuracion.carpeta_datos() == Path("D:/cdr")


def test_token(monkeypatch):
    monkeypatch.setenv("TELCO_API_TOKEN", "abc123")
    assert configuracion.token() == "abc123"


@pytest.mark.parametrize("valor", [None, ""])
def test_token_faltante_o_vacio(monkeypatch, valor):
    if valor is None:
        monkeypatch.delenv("TELCO_API_TOKEN", raising=False)
    else:
        monkeypatch.setenv("TELCO_API_TOKEN", valor)
    with pytest.raises(RuntimeError):
        configuracion.token()


def test_umbral_por_defecto(monkeypatch):
    monkeypatch.delenv("TELCO_UMBRAL", raising=False)
    assert configuracion.umbral_rechazo() == 5.0


def test_umbral_desde_entorno(monkeypatch):
    monkeypatch.setenv("TELCO_UMBRAL", "2.5")
    assert configuracion.umbral_rechazo() == 2.5


def test_umbral_invalido(monkeypatch):
    monkeypatch.setenv("TELCO_UMBRAL", "cinco")
    with pytest.raises(ValueError, match="cinco"):
        configuracion.umbral_rechazo()
```

## Explicación

`monkeypatch` cambia el entorno **solo durante la prueba** y lo restaura al terminar, aunque la prueba falle. Sin él, `os.environ["TELCO_API_TOKEN"] = "x"` en una prueba contaminaría a las siguientes, y el resultado dependería del orden en que pytest las ejecute.

La comprobación "independientes del entorno" es la lección más importante: una prueba que pasa en tu computador porque **tú** tienes `TELCO_UMBRAL` definido y falla en GitHub Actions (donde no existe) es una de las fuentes más comunes de "en mi máquina funciona". Cada prueba debe fijar **todo** el entorno que le importa: lo que debe existir, con `setenv`; lo que no debe existir, con `delenv(..., raising=False)`.

`parametrize` sobre `[None, ""]` cubre con una sola prueba los dos caminos del `if not valor`: la variable ausente y la variable vacía.
