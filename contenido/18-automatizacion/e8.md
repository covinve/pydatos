## Enunciado

Ahora con `requests` de verdad. Las pruebas levantan un **servidor HTTP local** que imita la API de facturación, incluidos sus malos días: errores 503, límites de peticiones (429 con `Retry-After`), respuestas lentas y tokens inválidos.

Completa la clase `ClienteAPI` en `ejercicios/m18-e8/cliente_api.py`. El docstring de la clase describe las reglas comunes (token, sesión, *timeout*, reintentos) y cada método describe su petición:

| Método | Petición | Particularidad |
|---|---|---|
| `tarifa(plan_id)` | `GET /tarifas/{plan_id}` | 404 → `LookupError` |
| `consumos(periodo, tamano)` | `GET /consumos?periodo&pagina&tamano` | Generador, paginación por número |
| `registrar_ajuste(...)` | `POST /ajustes` | Clave de idempotencia |

Este ejercicio junta todo el módulo: lo que hiciste en los ejercicios 4 y 5, pero contra una red real.

## Pista 1

Concentra **todo** lo común en un método privado, y que los métodos públicos solo armen la petición:

```python
def _pedir(self, metodo, ruta, **kwargs):
    url = f"{self.url_base}{ruta}"
    for intento in range(self.intentos):
        espera = self.base * 2 ** intento
        try:
            r = self.sesion.request(metodo, url, timeout=self.timeout, **kwargs)
        except (requests.ConnectionError, requests.Timeout):
            if intento == self.intentos - 1:
                raise
        else:
            ...
        self.dormir(espera)
```

## Pista 2

Dentro del `else`:

- `401`/`403` → `raise PermissionError(...)`.
- No transitorio (ni 429 ni 5xx) → `return r` (el método público decide qué hacer con un 404).
- Transitorio en el último intento → `r.raise_for_status()`.
- 429 con `Retry-After` → `espera = float(r.headers["Retry-After"])`.

Para el POST: `self._pedir("POST", "/ajustes", json={...}, headers={"Idempotency-Key": clave})`.

## Solución

```python cliente_api.py
"""Ejercicio m18-e8: un cliente de verdad para la API de tarifas y consumos.

Las pruebas levantan un servidor HTTP local que se comporta como la API real (incluidos sus fallos).
"""

from __future__ import annotations

import os
import time
from collections.abc import Callable, Iterator

import requests


class ClienteAPI:
    """Cliente de la API de facturación.

    - token: si es None, se lee de la variable de entorno TELCO_API_TOKEN; si no hay, ValueError.
    - Todas las peticiones usan una requests.Session con la cabecera "Authorization: Bearer <token>"
      y timeout=self.timeout.
    - Reintentos (hasta `intentos` llamadas en total) ante requests.ConnectionError, requests.Timeout,
      estado 429 o 5xx, esperando con self.dormir(segundos): Retry-After si el 429 lo trae;
      si no, base * 2**n (n = número de reintento, empezando en 0). Si se agotan: se relanza la
      excepción o se llama raise_for_status() sobre la última respuesta.
    - 401 o 403 → PermissionError inmediatamente (sin reintentar).
    """

    def __init__(self, url_base: str, token: str | None = None, timeout: float = 10, intentos: int = 4,
                 base: float = 1.0, dormir: Callable[[float], None] = time.sleep):
        token = token or os.environ.get("TELCO_API_TOKEN")
        if not token:
            raise ValueError("Falta el token: pásalo o define la variable de entorno TELCO_API_TOKEN")
        self.url_base = url_base.rstrip("/")
        self.timeout = timeout
        self.intentos = intentos
        self.base = base
        self.dormir = dormir
        self.sesion = requests.Session()
        self.sesion.headers["Authorization"] = f"Bearer {token}"
        self.sesion.headers["User-Agent"] = "curso-pydatos/1.0"

    def _pedir(self, metodo: str, ruta: str, **kwargs) -> requests.Response:
        url = f"{self.url_base}{ruta}"
        for intento in range(self.intentos):
            ultimo = intento == self.intentos - 1
            espera = self.base * 2 ** intento
            try:
                r = self.sesion.request(metodo, url, timeout=self.timeout, **kwargs)
            except (requests.ConnectionError, requests.Timeout):
                if ultimo:
                    raise
            else:
                if r.status_code in (401, 403):
                    raise PermissionError(f"{r.status_code} en {ruta}: revisa el token y sus permisos")
                if r.status_code != 429 and r.status_code < 500:
                    return r
                if ultimo:
                    r.raise_for_status()
                if r.status_code == 429 and "Retry-After" in r.headers:
                    espera = float(r.headers["Retry-After"])
            self.dormir(espera)
        raise AssertionError("inalcanzable")

    def tarifa(self, plan_id: str) -> dict:
        r = self._pedir("GET", f"/tarifas/{plan_id}")
        if r.status_code == 404:
            raise LookupError(f"No existe la tarifa del plan {plan_id}")
        r.raise_for_status()
        return r.json()

    def consumos(self, periodo: str, tamano: int = 20) -> Iterator[dict]:
        pagina = 1
        while True:
            r = self._pedir("GET", "/consumos", params={"periodo": periodo, "pagina": pagina, "tamano": tamano})
            r.raise_for_status()
            cuerpo = r.json()
            yield from cuerpo["datos"]
            if pagina >= cuerpo["total_paginas"]:
                return
            pagina += 1

    def registrar_ajuste(self, factura_id: str, valor: int, motivo: str) -> dict:
        r = self._pedir(
            "POST", "/ajustes",
            json={"factura_id": factura_id, "valor": valor, "motivo": motivo},
            headers={"Idempotency-Key": f"{factura_id}:{valor}:{motivo}"},
        )
        r.raise_for_status()
        return r.json()
```

## Explicación

`_pedir` es el corazón: **una sola** implementación de autenticación, *timeout*, reintentos y manejo de errores, usada por todos los métodos. Si mañana la API cambia el límite de peticiones o agregas un registro de cada llamada, lo cambias en un lugar.

La prueba del ajuste muestra por qué la **idempotencia** importa en APIs. El servidor recibió el primer POST y registró el ajuste, pero la respuesta "se perdió" (503). Tu cliente no puede saber si el ajuste quedó o no, así que reintenta. Sin la clave `Idempotency-Key`, el cliente tendría el ajuste **dos veces** en su factura. Con ella, el servidor reconoce el reintento y no lo duplica. (Por eso el cliente solo reintenta POST con clave; en tu trabajo, pregunta si la API las soporta antes de reintentar escrituras.)

Para usarlo en la oficina:

```python
cliente = ClienteAPI("https://api-interna.empresa.com/v1")   # token desde TELCO_API_TOKEN
for consumo in cliente.consumos("202609", tamano=500):
    ...
```

:::consejo Proxies corporativos
Muchas empresas salen a internet por un **proxy**. `requests` respeta las variables `HTTPS_PROXY` y `NO_PROXY`; si una API interna falla con errores de conexión que en casa no ves, pregunta a TI por la configuración del proxy. Y si ves errores de certificado (`SSLError`), **no** uses `verify=False`: pide el certificado raíz de la empresa y usa `verify="ruta/al/certificado.pem"`.
:::
