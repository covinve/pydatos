## Enunciado

Escribe con **pydantic-settings** la configuración que usará tu pipeline del proyecto final. El docstring de `ejercicios/m21-e7/config_pipeline.py` define cada campo con su tipo, valor por defecto y regla de validación, más dos piezas:

- `resumen()`: los valores listos para mostrar, **con el secreto oculto**;
- `cargar(env_file=".env", **sobrescritos)`: la forma de crearla desde la CLI (los `None` no cuentan).

Las pruebas trabajan en una carpeta temporal **sin** las variables `TELCO_` de tu computador, y verifican la precedencia (sobrescritos > entorno > `.env` > por defecto), cada validación por separado y que el secreto nunca aparezca impreso.

## Solución

```python config_pipeline.py
"""Ejercicio m21-e7: la configuración del pipeline, validada con pydantic-settings."""

from __future__ import annotations

import re
from pathlib import Path

from pydantic import DirectoryPath, Field, SecretStr, field_validator
from pydantic_settings import BaseSettings, SettingsConfigDict


class ConfigPipeline(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="TELCO_", env_file=".env", env_file_encoding="utf-8",
                                      frozen=True, extra="ignore")

    datos: DirectoryPath
    salidas: Path = Path("salidas")
    periodo: str
    umbral_rechazo: float = Field(5.0, ge=0, le=100)
    memoria_duckdb: str = "4GB"
    hilos: int = Field(4, ge=1, le=64)
    correos_alerta: list[str] = []
    db_url: SecretStr | None = None

    @field_validator("periodo")
    @classmethod
    def _periodo(cls, valor: str) -> str:
        if not re.fullmatch(r"\d{4}(0[1-9]|1[0-2])", valor):
            raise ValueError("el periodo debe tener formato AAAAMM (mes 01 a 12)")
        return valor

    @field_validator("memoria_duckdb")
    @classmethod
    def _memoria(cls, valor: str) -> str:
        valor = valor.strip().upper()
        if not re.fullmatch(r"\d+(MB|GB)", valor):
            raise ValueError("usa un formato como 512MB u 8GB")
        return valor

    @field_validator("correos_alerta")
    @classmethod
    def _correos(cls, valor: list[str]) -> list[str]:
        malos = [c for c in valor if "@" not in c]
        if malos:
            raise ValueError(f"correos inválidos: {malos}")
        return valor

    def resumen(self) -> dict[str, str]:
        r = {campo: str(valor) for campo, valor in self.model_dump().items()}
        r["db_url"] = "***" if self.db_url else ""
        r["correos_alerta"] = ", ".join(self.correos_alerta)
        return r


def cargar(env_file: str | Path | None = ".env", **sobrescritos: object) -> ConfigPipeline:
    return ConfigPipeline(_env_file=env_file, **{k: v for k, v in sobrescritos.items() if v is not None})
```

## Explicación

Toda la configuración del pipeline cabe en una clase de 50 líneas, y a cambio obtienes:

- **Un solo lugar** donde ver qué se puede configurar, con qué valores por defecto y qué reglas.
- **Conversión automática**: `"8gb"` → `"8GB"`, `'["a@x","b@y"]'` → lista, `"cdr"` → `Path` verificado.
- **Errores al arrancar** con el nombre del campo: la prueba de validaciones comprueba que cada error señale **solo** el campo culpable.
- **Secretos protegidos**: `SecretStr` no se imprime en `repr`, en `str`, en los mensajes de error de pydantic, ni en `resumen()`.

`DirectoryPath` merece una mención: verificar **al arrancar** que la carpeta de datos existe convierte un error de las 6:47 ("FileNotFoundError" a mitad del proceso) en uno de las 6:00 ("datos: Path does not point to a directory"), antes de crear archivos de salida a medias.

La prueba con `autouse=True` que borra las variables `TELCO_` es el mismo cuidado del ejercicio 3 del módulo 20: tus pruebas no pueden depender de cómo esté configurado tu computador.
