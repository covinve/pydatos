Las funciones puras se prueban fácil: llamas y comparas. Pero tus programas también leen archivos, imprimen, leen variables de entorno y escriben logs. pytest trae herramientas para todo eso.

## Archivos: tmp_path

Nunca uses los datos reales en las pruebas: crea archivos pequeños, con exactamente los casos que quieres probar, en una carpeta temporal que pytest borra sola.

```python
def test_cuenta_registros_por_tipo(tmp_path):
    archivo = tmp_path / "cdr.csv"
    archivo.write_text(
        "cdr_id|linea_origen|tipo|duracion_seg\n"
        "1|3001|VOZ|125\n"
        "2|3001|SMS|0\n"
        "3|3002|VOX|10\n",
        encoding="utf-8",
    )

    resumen = resumir(archivo)

    assert resumen["por_tipo"] == {"SMS": 1, "VOX": 1, "VOZ": 1}
```

:::consejo Datos de prueba pequeños y elocuentes
Tres o cuatro registros elegidos a mano, uno por caso, valen más que mil registros aleatorios: cuando la prueba falla, entiendes por qué.
:::

:::reto Un archivo de prueba hecho a mano
El módulo `resumen.py` tiene `contar_por_tipo(ruta)`, que lee un archivo de CDR separado por `|` (con encabezado y el tipo en la tercera columna) y devuelve un diccionario `{tipo: cantidad}`.

Escribe una prueba que use `tmp_path` para crear un archivo pequeño, con los casos que elijas, y verifique el resultado. El curso la corre contra una versión con error que **cuenta también el encabezado** como un tipo.

```pyreto

def test_cuenta_por_tipo(tmp_path):
    # 1. Crea el archivo en tmp_path
    # 2. Llama a contar_por_tipo
    # 3. Verifica el diccionario
    ...
```

:::pista
`archivo = tmp_path / "cdr.csv"` y `archivo.write_text("cdr_id|linea|tipo\n1|3001|VOZ\n2|3001|SMS\n3|3002|VOZ\n", encoding="utf-8")`. Luego `assert contar_por_tipo(archivo) == {"VOZ": 2, "SMS": 1}`.

## Variables de entorno, atributos y argumentos: monkeypatch

`monkeypatch` cambia algo **solo durante la prueba** y lo restaura al terminar:

```python
def test_lee_la_carpeta_de_entrada_del_entorno(monkeypatch, tmp_path):
    monkeypatch.setenv("CARPETA_CDR", str(tmp_path))
    assert carpeta_entrada() == tmp_path


def test_argumentos_de_terminal(monkeypatch, capsys):
    monkeypatch.setattr("sys.argv", ["telco-formato", "48719.5"])
    main()
    assert capsys.readouterr().out == "$48.720\n"


def test_reintento_sin_esperar(monkeypatch):
    esperas = []
    monkeypatch.setattr("time.sleep", esperas.append)   # reemplaza sleep por una función que solo anota
    con_reintentos(funcion_que_falla_dos_veces, espera=1)
    assert esperas == [1, 2]
```

Esto se llama **reemplazar una dependencia** (*mock*): la prueba no espera de verdad, no depende de la hora ni de la configuración de tu computador.

## Lo que se imprime: capsys

```python
def test_reporte_imprime_el_total(capsys):
    imprimir_reporte({"total": 48719})
    salida = capsys.readouterr().out
    assert "Total: $48.719" in salida
```

:::reto Entorno y pantalla bajo control
El módulo `reporte.py` tiene `imprimir_saludo()`: lee la variable de entorno `REGION` (si no existe, usa `"NACIONAL"`) e imprime `Reporte de la región ANDINA`.

Escribe **dos** pruebas:

1. con `monkeypatch.setenv`, pon `REGION` en `ANDINA` y, con `capsys`, verifica que se imprime `Reporte de la región ANDINA`;
2. con `monkeypatch.delenv("REGION", raising=False)`, verifica que sin la variable se imprime la región `NACIONAL`.

El curso las corre contra una versión que ignora la variable y siempre dice `NACIONAL`, y contra otra que se cae si la variable no existe.

```pyreto
from reporte import imprimir_saludo


def test_usa_la_region_del_entorno(monkeypatch, capsys):
    ...


def test_sin_variable_usa_nacional(monkeypatch, capsys):
    ...
```

:::pista
`monkeypatch.setenv("REGION", "ANDINA")`, luego `imprimir_saludo()` y `assert "Reporte de la región ANDINA" in capsys.readouterr().out`. La segunda es igual, pero quitando la variable con `delenv`.
:::

## La bitácora: caplog

```python
import logging


def test_advierte_lineas_desconocidas(caplog):
    with caplog.at_level(logging.WARNING):
        validar([{"linea_origen": "3999999999", "tipo": "VOZ"}], lineas_clientes={"3001"})
    assert "3999999999" in caplog.text
    assert caplog.records[0].levelname == "WARNING"
```

## La hora actual: inyectarla en lugar de leerla

Una función que llama a `datetime.now()` adentro da resultados distintos cada día: es difícil de probar. La solución más limpia no es un truco de pytest sino de diseño: **recibir la fecha como parámetro**.

:::comparar
:::mal Difícil de probar
```python
def antiguedad(fecha_alta):
    return (date.today() - fecha_alta).days // 365
```
:::
:::bien Fácil de probar
```python
def antiguedad(fecha_alta, hoy=None):
    hoy = hoy or date.today()
    return (hoy - fecha_alta).days // 365

def test_antiguedad():
    assert antiguedad(date(2020, 5, 10), hoy=date(2026, 9, 30)) == 6
```
:::
:::

:::reto Inyecta la fecha
`dias_para_vencer` lee la fecha de hoy por dentro, así que da un resultado distinto cada día y no se puede probar. Cámbiala para que reciba `hoy` como parámetro opcional (por defecto, la fecha actual), sin cambiar lo que calcula.

```pyreto
from datetime import date


def dias_para_vencer(vencimiento):
    return (vencimiento - date.today()).days


print(dias_para_vencer(date(2026, 10, 20)))
```

:::pista
Igual que `antiguedad`: `def dias_para_vencer(vencimiento, hoy=None):` y en la primera línea `hoy = hoy or date.today()`.
:::

```pyprueba
from datetime import date


def prueba_con_hoy():
    """Con hoy fijo, el resultado es siempre el mismo"""
    requiere("dias_para_vencer")
    igual(dias_para_vencer(date(2026, 10, 20), hoy=date(2026, 10, 5)), 15)
    igual(dias_para_vencer(date(2026, 10, 1), hoy=date(2026, 10, 5)), -4, "ya vencida")


def prueba_sin_hoy():
    """Sin hoy, usa la fecha actual"""
    igual(dias_para_vencer(date.today()), 0)
```

```pysolucion
from datetime import date


def dias_para_vencer(vencimiento, hoy=None):
    hoy = hoy or date.today()
    return (vencimiento - hoy).days


print(dias_para_vencer(date(2026, 10, 20)))
```
:::
