## Enunciado

`ejercicios/m22-e7/app/resumen.py` es una aplicación pequeña (ya hecha) que lee `/datos/cdr.csv` y escribe `/salidas/resumen.json`. Escribe su **`Dockerfile`** y su **`.dockerignore`** en `ejercicios/m22-e7/`:

- Imagen base `python:3.12-slim`.
- `ENV` con `PYTHONUNBUFFERED=1` y `PYTHONDONTWRITEBYTECODE=1`.
- `WORKDIR /app`; luego copia **solo** `requirements.txt` e instala con `pip install --no-cache-dir -r requirements.txt`; después copia la carpeta `app/` (no `COPY . .`).
- Un usuario sin privilegios (`useradd`) y `USER` con ese usuario.
- `ENTRYPOINT ["python", "-m", "app.resumen"]`.
- `.dockerignore` que excluya al menos `datos_prueba`, `salidas`, `.env`, `.venv` y `**/__pycache__`.

Las pruebas revisan el Dockerfile **siempre**; y si tienes Docker funcionando (en casa o en Codespaces), además **construyen la imagen y la ejecutan** con los datos de prueba montados como volumen. En la oficina, esas pruebas se saltan.

Cuando pase, pruébalo a mano en casa con datos más grandes:

```powershell
docker build -t telco-resumen:1.0 ejercicios/m22-e7
docker run --rm -v D:\datos\100MB:/datos:ro -v ${PWD}\salidas:/salidas telco-resumen:1.0
```

## Pista 2

El usuario: `RUN useradd --create-home --uid 1000 telco` y después `USER telco`. Como `/salidas` es un volumen montado, el usuario necesita permiso de escritura ahí: en Docker Desktop para Windows las carpetas montadas se pueden escribir; en Linux, el usuario `1000` suele coincidir con tu usuario.

## Solución

```dockerfile Dockerfile
FROM python:3.12-slim

ENV PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY app/ app/

RUN useradd --create-home --uid 1000 telco
USER telco

ENTRYPOINT ["python", "-m", "app.resumen"]
```

```text .dockerignore
datos_prueba/
salidas/
.env
.venv/
**/__pycache__
.pytest_cache/
test_*.py
Dockerfile
.dockerignore
```

## Explicación

Lo que las pruebas con Docker comprobaron es exactamente lo que necesitas en producción:

- **La imagen funciona con datos montados**: el mismo resultado que ejecutar `resumir` en tu Windows. La aplicación no sabe ni le importa si corre en un contenedor: recibe rutas por variables de entorno (con valores por defecto para el contenedor).
- **Sin volumen, el error es claro** (código 2 y un mensaje que menciona el volumen): el error más común al usar una imagen ajena es olvidar montar los datos.
- **No corre como root**, y **no contiene datos** ni archivos de pruebas: `.dockerignore` y `COPY app/` (en lugar de `COPY . .`) controlan qué entra.

El orden de las capas se nota al reconstruir: si cambias una línea de `resumen.py` y vuelves a ejecutar `docker build`, Docker reutiliza las capas de la imagen base y de `pip install` ("CACHED") y solo rehace `COPY app/`. Con un `requirements.txt` real de pandas y duckdb, eso es la diferencia entre 2 segundos y 2 minutos.

Agregar `Dockerfile` y `.dockerignore` al propio `.dockerignore` es un detalle de limpieza: no hacen falta dentro de la imagen, y así cambiarlos no invalida la caché del `COPY`.
