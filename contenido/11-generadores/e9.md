## Enunciado

Un aliado no puede recibir un archivo de 20 GB: pide partes de un millón de registros, cada una con su encabezado, y a veces comprimidas. Además, muchos archivos de mediación llegan **comprimidos en gzip** (`.csv.gz`).

Completa `ejercicios/m11-e9/dividir.py`:

1. `abrir_texto(ruta)` → abre en modo texto UTF-8; si la ruta termina en `.gz`, usa `gzip.open(ruta, "rt", encoding="utf-8")` para descomprimir **al vuelo**, sin crear el archivo descomprimido.
2. `dividir(ruta, registros_por_parte, carpeta_salida, comprimir=False)` → crea las partes `<nombre>_parte_001.csv`, `_parte_002.csv`… (con `.csv.gz` si `comprimir=True`), cada una con el **encabezado original** y como máximo `registros_por_parte` registros. Devuelve la lista de rutas en orden.

Detalles que revisan las pruebas:

- el nombre base no lleva extensiones: `cdr.csv.gz` → `cdr_parte_001.csv`;
- si los registros caben exacto, **no** debe quedar una parte vacía al final;
- un archivo sin registros produce **una** parte con solo el encabezado;
- la carpeta de salida se crea si no existe;
- nada de `read()`, `readlines()` ni `read_text()`: el archivo se recorre línea por línea.

## Pista 1

`itertools.batched(archivo, registros_por_parte)` agrupa las líneas en lotes; cada lote es una parte. Como trabaja sobre el iterador del archivo, nunca carga más de un lote en memoria:

```python
with abrir_texto(ruta) as archivo:
    encabezado = next(archivo)
    for numero, lote in enumerate(batched(archivo, registros_por_parte), start=1):
        ...
```

Un lote de un millón de líneas son unos 80 MB: aceptable. Si quisieras aún menos memoria, escribirías línea por línea y cambiarías de archivo al llegar al límite.

## Pista 2

El nombre base: `ruta.name.split(".")[0]`. Para escribir, elige la función según `comprimir`:

```python
abrir = gzip.open if comprimir else open
with abrir(destino, "wt", encoding="utf-8") as salida:
    salida.write(encabezado)
    salida.writelines(lote)
```

Para el caso sin registros: si al terminar no se creó ninguna parte, crea la primera solo con el encabezado.

## Solución

```python dividir.py
"""Ejercicio m11-e9: dividir un archivo de CDR (normal o .gz) en partes de N registros.

Uso:
    python ejercicios/m11-e9/dividir.py datos/1GB/cdr.csv 1000000 partes/
"""

from __future__ import annotations

import gzip
import sys
from itertools import batched
from pathlib import Path


def abrir_texto(ruta: Path):
    if ruta.suffix == ".gz":
        return gzip.open(ruta, "rt", encoding="utf-8")
    return open(ruta, encoding="utf-8")


def escribir_parte(destino: Path, encabezado: str, lineas, comprimir: bool) -> None:
    abrir = gzip.open if comprimir else open
    with abrir(destino, "wt", encoding="utf-8") as salida:
        salida.write(encabezado)
        salida.writelines(lineas)


def dividir(ruta: Path, registros_por_parte: int, carpeta_salida: Path, comprimir: bool = False) -> list[Path]:
    carpeta_salida.mkdir(parents=True, exist_ok=True)
    base = ruta.name.split(".")[0]
    extension = ".csv.gz" if comprimir else ".csv"
    partes = []
    with abrir_texto(ruta) as archivo:
        encabezado = next(archivo)
        for numero, lote in enumerate(batched(archivo, registros_por_parte), start=1):
            destino = carpeta_salida / f"{base}_parte_{numero:03d}{extension}"
            escribir_parte(destino, encabezado, lote, comprimir)
            partes.append(destino)
    if not partes:
        destino = carpeta_salida / f"{base}_parte_001{extension}"
        escribir_parte(destino, encabezado, [], comprimir)
        partes.append(destino)
    return partes


if __name__ == "__main__":
    partes = dividir(Path(sys.argv[1]), int(sys.argv[2]), Path(sys.argv[3]))
    print(f"{len(partes)} partes creadas")
```

## Explicación

`gzip.open(..., "rt")` devuelve un objeto que se recorre igual que un archivo normal, pero descomprime en memoria a medida que lees. Un CDR de 20 GB suele comprimirse a 3–4 GB: procesarlo comprimido ahorra disco y, muchas veces, también tiempo (leer del disco es más lento que descomprimir).

Como `abrir_texto` devuelve en ambos casos algo que se usa igual, el resto del código no necesita saber si el archivo estaba comprimido. Es el mismo principio de los lectores enchufables del módulo 8.

`batched` evita una trampa clásica: con un contador manual es fácil terminar con una última parte vacía cuando los registros caben exactos. La prueba `test_division_exacta` existe justamente para ese caso borde.
