## Enunciado

Un día con muchos menos CDR de lo normal suele significar que un archivo **no llegó** (fuga de ingresos en la mediación). Uno con muchos más, una carga **duplicada**.

1. `registros_por_dia(cdr)` → Serie con la cantidad de CDR con `fecha_inicio` válida por día (`date`), indexada por fecha y ordenada. Usa `pd.to_datetime(..., format="%Y-%m-%d %H:%M:%S", errors="coerce")`.
2. `cercas_tukey(serie, k=1.5)` → tupla `(bajo, alto)` con `p25 − k·IQR` y `p75 + k·IQR` (percentiles de Pandas, `quantile`).
3. `dias_raros(serie, k=1.5)` → DataFrame con columnas `dia`, `registros` y `tipo` (`"bajo"` o `"alto"`) de los días fuera de las cercas, ordenado por día.

from datetime import date

import pandas as pd

CDR = pd.read_csv("cdr.csv", sep="|")


def prueba_por_dia():
    """Conteo por día con fechas válidas"""
    requiere("registros_por_dia")
    s = registros_por_dia(CDR)
    fechas = pd.to_datetime(CDR["fecha_inicio"], format="%Y-%m-%d %H:%M:%S", errors="coerce")
    igual(int(s.sum()), int(fechas.notna().sum()))
    igual(list(s.index), sorted(s.index))
    assert isinstance(s.index[0], date), "El índice son fechas (date)"


def prueba_cercas():
    """Fórmula de Tukey"""
    requiere("cercas_tukey")
    s = pd.Series([10, 12, 11, 13, 12, 50, 1])
    p25, p75 = s.quantile(0.25), s.quantile(0.75)
    igual(cercas_tukey(s), (p25 - 1.5 * (p75 - p25), p75 + 1.5 * (p75 - p25)))
    igual(cercas_tukey(s, k=3), (p25 - 3 * (p75 - p25), p75 + 3 * (p75 - p25)))


def prueba_dias_plantados():
    """Detecta un día caído y uno duplicado"""
    requiere("dias_raros")
    s = registros_por_dia(CDR).copy()
    caido, duplicado = s.index[3], s.index[10]
    s[caido] = 2
    s[duplicado] = s.median() * 3
    r = dias_raros(s)
    igual(list(r.columns), ["dia", "registros", "tipo"])
    filas = {fila.dia: fila.tipo for fila in r.itertuples()}
    igual(filas.get(caido), "bajo")
    igual(filas.get(duplicado), "alto")
    igual(r["dia"].tolist(), sorted(r["dia"].tolist()))


def prueba_sin_raros():

    s = pd.Series([100, 101, 99, 100, 102], index=pd.date_range("2026-09-01", periods=5).date)

## Pista 2

Con las cercas, dos máscaras: `serie < bajo` y `serie > alto`. Arma el DataFrame con `np.where` o concatenando dos partes, y no olvides `reset_index`.

## Solución

```python
import numpy as np
import pandas as pd


def registros_por_dia(cdr):
    fechas = pd.to_datetime(cdr["fecha_inicio"], format="%Y-%m-%d %H:%M:%S", errors="coerce").dropna()
    return fechas.dt.date.value_counts().sort_index()


def cercas_tukey(serie, k=1.5):
    p25, p75 = serie.quantile(0.25), serie.quantile(0.75)
    iqr = p75 - p25
    return p25 - k * iqr, p75 + k * iqr


def dias_raros(serie, k=1.5):
    bajo, alto = cercas_tukey(serie, k)
    fuera = serie[(serie < bajo) | (serie > alto)].sort_index()
    return pd.DataFrame({
        "dia": list(fuera.index),
        "registros": fuera.to_numpy(),
        "tipo": np.where(fuera.to_numpy() < bajo, "bajo", "alto"),
    })


cdr = pd.read_csv("cdr.csv", sep="|")
por_dia = registros_por_dia(cdr)
print(por_dia.describe())
print(cercas_tukey(por_dia))
```

## Explicación

Este es un **control de completitud**, de los más simples y útiles del aseguramiento de ingresos: vigilar el volumen diario. Un día con 2 registros cuando lo normal son 130 no necesita un modelo sofisticado para preocupar a cualquiera; necesita que alguien lo **mire** a tiempo. Automatizado en la tarea diaria del módulo 18, con una alerta del módulo 19, ese archivo perdido se recupera el mismo día y no en la conciliación de fin de mes.

Las cercas de Tukey usan percentiles, así que el día caído no "arrastra" el umbral (como sí haría con media y desviación). `k = 1.5` es el valor de los diagramas de caja; `k = 3` marca solo lo **muy** extremo, útil si las alertas son demasiadas.

En datos reales conviene comparar cada día con **días del mismo tipo** (lunes con lunes, festivos aparte): el domingo siempre tiene menos llamadas y no por eso falta un archivo. Es la misma idea de comparar dentro del grupo del ejercicio 2.
