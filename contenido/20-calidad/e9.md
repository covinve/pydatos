## Enunciado

`ejercicios/m20-e9/proyecto/` es un paquete pequeño (`src/telco_calidad/`) con sus pruebas. Déjalo como un proyecto profesional, donde la calidad se verifica sola:

1. **`proyecto/pyproject.toml`** con:
   - `[build-system]` (por ejemplo, setuptools) y `[project]` con `name = "telco-calidad"`, `version`, `requires-python` y `[project.optional-dependencies]` `dev` con pytest, ruff y mypy;
   - `[tool.ruff.lint]` con `select` que incluya al menos `E`, `F`, `B` e `I`;
   - `[tool.mypy]` con `strict = true`;
   - `[tool.pytest.ini_options]` con `testpaths = ["tests"]` y `pythonpath = ["src"]`.
2. **Arregla `src/telco_calidad/reglas.py`** hasta que pasen `ruff check`, `ruff format --check`, `mypy src` y `pytest` (las pruebas del proyecto describen el comportamiento correcto: hay un error clásico escondido).
3. **`proyecto/.pre-commit-config.yaml`** con los ganchos de ruff (`ruff` y `ruff-format`), `check-added-large-files` y `detect-private-key`.
4. **`proyecto/.github/workflows/pruebas.yml`** que, en cada `push` y `pull_request`, en Ubuntu **y** Windows, instale con `pip install -e ".[dev]"` y ejecute `ruff check`, `mypy` y `pytest`.

Desde `ejercicios/m20-e9/proyecto/` puedes ir probando:

```powershell
python -m ruff check .
python -m ruff format .
python -m mypy src
python -m pytest
```

:::consejo Pruébalo en GitHub
Cuando pase `python comprobar.py m20-e9`, copia la carpeta `proyecto/` a un repositorio nuevo en tu cuenta de GitHub, haz *push* y mira la pestaña **Actions**: verás las cuatro máquinas (2 sistemas × 2 versiones de Python) ejecutando tus verificaciones.
:::

## Pista 1

`ruff check . --fix` corrige solo el orden de los `import` y los que sobran. Los otros dos problemas son conceptuales:

- `rechazos=[]` como valor por defecto se **comparte** entre llamadas (módulo 5): usa `rechazos: list[tuple[str, str]] | None = None` y crea la lista adentro.
- `except:` atrapa **todo**, incluso `KeyboardInterrupt`: atrapa solo lo que esperas, `(TypeError, ValueError)`.

## Pista 2

Para mypy estricto, `dict` a secas no basta: `planes: dict[str, str]`. Y `leer_umbral` recibe texto o `None`: `texto: str | None`.

Un esqueleto del workflow:

```yaml
name: Pruebas
on:
  push:
  pull_request:
jobs:
  pruebas:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest]
        python-version: ["3.12", "3.13"]
    steps:
      - uses: actions/checkout@v4
      ...
```

## Solución

```toml proyecto/pyproject.toml
[build-system]
requires = ["setuptools>=69"]
build-backend = "setuptools.build_meta"

[project]
name = "telco-calidad"
version = "0.1.0"
description = "Reglas pequeñas de facturación, con calidad automatizada"
requires-python = ">=3.12"
dependencies = []

[project.optional-dependencies]
dev = ["pytest>=8", "pytest-cov", "ruff>=0.6", "mypy>=1.10", "pre-commit"]

[tool.setuptools.packages.find]
where = ["src"]

[tool.ruff]
line-length = 110

[tool.ruff.lint]
select = ["E", "F", "W", "I", "B", "UP", "SIM"]

[tool.mypy]
strict = true

[tool.pytest.ini_options]
testpaths = ["tests"]
pythonpath = ["src"]
```

```python proyecto/src/telco_calidad/reglas.py
def minutos(segundos: int) -> int:
    return (segundos + 59) // 60


def agregar_rechazo(
    cdr_id: str, motivo: str, rechazos: list[tuple[str, str]] | None = None
) -> list[tuple[str, str]]:
    if rechazos is None:
        rechazos = []
    rechazos.append((cdr_id, motivo))
    return rechazos


def leer_umbral(texto: str | None) -> float:
    try:
        return float(texto)  # type: ignore[arg-type]
    except (TypeError, ValueError):
        return 5.0


def plan_o_defecto(planes: dict[str, str], plan_id: str) -> str | None:
    return planes.get(plan_id)
```

```yaml proyecto/.pre-commit-config.yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.6.9
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.6.0
    hooks:
      - id: check-added-large-files
        args: [--maxkb=5000]
      - id: detect-private-key
      - id: end-of-file-fixer
      - id: trailing-whitespace
```

```yaml proyecto/.github/workflows/pruebas.yml
name: Pruebas

on:
  push:
  pull_request:

jobs:
  pruebas:
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, windows-latest]
        python-version: ["3.12", "3.13"]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python-version }}
          cache: pip
      - name: Instalar
        run: pip install -e ".[dev]"
      - name: Estilo
        run: |
          ruff check .
          ruff format --check .
      - name: Tipos
        run: mypy src
      - name: Pruebas
        run: pytest --cov=telco_calidad --cov-report=term-missing
```

## Explicación

Con estos cuatro archivos, el proyecto se defiende solo:

| Momento | Qué se verifica | Herramienta |
|---|---|---|
| Al guardar (en VS Code) | Formato y errores obvios | Extensión de ruff |
| Al hacer `git commit` | Estilo, archivos grandes, llaves privadas | pre-commit |
| Al hacer `git push` | Todo, en Windows y Linux, en dos versiones de Python | GitHub Actions |

El "error clásico escondido" era `rechazos=[]`: la lista por defecto se crea **una vez**, al definir la función, y todas las llamadas la comparten. La regla `B006` de ruff (del grupo `B`, *bugbear*) lo detecta automáticamente; por eso conviene activar más que solo `E` y `F`.

¿Y ese `# type: ignore[arg-type]` en la solución? `float(None)` es exactamente el caso que queremos atrapar con `except TypeError`, pero mypy (con razón) se queja de pasar `str | None` a `float`. Es un `ignore` **con código** y justificado. Una alternativa sin `ignore` es `if texto is None: return 5.0` antes del `try`: elige la que te parezca más clara y deja un comentario si no es obvia.

`fail-fast: false` en la matriz hace que, si falla Windows, igual veas el resultado de Ubuntu: así sabes si el problema es del sistema operativo o del código.
