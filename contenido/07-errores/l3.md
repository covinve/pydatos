`print` sirve mientras desarrollas. Pero un proceso que corre solo cada madrugada necesita dejar un **registro** (*log*): qué archivo procesó, cuántos registros, qué advertencias hubo, a qué hora falló. Para eso está el módulo `logging`.

## Por qué no print

| | `print` | `logging` |
|---|---|---|
| Niveles de importancia | No | `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| Fecha y hora automáticas | No | Sí, con el formato que quieras |
| Enviar a un archivo | Hay que programarlo | Una línea de configuración |
| Silenciar el detalle en producción | Borrar los `print` | Cambiar el nivel |
| Saber de qué módulo viene | No | Sí (`%(name)s`) |

## Primeros pasos

```pyrun
import logging
import sys

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s | %(levelname)-8s | %(name)s | %(message)s",
    datefmt="%H:%M:%S",
    stream=sys.stdout,
    force=True,
)
log = logging.getLogger("validador")

log.debug("Detalle fino: no se muestra con nivel INFO")
log.info("Procesando cdr_20260930.csv")
log.warning("Línea 1534: duración negativa (-45), se descarta")
log.error("No se encontró el archivo de clientes")
log.info("Terminado: 4.064 registros, 121 errores")
```

## Los niveles

| Nivel | Para qué | Ejemplo |
|---|---|---|
| `DEBUG` | Detalle para depurar | "Fila 15: campos = [...]" |
| `INFO` | Hitos normales del proceso | "Archivo leído: 4.064 registros" |
| `WARNING` | Algo raro pero el proceso sigue | "Línea desconocida 3999…" |
| `ERROR` | Algo falló; una parte no se pudo hacer | "No se pudo escribir el reporte" |
| `CRITICAL` | El proceso no puede continuar | "Base de datos inaccesible" |

Con `level=logging.INFO` se muestran INFO y todo lo de arriba; con `level=logging.WARNING`, solo advertencias y errores.

:::reto Cada mensaje con su nivel
El logging ya está configurado. Registra estos cuatro eventos con el nivel que corresponde, en este orden:

1. `Inicio del proceso del periodo 202609`

3. `No se pudo escribir el reporte de errores` (una parte falló)
4. `Detalle: 15 campos leídos` (solo sirve para depurar: con nivel INFO **no** debe aparecer)

:::pista
Los métodos son `log.debug`, `log.info`, `log.warning` y `log.error`. Un hito normal es `info`; algo raro pero que no detiene el proceso es `warning`; una parte que falló es `error`; el detalle fino es `debug`.
:::

## Un logger por módulo

La convención es crear un logger con el nombre del módulo al inicio de cada archivo:

```python
import logging

log = logging.getLogger(__name__)
```

Así cada mensaje dice de qué parte del programa viene, y puedes subir o bajar el detalle de un módulo sin tocar los demás.

## Registrar errores con traceback

`log.exception(...)` se usa dentro de un `except`: registra el mensaje **y el traceback completo**.

```pyrun
import logging
import sys

logging.basicConfig(level=logging.INFO, format="%(levelname)s | %(message)s", stream=sys.stdout, force=True)
log = logging.getLogger("facturacion")

def cargar_tarifa(tarifas, destino):
    try:
        return tarifas[destino]
    except KeyError:
        log.exception("No hay tarifa para el destino %r", destino)
        return None

cargar_tarifa({"LOCAL": 100}, "SATELITAL")
```

:::consejo Pasa los datos como argumentos
Escribe `log.info("Procesados %d registros", n)` en lugar de `log.info(f"Procesados {n} registros")`. Con el primer estilo, si el nivel está desactivado, Python ni siquiera arma el texto. Para mensajes ocasionales da igual; dentro de un bucle de millones de registros se nota.
:::

:::reto Advertencias dentro del bucle
Recorre `duraciones` y, por cada duración negativa, registra una **advertencia** pasando los datos como argumentos (no con f-string):

`Registro 2: duración negativa -45`

Al final registra con nivel INFO: `Procesados 5 registros, 2 descartados`.

```pyreto
import logging
import sys

logging.basicConfig(level=logging.INFO, format="%(levelname)s | %(message)s", stream=sys.stdout, force=True)
log = logging.getLogger("validador")

duraciones = [125, -45, 61, -1, 300]

# Recorre (numerando desde 1) y registra

```

:::pista
`for numero, d in enumerate(duraciones, start=1):` y `log.warning("Registro %d: duración negativa %d", numero, d)`. Cuenta los descartados para el mensaje final.
:::

```pyprueba
def prueba_mensajes():
    """Advierte cada negativa y resume al final"""
    lineas = [l for l in salida.strip().splitlines() if l.strip()]
    igual(lineas, [
        "WARNING | Registro 2: duración negativa -45",
        "WARNING | Registro 4: duración negativa -1",
        "INFO | Procesados 5 registros, 2 descartados",
    ])


def prueba_argumentos():
    """Pasa los datos como argumentos, no con f-string"""
    assert 'log.warning(f"' not in codigo and "log.warning(f'" not in codigo, 'Usa log.warning("... %d ...", valor) en lugar de una f-string'
```

```pysolucion
import logging
import sys

logging.basicConfig(level=logging.INFO, format="%(levelname)s | %(message)s", stream=sys.stdout, force=True)
log = logging.getLogger("validador")

duraciones = [125, -45, 61, -1, 300]

descartados = 0
for numero, d in enumerate(duraciones, start=1):
    if d < 0:
        log.warning("Registro %d: duración negativa %d", numero, d)
        descartados += 1

log.info("Procesados %d registros, %d descartados", len(duraciones), descartados)
```
:::

## Enviar el log a un archivo

En un script real configuras el log una vez, al arrancar, con dos destinos: la terminal y un archivo.

```python
import logging
from pathlib import Path


def configurar_log(carpeta: Path, nivel=logging.INFO) -> None:
    carpeta.mkdir(exist_ok=True)
    formato = logging.Formatter("%(asctime)s | %(levelname)-8s | %(name)s | %(message)s")

    archivo = logging.FileHandler(carpeta / "validador.log", encoding="utf-8")
    archivo.setFormatter(formato)

    consola = logging.StreamHandler()
    consola.setFormatter(formato)

    raiz = logging.getLogger()
    raiz.setLevel(nivel)
    raiz.addHandler(archivo)
    raiz.addHandler(consola)
```

:::error Configura el logging solo en el programa principal
Las funciones y módulos reutilizables solo **usan** `logging.getLogger(__name__)`. La configuración (`basicConfig`, handlers, nivel) va en el punto de entrada del programa (el `if __name__ == "__main__":`). Si cada módulo configura su propio logging, los mensajes salen duplicados o desaparecen.
:::

:::telco El log como evidencia
Cuando un cliente reclama una factura o auditoría pregunta qué pasó con el archivo del 30 de septiembre, el log es tu evidencia: qué archivo se procesó, a qué hora, cuántos registros se descartaron y por qué. Un buen log ahorra horas de investigación.
:::

## Cuestionario

? Tu proceso encuentra una línea de CDR que no pertenece a ningún cliente y la descarta, pero sigue. ¿Qué nivel usas?
- [ ] `DEBUG`
- [ ] `INFO`
- [x] `WARNING`
- [ ] `CRITICAL`
> Es algo anómalo que conviene revisar, pero el proceso continúa: es una advertencia.

? ¿Qué diferencia hay entre `log.error(...)` y `log.exception(...)`?
- [ ] Ninguna
- [x] `log.exception` también registra el traceback; se usa dentro de un `except`
- [ ] `log.exception` detiene el programa
- [ ] `log.error` no muestra el mensaje
> Ambos usan nivel ERROR, pero `exception` agrega la traza completa de la excepción que se está manejando.

? ¿Dónde se debe configurar el logging (formato, archivo, nivel)?
- [ ] En cada función
- [ ] En cada módulo
- [x] Una sola vez, en el punto de entrada del programa
- [ ] En el `requirements.txt`
> Los módulos solo piden su logger con `getLogger(__name__)`; quien ejecuta el programa decide adónde van los mensajes.
