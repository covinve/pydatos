## Enunciado

El equipo recibe CDR en varios formatos y cada formato tiene su **lector** en el paquete `lectores` (ya está en tu carpeta de trabajo):

```text
lectores/
├── __init__.py
├── _base.py          ← utilidades internas (empieza con _: no es un lector)
├── pipe.py           ← EXTENSIONES = (".csv", ".psv"), leer(ruta) -> list[dict]
├── ancho_fijo.py     ← EXTENSIONES = (".txt", ".dat")
├── jsonl.py          ← EXTENSIONES = (".jsonl",)
└── roto.py           ← tiene un error y no se puede importar
```

Cada lector es un módulo con una tupla `EXTENSIONES` y una función `leer(ruta)`. Escribe:

1. `descubrir_lectores()` → recorre **automáticamente** los módulos del paquete con `pkgutil.iter_modules` y devuelve un diccionario `extension → módulo`:
   - ignora los módulos cuyo nombre empieza con `_`;
   - ignora los módulos que no tienen `EXTENSIONES` o `leer`;
   - si un módulo falla al importarse, **no** debe romper el descubrimiento: agrégalo a la lista global `LECTORES_CON_ERROR` (con su nombre completo, por ejemplo `"lectores.roto"`) y sigue.
2. `leer_cualquiera(ruta)` → elige el lector según la extensión del archivo (sin importar mayúsculas: `.CSV` también vale) y devuelve lo que devuelva su `leer`. Si no hay lector, lanza `ValueError("No hay lector para archivos .xlsx")`.

Agregar un formato nuevo debe consistir **solo** en agregar un módulo al paquete.

## Pista 1

`pkgutil.iter_modules(lectores.__path__, prefix="lectores.")` recorre los módulos del paquete y entrega objetos con atributo `.name` (el nombre completo, por ejemplo `"lectores.pipe"`). Importa cada uno con `importlib.import_module`.

Para saber si el nombre corto empieza con `_`: `nombre.rsplit(".", 1)[1].startswith("_")`.

## Pista 2

Envuelve el import en `try/except Exception` (aquí sí tiene sentido atrapar todo: un plugin defectuoso no debe tumbar el programa, pero hay que registrarlo). Comprueba que el módulo tenga lo necesario con `hasattr(modulo, "EXTENSIONES") and hasattr(modulo, "leer")`.

En `leer_cualquiera`: `Path(ruta).suffix.lower()` da la extensión en minúsculas.

## Solución

```python
import importlib
import pkgutil
from pathlib import Path

import lectores

LECTORES_CON_ERROR = []


def descubrir_lectores():
    encontrados = {}
    LECTORES_CON_ERROR.clear()
    for info in pkgutil.iter_modules(lectores.__path__, prefix="lectores."):
        if info.name.rsplit(".", 1)[1].startswith("_"):
            continue
        try:
            modulo = importlib.import_module(info.name)
        except Exception:
            LECTORES_CON_ERROR.append(info.name)
            continue
        if not (hasattr(modulo, "EXTENSIONES") and hasattr(modulo, "leer")):
            continue
        for extension in modulo.EXTENSIONES:
            encontrados[extension.lower()] = modulo
    return encontrados


def leer_cualquiera(ruta):
    extension = Path(ruta).suffix.lower()
    lector = descubrir_lectores().get(extension)
    if lector is None:
        raise ValueError(f"No hay lector para archivos {extension}")
    return lector.leer(ruta)


print(sorted(descubrir_lectores()))
print(leer_cualquiera("cdr.psv"))
```

## Explicación

Esto es una **arquitectura de plugins**, la misma idea que usan pytest (descubre los archivos `test_*.py`), Pandas (`read_csv`, `read_parquet`…) o VS Code con sus extensiones:

- El núcleo (`leer_cualquiera`) no conoce los formatos: los **descubre**.
- Cada formato es un módulo independiente que cumple un "contrato" mínimo: `EXTENSIONES` y `leer`.
- Agregar un formato es agregar un archivo. La última prueba lo verifica creando `tsv.py` sobre la marcha.

Atrapar `Exception` es normalmente mala idea, pero aquí es una decisión consciente y **registrada**: un plugin roto no debe impedir que funcionen los demás, y `LECTORES_CON_ERROR` deja constancia para revisarlo. Atrapar sin registrar sí sería un error.
