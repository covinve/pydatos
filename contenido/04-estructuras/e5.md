## Enunciado

Antes de facturar, auditoría pide un informe de calidad cruzando tres fuentes:

- `cdr_ids`: los identificadores de todos los CDR del archivo (con posibles repetidos).
- `lineas_cdr`: las líneas de origen que aparecen en los CDR (con repetidos).
- `lineas_clientes`: las líneas de los clientes activos.

Escribe `auditar_fuentes(cdr_ids, lineas_cdr, lineas_clientes)` que devuelva un diccionario con:

| Clave | Contenido |
|---|---|
| `"ids_duplicados"` | Lista **ordenada** de los IDs que aparecen más de una vez (cada uno una sola vez en la lista) |
| `"registros_duplicados"` | Cuántos registros sobran por duplicación (si un ID aparece 3 veces, sobran 2) |
| `"lineas_sin_cliente"` | Lista ordenada de líneas con CDR que no son de ningún cliente |
| `"clientes_sin_consumo"` | Lista ordenada de líneas de clientes sin ningún CDR |
| `"lineas_ok"` | Cantidad de líneas que tienen CDR y son de un cliente |

```python
auditar_fuentes([1, 2, 3, 2, 4, 2, 5, 1],
                ["3001", "3002", "3001", "3999"],
                ["3001", "3002", "3003"])
# {"ids_duplicados": [1, 2], "registros_duplicados": 3,
#  "lineas_sin_cliente": ["3999"], "clientes_sin_consumo": ["3003"], "lineas_ok": 2}
```

## Pista 1

Para los duplicados, el patrón "¿ya lo vi?" con dos conjuntos: `vistos` y `duplicados`. Cada vez que un ID ya está en `vistos`, súmalo a `registros_duplicados` y agrégalo a `duplicados`.

Para las líneas, convierte ambas listas en conjuntos y usa diferencia (`-`) e intersección (`&`).

## Pista 2

Otra forma de contar duplicados: `registros_duplicados = len(cdr_ids) - len(set(cdr_ids))`. Para la lista de IDs repetidos, `Counter(cdr_ids)` te dice cuántas veces aparece cada uno:

```python
from collections import Counter
conteo = Counter(cdr_ids)
repetidos = [cdr_id for cdr_id, veces in conteo.items() if veces > 1]
```

:::error Evita esto
`[x for x in cdr_ids if cdr_ids.count(x) > 1]` funciona con pocos datos, pero `count` recorre toda la lista cada vez: con 200.000 registros son 40.000 millones de comparaciones y la prueba se queda sin tiempo.
:::

## Solución

```python
from collections import Counter


def auditar_fuentes(cdr_ids, lineas_cdr, lineas_clientes):
    conteo = Counter(cdr_ids)
    ids_duplicados = sorted(cdr_id for cdr_id, veces in conteo.items() if veces > 1)
    registros_duplicados = len(cdr_ids) - len(conteo)

    con_cdr = set(lineas_cdr)
    clientes = set(lineas_clientes)
    return {
        "ids_duplicados": ids_duplicados,
        "registros_duplicados": registros_duplicados,
        "lineas_sin_cliente": sorted(con_cdr - clientes),
        "clientes_sin_consumo": sorted(clientes - con_cdr),
        "lineas_ok": len(con_cdr & clientes),
    }


print(auditar_fuentes([1, 2, 3, 2, 4, 2, 5, 1], ["3001", "3002", "3001", "3999"], ["3001", "3002", "3003"]))
```

## Explicación

- **`len(conteo)`** es la cantidad de IDs distintos, así que `len(cdr_ids) - len(conteo)` son exactamente los registros que sobran.
- **Tres operaciones de conjuntos** responden tres preguntas de negocio en una línea cada una.
- **La prueba de 200.000 registros** existe para recordarte que una solución que "funciona" con 8 datos puede ser inútil con datos reales. Con conjuntos y `Counter`, este código procesa millones de registros en segundos.

Este informe de calidad es el que deberías generar **antes** de cada ciclo de facturación: los clientes sin consumo pueden ser líneas inactivas, y las líneas sin cliente pueden ser consumo que nadie va a pagar.
