Un programa automatizado no tiene a nadie mirando la pantalla. Tiene que recibir sus datos por **argumentos**, avisar si falló con un **código de salida**, escribir lo que hizo en un **registro** y poder ejecutarse dos veces sin causar daño.

## Argumentos con argparse

En lugar de cambiar rutas dentro del código, recíbelas desde la línea de comandos:

```pyrun
import argparse


def crear_parser():
    p = argparse.ArgumentParser(prog="resumen_cdr", description="Resume un archivo de CDR.")
    p.add_argument("archivo", help="Ruta del cdr.csv")
    p.add_argument("--tipo", choices=["VOZ", "SMS", "DATOS"], help="Filtra por tipo")
    p.add_argument("--top", type=int, default=5, help="Cantidad de líneas a mostrar (por defecto 5)")
    p.add_argument("-v", "--detallado", action="store_true", help="Muestra más información")
    return p


parser = crear_parser()
args = parser.parse_args(["cdr.csv", "--tipo", "VOZ", "--top", "3"])    # en un script real: parse_args()
print(args)
print(args.archivo, args.tipo, args.top, args.detallado)
parser.print_help()
```

`argparse` convierte tipos (`type=int`), valida opciones (`choices`), pone valores por defecto y genera la ayuda (`--help`) automáticamente. Si el usuario se equivoca, muestra el error y termina con código 2.

:::consejo Separa main(argv)
Escribe `def main(argv=None):` que llame `parser.parse_args(argv)`. En producción `argv=None` lee la línea de comandos; en las pruebas le pasas una lista. Así tu script es **probable** sin ejecutar procesos.
:::

## Códigos de salida

Todo programa termina con un número: **0 es éxito**, cualquier otro es error. El Programador de tareas, los *pipelines* de GitHub Actions y otros scripts lo usan para saber si siguieron o no.

| Código | Convención habitual |
|---|---|
| 0 | Todo bien |
| 1 | Error general (excepción no controlada) |
| 2 | Uso incorrecto (argumentos inválidos) |
| 3+ | Los que tú definas: "sin archivos que procesar", "otro proceso en curso"… |

```python
import sys

def main(argv=None) -> int:
    args = crear_parser().parse_args(argv)
    if not Path(args.archivo).exists():
        print(f"No existe {args.archivo}", file=sys.stderr)    # los errores van a stderr
        return 3
    ...
    return 0

if __name__ == "__main__":
    sys.exit(main())                                           # convierte el return en código de salida
```

En PowerShell, el código del último programa queda en `$LASTEXITCODE`.

## Rutas que funcionan desde cualquier lugar

Un error clásico: el script funciona cuando lo ejecutas desde su carpeta, pero el Programador de tareas lo ejecuta desde `C:\Windows\System32` y no encuentra nada. Construye las rutas **relativas al script**:

```python
from pathlib import Path

CARPETA_SCRIPT = Path(__file__).resolve().parent
CONFIG = CARPETA_SCRIPT / "config.toml"
```

## El patrón bandeja de entrada

Muchísimos procesos de facturación siguen este esquema:

:::pasos Bandeja de entrada → proceso → archivados
:::paso 1. Llegan archivos
Otro sistema deja archivos en `entrada/` (por SFTP, una carpeta compartida, un correo…).
:::
:::paso 2. Se procesan
Tu programa toma cada archivo **completo** (cuidado con los que aún se están copiando: espera a que su tamaño deje de cambiar, o que el emisor use un nombre temporal y luego lo renombre).
:::
:::paso 3. Se archivan
Si salió bien, el archivo se **mueve** a `procesados/AAAA-MM-DD/`; si falló, a `errores/`, con un registro de por qué. Así `entrada/` solo contiene lo pendiente y nada se procesa dos veces.
:::
:::

```pyrun
from pathlib import Path
import shutil

entrada, procesados = Path("entrada"), Path("procesados")
for carpeta in (entrada, procesados):
    shutil.rmtree(carpeta, ignore_errors=True)
    carpeta.mkdir()
for dia in ("01", "02", "03"):
    (entrada / f"cdr_202609{dia}.csv").write_text("cdr_id|tipo\n1|VOZ\n", encoding="utf-8")
(entrada / "LEAME.txt").write_text("no es un CDR", encoding="utf-8")

for archivo in sorted(entrada.glob("cdr_*.csv")):
    filas = len(archivo.read_text(encoding="utf-8").splitlines()) - 1
    destino = procesados / archivo.name
    shutil.move(archivo, destino)                     # mover = no se procesa otra vez
    print(f"{archivo.name}: {filas} fila(s) → {destino}")

print("Quedan en entrada:", [a.name for a in entrada.iterdir()])
```

:::telco Idempotencia, otra vez
Pregúntate siempre: "¿qué pasa si este proceso se ejecuta dos veces?" o "¿qué pasa si se cae a la mitad y lo reinicio?". Mover los archivos al terminar, cargar con clave primaria (módulo 17) y escribir las salidas con un nombre temporal que se renombra al final hacen que la respuesta sea "nada malo".
:::

## Cuestionario

? ¿Qué código de salida indica que un programa terminó bien?
- [x] 0
- [ ] 1
- [ ] -1
- [ ] 200
> Por convención, 0 es éxito y cualquier otro número indica algún error.

? ¿Por qué conviene escribir `main(argv=None)` y llamar `parse_args(argv)`?
- [ ] Porque argparse lo exige
- [x] Para poder probar el programa pasándole una lista de argumentos, sin ejecutar procesos
- [ ] Para que sea más rápido
- [ ] Para no necesitar `if __name__ == "__main__"`
> Con `argv=None` lee la línea de comandos real; en las pruebas le das la lista que quieras.

? Tu script lee `config.toml` y funciona a mano, pero falla en el Programador de tareas. ¿Causa probable?
- [ ] El Programador no soporta Python
- [x] La ruta es relativa al directorio actual, que en la tarea es otro; usa `Path(__file__).resolve().parent`
- [ ] El archivo está corrupto
- [ ] Falta `argparse`
> El directorio actual depende de quién ejecuta el programa; la ubicación del script no.
