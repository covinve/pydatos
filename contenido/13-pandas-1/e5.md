## Solución

```python
import numpy as np
import pandas as pd

cdr = pd.read_csv("cdr.csv", sep="|", dtype={"linea_origen": "string", "linea_destino": "string"})


def optimizar(cdr):
    o = cdr.astype({"tipo": "category", "destino": "category", "celda": "category"})
    for col in ["cdr_id", "duracion_seg"]:
        o[col] = pd.to_numeric(o[col], downcast="integer")
    candidata = o["mb"].astype("float32")
    if (np.round(candidata.astype("float64"), 3) == np.round(o["mb"], 3)).all():
        o["mb"] = candidata
    return o


def informe_memoria(original, optimizado):
    antes = original.memory_usage(deep=True).sum() / 1024
    despues = optimizado.memory_usage(deep=True).sum() / 1024
    return {
        "antes_kb": round(antes, 1),
        "despues_kb": round(despues, 1),
        "ahorro_pct": round((1 - despues / antes) * 100, 1),
    }


opt = optimizar(cdr)
print(opt.dtypes)
print(informe_memoria(cdr, opt))
```

## Explicación

`astype` devuelve un DataFrame nuevo, así que el original no cambia. La verificación de `float32` aplica el principio *guarda pequeño solo si no pierdes información*: `float32` tiene unos 7 dígitos de precisión, suficiente para `4000.123` pero no para valores con muchos enteros y decimales.

Con 14 millones de registros, estas optimizaciones pueden bajar el DataFrame de unos 3 GB a menos de 1 GB. Puedes pedir los tipos directamente al leer (`dtype={"tipo": "category", ...}` en `read_csv`), y así el archivo nunca ocupa la memoria "grande".
