Los errores que lanzan excepciones son los fáciles: Python te dice dónde están. Los difíciles son los que **no fallan**: el programa termina feliz y el total está mal. Para esos necesitas un método y una herramienta.

## Un método para cualquier error

1. **Reprodúcelo.** Consigue el dato o el caso exacto que lo provoca. Un error que no puedes repetir no lo puedes arreglar.
2. **Achícalo.** Reduce el caso al mínimo: de un archivo de un millón de registros a los 3 que fallan. Muchas veces, al achicarlo, ves la causa.
3. **Formula una hipótesis.** "Creo que el slicing toma una posición de menos".
4. **Compruébala** mirando los valores reales (con el depurador, no adivinando).
5. **Arregla y deja una prueba** que falle con el error y pase con el arreglo (módulo 10). Así no vuelve.

:::consejo El patito de goma
Explica el código, línea por línea y en voz alta, a alguien… o a un patito de goma. Al verbalizar lo que *debería* hacer cada línea, muy a menudo descubres dónde no lo hace. Funciona sorprendentemente bien.
:::

## El depurador de VS Code

El depurador detiene el programa en la línea que elijas y te deja **mirar todas las variables** y avanzar paso a paso. Es como el visualizador de estas lecciones, pero con tu código real.

:::pasos Tu primera sesión de depuración
:::paso 1 · Pon un punto de interrupción
Haz clic a la izquierda del número de línea (aparece un punto rojo) en la línea donde quieres detenerte. Por ejemplo, dentro del bucle que acumula los minutos.
:::
:::paso 2 · Inicia con F5
Pulsa **F5** y elige **Python Debugger: Current File**. El programa corre normalmente hasta llegar al punto rojo, y se detiene **antes** de ejecutar esa línea.
:::
:::paso 3 · Mira las variables
El panel **Variables** (izquierda) muestra todas las variables y sus valores. Pasa el mouse sobre cualquier variable del código para ver su valor. En **Watch** puedes escribir expresiones, como `linea[35:40]`.
:::
:::paso 4 · Avanza paso a paso
| Tecla | Acción |
|---|---|
| **F10** | Ejecuta la línea actual y pasa a la siguiente (*Step Over*) |
| **F11** | Entra en la función que se llama en esta línea (*Step Into*) |
| **Shift + F11** | Termina la función actual y vuelve a quien la llamó (*Step Out*) |
| **F5** | Continúa hasta el siguiente punto de interrupción |
| **Shift + F5** | Detiene la depuración |
:::
:::paso 5 · Usa la consola de depuración
En la pestaña **Debug Console** puedes escribir código Python mientras el programa está detenido: `int(linea[67:73])`, `len(errores)`… Es la forma más rápida de probar una hipótesis.
:::
:::

## Puntos de interrupción condicionales

Si el error ocurre en el registro 1.534.221, no vas a pulsar F5 un millón de veces. Clic derecho sobre el punto rojo → **Edit Breakpoint** → escribe una condición, por ejemplo:

```python
numero == 1534221
```

o

```python
duracion < 0 and tipo == "VOZ"
```

El programa solo se detendrá cuando la condición sea verdadera.

## breakpoint() en el código

Si ejecutas desde la terminal, puedes escribir `breakpoint()` en la línea donde quieres detenerte. Se abre **pdb**, el depurador de texto de Python:

```python
for numero, linea in enumerate(archivo, start=1):
    if numero == 1534221:
        breakpoint()
    ...
```

| Comando pdb | Acción |
|---|---|
| `p variable` | Muestra el valor |
| `n` | Siguiente línea |
| `s` | Entra en la función |
| `c` | Continúa |
| `l` | Muestra el código alrededor |
| `q` | Sale |

:::error No dejes breakpoint() en el código
Un `breakpoint()` olvidado deja el proceso nocturno detenido esperando que alguien escriba. `ruff` (regla `T100`) puede avisarte.
:::

## print también vale (con método)

Cuando no puedes usar el depurador (en un servidor, por ejemplo), un `print` o un `log.debug` bien puesto sirve, siempre que muestre **valores con contexto**:

```pyrun
registro = "00000000000233027032633040879936   VOZ  NACIONAL     20260913103128000030000000.000CEL97932"
tipo = registro[35:39]   # ¿bug?
print(f"{tipo=}")        # f-string con = muestra el nombre y el valor con comillas
print(f"{registro[35:40]=}")
```

El `=` dentro del f-string (`{tipo=}`) imprime `tipo='VOZ '`: con el nombre y con comillas, que dejan ver los espacios.

:::reto El total que no cuadra
Esta función debería devolver los minutos facturables de **voz** de unos registros de ancho fijo (el tipo va en las posiciones 36 a 40 y la duración en las 68 a 73). Con los tres registros de ejemplo debería dar `3`, pero devuelve `0`. No hay ningún error: el resultado simplemente está mal.

Aplica el método: agrega `print(f"{tipo=}")` y `print(f"{segundos=}")` dentro del bucle, mira los valores reales, formula una hipótesis y corrige **los dos** errores.

```pyreto
def minutos_de_voz(registros):
    total = 0
    for registro in registros:
        tipo = registro[35:39]
        segundos = int(registro[67:73])
        if tipo == "VOZ":
            total += segundos // 60
    return total


REGISTROS = [
    "00000000000233027032633040879936   VOZ  NACIONAL     20260913103128000030000000.000CEL97932",
    "0000000000033001234567             DATOS             20260913110000000000000015.131CEL11111",
    "00000000000430012345673109876543   VOZ  LOCAL        20260913120000000061000000.000CEL22222",
]
print(minutos_de_voz(REGISTROS))
```

:::pista
`tipo=` muestra `'VOZ '`: el corte toma una posición de menos y deja un espacio. Usa `registro[35:40].strip()`. Y una llamada de 30 segundos debe cobrar 1 minuto: recuerda la regla del minuto iniciado, `(segundos + 59) // 60`.
:::

```pyprueba
R1 = "00000000000233027032633040879936   VOZ  NACIONAL     20260913103128000030000000.000CEL97932"
R2 = "0000000000033001234567             DATOS             20260913110000000000000015.131CEL11111"
R3 = "00000000000430012345673109876543   VOZ  LOCAL        20260913120000000061000000.000CEL22222"


def prueba_ejemplo():
    """Con los tres registros da 3 minutos"""
    requiere("minutos_de_voz")
    igual(minutos_de_voz([R1, R2, R3]), 3)


def prueba_minuto_iniciado():
    """Una llamada de 30 segundos cobra 1 minuto"""
    igual(minutos_de_voz([R1]), 1)


def prueba_ignora_datos():
    """Los registros de DATOS no suman"""
    igual(minutos_de_voz([R2]), 0)
```

```pysolucion
def minutos_de_voz(registros):
    total = 0
    for registro in registros:
        tipo = registro[35:40].strip()
        segundos = int(registro[67:73])
        if tipo == "VOZ":
            total += (segundos + 59) // 60
    return total


REGISTROS = [
    "00000000000233027032633040879936   VOZ  NACIONAL     20260913103128000030000000.000CEL97932",
    "0000000000033001234567             DATOS             20260913110000000000000015.131CEL11111",
    "00000000000430012345673109876543   VOZ  LOCAL        20260913120000000061000000.000CEL22222",
]
print(minutos_de_voz(REGISTROS))
```
:::

:::telco El error que no falla
El tipo de error más caro en facturación es el silencioso: un redondeo distinto, un campo leído una posición corrida, un filtro que deja pasar registros duplicados. No hay traceback. Por eso existen las conciliaciones contra `esperado.json` y, más adelante, las pruebas automáticas: son la forma de detectar lo que no explota.
:::

## Cuestionario

? El programa termina sin errores pero el total está mal. ¿Cuál es el primer paso?
- [ ] Reescribir todo desde cero
- [x] Reproducir el error con el caso más pequeño posible
- [ ] Agregar `try/except` en todas las funciones
- [ ] Ejecutarlo de nuevo esperando otro resultado
> Sin un caso reproducible y pequeño es imposible verificar hipótesis. Achicar el problema suele revelar la causa.

? En VS Code, ¿qué hace F10 durante la depuración?
- [x] Ejecuta la línea actual y se detiene en la siguiente
- [ ] Entra en la función de la línea actual
- [ ] Termina el programa
- [ ] Reinicia la depuración
> F10 es *Step Over*: avanza una línea sin entrar en las funciones que llama. F11 sí entra.

? ¿Qué imprime `x = 5; print(f"{x=}")`?
- [ ] `5`
- [ ] `x`
- [x] `x=5`
- [ ] Un error
> El `=` dentro de las llaves imprime la expresión, el signo igual y el valor. Muy útil para depurar.
