Cada vez que resolviste un ejercicio, unas pruebas automáticas te dijeron si estaba bien. Ahora vas a escribirlas tú, para tu propio código.

## ¿Por qué pruebas automáticas?

- **Atrapan errores antes** que los clientes, auditoría o contabilidad.
- **Te dan valor para cambiar el código**: si refactorizas y las pruebas siguen pasando, no rompiste nada.
- **Documentan el comportamiento**: una prueba como `test_llamada_de_0_segundos_no_se_cobra` explica la regla mejor que un comentario.
- **Son baratas de repetir**: probar a mano 30 casos toma una hora; pytest los corre en un segundo, cada vez que quieras.

## Una prueba es una función con assert

```python
# tarifas.py
def minutos_facturables(segundos: int) -> int:
    return (segundos + 59) // 60
```

```python
# test_tarifas.py
from tarifas import minutos_facturables


def test_un_minuto_exacto():
    assert minutos_facturables(60) == 1


def test_un_segundo_se_cobra_como_minuto():
    assert minutos_facturables(1) == 1


def test_llamada_sin_contestar_no_se_cobra():
    assert minutos_facturables(0) == 0
```

pytest **descubre** solo las pruebas: archivos que empiezan con `test_`, y dentro de ellos funciones que empiezan con `test_`. No hace falta registrarlas en ningún lado.

## Ejecutar pytest

```powershell
python -m pytest                       # todas las pruebas de la carpeta actual (y subcarpetas)
python -m pytest tests/test_tarifas.py # un archivo
python -m pytest -k minuto             # solo las que tienen "minuto" en el nombre
python -m pytest -x                    # detenerse en el primer fallo
python -m pytest -v                    # mostrar cada prueba con su resultado
python -m pytest --lf                  # solo las que fallaron la última vez
```

## Leer un fallo

Cuando una prueba falla, pytest muestra exactamente qué esperaba y qué obtuvo:

```text
    def test_un_minuto_exacto():
>       assert minutos_facturables(60) == 1
E       assert 2 == 1
E        +  where 2 = minutos_facturables(60)

test_tarifas.py:5: AssertionError
========================= 1 failed, 2 passed in 0.03s =========================
```

pytest **reescribe** los `assert` para mostrar los valores de cada parte de la expresión. Por eso con pytest basta un `assert` simple: no necesitas funciones especiales como `assertEqual`.

## El patrón AAA: preparar, actuar, verificar

Las pruebas claras siguen tres pasos, a menudo separados por una línea en blanco:

```python
def test_valor_voz_cobra_solo_el_exceso():
    plan = Plan("HOG30", cargo_fijo=35900, minutos_incluidos=300, tarifa_minuto=120)   # Arrange: preparar

    valor = plan.valor_voz(342)                                                       # Act: actuar

    assert valor == 42 * 120                                                          # Assert: verificar
```

:::consejo Una idea por prueba
Una prueba que verifica diez cosas te dice "algo falló" cuando falla. Diez pruebas pequeñas, con nombres descriptivos, te dicen **qué** falló. El nombre de la prueba debería leerse como una regla de negocio.
:::

## Nombres que documentan

:::comparar
:::mal Nombres que no dicen nada
```python
def test_1(): ...
def test_minutos(): ...
def test_caso_raro(): ...
```
:::
:::bien Nombres que explican la regla
```python
def test_61_segundos_se_cobran_como_2_minutos(): ...
def test_plan_ilimitado_no_cobra_exceso(): ...
def test_descuento_no_aplica_en_la_fecha_de_corte(): ...
```
:::
:::

## Dónde van las pruebas

```text
mi-proyecto/
├── src/
│   └── facturacion/
│       ├── reglas.py
│       └── facturas.py
└── tests/
    ├── test_reglas.py
    └── test_facturas.py
```

Un archivo de pruebas por módulo es un buen punto de partida.

:::telco Pruebas con números del negocio
Las mejores pruebas de facturación usan casos que alguien de negocio reconocería: "un cliente HOG30 que habló 342 minutos paga $5.040 adicionales". Si un analista de facturación puede leer tus pruebas y decir "sí, así es la regla", tienes pruebas valiosas.
:::

## Cuestionario

? ¿Cómo encuentra pytest las pruebas?
- [ ] Hay que registrarlas en un archivo de configuración
- [x] Busca archivos `test_*.py` y dentro de ellos funciones `test_*`
- [ ] Ejecuta todas las funciones del proyecto
- [ ] Solo las que tienen el decorador `@test`
> El descubrimiento es por convención de nombres.

? ¿Qué hace `python -m pytest -x`?
- [ ] Ejecuta las pruebas en paralelo
- [x] Se detiene en la primera prueba que falla
- [ ] Muestra la cobertura
- [ ] Ignora los fallos
> Muy útil cuando hay muchos fallos y quieres concentrarte en el primero.

? ¿Cuál es el mejor nombre para una prueba?
- [ ] `test_caso3`
- [ ] `test_funcion`
- [x] `test_plan_ilimitado_no_cobra_exceso_de_voz`
- [ ] `prueba`
> Un nombre descriptivo documenta la regla y, al fallar, te dice exactamente qué se rompió.
