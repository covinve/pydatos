En el módulo 16 usaste SQL para consultar **archivos**. Una **base de datos** va más allá: guarda los datos de forma permanente, los protege con reglas, permite que muchos programas los lean y escriban a la vez, y encuentra un registro entre millones en milisegundos gracias a los **índices**.

En las telcos, la facturación vive en bases de datos (Oracle, PostgreSQL, SQL Server). Saber trabajar con ellas desde Python te permite automatizar extracciones, cargas y conciliaciones.

## SQLite: una base de datos en un archivo

**SQLite** viene incluida en Python (`import sqlite3`), no necesita servidor ni permisos de administrador y guarda todo en **un solo archivo**. Es perfecta para aprender, para prototipos, para pruebas y para herramientas personales. El SQL que aprendas aquí sirve casi igual en PostgreSQL.

```pyrun
import sqlite3

con = sqlite3.connect(":memory:")       # en memoria; usa "telco.db" para un archivo
con.execute("""
    CREATE TABLE planes (
        plan_id TEXT PRIMARY KEY,
        nombre  TEXT NOT NULL,
        cargo_fijo INTEGER NOT NULL
    )
""")
con.execute("INSERT INTO planes VALUES ('BAS10', 'Básico 10', 25900)")
con.execute("INSERT INTO planes VALUES ('ILIM', 'Ilimitado', 89900)")
con.commit()                            # confirma los cambios

for fila in con.execute("SELECT plan_id, cargo_fijo FROM planes ORDER BY cargo_fijo DESC"):
    print(fila)
```

:::pasos El ciclo de trabajo con una base de datos
:::paso 1. Conectar
`con = sqlite3.connect("telco.db")` abre (o crea) el archivo. Con PostgreSQL sería una dirección de servidor, usuario y contraseña.
:::
:::paso 2. Ejecutar
`con.execute(sql, parametros)` envía una instrucción y devuelve un **cursor**, que recorre las filas del resultado.
:::
:::paso 3. Confirmar
Los cambios (`INSERT`, `UPDATE`, `DELETE`) quedan pendientes hasta `con.commit()`. Si algo falla, `con.rollback()` los deshace.
:::
:::paso 4. Cerrar
`con.close()` libera el archivo. Si no confirmaste, los cambios pendientes se pierden.
:::
:::

En la conexión `con` (en memoria):

1. Crea la tabla `lineas` con las columnas `linea` (texto, clave primaria), `plan_id` (texto, obligatorio) y `activa` (entero).

| linea | plan_id | activa |
|---|---|---|
| 3001112233 | HOG30 | 1 |
| 3104445566 | ILIM | 1 |
| 3157778899 | BAS10 | 0 |

3. Crea `activas`: cuántas líneas tienen `activa = 1`, consultándolo con SQL.


:::pista
`CREATE TABLE lineas (linea TEXT PRIMARY KEY, plan_id TEXT NOT NULL, activa INTEGER)`. Para insertar varias: `con.executemany("INSERT INTO lineas VALUES (?, ?, ?)", filas)` y luego `con.commit()`. El conteo: `con.execute("SELECT COUNT(*) FROM lineas WHERE activa = 1").fetchone()[0]`.
:::

```pyprueba
def prueba_tabla():
    """La tabla tiene las tres líneas"""
    requiere("con")
    filas = con.execute("SELECT linea, plan_id, activa FROM lineas ORDER BY linea").fetchall()
    igual(filas, [("3001112233", "HOG30", 1), ("3104445566", "ILIM", 1), ("3157778899", "BAS10", 0)])


def prueba_clave_primaria():
    """linea es la clave primaria"""
    columnas = con.execute("PRAGMA table_info(lineas)").fetchall()
    pk = [c[1] for c in columnas if c[5]]
    igual(pk, ["linea"], "clave primaria")


def prueba_activas():
    """activas = 2"""
    requiere("activas")
    igual(activas, 2)
```

```pysolucion
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE lineas (linea TEXT PRIMARY KEY, plan_id TEXT NOT NULL, activa INTEGER)")
con.executemany("INSERT INTO lineas VALUES (?, ?, ?)", [
    ("3001112233", "HOG30", 1),
    ("3104445566", "ILIM", 1),
    ("3157778899", "BAS10", 0),
])
con.commit()
activas = con.execute("SELECT COUNT(*) FROM lineas WHERE activa = 1").fetchone()[0]

print(activas)
```

## Leer resultados

```pyrun
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE cdr (cdr_id INTEGER, linea TEXT, tipo TEXT, duracion_seg INTEGER)")
con.executemany("INSERT INTO cdr VALUES (?, ?, ?, ?)", [
    (1, "3001112233", "VOZ", 125), (2, "3001112233", "SMS", 0), (3, "3104445566", "VOZ", 61),
])

cur = con.execute("SELECT linea, COUNT(*), SUM(duracion_seg) FROM cdr GROUP BY linea")
print(cur.fetchall())                    # lista de tuplas

print(con.execute("SELECT COUNT(*) FROM cdr").fetchone()[0])   # un solo valor

con.row_factory = sqlite3.Row            # filas que se leen por nombre
fila = con.execute("SELECT * FROM cdr WHERE cdr_id = 3").fetchone()
print(fila["linea"], fila["duracion_seg"], dict(fila))
```

| Método | Devuelve |
|---|---|
| `cur.fetchone()` | La siguiente fila (o `None`) |
| `cur.fetchall()` | Todas las filas restantes (¡cuidado con millones!) |
| `cur.fetchmany(10_000)` | Las siguientes 10 000: para recorrer resultados grandes por lotes |
| `for fila in cur:` | Una a una, sin cargar todo en memoria |

:::reto Lee los resultados
La tabla `cdr` ya tiene datos. Con consultas SQL:

- `por_tipo`: un diccionario `{tipo: cantidad}` (usa `GROUP BY` y `fetchall`);
- `total_voz`: la suma de `duracion_seg` de la VOZ (un solo valor, con `fetchone`);
- `cdr_4`: el registro con `cdr_id = 4` como **diccionario** (usa `sqlite3.Row`).

```pyreto
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE cdr (cdr_id INTEGER, linea TEXT, tipo TEXT, duracion_seg INTEGER)")
con.executemany("INSERT INTO cdr VALUES (?, ?, ?, ?)", [
    (1, "3001112233", "VOZ", 125), (2, "3001112233", "SMS", 0), (3, "3104445566", "VOZ", 61),
    (4, "3104445566", "DATOS", 900), (5, "3001112233", "VOZ", 300),
])

# por_tipo, total_voz y cdr_4

print(por_tipo, total_voz, cdr_4)
```

:::pista
`dict(con.execute("SELECT tipo, COUNT(*) FROM cdr GROUP BY tipo").fetchall())`. Para leer por nombre: `con.row_factory = sqlite3.Row` y `dict(con.execute("SELECT * FROM cdr WHERE cdr_id = ?", (4,)).fetchone())`.
:::

```pyprueba
def prueba_por_tipo():
    """por_tipo cuenta cada tipo"""
    requiere("por_tipo")
    igual(dict(por_tipo), {"VOZ": 3, "SMS": 1, "DATOS": 1})


def prueba_total_voz():
    """total_voz = 486"""
    requiere("total_voz")
    igual(total_voz, 486)


def prueba_cdr_4():
    """cdr_4 es un diccionario con el registro 4"""
    requiere("cdr_4")
    igual(dict(cdr_4), {"cdr_id": 4, "linea": "3104445566", "tipo": "DATOS", "duracion_seg": 900})
```

```pysolucion
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE cdr (cdr_id INTEGER, linea TEXT, tipo TEXT, duracion_seg INTEGER)")
con.executemany("INSERT INTO cdr VALUES (?, ?, ?, ?)", [
    (1, "3001112233", "VOZ", 125), (2, "3001112233", "SMS", 0), (3, "3104445566", "VOZ", 61),
    (4, "3104445566", "DATOS", 900), (5, "3001112233", "VOZ", 300),
])

por_tipo = dict(con.execute("SELECT tipo, COUNT(*) FROM cdr GROUP BY tipo").fetchall())
total_voz = con.execute("SELECT SUM(duracion_seg) FROM cdr WHERE tipo = 'VOZ'").fetchone()[0]
con.row_factory = sqlite3.Row
cdr_4 = dict(con.execute("SELECT * FROM cdr WHERE cdr_id = ?", (4,)).fetchone())

print(por_tipo, total_voz, cdr_4)
```

## Consultas parametrizadas

Nunca armes el SQL pegando valores con `f"..."` o `+`. Usa **marcadores** `?` y pasa los valores aparte:

:::comparar
:::mal Pegar el valor en el texto
```python
linea = input("Línea: ")
con.execute(f"SELECT * FROM cdr WHERE linea = '{linea}'")
```
Si alguien escribe `' OR '1'='1`, la consulta queda `WHERE linea = '' OR '1'='1'` y devuelve **todo**. Con `'; DROP TABLE cdr; --` podría borrar la tabla.
:::
:::bien Marcadores y parámetros
```python
linea = input("Línea: ")
con.execute("SELECT * FROM cdr WHERE linea = ?", (linea,))
```
El valor viaja separado del SQL: la base de datos nunca lo interpreta como código. Además maneja solita comillas, fechas y nulos.
:::
:::

Esto se llama **inyección SQL** y es una de las vulnerabilidades más comunes del mundo. La regla es simple: **valores siempre con parámetros**. Los nombres de tablas y columnas no se pueden parametrizar; si vienen de fuera, compáralos contra una lista de nombres permitidos.

```pyrun
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE cdr (linea TEXT, tipo TEXT)")
con.executemany("INSERT INTO cdr VALUES (?, ?)", [("3001", "VOZ"), ("3002", "SMS")])

malicioso = "x' OR '1'='1"
print("Pegado:     ", con.execute(f"SELECT * FROM cdr WHERE linea = '{malicioso}'").fetchall())
print("Parametrizado:", con.execute("SELECT * FROM cdr WHERE linea = ?", (malicioso,)).fetchall())
print("Con nombre:  ", con.execute("SELECT * FROM cdr WHERE tipo = :t", {"t": "VOZ"}).fetchall())
```

:::consejo La tupla de un elemento
`(linea,)` con coma: `(linea)` sin coma es solo `linea` entre paréntesis, y sqlite3 intentaría tomar cada carácter como un parámetro distinto.
:::

:::reto Cierra la puerta a la inyección
Esta función busca los CDR de una línea, pero pega el valor en el SQL: con la "línea" `x' OR '1'='1` devuelve **todos** los registros. Corrígela con parámetros. Agrega además el parámetro `tipo`, también con marcador.

```pyreto
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE cdr (linea TEXT, tipo TEXT, duracion_seg INTEGER)")
con.executemany("INSERT INTO cdr VALUES (?, ?, ?)", [
    ("3001", "VOZ", 125), ("3001", "SMS", 0), ("3002", "VOZ", 61),
])


def buscar(con, linea, tipo):
    return con.execute(f"SELECT * FROM cdr WHERE linea = '{linea}'").fetchall()


print(buscar(con, "3001", "VOZ"))             # [('3001', 'VOZ', 125)]
print(buscar(con, "x' OR '1'='1", "VOZ"))     # []
```

:::pista
`con.execute("SELECT * FROM cdr WHERE linea = ? AND tipo = ?", (linea, tipo)).fetchall()`. Sin f-string: los valores viajan en la tupla.
:::

```pyprueba
import sqlite3


def _con():
    c = sqlite3.connect(":memory:")
    c.execute("CREATE TABLE cdr (linea TEXT, tipo TEXT, duracion_seg INTEGER)")
    c.executemany("INSERT INTO cdr VALUES (?, ?, ?)", [("3001", "VOZ", 125), ("3001", "SMS", 0), ("3002", "VOZ", 61)])
    return c


def prueba_busca():
    """Filtra por línea y tipo"""
    requiere("buscar")
    igual(buscar(_con(), "3001", "VOZ"), [("3001", "VOZ", 125)])
    igual(buscar(_con(), "3001", "SMS"), [("3001", "SMS", 0)])


def prueba_inyeccion():
    """La inyección no devuelve nada"""
    igual(buscar(_con(), "x' OR '1'='1", "VOZ"), [])
    igual(buscar(_con(), "3001", "x' OR '1'='1"), [])
```

```pysolucion
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE cdr (linea TEXT, tipo TEXT, duracion_seg INTEGER)")
con.executemany("INSERT INTO cdr VALUES (?, ?, ?)", [
    ("3001", "VOZ", 125), ("3001", "SMS", 0), ("3002", "VOZ", 61),

print(buscar(con, "3001", "VOZ"))             # [('3001', 'VOZ', 125)]
print(buscar(con, "x' OR '1'='1", "VOZ"))     # []
```

## `with` y las conexiones

`with con:` abre una **transacción**: si el bloque termina bien hace `commit()`, y si hay una excepción hace `rollback()`. Ojo: **no cierra** la conexión.

```python
con = sqlite3.connect("telco.db")
with con:                                   # commit o rollback automático
    con.execute("UPDATE facturas SET estado = 'PAGADA' WHERE factura_id = ?", (1234,))
con.close()
```

:::telco Tu primera herramienta con base de datos
Un archivo `.db` de SQLite es una forma excelente de guardar los resultados de tus procesos diarios (resúmenes, rechazos, conciliaciones) y consultarlos después con SQL, sin pedirle nada a nadie ni instalar nada en la oficina. Para abrirlo visualmente, la extensión **SQLite Viewer** de VS Code no requiere permisos de administrador.

## Cuestionario

? ¿Cuándo se guardan en el archivo los cambios de un `INSERT`?
- [ ] Inmediatamente
- [x] Al hacer `con.commit()` (o al terminar bien un bloque `with con:`)
- [ ] Al hacer `con.close()`
- [ ] Al hacer `fetchall()`
> Hasta el `commit`, los cambios están pendientes y se pueden deshacer con `rollback()`.

? ¿Cuál es la forma segura de buscar una línea que escribió un usuario?
- [ ] `con.execute(f"SELECT * FROM cdr WHERE linea = '{linea}'")`
- [ ] `con.execute("SELECT * FROM cdr WHERE linea = '" + linea + "'")`
- [x] `con.execute("SELECT * FROM cdr WHERE linea = ?", (linea,))`
- [ ] `con.execute("SELECT * FROM cdr WHERE linea = " + repr(linea))`
> Con parámetros el valor nunca se interpreta como SQL, así que la inyección es imposible.

? Un resultado tiene 30 millones de filas. ¿Cómo lo recorres?
- [ ] `fetchall()` y un `for`
- [x] Iterando el cursor o con `fetchmany()` por lotes
- [ ] Con `fetchone()` una sola vez
- [ ] No se puede desde Python
> `fetchall()` cargaría las 30 millones de tuplas en memoria; iterar o leer por lotes mantiene la memoria constante.
