## Enunciado

`ejercicios/m20-e8/repositorio_sqlite.py` es un adaptador SQLite de clientes que **funciona bien**. Tu trabajo es escribir **su suite de pruebas de integración**, contra SQLite de verdad:

1. En `tests/conftest.py`, los *fixtures*:
   - `datos_prueba` con `scope="session"`: la carpeta `tests/datos_prueba` (tiene un `clientes.csv` en latin-1).
   - `repo`: un `ClientesSQLite` sobre un archivo en `tmp_path`, que se **cierra** después de la prueba (`yield` y `repo.cerrar()`).
2. En `tests/test_repositorio.py`, al menos **6** pruebas que usen esos *fixtures*.

`test_zz_comprobacion.py` ejecuta tu suite contra el adaptador correcto (debe pasar) y contra **siete** versiones con errores sembrados (cada una debe hacer fallar tu suite). No lo modifiques.

Pregúntate qué podría estar mal en un adaptador de base de datos: ¿el orden?, ¿los tipos que vuelven?, ¿un segundo `guardar` de la misma línea?, ¿los datos sobreviven a cerrar y reabrir?, ¿las tildes del CSV?

## Pista 1

```python
# tests/conftest.py
@pytest.fixture(scope="session")
def datos_prueba():
    return Path(__file__).parent / "datos_prueba"


@pytest.fixture
def repo(tmp_path):
    r = ClientesSQLite(tmp_path / "clientes.db")
    yield r
    r.cerrar()
```

Para probar la persistencia necesitas **otra** conexión al mismo archivo: `ClientesSQLite(ruta)` de nuevo. Puedes obtener la ruta del archivo con `repo.con.execute("PRAGMA database_list").fetchone()[2]`, o hacer un *fixture* `ruta_bd` que usen ambos.

## Solución

```python tests/conftest.py
"""Fixtures compartidos de las pruebas del adaptador SQLite."""

import sys
from pathlib import Path

import pytest

sys.path.insert(0, str(Path(__file__).resolve().parent.parent))   # para importar repositorio_sqlite

from repositorio_sqlite import ClientesSQLite  # noqa: E402


@pytest.fixture(scope="session")
def datos_prueba():
    return Path(__file__).parent / "datos_prueba"


@pytest.fixture
def ruta_bd(tmp_path):
    return tmp_path / "clientes.db"


@pytest.fixture
def repo(ruta_bd):
    r = ClientesSQLite(ruta_bd)
    yield r
    r.cerrar()
```

```python tests/test_repositorio.py
"""Pruebas de integración del adaptador ClientesSQLite."""

import csv
from datetime import date

import pytest

from repositorio_sqlite import Cliente, ClienteNoEncontrado, ClientesSQLite, cargar_csv

ANA = Cliente("3001112233", "Ana Gómez", "HOG30", date(2021, 3, 4))
LUIS = Cliente("3001112200", "Luis Díaz", "HOG30", date(2022, 7, 1))
EMPRESA = Cliente("3104445566", "Ñandú S.A.S.", "EMP100", date(2019, 1, 15))


def test_guardar_y_obtener(repo):
    repo.guardar(ANA)
    obtenido = repo.obtener(ANA.linea)
    assert obtenido == ANA
    assert isinstance(obtenido.fecha_alta, date)


def test_no_encontrado(repo):
    with pytest.raises(ClienteNoEncontrado):
        repo.obtener("3000000000")


def test_guardar_reemplaza(repo):
    repo.guardar(ANA)
    repo.guardar(Cliente(ANA.linea, ANA.nombre, "ILIM", ANA.fecha_alta))
    assert repo.contar() == 1
    assert repo.obtener(ANA.linea).plan_id == "ILIM"


def test_del_plan_ordenado(repo):
    for c in (ANA, EMPRESA, LUIS):
        repo.guardar(c)
    assert repo.del_plan("HOG30") == [LUIS, ANA]
    assert repo.del_plan("OTRO") == []


def test_persiste_al_reabrir(repo, ruta_bd):
    repo.guardar(EMPRESA)
    otro = ClientesSQLite(ruta_bd)
    try:
        assert otro.obtener(EMPRESA.linea) == EMPRESA
    finally:
        otro.cerrar()


def test_cargar_csv(repo, datos_prueba):
    with open(datos_prueba / "clientes.csv", encoding="latin-1", newline="") as f:
        filas = list(csv.DictReader(f))
    assert cargar_csv(repo, datos_prueba / "clientes.csv") == len(filas)
    assert repo.contar() == len(filas)
    con_tilde = next(f for f in filas if any(ch in f["nombre"] for ch in "áéíóúñÁÉÍÓÚÑ"))
    assert repo.obtener(con_tilde["linea"]).nombre == con_tilde["nombre"]
```

## Explicación

Cada mutante representa un error real de adaptadores de base de datos, y cada uno necesitó una prueba distinta:

| Mutante | Prueba que lo atrapa |
|---|---|
| Orden invertido | `test_del_plan_ordenado` (con al menos dos clientes en desorden) |
| Fecha como texto | `isinstance(obtenido.fecha_alta, date)` y la igualdad con el objeto original |
| `guardar` no reemplaza | `test_guardar_reemplaza` |
| No confirma | `test_persiste_al_reabrir`: con la **misma** conexión, ¡los datos sin confirmar sí se ven! |
| `obtener` devuelve `None` | `test_no_encontrado` |
| CSV con utf-8 | Comparar un nombre con tilde contra el CSV leído en latin-1 |
| Conteo equivocado | Comparar el retorno de `cargar_csv` con la cantidad real de filas |

La persistencia es la lección más fina: un adaptador que olvida el `commit` pasa todas las pruebas que usan una sola conexión, y pierde los datos en producción. Solo una prueba de **integración** (que reabre el archivo de verdad) lo detecta.

Los *fixtures* en `conftest.py` mantienen las pruebas cortas y enfocadas: cada una pide lo que necesita (`repo`, `ruta_bd`, `datos_prueba`) y pytest se encarga de crearlo, entregarlo limpio y cerrarlo al terminar.
