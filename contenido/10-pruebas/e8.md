## Enunciado

El módulo `validacion.py` (en tu carpeta de trabajo) tiene `clasificar_cdr(linea_origen, tipo, duracion_seg, fecha_inicio)`, el clasificador del módulo 3. Devuelve el **primer** problema en este orden: `"linea_vacia"`, `"tipo_desconocido"`, `"duracion_negativa"`, `"fecha_invalida"`, o `"valido"`. La fecha debe tener formato `AAAA-MM-DD HH:MM:SS` y ser real.

Escribe la batería de pruebas más fuerte que puedas. El curso la ejecutará contra **ocho mutantes**, cada uno con un error distinto y sutil. Para aprobar, tus pruebas deben pasar con el código correcto y **atrapar a los ocho**.

No te diremos cuáles son los mutantes: piensa como alguien que se equivoca al programar la regla.

## Solución

```python
import pytest

from validacion import clasificar_cdr

FECHA = "2026-09-13 10:31:28"


@pytest.mark.parametrize(
    ("linea", "tipo", "duracion", "fecha", "esperado"),
    [
        ("3001234567", "VOZ", 125, FECHA, "valido"),
        ("3001234567", "SMS", 0, FECHA, "valido"),
        ("3001234567", "DATOS", 0, FECHA, "valido"),
        ("3001234567", "VOZ", 100_000, FECHA, "valido"),
        ("", "VOZ", 10, FECHA, "linea_vacia"),
        ("   ", "VOZ", 10, FECHA, "linea_vacia"),
        ("3001234567", "VOX", 10, FECHA, "tipo_desconocido"),
        ("3001234567", "voz", 10, FECHA, "tipo_desconocido"),
        ("3001234567", "VOZ", -1, FECHA, "duracion_negativa"),
        ("3001234567", "VOZ", 10, "2026-09-31 10:15:00", "fecha_invalida"),
        ("3001234567", "VOZ", 10, "2026-09-13 10:31:60", "fecha_invalida"),
        ("3001234567", "VOZ", 10, "2026/09/13 10:31:28", "fecha_invalida"),
        ("", "VOX", -5, "malo", "linea_vacia"),
        ("3001234567", "VOX", -5, "malo", "tipo_desconocido"),
        ("3001234567", "SMS", -5, "malo", "duracion_negativa"),
    ],
)
def test_clasificar_cdr(linea, tipo, duracion, fecha, esperado):
    assert clasificar_cdr(linea, tipo, duracion, fecha) == esperado
```

## Explicación

Los ocho mutantes representan errores reales y frecuentes:

| Mutante | Error | Caso que lo atrapa |
|---|---|---|
| 1 | No quita espacios antes de ver si la línea está vacía | `"   "` |
| 2 | `<=` en lugar de `<` | duración 0 |
| 3 | Olvidó un tipo válido | un `SMS` válido |
| 4 | Ignora los segundos de la fecha | `:60` en los segundos |
| 5 | La validación de fecha nunca falla | cualquier fecha inválida |
| 6 | Revisa las reglas en otro orden | un CDR con varios errores |
| 7 | Acepta minúsculas | `"voz"` |
| 8 | Inventa un límite de duración | una llamada muy larga y válida |

Cuatro de los ocho solo se atrapan con casos que la mayoría no escribiría a la primera: espacios, el límite exacto, varios errores juntos y valores inusuales pero válidos. Pensar en **cómo podría fallar** el código es la habilidad central de quien escribe buenas pruebas.
