El peor momento para descubrir que `TELCO_UMBRAL=dos` no es un número es a las 6:47, después de procesar 15 GB. **pydantic-settings** lee la configuración de todas las fuentes, la **convierte** a los tipos correctos y la **valida** al arrancar: si algo está mal, el programa no empieza y te dice exactamente qué.

## Una clase de configuración

```python
from pathlib import Path

from pydantic import Field, SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict


class Config(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="TELCO_", env_file=".env", env_file_encoding="utf-8")

    datos: Path = Path("datos")
    umbral_rechazo: float = Field(5.0, ge=0, le=100)
    tamano_lote: int = Field(100_000, gt=0)
    enviar_alertas: bool = False
    correos_alerta: list[str] = []
    db_url: SecretStr | None = None


config = Config()                          # lee entorno + .env, convierte y valida
print(config.umbral_rechazo, config.datos)
print(config.db_url)                       # SecretStr('**********')
url = config.db_url.get_secret_value()     # el valor real, solo donde se necesita
```

| Variable de entorno | Campo | Conversión |
|---|---|---|
| `TELCO_DATOS=D:/cdr` | `datos` | `Path("D:/cdr")` |
| `TELCO_UMBRAL_RECHAZO=2.5` | `umbral_rechazo` | `2.5` (y verifica 0–100) |
| `TELCO_ENVIAR_ALERTAS=true` | `enviar_alertas` | `True` (acepta `true`, `1`, `yes`, `on`…) |
| `TELCO_CORREOS_ALERTA=["a@x.co","b@x.co"]` | `correos_alerta` | Lista (en formato JSON) |
| `TELCO_DB_URL=postgresql://...` | `db_url` | `SecretStr`: no se imprime |

## Errores claros al arrancar

```text
$ set TELCO_UMBRAL_RECHAZO=dos
$ python -m conciliacion
pydantic_core._pydantic_core.ValidationError: 1 validation error for Config
umbral_rechazo
  Input should be a valid number, unable to parse string as a number [type=float_parsing, input_value='dos', input_type=str]
```

Compáralo con un `float(os.environ["TELCO_UMBRAL"])` perdido en la línea 340: aquí el error dice **qué** campo, **qué** valor llegó y **qué** se esperaba, antes de tocar un solo archivo.

## Validaciones propias

```python
from pydantic import field_validator


class Config(BaseSettings):
    ...
    periodo: str = "202609"
    memoria_duckdb: str = "4GB"

    @field_validator("periodo")
    @classmethod
    def periodo_valido(cls, valor: str) -> str:
        if len(valor) != 6 or not valor.isdigit() or not 1 <= int(valor[4:]) <= 12:
            raise ValueError("el periodo debe tener formato AAAAMM")
        return valor

    @field_validator("memoria_duckdb")
    @classmethod
    def memoria_valida(cls, valor: str) -> str:
        if not valor.upper().endswith(("MB", "GB")) or not valor[:-2].isdigit():
            raise ValueError("usa un formato como 512MB u 8GB")
        return valor.upper()
```

## Precedencia y argumentos

Por defecto, pydantic-settings aplica: **argumentos al crear** `Config(umbral_rechazo=1.5)` > variables de entorno > `.env` > valores por defecto. Así, en la CLI basta con pasar lo que el usuario escribió:

```python
@app.command()
def conciliar(umbral: float | None = None):
    sobrescritos = {"umbral_rechazo": umbral} if umbral is not None else {}
    config = Config(**sobrescritos)
    ...
```

Para agregar un archivo TOML como fuente intermedia, `SettingsConfigDict(toml_file="config.toml")` y sobrescribir `settings_customise_sources` (lo harás en el ejercicio 9), o leerlo tú con `tomllib` y pasarlo como base.

:::capo Configuración inmutable y en un solo lugar
Crea la configuración **una vez**, al arrancar (en la raíz de composición del módulo 19), y pásala a quien la necesite. Si cada función llama `Config()` por su cuenta, el `.env` se lee mil veces y las pruebas tienen que parchear en mil lugares. Con `model_config = SettingsConfigDict(frozen=True, ...)` nadie puede cambiarla a mitad del proceso.
:::

## Cuestionario

? ¿Cuándo detecta pydantic-settings que `TELCO_UMBRAL_RECHAZO=dos` no es un número?
- [ ] Al usar el valor por primera vez
- [x] Al crear `Config()`, al arrancar el programa
- [ ] Nunca: lo guarda como texto
- [ ] Al terminar el proceso
> La validación ocurre al construir el objeto, antes de que empiece el trabajo.

? ¿Para qué sirve `SecretStr`?
- [ ] Para cifrar la contraseña en el disco
- [x] Para que el valor no aparezca al imprimir o registrar la configuración; se obtiene con `get_secret_value()`
- [ ] Para generar contraseñas
- [ ] Para guardar el secreto en Git de forma segura
> Evita filtraciones accidentales en `print`, logs y mensajes de error.

? Con `env_prefix="TELCO_"`, ¿qué variable llena el campo `tamano_lote`?
- [ ] `tamano_lote`
- [ ] `TAMANO_LOTE`
- [x] `TELCO_TAMANO_LOTE`
- [ ] `TELCO.tamano_lote`
> El prefijo se antepone al nombre del campo (sin distinguir mayúsculas).
