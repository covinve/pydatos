Las herramientas de calidad solo sirven si se usan **siempre**. La forma de lograrlo es que no dependan de tu memoria: que se ejecuten solas antes de cada *commit* y en cada *push*.

## ruff: estilo y errores en un solo comando

**ruff** reemplaza a varias herramientas (flake8, isort, black…) y es rapidísimo:

```powershell
ruff check .            # busca problemas
ruff check . --fix      # corrige los que se pueden corregir solos
ruff format .           # formatea el código (estilo uniforme)
```

```text
validador.py:3:8: F401 [*] `os` imported but unused
validador.py:21:5: E722 Do not use bare `except`
validador.py:40:12: B006 Do not use mutable data structures for argument defaults
Found 3 errors.
[*] 1 fixable with the `--fix` option.
```

Esos tres son errores reales que viste en el curso: un `import` que sobra, un `except:` que se traga todo (módulo 7) y una lista como valor por defecto (módulo 5).

```toml
# pyproject.toml
[tool.ruff]
line-length = 110

[tool.ruff.lint]
select = ["E", "F", "W", "I", "B", "UP", "SIM", "PL"]   # estilo, errores, imports, bugs, modernización…
ignore = ["PLR2004"]                                     # números mágicos: en reglas de negocio son normales
```

## pre-commit: verificar antes de confirmar

**pre-commit** ejecuta verificaciones automáticamente cada vez que haces `git commit`; si algo falla, el *commit* no se hace:

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.6.9
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.6.0
    hooks:
      - id: check-added-large-files       # evita subir por error un CSV de 2 GB
        args: [--maxkb=5000]
      - id: detect-private-key            # evita subir llaves privadas
      - id: end-of-file-fixer
      - id: trailing-whitespace
```

```powershell
pip install pre-commit
pre-commit install            # una vez por repositorio: instala el gancho en .git/hooks
pre-commit run --all-files    # ejecutarlo a mano sobre todo
```

Funciona sin permisos de administrador: solo vive en tu entorno virtual y en la carpeta `.git` del proyecto.

:::telco La red contra los accidentes
`check-added-large-files` y `detect-private-key` te protegen del peor error posible en un repositorio público: subir datos reales de clientes o una contraseña. Agrega también `datos/`, `salidas/` y `.env` a `.gitignore`, y nunca hagas `git add .` sin revisar `git status` antes.
:::

## GitHub Actions: verificar en cada push

GitHub ejecuta gratis (para repositorios públicos) un *workflow* cada vez que subes cambios: crea una máquina limpia, instala tu proyecto y corre las pruebas. Si algo falla, te avisa y marca el *commit* con una ❌.

```yaml
# .github/workflows/pruebas.yml
name: Pruebas

on:
  push:
    branches: [main]
  pull_request:

jobs:
  pruebas:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest]      # la oficina usa Windows: pruébalo también
        python-version: ["3.12", "3.13"]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python-version }}
          cache: pip
      - run: pip install -e ".[dev]"
      - run: ruff check .
      - run: mypy src
      - run: pytest --cov=src --cov-report=term-missing
```

:::pasos Qué pasa en cada push
:::paso 1. Disparo
Haces `git push`. GitHub ve el archivo en `.github/workflows/` y arranca el *workflow*.
:::
:::paso 2. Matriz
Crea cuatro máquinas limpias: Ubuntu y Windows, con Python 3.12 y 3.13. Así detectas "en mi computador funciona" (una ruta con `\`, una librería que olvidaste en `pyproject.toml`).
:::
:::paso 3. Pasos
En cada una: descarga el código, instala, ejecuta ruff, mypy y pytest. Si un paso falla, la máquina se detiene con ❌.
:::
:::paso 4. Resultado
En la pestaña **Actions** del repositorio ves cada ejecución con su registro completo. En un *pull request*, GitHub muestra el resultado antes de que lo unas.
:::
:::

:::reto Escribe tu workflow
Escribe en la variable `workflow` el YAML de un *workflow* de GitHub Actions llamado `Calidad` que (las pruebas lo leen con `yaml.safe_load`):

- se dispare en `push` a `main` y en `pull_request`;
- tenga un trabajo `verificar` que corra en una **matriz** con `ubuntu-latest` y `windows-latest`, y Python `"3.12"`;
- en sus pasos use `actions/checkout@v4` y `actions/setup-python@v5`, instale con `pip install -e ".[dev]"` y ejecute `ruff check .` y `pytest`.

```pyreto
workflow = """

"""
```

:::pista
Copia la estructura del ejemplo de la lección y ajústala: `jobs:` → `verificar:` → `runs-on: ${{ matrix.os }}` y `strategy: matrix: os: [...]`. Los pasos que ejecutan comandos van con `- run: ...`. Ojo: YAML lee `on` como palabra clave; aquí puedes escribirla normal.
:::

```pyprueba
import yaml


def _leer():
    try:
        datos = yaml.safe_load(workflow)
    except yaml.YAMLError as e:
        raise AssertionError(f"El YAML tiene un error de formato: {e}") from None
    assert isinstance(datos, dict), "El workflow debe ser un diccionario YAML"
    return datos


def prueba_disparo():
    """Se dispara en push a main y en pull_request"""
    datos = _leer()
    igual(datos.get("name"), "Calidad", "name")
    disparo = datos.get("on", datos.get(True))
    assert isinstance(disparo, dict), "Falta la sección on:"
    igual(disparo.get("push", {}).get("branches"), ["main"], "push.branches")
    assert "pull_request" in disparo, "Falta pull_request"


def prueba_matriz():
    """El trabajo verificar corre en Ubuntu y Windows"""
    trabajo = _leer().get("jobs", {}).get("verificar")
    assert trabajo, "Falta el trabajo verificar"
    matriz = trabajo.get("strategy", {}).get("matrix", {})
    igual(sorted(matriz.get("os", [])), ["ubuntu-latest", "windows-latest"], "matrix.os")
    igual([str(v) for v in matriz.get("python-version", [])], ["3.12"], "matrix.python-version")


def prueba_pasos():
    """Los pasos instalan y verifican"""
    pasos = _leer()["jobs"]["verificar"].get("steps", [])
    usos = [p.get("uses", "") for p in pasos]
    comandos = " | ".join(p.get("run", "") for p in pasos)
    assert "actions/checkout@v4" in usos and "actions/setup-python@v5" in usos, "Usa checkout@v4 y setup-python@v5"
    for comando in ('pip install -e ".[dev]"', "ruff check .", "pytest"):
        assert comando in comandos, f"Falta el paso: {comando}"
```

```pysolucion

  push:
    branches: [main]

```

:::consejo Las dependencias de desarrollo
En `pyproject.toml`, separa lo que necesita el programa de lo que necesitas para desarrollarlo:

```toml
[project.optional-dependencies]
dev = ["pytest", "pytest-cov", "mypy", "ruff", "pandas-stubs"]
```

`pip install -e ".[dev]"` instala ambas. Lo verás a fondo en el módulo 21.
