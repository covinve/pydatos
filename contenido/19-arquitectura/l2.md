El dominio debe leerse casi como el reglamento de facturación. Para eso, los conceptos del negocio (dinero, periodo, plan, factura) se vuelven **tipos** con nombre, en lugar de números y textos sueltos.

## Objetos de valor

Un **objeto de valor** se define por su contenido: dos `Periodo("202609")` son el mismo periodo. Son **inmutables** y se validan al crearlos, así que si existe, es válido.

```pyrun
from dataclasses import dataclass


@dataclass(frozen=True, order=True)
class Periodo:
    valor: str

    def __post_init__(self):
        if len(self.valor) != 6 or not self.valor.isdigit() or not 1 <= int(self.valor[4:]) <= 12:
            raise ValueError(f"Periodo inválido: {self.valor!r} (formato AAAAMM)")

    @property
    def anio(self) -> int:
        return int(self.valor[:4])

    @property
    def mes(self) -> int:
        return int(self.valor[4:])

    def siguiente(self) -> "Periodo":
        return Periodo(f"{self.anio + self.mes // 12}{self.mes % 12 + 1:02d}")


p = Periodo("202612")
print(p, p.anio, p.mes, "→", p.siguiente())
print(Periodo("202609") == Periodo("202609"), Periodo("202609") < Periodo("202610"))
for malo in ("202613", "2026-09", "26"):
    try:
        Periodo(malo)
    except ValueError as e:
        print("❌", e)
try:
    p.valor = "202701"
except Exception as e:
    print("Inmutable:", type(e).__name__)
```

| `@dataclass(...)` | Efecto |
|---|---|
| `frozen=True` | No se pueden cambiar los atributos (y se puede usar como clave de diccionario) |
| `order=True` | Permite `<`, `>`, `sorted()` |
| `__post_init__` | Se ejecuta después de crear: el lugar para **validar** |
| `slots=True` | Usa menos memoria (útil con millones de objetos) |

## ¿Por qué no un simple `str` o `int`?

:::comparar
:::mal Tipos primitivos
```python
def emitir(periodo: str, total: int, iva: int): ...

emitir(total, "202609", iva)          # ¿error? Python no se queja hasta que algo explota
emitir("2026-09", 50000, 0.19)        # formato equivocado, IVA como porcentaje
```
:::
:::bien Tipos del dominio
```python
def emitir(periodo: Periodo, total: Dinero): ...

emitir(Periodo("2026-09"), ...)       # ValueError inmediato, con un mensaje claro
```
El error aparece **donde se cometió**, no tres funciones después. Y mypy (módulo 20) puede detectar argumentos cambiados antes de ejecutar.
:::
:::

## Entidades

Una **entidad** tiene identidad propia que se mantiene aunque cambien sus datos: un cliente sigue siendo el mismo aunque cambie de plan. Se comparan por su identificador:

```python
@dataclass
class Cliente:
    linea: str              # identidad
    plan_id: str            # puede cambiar
    segmento: str

    def __eq__(self, otro):
        return isinstance(otro, Cliente) and otro.linea == self.linea

    def __hash__(self):
        return hash(self.linea)
```

## Reglas puras

Las reglas del dominio son **funciones puras**: el mismo resultado para la misma entrada, sin efectos secundarios. Son las más fáciles de probar y de entender.

```pyrun
from dataclasses import dataclass
from datetime import date

FECHA_CORTE_ANTIGUEDAD = date(2023, 9, 1)


@dataclass(frozen=True)
class Plan:
    plan_id: str
    cargo_fijo: int
    minutos_incluidos: int
    tarifa_minuto: int
    tarifa_minuto_internacional: int


@dataclass(frozen=True)
class Consumo:
    minutos_nacionales: int
    minutos_internacionales: int


def redondear(valor: float) -> int:
    """Al peso más cercano; 0,5 sube."""
    return int(valor + 0.5)


def descuento(plan: Plan, segmento: str, fecha_alta: date) -> int:
    if segmento == "EMPRESARIAL" and fecha_alta < FECHA_CORTE_ANTIGUEDAD:
        return redondear(plan.cargo_fijo * 0.10)
    return 0


def valor_consumo(plan: Plan, c: Consumo) -> int:
    voz = 0 if plan.minutos_incluidos == -1 else max(0, c.minutos_nacionales - plan.minutos_incluidos) * plan.tarifa_minuto
    return voz + c.minutos_internacionales * plan.tarifa_minuto_internacional


emp = Plan("EMP100", 79900, 1000, 100, 800)
print(descuento(emp, "EMPRESARIAL", date(2022, 5, 1)), descuento(emp, "EMPRESARIAL", date(2024, 1, 1)))
print(valor_consumo(emp, Consumo(1042, 3)))
```

:::telco El dominio como documentación
Un archivo `dominio.py` bien escrito es la mejor documentación de las reglas de facturación: alguien de negocio puede leerlo con tu ayuda y confirmar "sí, así es el descuento". Y cuando la regla cambie (porque cambiará), sabes exactamente qué archivo tocar y qué pruebas actualizar.
:::

## Cuestionario

? ¿Qué caracteriza a un objeto de valor?

- [ ] Siempre guarda dinero
- [ ] Se guarda en la base de datos
> Dos objetos de valor con el mismo contenido son intercambiables, como dos billetes de 10.000.

? ¿Dónde se valida que un `Periodo` tenga formato `AAAAMM`?
- [ ] En cada función que lo usa
- [x] En `__post_init__`, al crearlo
- [ ] En la CLI
- [ ] En la base de datos
> Validar al crear garantiza que todo `Periodo` que exista sea válido.

? ¿Por qué las reglas del dominio deberían ser funciones puras?
- [ ] Porque son más rápidas
- [x] Porque con la misma entrada dan el mismo resultado y no tienen efectos secundarios: se prueban y entienden fácilmente
- [ ] Porque Python lo exige
- [ ] Porque así no necesitan parámetros
> Una función pura se prueba con una línea, sin preparar archivos ni bases de datos.
