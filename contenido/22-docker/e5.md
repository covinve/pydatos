## Enunciado

Docker Compose arranca los servicios respetando `depends_on`. Escribe ese cálculo.

`servicios` es un diccionario `{nombre: lista_de_dependencias}`. Escribe:

1. `orden_arranque(servicios)` → lista con todos los servicios en un orden válido: cada uno **después** de sus dependencias. Si hay varios disponibles a la vez, primero el de **nombre menor** (orden alfabético), para que el resultado sea predecible.
   - Una dependencia que no existe → `KeyError` con su nombre.
   - Un ciclo (`a` depende de `b` y `b` de `a`) → `ValueError` con los servicios que quedaron atrapados, en orden alfabético.
2. `niveles(servicios)` → lista de listas: en el nivel 0 los que no dependen de nadie, en el nivel 1 los que solo dependen del nivel 0, etc. (los de un mismo nivel podrían arrancar **en paralelo**). Cada nivel ordenado.
3. `afectados(servicios, caido)` → los servicios (ordenados) que dependen **directa o indirectamente** de `caido`.

## Pruebas

P = {"app": ["bd", "redis"], "bd": [], "redis": [], "reportes": ["app"], "migraciones": ["bd"], "panel": ["reportes", "bd"]}


def prueba_orden():
    """Orden válido y predecible"""
    requiere("orden_arranque")
    igual(orden_arranque(P), ["bd", "migraciones", "redis", "app", "reportes", "panel"])

def prueba_errores():

## Pista 1

El algoritmo de Kahn: lleva la cuenta de cuántas dependencias **pendientes** tiene cada servicio. Los que tienen 0 están listos.

```python
pendientes = {s: len(deps) for s, deps in servicios.items()}
dependientes = {s: [] for s in servicios}
for s, deps in servicios.items():
    for d in deps:
        dependientes[d].append(s)       # KeyError si d no existe
listos = sorted(s for s, n in pendientes.items() if n == 0)
```

Saca siempre el menor de `listos` (`heapq` o `listos.pop(0)` después de ordenar), agrégalo al orden y descuenta 1 a cada uno de sus dependientes.

## Pista 2

Si al terminar el orden tiene menos servicios que el diccionario, los que faltan están en un ciclo (o dependen de uno). Para `niveles`, en lugar de sacar de a uno, saca **todos** los listos de una vez como un nivel. Para `afectados`, recorre `dependientes` desde `caido` (en anchura o profundidad).

## Solución

```python
import heapq


def _dependientes(servicios):
    dependientes = {s: [] for s in servicios}
    for s, deps in servicios.items():
        for d in deps:
            if d not in servicios:
                raise KeyError(f"{s} depende de un servicio que no existe: {d}")
            dependientes[d].append(s)
    return dependientes


def _ciclo(servicios, ordenados):
    atrapados = sorted(set(servicios) - set(ordenados))
    raise ValueError(f"Hay un ciclo de dependencias entre: {', '.join(atrapados)}")


def orden_arranque(servicios):
    dependientes = _dependientes(servicios)
    pendientes = {s: len(set(deps)) for s, deps in servicios.items()}
    listos = [s for s, n in pendientes.items() if n == 0]
    heapq.heapify(listos)
    orden = []
    while listos:
        s = heapq.heappop(listos)
        orden.append(s)
        for d in dependientes[s]:
            pendientes[d] -= 1
            if pendientes[d] == 0:
                heapq.heappush(listos, d)
    if len(orden) < len(servicios):
        _ciclo(servicios, orden)
    return orden


def niveles(servicios):
    dependientes = _dependientes(servicios)
    pendientes = {s: len(set(deps)) for s, deps in servicios.items()}
    nivel = sorted(s for s, n in pendientes.items() if n == 0)
    resultado, vistos = [], 0
    while nivel:
        resultado.append(nivel)
        vistos += len(nivel)
        siguiente = []
        for s in nivel:
            for d in dependientes[s]:
                pendientes[d] -= 1
                if pendientes[d] == 0:
                    siguiente.append(d)
        nivel = sorted(siguiente)
    if vistos < len(servicios):
        _ciclo(servicios, [s for n in resultado for s in n])
    return resultado


def afectados(servicios, caido):
    dependientes = _dependientes(servicios)
    vistos, por_visitar = set(), [caido]
    while por_visitar:
        for d in dependientes[por_visitar.pop()]:
            if d not in vistos:
                vistos.add(d)
                por_visitar.append(d)
    return sorted(vistos)


PIPELINE = {"app": ["bd", "redis"], "bd": [], "redis": [], "reportes": ["app"], "migraciones": ["bd"]}
print(orden_arranque(PIPELINE))
print(niveles(PIPELINE))
print(afectados(PIPELINE, "bd"))
```

## Explicación

Esto es un **ordenamiento topológico**, el mismo cálculo que usan Compose, los gestores de tareas como Airflow, `make` o pip al decidir en qué orden instalar paquetes. Aparece en cualquier problema donde unas cosas deben ocurrir antes que otras: en facturación, "validar → cargar → facturar → conciliar → reportar".

`niveles` muestra la oportunidad de paralelismo: `bd` y `redis` pueden arrancar a la vez; `app` y `migraciones` esperan solo a lo suyo. Es la misma idea del `ProcessPoolExecutor` del módulo 16 aplicada a tareas con dependencias.

`afectados` responde la pregunta operativa: "si la base de datos se cae, ¿qué se rompe?". En un sistema con decenas de servicios, tenerla automatizada ahorra mucho tiempo en un incidente.

El heap (`heapq`) mantiene los listos ordenados de forma eficiente: con miles de nodos, ordenar la lista completa en cada paso sería mucho más lento.
