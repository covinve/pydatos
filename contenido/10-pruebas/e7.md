## Enunciado

`ejercicios/m10-e7/facturacion.py` tiene las reglas de facturación completas del curso (`calcular_factura` y sus funciones auxiliares). **No lo modifiques.**

Escribe en `test_facturacion.py` una batería de pruebas que cumpla dos metas:

1. **Cobertura del 100 %**, incluyendo ramas (`--cov-branch`): cada `if` debe ejecutarse por sus dos caminos.
2. **Atrapar siete mutantes**: versiones del módulo con errores típicos de facturación (redondeo, ilimitados, fecha de corte, segmentos, megas, internacional, tarifas).

Puedes ver tu cobertura mientras trabajas:

```powershell
cd ejercicios/m10-e7
python -m pytest test_facturacion.py --cov=facturacion --cov-branch --cov-report=term-missing
cd ../..
python comprobar.py m10-e7
```

:::consejo Construye tus propios planes
Nada te obliga a usar los planes del catálogo. Para probar una regla en aislamiento, crea un plan a la medida: por ejemplo, uno con minutos ilimitados pero con tarifa distinta de cero. Así una regla mal implementada no queda "escondida" detrás de una tarifa en cero.
:::

## Pista 1

Empieza con una fixture o función auxiliar que construya planes y consumos con valores por defecto, para que cada prueba solo cambie lo que le importa:

```python
def plan(**cambios):
    base = {"cargo_fijo": 35900, "minutos_incluidos": 300, "mb_incluidos": 15360, "sms_incluidos": 100,
            "tarifa_minuto": 120, "tarifa_minuto_internacional": 950, "tarifa_mb": 18, "tarifa_sms": 60}
    return {**base, **cambios}
```

Luego recorre cada regla de **Referencia → Datos del curso** y escribe al menos una prueba por regla, más sus límites.

## Pista 2

Los mutantes más difíciles:

- **Redondeo del banquero:** necesitas un IVA que termine exactamente en ,5 con la parte entera **par** (con impar, `round` y la regla comercial coinciden). Un subtotal de $38.150 da un IVA de $7.248,5: la regla comercial da 7.249 y `round()` da 7.248. Con el plan base, 125 megas adicionales (125 × 18 = 2.250) llevan el subtotal a 38.150.
- **Ilimitado que cobra:** el plan ilimitado del catálogo tiene tarifas en cero, así que el error no se nota. Usa un plan con `minutos_incluidos=-1` y `tarifa_minuto=120`.
- **Fecha de corte:** prueba exactamente `"2023-09-01"`.

## Solución

```python test_facturacion.py
import pytest

from facturacion import calcular_factura


def plan(**cambios):
    base = {"cargo_fijo": 35900, "minutos_incluidos": 300, "mb_incluidos": 15360, "sms_incluidos": 100,
            "tarifa_minuto": 120, "tarifa_minuto_internacional": 950, "tarifa_mb": 18, "tarifa_sms": 60}
    return {**base, **cambios}


def consumo(nac=0, inter=0, mb=0.0, sms=0):
    return {"minutos_nacionales": nac, "minutos_internacionales": inter, "mb": mb, "sms": sms}


RESIDENCIAL = {"segmento": "RESIDENCIAL", "fecha_alta": "2010-01-01"}


def empresarial(fecha_alta):
    return {"segmento": "EMPRESARIAL", "fecha_alta": fecha_alta}


def test_factura_con_todos_los_excesos():
    f = calcular_factura(RESIDENCIAL, plan(), consumo(342, 3, 15500.2, 120))
    assert (f["valor_voz"], f["valor_internacional"], f["valor_datos"], f["valor_sms"]) == (5040, 2850, 2538, 1200)
    assert (f["subtotal"], f["iva"], f["total"]) == (47528, 9030, 56558)


def test_sin_consumo_solo_cargo_fijo():
    f = calcular_factura(RESIDENCIAL, plan(), consumo())
    assert f["subtotal"] == 35900 and f["descuento"] == 0


def test_iva_redondeo_comercial_con_parte_entera_par():
    f = calcular_factura(RESIDENCIAL, plan(), consumo(mb=15360 + 125))
    assert f["subtotal"] == 38150
    assert f["iva"] == 7249


@pytest.mark.parametrize("campo", ["minutos_incluidos", "mb_incluidos", "sms_incluidos"])
def test_ilimitado_no_cobra_aunque_tenga_tarifa(campo):
    f = calcular_factura(RESIDENCIAL, plan(**{campo: -1}), consumo(5000, 0, 99999.0, 5000))
    clave = {"minutos_incluidos": "valor_voz", "mb_incluidos": "valor_datos", "sms_incluidos": "valor_sms"}[campo]
    assert f[clave] == 0


def test_megas_se_redondean_hacia_arriba():
    f = calcular_factura(RESIDENCIAL, plan(), consumo(mb=15360.001))
    assert f["valor_datos"] == 18


def test_descuento_empresarial_antiguo():
    f = calcular_factura(empresarial("2020-05-10"), plan(cargo_fijo=79900), consumo())
    assert f["descuento"] == 7990
    assert f["subtotal"] == 71910


def test_sin_descuento_en_la_fecha_de_corte():
    assert calcular_factura(empresarial("2023-09-01"), plan(), consumo())["descuento"] == 0


def test_residencial_antiguo_sin_descuento():
    assert calcular_factura(RESIDENCIAL, plan(), consumo())["descuento"] == 0
```

## Explicación

Llegar al 100 % de cobertura fue fácil: bastaron unas pocas pruebas. Atrapar los siete mutantes exigió pensar:

| Mutante | Qué lo atrapa |
|---|---|
| Redondeo del banquero | Un IVA terminado en ,5 con parte entera par |
| Ilimitado que cobra | Un plan ilimitado con tarifa distinta de cero |
| `<=` en la fecha de corte | La fecha de corte exacta |
| Descuento para residenciales | Un residencial antiguo |
| Megas sin redondear | Megas con decimales sobre lo incluido |
| Olvida lo internacional | Un consumo con minutos internacionales |
| SMS con tarifa equivocada | Un exceso de SMS en un plan donde las tarifas difieren |

Esta es la lección central del módulo: **la cobertura te dice qué código ejecutaste; los mutantes te dicen qué errores detectarías**. Con 100 % de cobertura y solo el caso del ilimitado del catálogo, el mutante "ilimitado que cobra" habría sobrevivido.
