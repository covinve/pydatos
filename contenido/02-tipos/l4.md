Validar datos es hacer preguntas de sí o no: ¿la duración es positiva?, ¿la línea tiene 10 dígitos?, ¿el tipo es válido? Las respuestas son **booleanos**: `True` o `False`.

## Comparaciones

| Operador | Significado | Ejemplo | Resultado |
|---|---|---|---|
| `==` | igual | `"VOZ" == "VOZ"` | `True` |
| `!=` | distinto | `120 != 0` | `True` |
| `<` `>` | menor, mayor | `-5 < 0` | `True` |
| `<=` `>=` | menor o igual, mayor o igual | `60 >= 60` | `True` |
| `in` | ¿está contenido? | `"VOZ" in ("VOZ", "SMS", "DATOS")` | `True` |

```pyrun
duracion = 125
tipo = "VOZ"

print(duracion > 0)
print(tipo == "voz")              # distingue mayúsculas
print(tipo in ("VOZ", "SMS", "DATOS"))
print(0 <= duracion <= 7200)      # comparación encadenada
```

:::error `=` asigna, `==` compara
`tipo = "VOZ"` le pone la etiqueta `tipo` al texto. `tipo == "VOZ"` pregunta si son iguales. Confundirlos es el error más común al empezar.
:::

## and, or, not

| Operador | Es `True` cuando… |
|---|---|
| `a and b` | ambos son verdaderos |
| `a or b` | al menos uno es verdadero |
| `not a` | `a` es falso |

```pyrun
linea = "3001234567"

tiene_10_digitos = len(linea) == 10 and linea.isdigit()
es_movil = linea.startswith("3")
es_valida = tiene_10_digitos and es_movil

print(tiene_10_digitos, es_movil, es_valida)
print(not es_valida)
```

Una validación completa del CDR se ve así; observa cómo cambian los valores:

```pytrace
tipo = "VOZ"
duracion = -45
tipo_ok = tipo in ("VOZ", "SMS", "DATOS")
duracion_ok = duracion >= 0
es_valido = tipo_ok and duracion_ok
print(es_valido)
```

:::capo Evaluación en cortocircuito
`and` deja de evaluar en cuanto encuentra un `False`, y `or` en cuanto encuentra un `True`. Por eso esto es seguro: `len(linea) == 10 and linea[0] == "3"`. Si la línea está vacía, nunca se evalúa `linea[0]` (que daría error).
:::

## Verdadero y falso más allá de True y False

Cualquier valor puede usarse como condición. Estos valores se consideran **falsos**; todo lo demás es verdadero:

| Falsos |
|---|
| `False`, `None` |
| `0`, `0.0` |
| `""` (texto vacío) |
| `[]`, `()`, `{}` (colecciones vacías) |

```pyrun
print(bool(""))
print(bool("  "))      # ¡un espacio no es vacío!
print(bool("  ".strip()))
print(bool(0), bool(-1))
print(bool("False"))   # texto no vacío: verdadero
```

## None: la ausencia de valor

`None` significa "no hay dato". **No es lo mismo** que `0` ni que `""`:

- Un cliente con **0 minutos** habló cero minutos: hay dato.
- Un cliente con **minutos `None`** no tiene registro: no sabemos cuánto habló.

Se pregunta por `None` con `is`, no con `==`:

```pyrun
fecha_baja = None
descuento = 0

print(fecha_baja is None)
print(descuento is None)
print(descuento == 0)
```

:::telco Vacío no es cero
En un CDR, `linea_destino` vacía en un registro de `DATOS` es normal: no hay destino. Pero `linea_origen` vacía es un error (`linea_vacia` en las reglas del curso). Confundir "vacío", "cero" y "no hay dato" produce validaciones que dejan pasar registros malos o rechazan registros buenos.
:::

? ¿Cuál de estos valores es **verdadero** al usarlo como condición?
- [ ] `""`
- [ ] `0`
- [x] `"0"`
- [ ] `None`
> `"0"` es un texto con un carácter: no está vacío, así que es verdadero. Solo el texto vacío `""` es falso.

? ¿Cuál es la forma recomendada de preguntar si `fecha_baja` no tiene valor?
- [ ] `fecha_baja == None`
- [x] `fecha_baja is None`
- [ ] `fecha_baja == 0`
- [ ] `not fecha_baja == ""`
> `None` es un valor único y se compara con `is`. Además, `== None` puede comportarse distinto en objetos como las columnas de Pandas.
