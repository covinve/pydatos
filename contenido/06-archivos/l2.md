## Texto, bytes y codificación

Un archivo en disco guarda **bytes** (números de 0 a 255). Una **codificación** (*encoding*) es la regla que traduce esos bytes a caracteres.

```pyrun
texto = "Gómez"

en_utf8 = texto.encode("utf-8")
en_latin1 = texto.encode("latin-1")

print(en_utf8, len(en_utf8), "bytes")
print(en_latin1, len(en_latin1), "bytes")
```

La `ó` ocupa **dos bytes** en UTF-8 (`\xc3\xb3`) y **uno** en latin-1 (`\xf3`). Si lees con una regla distinta a la que se usó para escribir, aparecen los problemas:

```pyrun
bytes_utf8 = "Gómez".encode("utf-8")
bytes_latin1 = "Gómez".encode("latin-1")

print(bytes_utf8.decode("latin-1"))    # UTF-8 leído como latin-1 → mojibake
print(bytes_latin1.decode("utf-8"))    # latin-1 leído como UTF-8 → error  # error esperado
```

| Síntoma | Causa probable | Solución |
|---|---|---|
| `GÃ³mez`, `NÃºÃ±ez` | Archivo **UTF-8** leído como latin-1/cp1252 | Leer con `encoding="utf-8"` |
| `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xf3` | Archivo **latin-1** leído como UTF-8 | Leer con `encoding="latin-1"` |
| `ï»¿cdr_id` al inicio del archivo | UTF-8 **con BOM** (típico de Excel) | Leer con `encoding="utf-8-sig"` |
| `G?mez` o `G�mez` | Alguien convirtió mal antes y **se perdió** el carácter | No tiene arreglo: hay que pedir el archivo de nuevo |

:::reto Repara el mojibake
Un sistema guardó los nombres en UTF-8 y otro los leyó como latin-1. Por eso ves `GÃ³mez`. Como los bytes no se perdieron, el daño se puede deshacer: vuelve a los bytes con la codificación **equivocada** y decodifícalos con la **correcta**.

Escribe `reparar(texto)` que haga ese viaje de ida y vuelta.

:::capo latin-1 nunca falla al leer
latin-1 asigna un carácter a **cada uno** de los 256 bytes posibles. Por eso leer cualquier archivo como latin-1 nunca da error… pero si el archivo era UTF-8, el resultado será basura. "No da error" no significa "está bien".
:::

## Cómo saber la codificación de un archivo

No hay una forma 100 % segura, pero esta estrategia funciona casi siempre: **intenta UTF-8; si falla, es latin-1** (o cp1252, su primo de Windows).

```pyrun
from pathlib import Path

Path("clientes_legado.csv").write_bytes("cliente_id,nombre\nCL1,Inés Núñez\n".encode("latin-1"))
Path("clientes_nuevo.csv").write_bytes("cliente_id,nombre\nCL1,Inés Núñez\n".encode("utf-8"))


def detectar_encoding(ruta, muestra=1_000_000):
    datos = Path(ruta).read_bytes()[:muestra]
    try:
        datos.decode("utf-8")
        return "utf-8"
    except UnicodeDecodeError:
        return "latin-1"


for nombre in ["clientes_legado.csv", "clientes_nuevo.csv"]:
    enc = detectar_encoding(nombre)
    print(nombre, "→", enc, "→", Path(nombre).read_text(encoding=enc).splitlines()[1])
```

:::consejo Revisa los bytes cuando dudes
`Path(ruta).read_bytes()[:200]` te muestra los primeros bytes crudos. Si ves `\xc3` seguido de otro byte, es UTF-8; si ves `\xe1`, `\xe9`, `\xf3` sueltos, es latin-1.
:::

:::pista
`with open("clientes.csv", encoding="latin-1") as f:` y `next(f)` para saltar el encabezado. Con `campos = linea.rstrip("\n").split(",")`, el nombre es `campos[1]` y la ciudad `campos[5]`.

```pyprueba
def _esperado():
    nombres, lugares = [], set()
    with open("clientes.csv", encoding="latin-1") as f:
        next(f)
        for linea in f:
            c = linea.rstrip("\n").split(",")
            if "ñ" in c[1]:
                nombres.append(c[1])
            lugares.add(c[5])
    return nombres, lugares


def prueba_nombres():
    """con_enie tiene los nombres con ñ, bien escritos"""
    requiere("con_enie")

    igual(con_enie, _esperado()[0])


def prueba_ciudades():
    """ciudades tiene las ciudades distintas"""
    requiere("ciudades")
    igual(set(ciudades), _esperado()[1])
```

## La opción `errors`

Cuando un archivo tiene **algunos** bytes dañados y no puedes pedir otro, `errors=` decide qué hacer:

```pyrun
datos = b"Juan P\xe9rez|3001234567\nAna G\xc3\xb3mez|3109876543\n"   # mezcla de encodings

print(datos.decode("utf-8", errors="replace"))   # reemplaza lo inválido por �
```

| Valor | Efecto |
|---|---|
| `"strict"` (por defecto) | Lanza `UnicodeDecodeError` |
| `"replace"` | Reemplaza por `�` y sigue |
| `"ignore"` | Descarta los bytes inválidos (peligroso: pierdes información sin enterarte) |

## Convertir un archivo a UTF-8

La mejor práctica: convierte los archivos legados a UTF-8 **una vez**, al recibirlos, y trabaja siempre en UTF-8:

```pyrun
from pathlib import Path

Path("legado.csv").write_bytes("nombre\nMuñoz\nPeña\n".encode("latin-1"))

with open("legado.csv", encoding="latin-1") as origen, \
     open("convertido.csv", "w", encoding="utf-8") as destino:
    for linea in origen:
        destino.write(linea)

print(Path("convertido.csv").read_bytes())
```

Fíjate que se procesa **línea por línea**: funciona igual con un archivo de 10 GB.

Convierte `clientes.csv` (latin-1) en `clientes_utf8.csv` (UTF-8), **línea por línea**. Una conversión de encoding no cambia el contenido: el texto del archivo nuevo debe ser idéntico al original, solo cambian los bytes con que se guarda.

## Cuestionario

? Abres un archivo y ves `NÃºÃ±ez`. ¿Qué pasó?
- [x] Un archivo UTF-8 se leyó como latin-1/cp1252
- [ ] Un archivo latin-1 se leyó como UTF-8

> Cada carácter acentuado de UTF-8 son dos bytes; leídos como latin-1 se convierten en dos caracteres raros (`Ãº`).

? ¿Por qué leer todo como latin-1 "para que nunca falle" es mala idea?
- [ ] Porque es más lento
- [x] Porque nunca da error, pero si el archivo era UTF-8 el texto queda mal sin que te enteres
- [ ] Porque latin-1 no existe en Python

> latin-1 acepta cualquier byte, así que oculta el problema en lugar de avisarte.

? Un CSV exportado desde Excel empieza con `ï»¿cdr_id`. ¿Con qué encoding lo lees?
- [ ] `latin-1`
- [ ] `ascii`
- [x] `utf-8-sig`
- [ ] `cp1252`
> Esos tres caracteres son la marca BOM de UTF-8. `utf-8-sig` la reconoce y la descarta.
